本页集中说明 CLI 与 MCP 的共同业务规则。具体命令与工具参数分别看[CLI 参考](/cn/cli/reference)和[MCP 参考](/cn/mcp/tools)。当前依据是已发布 CLI 0.14.0／MCP 1.12.0。搜索附加费以实际返回的 `search_charges` 为准。

<span id="models" />
## 如何选择模型

1. 先确定任务类型：图片生成或编辑、文生／图生视频、音乐或语音；整理数量、画质、时长、参考素材和预算。
2. 查询当前账户可用目录，使用返回的准确模型 ID，核对参数 schema。系列名、别名和展示名不能自动当作提交 ID。
3. 优先比较符合任务的新款或推荐系列，再按质量、素材支持、费用和等待时间解释选择理由。平台没有提供热度统计时，不声称某型号“最火”。
4. 确认该模型的必填字段、范围和互斥参数，再用最终输入估价。换模型或改输入后重新确认。

可优先比较的系列包括图片 GPT Image 2.5／2.0、Seedream 5.0，视频 Seedance 2.5／2.0、Wan 3.0，音乐 Suno v6；这些名称是查询方向，不保证当前账户全部可用。旁白和配音应选语音模型。示例型号用于说明流程，不构成默认推荐。

| 要查询的内容 | CLI | MCP |
|---|---|---|
| 可用模型 | `models search`、`models recommend` | `search_models`、`recommend_models` |
| 准确参数与限制 | `models show`、`models schema` | `get_model` |
| 模型资料 | `docs search` | `search_docs` |
| 最终输入的预计费用 | `estimate` | `estimate_cost` |

<span id="pricing" />
## 如何阅读报价

| 报价状态 | 意义 | 下一步 |
|---|---|---|
| `estimated` | 返回预计金额，仍以实际结算为准 | 展示方案、费用及已知限制，再取得本次批准 |
| `partial` | 价格因素不完整 | 不当作完整总价；说明缺少因素，补齐后再确认 |
| `token_billed` | GPT Image、Gemini Omni Flash 按 token 计费模型的参考价：提交时预扣的金额，按实际 token 结算 | 作为参考价展示，不当作固定总价；完成后按实际用量多退少补 |
| `needs_input` | 缺少必要输入 | 补齐时长、参考等信息后重新估算 |
| `no_price` | 没有可用价格 | 不写成免费，不自动提交 |

GPT Image 按 token 计费的模型（`gpt-image-1.5`、`gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`）返回 `token_billed` 和参考价，即这次输入在提交时会预扣的积分：按尺寸和画质算出的输出 token、提示词 token，以及每张参考图或遮罩 1,536 token，再乘以 `n`。`size` 为 `auto` 时按 2048×2048 计算，填写尺寸后参考价更接近实际。`gpt-image-2.6` 生成 GIF 时，按所有帧拼成的那一张图计算（`size` 为 `auto` 时每帧 512×512）。任务完成后按实际 token 用量结算，多退少补，实际可能更低或略高。这些模型不采用 `pricing_parameters` 里的 token 数。设置 `max_cost_usd` 时，参考价的 1.5 倍不超过上限才会提交。

Gemini Omni Flash 视频模型（`gemini-omni-flash-*`、`gemini-omni-1.1-flash-*`、`gemini-omni-1.2-flash-*`）也返回 `token_billed` 和参考价，算法和提交时的预扣一样：按输出的清晰度和时长算视频输出 token，加上提示词 token、每张输入图片 2,020 token，以及输入视频或参考视频的 token。有输入视频或参考视频时，把视频时长填进 `media_seconds`（MCP）或 `--media-seconds`（CLI）；有几个参考视频时，填最长的那个。没有时长就算不出参考价，估价会提示补上。请求里不带视频的清晰度，EvoLink 要到提交时才读取，所以参考价按 4k 计算，同时给出输入为较低清晰度时的价格（一般是 720p），两个价格都要展示给用户。这些模型同样不采用 `pricing_parameters` 里的 token 数，`max_cost_usd` 也按参考价的 1.5 倍比较。任务完成后按实际 token 用量结算，多退少补。

把用量填成 0、使总价为 0 时，按缺少用量处理：媒体生成没有免费的。

同时检查 `input_valid`、`problems`、`basis` 与 `warnings`。目录起价不能替代本次完整报价。分辨率、声音、参考素材、实际输入时长和音频计费方式都可能影响费用。

Seedance 2.5 生成开启 `draft: true` 且省略 `quality` 时，使用 `480p`。报价返回 `effective_input` 和 `defaults_applied` 时，确认前展示这些实际生效的参数，生成按同一组参数提交。草稿转正式有独立输入；某个模型的检查规则不自动适用于其他模型或操作。

`seedance-2.5-video-edit` 的 `input.duration: -1` 表示编辑模式。估价所需的预计输出秒数单独放在 `pricing_parameters.duration_seconds`，不替代生成参数，也不代表最终实际用量。

搜索默认关闭的七个媒体入口是 `doubao-seedream-5.0-lite`、`gemini-3-pro-image-preview`、`gemini-3.1-flash-image-preview`、`gemini-nano-banana-2.1`、`seedance-2.0-text-to-video`、`seedance-2.0-fast-text-to-video` 和 `seedance-2.5-text-to-video`。Seedream 用 `model_params.tools: [{"type":"web_search"}]` 开启；其余用 `model_params.web_search: true`。Gemini 3.1 Flash Image 和 Nano Banana 2.1 还支持独立的 `model_params.image_search: true`。

用户未明确要求或同意开启时，Agent 应保持网页和图片搜索关闭，不能自行开启，也不能因为示例开启就照抄。Agent 认为需要搜索时，应先说明每次搜索的附加费和总费用未知，等待用户明确同意后再开启。不含搜索的任务批准不授权追加搜索；改变搜索设置后要重新估价并取得批准。这是 Agent 的操作指引，服务端不会核验聊天中的同意。

搜索关闭时无需额外收费提醒。最终请求开启搜索时，即使用户已要求搜索，也要在批准生成前说明每种搜索的动态单价。次数未知时展示“按 0 次搜索计算的已知费用部分，不含搜索费”，标为 `partial`；其他未知用量（例如文本或思考 token）也不包含在小计中。一条任务可能不触发搜索，也可能搜索多次；实际次数受任务内容和模型执行策略影响，生成前无法确定搜索总费用。网页与图片搜索分别计费。

`pricing_parameters.search_count` 和 `image_search_count` 表示预计用量，不限制执行次数；预计 0 次不等于关闭搜索。不完整估价无法比较用户明确设置的预算。不能编造预计次数来消除未知项。旧客户端如果把“搜索开启、未给预计次数”报成完整估价，应先升级，再批准该报价。

已发布版本主要使用公开默认价，并非完整的账户折扣、实际计量或账户结算 Quote。新价格接口和候选代码存在，不表示生产客户端已经接入。报价不完整或无法比较用户预算时暂停提交，解释缺少的信息。美元换算参考为 68 积分约 $1，具体以实际响应和账户记录为准。

<span id="approval" />
## 费用批准与预算

展示准确模型、最终输入、输出规格、数量、预计费用及限制，再由用户明确批准本次生成。修改模型、素材、参数、身份或价格后，重新核价与确认。批准 24 小时内有效；过期后，只要输入和价格都没变，仍按原批准提交，结果里会说明（`approval_expired`）。

| 约束 | 当前含义 |
|---|---|
| 账户登录 | 允许使用账户服务 |
| 宿主工具或命令许可 | 允许 Agent 执行操作 |
| 单次费用批准 | 用户接受本次方案与预计费用 |
| 显式 `max_cost_usd` | 已发布版提交前与估价比较（参考价要按 1.5 倍比较），**不是最终扣费硬上限** |
| 平台 Key 额度 | 账户设置的日额度、总额度和权限约束 |

这些约束分别检查。不能把登录或宿主许可当作费用批准；不能删预算、换 Key 或换入口绕过拒绝。最终扣费硬上限仍需对应服务端能力上线，当前文档不承诺结算绝不超额。

CLI 保存本地 `quote_id`，使用 `--confirm` 提交；原生 MCP 由 Agent 保存本次输入、估价与明确批准记录，没有 CLI 的本地报价文件或会话级服务端批准按钮。操作步骤分别见[CLI 确认流程](/cn/cli/billing#pricing)和[MCP 确认流程](/cn/mcp/billing#pricing)。

<span id="skip-estimate" />
### 不估价直接生成

用户明确说不用估价、不用确认（例如“直接生成”）时，Agent 不报价，直接提交：MCP 传 `skip_estimate: true`，CLI 加 `--skip-estimate`。范围按用户说的来：这一个任务、这一批，或这次对话后面的所有生成。Agent 不能从沉默、余额或自己的建议推断用户同意。用户说这次对话后面都不用估价时，Agent 要提醒一次：后面的生成会直接提交、不再询问；想恢复估价，可以新开一个对话，或直接说“恢复估价”。输入不合法、用户明确给的预算仍会检查；开启搜索仍要用户同意；任务按实际用量计费。用户没说不用估价、而估价失败或给不出总价时，Agent 先问一句：要不要按实际用量直接生成。

<span id="batches" />
### 同一模型的多个任务

一次估价最多可以包含同一模型的 50 个输入（MCP 用 `inputs`，CLI 用 `--inputs-file`）：返回每个输入的价格、总价，以及只针对这一批的一个批准。批准后，一次调用提交所有输入，不等出图，马上返回任务编号；结果用 `list_tasks` 或 `tasks batch` 收。有的输入没提交成功时，用同一个请求编号和完全相同的输入补交：MCP 在 24 小时内用同一个 `client_request_id` 再调用一次；CLI 在第一次提交后 23 小时内运行 `tasks resume --quote`。已经成功的输入返回原来的任务，不会重复扣费。已成功、未提交、结果未知的输入，都不能换新的请求编号重新提交。GPT Image 等模型常常返回比 `n` 少的图片，所以每张图用一个输入。

<span id="authorization" />
## 账户权限、余额与额度

同账户 CLI 与远程 MCP OAuth 当前可以共用内部 Key 的权限、额度与暂停状态。调整共享 Key 会影响使用它的入口；每个宿主和 CLI 的登录会话仍分别管理。本地 stdio 按它配置的个人 API Key 执行。

模型、余额和任务查询不提交媒体生成。生成会计费，上传另受文件服务限制。额度或权限不足时处理对应账户设置；重新登录不会自动补余额或解除 Key 暂停。

任务明确失败（`status: failed`）时不收费，提交时预扣的积分会自动退回。超时、退出或关闭页面不能证明没有扣费或已经退款；退款是否已经到账，只能以明确返回的账务证据为准，用量查询不等于完整账单。

<span id="troubleshooting" />
## 搜索为空、参数报错或报价不完整

1. 放宽搜索关键词，保留任务和素材能力要求，确认实际账户与权限。
2. 重新查本型号 schema，检查字段名、必填项、枚举、数值范围和参考互斥；不复制其他型号参数。
3. 用最终输入重新估价，按上方状态表处理；不能用起价补齐未知倍率。
4. 尚未提交时重新确认；已提交或结果未知时先[恢复原任务](/cn/cli-mcp/tasks-and-files#recovery)。

具体错误字段与处理分别见[CLI 模型排错](/cn/cli/billing#models-and-pricing)和[MCP 模型排错](/cn/mcp/billing#models-and-pricing)。
