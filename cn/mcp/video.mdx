## 选择合适的输入方式

| 任务 | 需要检查 |
|---|---|
| 文生视频 | 提示词、时长、画幅、分辨率、是否带声音 |
| 图生视频 | 参考图片数量、首帧/尾帧字段和图片要求 |
| 参考视频或背景编辑 | 模型是否支持视频参考、文件时长、画质与声音要求 |
| 延长或升清晰度 | 专用型号及它支持的 `source_task_id` 或媒体输入 |

可以先比较 Seedance、Wan 等适用型号；明确指定模型时尊重用户选型。参数以实时 `get_model` / `models show` 为准，不能把 `video_urls` 等字段放进不支持它的模型。

## 示例需求

```text
用 EvoLink 做一段帆船出海短片：米白船帆、灰蓝海面、阴天柔光，纪实镜头。
想要 5 秒横版视频。先查模型、确认清晰度和声音设置，再报价，等我确认。
```

智能体先准备参数，再用 `estimate_cost` 或 CLI `estimate` 报价。用户批准后调用 `generate_video`，或 `evolink generate video --quote QUOTE_ID --confirm`。

## 参考视频费用

参考素材按[上传指南](/cn/mcp/files)提供。上传限制不等于模型限制：即使文件上传成功，模型仍可能对秒数、大小、分辨率或音轨有更严格要求。

<Warning>
按秒计费的视频请求如果包含 `video_urls`、`video_url` 或 `source_task_id`，发布价可能不能覆盖全部输入视频费用。MCP 会标记部分估价，并拒绝用 `max_cost_usd` 放行；补 `media_seconds` 不能解决这个缺口。不要未经许可删除预算重试。
</Warning>

分辨率、声音和参考素材可能影响价格。完整说明见[费用与上限](/cn/mcp/billing)。

## 等待和交付

视频一般是异步任务。保存返回的 `task_id`，用 `get_task` 查询；CLI 可用：

```bash
evolink tasks wait TASK_ID --timeout 1800 --json
evolink download TASK_ID --output ./sailing.mp4 --json
```

等待超时不代表生成失败。不要重复提交来查进度。完成后交付原视频链接和费用；内嵌首帧只是预览，不是完整视频。客户端可能不能内嵌播放，仍应提供可打开的原链接。自动换音轨、加字或本地修片需要另行得到用户授权。
