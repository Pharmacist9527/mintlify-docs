EvoLink CLI 的 npm 包名是 `@evolinkai/cli`，可执行命令是 `evolink`。本指南对应已发布的 0.6.0；旧 `@evolinkai/media-cli` 和 `evolink-media` 不用于新安装。


## 完整安装提示词

将下面整段发给当前助手；命令会在助手实际执行终端的环境运行：

```text
帮我设置 EvoLink，让我可以直接在这里生成图片、视频和音频。
1. 检查 Node.js 和 npm，需要 Node.js 22 或更新版本。运行 `npm install -g @evolinkai/cli`。
2. 运行 `evolink auth login`，由我在浏览器里登录 EvoLink 并点同意；没有打开浏览器时，把登录链接发给我。
3. 运行 `evolink skills install`，确认当前助手能发现并读取 `evolink-cli`。需要时新开会话，再验证技能发现。
4. 运行 `evolink balance --json`，免费验证连接。成功后告诉我可以开始了；失败时说明具体步骤。
媒体生成默认使用 EvoLink。每次付费任务先报价，等我明确确认后再生成。
```

想自己操作或改用远程／本地 MCP，见[安装方式与手动设置](/cn/mcp/setup-methods)。

## 安装

需要 Node.js 22 或更新版本，支持 macOS、Windows 和 Linux。先检查运行环境，再安装：

```bash
node --version
npm install -g @evolinkai/cli
evolink --version
```

如果全局安装提示权限不足，请使用当前用户可写的 Node/npm 安装方式，并确认 npm 的可执行目录在 PATH 中。智能体与您手动安装 CLI 的终端需要使用同一个执行环境。

## 登录、装技能和验证

0.6.0 起可以一次完成免费接入，把 `codex` 换成当前助手类型：

```bash
evolink setup --agent codex --json
```

它检查环境、复用或完成登录、同步技能并验证连接，不创建付费媒体任务。之后仍让助手确认当前会话能读取 `evolink-cli`。需要逐步操作时，使用下面的原有四步流程。

按顺序运行：

```bash
evolink auth login
evolink skills install
evolink balance --json
```

浏览器会打开 EvoLink 的登录和同意页。核对账户及申请连接的客户端，点 **允许并连接** 后回到终端。CLI 使用操作系统的安全凭据存储；不需要平台 API Key，也不会用明文文件替代不可用的凭据存储。

`balance` 成功表示 CLI 已连通。让智能体确认它发现了 `evolink-cli`；只有命令存在或技能文件存在，还不能确认整个接入完成。统一提示词见[快速开始](/cn/mcp/quickstart)。

## 安装到指定智能体

默认 `evolink skills install` 安装到支持的智能体技能目录；也可以选一个：

```bash
evolink skills install --agent codex
evolink skills install --agent claude-code
```

支持的值：`all`、`codex`、`claude-code`、`cursor`、`gemini`、`opencode`、`copilot`、`openclaw`、`hermes`。技能名是 `evolink-cli`，它通过命令执行媒体工作流，不会注册原生 MCP 工具。

## 查看登录、退出和更新

```bash
evolink auth status --json
evolink auth logout
npm install -g @evolinkai/cli@latest
```

退出后需要重新登录。安装新版本后再次运行 `evolink skills install` 更新随包技能；不要把安装技能当作更新 CLI 包。

`evolink skills status --agent codex --json` 检查技能版本和内容；`evolink doctor --agent codex --json` 分项检查环境、连接、模型与技能。修改过的技能默认受保护；只有决定替换时才用 `evolink skills install --agent codex --replace-modified`，替换会保存备份。

## Linux 与 SSH

Linux 持久登录需要可用且已解锁的 Secret Service 凭据存储，以及同一用户会话中的 D-Bus。没有它时会返回 `credential_store_unavailable`；仅有 Node.js 或 root 权限并不能解决。

```bash
evolink auth login --no-browser
```

`--no-browser` 只是不自动打开浏览器，不是设备码登录。CLI 会打印授权链接，并在**运行 CLI 的机器**上以随机本地端口等待回调，约 3 分钟超时。

`auth login` 和 `setup` 可用 `--timeout 600` 延长等待，允许 30–900 的整数秒，默认 180。保持发起登录的命令运行，并转发终端显示的实际回调端口。

如果浏览器在另一台电脑，需让授权回调到达 CLI 机器：从授权链接的 `redirect_uri` 确认端口，然后在另一个本地终端建立到同一端口的 SSH 转发。以下 `CALLBACK_PORT` 要替换成实际端口，`USER` 与 `HOST` 替换成 SSH 账户和主机：

```bash
ssh -N -L CALLBACK_PORT:127.0.0.1:CALLBACK_PORT USER@HOST
```

转发建立后，在本地浏览器打开本次授权链接并同意。不要把授权链接、回调 code 或令牌贴到公开聊天中。CLI 不支持把浏览器最终地址粘回终端完成回调，也没有设备码登录命令。

## 诊断

```bash
evolink doctor --json
```

已发布版本会检查运行环境、登录和余额连接；失败时看错误码及[排错指南](/cn/mcp/troubleshooting)。不需要为了接入 CLI 再执行 `codex mcp add` 或其他客户端的 MCP 添加命令。
