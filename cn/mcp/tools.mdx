## MCP 工具参考

本页说明远程 OAuth MCP 的 22 个工具。五个工作流工具（`get_media_workflow`、`analyze_video`、`get_video_analysis`、`generate_workflow_media`、`record_workflow_delivery`）和 `make_frames` 只提供给已登录的远程连接。工具名以实际 `tools/list` 为准。本地 stdio 不提供 `prepare_upload` / `get_upload`，`upload_file` 可增加已允许目录的本地路径。

JSON 中的 `name` / `arguments` 表示让 MCP 客户端调用工具，不是 REST 请求体；它们也不代表已批准费用。

| 工具 | 用途 | 生成计费 |
|---|---|---|
| search_models | 搜索可用模型与别名 | 无 |
| recommend_models | 比较符合需求和参考输入的模型 | 无 |
| search_docs | 搜索版本化官方模型参考索引 | 无 |
| get_model | 参数、schema、参考输入和价格 | 无 |
| estimate_cost | 检查输入与估价 | 无 |
| get_pricing_rules | 读取价格规则：登录或使用 API Key 时是你账户自己的价格，否则是公开默认价（参考价，不是报价） | 无 |
| generate_image | 图片生成/编辑 | 有 |
| generate_video | 视频生成/编辑/延长 | 有 |
| generate_audio | 音乐、歌曲或语音 | 有 |
| get_task | 单任务状态、结果与费用 | 无 |
| list_tasks | 批量 ID 查询或分页历史 | 无 |
| get_task_usage | 有限范围的已报告任务费用汇总 | 无 |
| check_balance | 账户余额和共享额度 | 无 |
| upload_file | URL/base64 参考上传 | 无，受文件配额限制 |
| prepare_upload | 本地大文件的一次性上传地址 | 无，受文件配额限制 |
| get_upload | 原上传状态与链接 | 无 |
| get_media_workflow | 读取工作流的分步规则和一个预估总价 | 无 |
| analyze_video | 为工作流的某一步分析视频 | 有，按 token |
| get_video_analysis | 取回还在进行的视频分析 | 无 |
| generate_workflow_media | 把一次付费生成作为工作流某一次运行的一个步骤提交 | 有 |
| record_workflow_delivery | 记录工作流某一次运行交付的是哪一条已完成的视频 | 无 |
| make_frames | 为不能运行命令的助手抽帧、裁剪、做视频总览图和带编号的拼图 | 无 |

### search_models

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| type | string | 否 | image/video/audio/all，默认 all |
| query | string | 否 | 最多 100 字符的搜索关键词 |
| limit | integer | 否 | 1–50，默认 20 |
| page | integer | 否 | 1–100000，默认 1 |

```json
{"name":"search_models","arguments":{"type":"image","query":"seedream","limit":5,"page":1}}
```

返回 models、total_matches、page、page_size、next_page；模型含规范 id、aliases、参考输入、文档覆盖和起价。关键词相关性优先，再考虑有无单价、平台偏好和 ID。不是质量/热度排名，起价不是任务总价，分页间可用性可能改变。

### recommend_models

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| type | string | 是 | image/video/audio |
| query | string | 否 | 最多 100 字符，所有搜索词需匹配 |
| references | string[] | 否 | image/video/audio，最多 3 项，默认空数组 |
| limit | integer | 否 | 1–10，默认 3 |

```json
{"name":"recommend_models","arguments":{"type":"video","query":"seedance","references":["image"],"limit":3}}
```

返回 documented 模型、reasons、reference_inputs、selection_basis 和单价。要求参考类型有明确输入字段；无匹配时应调整条件，不默默放弃所需参考。平台偏好是编辑规则，不是实时热门/发布日期榜。

### search_docs

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| query | string | 是 | 去空白后 1–100 字符 |
| type | string | 否 | image/video/audio/all，默认 all |
| limit | integer | 否 | 1–20，默认 5 |

```json
{"name":"search_docs","arguments":{"query":"first frame","type":"video","limit":5}}
```

返回 documents、total_matches、scope 和来源版本。检索当前可用模型的随包官方参考标题、ID 与参数描述，不抓取实时全站内容，也不是账户/账单文档搜索。

### get_model

必填 `model`，string，1–128 字符；使用搜索返回的 ID 或受支持别名。

```json
{"name":"get_model","arguments":{"model":"z-image-turbo"}}
```

返回规范型号、参数要求、示例、价格（登录或使用 API Key 时按你账户自己的价格）、reference_inputs、parameters_source，存在时给出 input_schema 及 schema 来源。参数与 schema 随版本维护，当前账户可用性实时查询；有缺失信息时遵循警告，不自行推断默认值。

### estimate_cost

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| model | string | 是 | 1–128 字符 |
| input | object | 否 | 计划提交的模型参数，省略为空对象 |
| inputs | object[] | 否 | 同一模型的 1–50 个输入，代替 input，顺序就是提交顺序 |
| pricing_parameters | object | 否 | 价格规则需要的实测用量或用户明确预期的用量，例如 `{"search_count":2}`；最多 100 项。GPT Image、Gemini Omni Flash、Qwen TTS 的 token 数不从这里取。不要编造 |
| pricing_source | string | 否 | 默认 pricing_rules，即已发布的价格规则；旧取值 account、public_reference 仍可传入，效果相同 |
| media_seconds | number | 否 | 大于 0、不超过 3600，仅估价用 |

```json
{"name":"estimate_cost","arguments":{"model":"z-image-turbo","input":{"prompt":"A cream ceramic coffee cup on a white background"}}}
```

返回 input_valid、problems、warnings、estimate、pricing_scope（`account` 是你账户自己的价格，`public_default` 是不含账户折扣的公开默认价）、final_budget_enforced，以及能读取时的余额/额度。estimate.status 可为 estimated、partial、token_billed、needs_input、no_price；token_billed 带参考价，按实际 token 结算。价格取决于输入里没有的用量时，估价不给金额，也不给 `pricing_quote`：`total_known` 为 false，`missing_usage` 列出缺少的每一项，`usage_help` 说明怎么补。见[费用说明](/cn/mcp/billing)。查询成功不等于输入有效或报价完整。

可以确认的估价还会返回 `pricing_quote`，也就是这次输入的批准凭证。用户批准后，把它和同样的输入一起传给生成工具。凭证从估价时起 24 小时内有效（`expires_at`），价格不高于批准时的价格：生成工具会重新估价，价格没变或更低就提交，价格规则更新过也一样。价格变高会被拒绝（`price_changed`），输入变了是 `quote_input_changed`，凭证过期是 `quote_expired`；这三种情况都要重新估价、重新确认。传 `inputs` 时，结果列出每个输入的估价和总价，一个 `pricing_quote` 只批准这几个输入，并且按这个顺序。它不能批准单个输入，单个输入的 `pricing_quote` 也不能批准一整批。

该工具没有 `max_cost_usd`，也不会返回 CLI 本地报价编号。MCP 预算放在生成工具。media_seconds 不改变输出时长，不补全未知参考视频倍率。

### get_pricing_rules

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| model | string | 否 | 单个模型 ID，最多 100 字符 |
| product_id | string | 否 | 按产品系列筛选 |
| operation | string | 否 | 按操作筛选，例如 `text_to_video` |
| modality | string | 否 | `text`、`image`、`video`、`audio` |
| lifecycle | string | 否 | `active`、`preview`、`deprecated` |
| view | string | 否 | `summary` 或 `full`，默认 `full` |

```json
{"name":"get_pricing_rules","arguments":{"model":"seedance-2.5-text-to-video","view":"full"}}
```

返回价格规则：各计费组件的单价（十进制字符串）、最低收费、档位和完整表达式，以及 price_scope、price_selection。登录或使用 API Key 时是你账户自己的价格（`price_scope: account`），否则是不含账户折扣的公开默认价（`price_scope: public_default`）。这是参考价，不是任务报价、账单或最终花费上限；不要把单价直接乘成账单。某次生成的预计费用仍用 `estimate_cost`，它按同一套规则对实际输入计算。结果为空只表示没有匹配的规则，不表示免费。查整份目录时，个别模型的规则读不出或不完整，会被略过并列在 `rejected_models`，`warnings` 里写出这些 ID，其余模型照常返回；被略过不表示免费。查单个模型时规则读不出仍直接报错。

### generate_image、generate_video、generate_audio

三工具共用顶层参数，按输出类型选择：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| model | string | 是 | 1–128 字符，对应媒体类型 |
| input | object | 否 | 按 get_model 的模型参数填，不放 model/callback_url |
| inputs | object[] | 否 | 同一模型的 1–50 个输入，代替 input，一次调用提交；见[整批提交](#batches) |
| prompt | string | 否 | input.prompt 的快捷方式，最多 20000 字符，仍受模型限制 |
| client_request_id | string | 否 | 16–96 字符，字母数字及 . _ -；同一请求恢复时复用；用 inputs 时最多 93 字符，因为每一项会加上 .NN |
| pricing_quote | object | 否 | estimate_cost 返回的批准凭证，只对应这次的输入或这一批，到 expires_at 为止有效；提交前按当前规则再核对 |
| pricing_parameters | object | 否 | 和传给 estimate_cost 的计费用量相同 |
| max_cost_usd | number | 否 | 大于 0、不超过 10000；仅提交前估价检查 |
| media_seconds | number | 否 | 大于 0、不超过 3600；仅估价提示 |
| wait_seconds | integer | 否 | 0–40；提交后等结果的秒数。图片默认 40，视频和音频默认 0；0 表示提交后马上返回 task_id。整批只能用 0 |
| skip_estimate | boolean | 否 | 只在用户明确说不用估价、不用确认时使用：不估价，直接提交。见[不估价直接生成](#skip-estimate) |
| workflow | object | 否 | 只在 EvoLink 工作流里使用：`run_id` 和 `step`。工作流里用的是 generate_workflow_media，它必须带这个参数 |

先查模型/参数、估价、展示限制并等待明确批准，再调用；用户明确说不用估价时除外（见下文）。以下只是调用形状：

```json
{"name":"generate_image","arguments":{"model":"z-image-turbo","input":{"prompt":"A cream ceramic coffee cup on a white background"},"client_request_id":"coffee-image-demo-001"}}
```

图片最多等待约 40 秒，完成则返回结果，否则给 task_id；视频/音频提交后返回 task_id，继续 get_task。`wait_seconds` 可以改这三个工具的等待时间。提交可能包含预扣信息，完成后的实际扣费单独确认。

任务还在运行时只查询，不能再调用生成工具“查看进度”。响应丢失时保留原 ID、账户、输入和请求编号；更换编号会创建新的付费意图。客户端重试保护不等于所有生产节点已实现相同后端幂等保证。

<span id="skip-estimate" />

**不估价直接生成。** 用户明确说不用估价或不用确认（例如“直接生成”“以后都直接生成”）时，助手跳过 `estimate_cost` 和确认，传 `skip_estimate: true`。范围按用户说的来：这一个任务、这一批，或这次对话后面的所有生成。助手不能从沉默、余额或自己的建议推断用户同意。用户说这次对话后面都不用估价时，助手要明确提醒一次：后面的生成会直接提交、不再询问；想恢复估价，可以新开一个对话，或直接说“恢复估价”。价格算不出来，或 `pricing_quote` 因为过期、价格变高、输入变了被拒绝，也照样提交，结果里会写明（`estimate_skipped`、`estimate_skip_reason`），按实际用量计费。输入不合法仍会被拒绝；用户明确给的 `max_cost_usd` 仍然生效，超过上限或没法按它核对价格时不会提交；开启模型联网搜索或图片搜索仍要用户同意。用户没说不用估价、而估价失败或给不出总价时，助手先问一句：要不要按实际用量直接生成。

<span id="batches" />

**整批提交。** 同一个模型要生成多个任务时，先把 `inputs`（1–50 项，每项和 `input` 一样）传给 `estimate_cost`，再连同返回的 `pricing_quote` 传给生成工具：一次估价，按总价确认一次，一次调用提交所有项（同时最多 10 个），并马上返回每一项的 `task_id` 或错误，不等出图。只要有一项输入不合法，就一项都不提交。`max_cost_usd` 管整批的总价；`media_seconds` 和 `pricing_parameters` 用于每一项。结果用 `list_tasks` 收（`task_ids`，每次最多 50 个）。不同模型的任务，每个任务调用一次，传 `wait_seconds: 0`。不要靠 `n` 凑张数：GPT Image 等模型常常返回比 `n` 少的图片，所以每张图用一项。

调用开始 25 秒后不再开始新的提交；已经开始的提交不会被打断，没来得及开始的项会列为未提交。要补交时，在第一次提交后 24 小时内用同一个 `client_request_id` 和完全相同的 `inputs` 再调用一次：结果里列为要补交的项会提交，已经成功的项返回原来的任务，不会重复扣费。这时 `pricing_quote` 如果已经过期，先对同样的输入重新估价，再传新的凭证。结果未知的项，稍后用同样的方式重试，或用 `list_tasks` 查。在这 24 小时里，已成功、未提交、结果未知的项，都不能换新的 `client_request_id` 重新提交，那样会创建新任务并另外扣费。过了 24 小时，同一个 `client_request_id` 不再能防止重复扣费：先用 `list_tasks` 查，再只把没成功的项作为新的一批提交，重新估价并使用新的 `client_request_id`。某一项的输入和这个 `client_request_id` 之前提交的不一样时，会被拒绝（`idempotency_conflict`）；它算新任务，要重新估价、重新确认，并用新的 `client_request_id`。

### get_task

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| task_id | string | 是 | 原任务 ID，4–128 字符的受支持 ID |
| wait_seconds | integer | 否 | 0–45，默认 30；含重试在内的整次调用上限。0 表示只读一次、不等待任务完成，这次读取仍可能最多约 15 秒 |

```json
{"name":"get_task","arguments":{"task_id":"TASK_ID_FROM_RESPONSE","wait_seconds":30}}
```

返回状态、进度、结果、已报告费用或错误。仍未完成时继续同一 ID。任务失败时返回错误码（`error.code`）、错误说明（`error.message`，与 API 返回的一致）和 `billing_note`：这个任务不收费，提交时预扣的积分会自动退回。原件通常 7 天内保存，缩略图是否展示由客户端决定。 极少数情况下，生成结果会以上游原始链接交付，有效期可能短于 7 天，请及时下载保存。

已完成的 Seedance 2.5 草稿还会返回 `draft_expires_at`：在这个时间之前，可以用 `seedance-2.5-draft-to-video` 转换它。由草稿转换出来的任务会返回 `source_task_id`，也就是那个草稿的任务 ID。

### list_tasks

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| task_ids | string[] | 否 | 1–50 个 ID，批量模式 |
| status | string | 否 | processing/completed/failed/cancelled |
| type | string | 否 | image/video/audio |
| model | string | 否 | 精确模型 ID，1–128 字符 |
| page | integer | 否 | 1–100000，默认第 1 页 |
| since / until | string | 否 | ISO 8601、Unix 秒、30m/2h/1d，最多 40 字符 |
| limit | integer | 否 | 1–50，默认 20 |

```json
{"name":"list_tasks","arguments":{"type":"video","since":"2h","page":1,"limit":20}}
```

```json
{"name":"list_tasks","arguments":{"task_ids":["TASK_ID_ONE","TASK_ID_TWO"]}}
```

task_ids 不能与 status/type/model/page/since/until 混用。批量返回 tasks 与 missing；历史返回 total/page/page_size/next_page/last_page。已完成的任务读不到结果链接或错误码时，仍保留基础页：details_status、每行的 details_reason（read_failed、invalid 或 not_returned）和 details_retry_task_ids 说明缺了什么、可以免费重试哪些；not_returned 的行用 get_task 逐个查。processing 包含排队，时间过滤只作用于当前页，total 是时间过滤前数量。账户历史不局限于当前聊天，空页不能证明提交没发生。

### get_task_usage

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| since | string | 否 | 默认 30d，创建时间下界 |
| until | string | 否 | 默认当前时间，含边界 |
| model | string | 否 | 精确 ID，1–128 字符 |
| type | string | 否 | image/video/audio |
| max_pages | integer | 否 | 1–20，默认 5；每页 50 条 |

```json
{"name":"get_task_usage","arguments":{"since":"7d","type":"video","max_pages":5}}
```

返回 totals、by_model、by_status、coverage 与 as_of。检查 missing_cost_tasks、truncated、concurrent_change_detected 和 complete_for_retained_tasks。它汇总账户保留的已完成任务报告费用，不是完整账单、支付/退款台账、仅 MCP 用量或结算上限。

### check_balance

无参数：

```json
{"name":"check_balance","arguments":{}}
```

返回 account_balance_credits/usd、spent_scope、spent_credits，以及可用时的总/当日额度与控制台链接。OAuth Key 花费覆盖同账户 CLI 和全部 OAuth MCP 会话，不是本次聊天的金额。

### upload_file

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file_url | string | 二选一 | 公开 HTTPS 媒体，不接受私网/凭据 URL |
| base64_data | string | 二选一 | 远程最多 1 MiB 解码后文件 |
| mime_type | string | 条件必填 | 裸 base64 必填；data URL 自带 MIME |
| file_name | string | 否 | 纯文件名，不含目录 |
| upload_path | string | 否 | 相对目录，不含 .. |

```json
{"name":"upload_file","arguments":{"file_url":"https://example.com/reference.png","file_name":"reference.png"}}
```

替换真实可访问 URL。返回 file_url、文件属性和有效期等。参考通常保留 7 天。远程不接受 file_path；本地 stdio 可用允许目录的绝对路径替代 URL/base64，三个来源只能选一个。接受上传格式不代表模型支持该素材。

### prepare_upload

必填 `file_name`（string，含扩展名决定类型），可选 `upload_path`（相对目录）。

```json
{"name":"prepare_upload","arguments":{"file_name":"reference.mp4"}}
```

返回 upload_id、upload_url、method:PUT、command、max_bytes、expires_at。地址有效约 15 分钟，一次使用，最大 **95 MiB**。在能读取文件的环境执行返回命令，确认成功后用 file_url；网页附件不一定能这样上传。地址含一次性授权，不公开，不追加个人 Key。

### get_upload

必填 `upload_id`，使用原准备返回值：

```json
{"name":"get_upload","arguments":{"upload_id":"UPLOAD_ID_FROM_RESPONSE"}}
```

状态有 waiting/uploading/done/failed/expired/outcome_unknown；done 才能使用已确认的 file_url。当前服务内状态约保留 1 小时，兼容文件服务可提供约 72 小时回执；若后端不支持或无法核实，可能返回 outcome_unknown。此查询不会重传原件；保留原 ID，先查状态与文件。

<span id="workflow-tools" />
### get_media_workflow

仅限已登录的远程连接。返回 EvoLink 工作流的分步规则（每次一个小节），以及计划中这一次运行的一个预估总价。见[广告复刻](/cn/cli-mcp/ad-rebuild)。

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| workflow | string | 是 | 工作流名称，目前是 `ad-rebuild` |
| section | string | 否 | 默认 `overview`，或之前的调用列出的小节 ID |
| run_id | string | 否 | 第一次调用时返回；同一次运行之后的每次调用都要带上 |
| estimate | object | 否 | `output_seconds`、`keyframes`，可选 `quality`（480p/720p/1080p/4k）、`aspect_ratio`、`creator_images` |

```json
{"name":"get_media_workflow","arguments":{"workflow":"ad-rebuild"}}
```

```json
{"name":"get_media_workflow","arguments":{"workflow":"ad-rebuild","run_id":"RUN_ID_FROM_RESPONSE","estimate":{"output_seconds":10,"keyframes":5,"quality":"720p","aspect_ratio":"9:16","creator_images":1}}}
```

第一次调用返回总览、`run_id` 和小节列表。带 `estimate` 而不带 `section` 时，只返回估价：`total_credits`、`total_usd`、包含的内容、`valid_until`，以及余额和 EvoLink MCP 额度上限（如果设了）是否够用（`enough_balance`、`short_by_credits`、`enough_limit`）。不产生任何费用。总价按你账户自己的价格计算（读不到时改用公开默认价格，估价里会写明），24 小时内有效；实际扣费以实际用量为准。

### analyze_video

仅限已登录的远程连接。为工作流的某一步分析一条视频。按 token 向已登录的账户计费，属于工作流预估总价的一部分；用户确认这个总价之前不要调用。

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| run_id | string | 是 | 来自 get_media_workflow |
| step | string | 是 | 工作流的步骤名，例如 `reference_analysis` 或 `delivery_check` |
| purpose | string | 是 | `breakdown`、`sound` 或 `compare` |
| video_url | string | `video_url` 和 `input_task_id` 二选一 | EvoLink 文件链接（上传得到）或 EvoLink 视频任务的结果链接；MP4 或 MOV，不超过 30 秒 |
| input_task_id | string | `video_url` 和 `input_task_id` 二选一 | 同一账户里一个已完成的视频任务的 ID。分析时读取它的视频，这次检查会和这个任务记在一起 |
| target | string | 仅 `compare` 需要 | 用来对照检查视频的计划 |
| attempt | integer | 否 | 默认 1；只有报错的下一步提示这样做时才加大 |

```json
{"name":"analyze_video","arguments":{"run_id":"RUN_ID_FROM_RESPONSE","step":"reference_analysis","purpose":"breakdown","video_url":"https://files.evolink.ai/YOUR_FILE.mp4"}}
```

```json
{"name":"analyze_video","arguments":{"run_id":"RUN_ID_FROM_RESPONSE","step":"delivery_check","purpose":"compare","input_task_id":"TASK_ID","target":"THE_PLAN"}}
```

`video_url` 和 `input_task_id` 只传其中一个。返回 `status`、`analysis`、`analysis_id`、token `usage`、`charged` 和 `charged_by_this_call`。扣费之前会先检查文件；读不到的链接、不是视频的文件、过长的文件都会被拒绝并说明原因。**同样的输入在 24 小时内再次调用，返回第一次的结果，不再扣费**（`charged_by_this_call:false`），所以超时或连接断开后，原样再发一次同一个调用即可。分析较慢时返回 `status:processing` 和一个 `analysis_id`，交给 get_video_analysis。每个账户每分钟、每天能发起的分析次数有限；报错会说明要等多久。每一笔扣费在控制台历史记录里显示为一次 Gemini 模型调用。

### get_video_analysis

仅限已登录的远程连接。必填 `analysis_id`，来自 analyze_video：

```json
{"name":"get_video_analysis","arguments":{"analysis_id":"ANALYSIS_ID_FROM_RESPONSE"}}
```

最多等待约 30 秒，返回已完成的分析，或者再次返回 `status:processing`。免费。结果保留约 1 小时；ID 已经不在时，用同样的输入把原来的 analyze_video 调用再发一次。

### generate_workflow_media

仅限已登录的远程连接，在工作流规则里写明了生成步骤时提供。把一次付费生成作为工作流某一次运行的一个步骤提交，这样以后可以从这一次运行找到这个任务。估价、批准、价格和重试都和 generate_image、generate_video、generate_audio 一样，其他参数也一样。

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| kind | string | 是 | `image`、`video` 或 `audio`：模型的类型 |
| workflow | object | 是 | `run_id`（来自 get_media_workflow）和 `step`（工作流规则里写明的生成步骤，例如 `keyframe` 或 `final_video`） |
| model | string | 是 | 这一类型的模型 |
| 其他参数 | | | 和生成工具一样：`input`、`inputs`、`pricing_quote`、`client_request_id`、`wait_seconds` 等 |

```json
{"name":"generate_workflow_media","arguments":{"kind":"video","model":"MODEL_ID","input":{"prompt":"..."},"pricing_quote":{"...":"from estimate_cost"},"workflow":{"run_id":"RUN_ID_FROM_RESPONSE","step":"final_video"}}}
```

返回的内容和生成工具一样。给出的步骤如果不是这一次运行里这一类型的生成步骤，会在提交之前被拒绝，不产生任何费用。把任务和它所属的运行关联起来只是一条记录：不改变价格，也不改变结果；记录做不成时，生成照样提交。

### record_workflow_delivery

仅限已登录的远程连接，和 generate_workflow_media 一起提供。免费。记录工作流某一次运行交付的是哪一条已完成的视频。

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| run_id | string | 是 | 来自 get_media_workflow |
| task_id | string | 是 | 这一次运行里生成的一个已完成的视频任务 |
| previous_task_id | string | 否 | 只在替换之前的选择时使用：之前记录的那个任务 |

```json
{"name":"record_workflow_delivery","arguments":{"run_id":"RUN_ID_FROM_RESPONSE","task_id":"TASK_ID"}}
```

返回 `delivered_task_id`。不是这一次运行、这个账户里已完成的视频任务，会被拒绝。如果暂时记录不了这个选择，照原计划交付视频，稍后再试。

### make_frames

仅限已登录的远程连接，和工作流工具一起提供。免费。它让不能运行命令的助手也能查看视频的画面、准备图片；能运行命令的助手在自己的机器上用 ffmpeg 做同样的事，速度更快。

| 参数 | 类型 | 必填 | 默认/范围 |
|---|---|---|---|
| action | string | 是 | `contact_sheet`、`frame`、`crop` 或 `board` |
| video_url | string | `contact_sheet` 和 `frame` 需要 | EvoLink 文件链接（上传得到）或 EvoLink 任务的结果链接；MP4 或 MOV，不超过 60 秒、200 MB |
| start_seconds | number | 否 | `contact_sheet`：这一段从第几秒开始；默认 0 |
| end_seconds | number | 否 | `contact_sheet`：这一段到第几秒结束；默认到视频结尾，最多从开始算起 30 秒；大于 1440p 的视频（例如 4K）最多 15 秒 |
| fps | integer | 否 | `contact_sheet`：每秒取几帧，1–10；默认 4 |
| tile_width | integer | 否 | `contact_sheet`：每一格的宽度（像素），120–512；默认用放得下的最大格子 |
| time_seconds | number | `frame` 需要 | 要取的那一帧的时间，从开头算起的秒数 |
| image_url | string | `crop` 需要 | PNG、JPEG 或 WebP 图片的 EvoLink 文件链接或结果链接，不超过 20 MB、3600 万像素 |
| x, y, width, height | integer | `crop` 需要 | 要裁出的矩形，单位是原图的像素；x 和 y 是它的左上角 |
| image_urls | string[] | `board` 需要 | 2–24 个 EvoLink 图片链接，按编号顺序排列 |
| save | boolean | 否 | `contact_sheet`、`board`：同时保存图片，并返回一个用户能打开的链接；单帧和裁剪的结果总是会保存 |

```json
{"name":"make_frames","arguments":{"action":"contact_sheet","video_url":"https://files.evolink.ai/YOUR_FILE.mp4","fps":2}}
```

- `contact_sheet`：按固定帧率取出视频的画面，拼成一张图，每一格标出时间；同时给出每一帧和前一帧相差多少（0 到 1），用来找剪切点。一张图最多看 30 秒，大于 1440p 的视频最多 15 秒，最多放 24 格；`next_start_seconds` 说明从哪里接着做下一张。
- `frame`：`time_seconds` 那一刻的原尺寸画面，保存为 PNG 文件链接，可以当作图片输入使用，例如做封面。如果存成 PNG 会超过 16 MB（细节很多的 4K 画面可能这样），就改存为同样尺寸的高质量 JPEG。
- `crop`：从图片里精确裁出一个矩形，不缩放，保存为 PNG 文件链接。
- `board`：把 2 到 24 张图片并排拼在一起，按给出的顺序编号，方便一起查看。

不产生任何费用（`charged: "no"`）。素材只能是 EvoLink 的文件链接或结果链接，其他链接会被拒绝。每个账户每分钟最多调用 `make_frames` 10 次；报错会说明要等多久。保存的图片和其他上传的文件一样会过期。

### 返回格式与错误

工具返回可读 text 和 structuredContent，失败可带 isError/error/next_step。完成媒体也可附 resource_link、可选 image 缩略图。不同客户端需支持这些内容；原件链接始终是交付依据，不保证所有宿主都显示预览。

先检查工具错误，再看 input_valid、估价状态、task.status 等业务结果。不要只看到 HTTP 200 就判定生成成功。提交超时可能已经创建任务，不能当作“未收费”；query 的失败也不能当作原任务失败。

## 任务进度和结果

余额与模型查询用于免费验证；get_task/list_tasks 用于已有任务，完成后立即交付原链接和实际费用。[创作与任务指南](/cn/mcp/overview#workflows)包含上传、恢复、保存和灰色缩略图处理，不要为显示问题自动重做付费媒体。

## MCP 协议与后台接口

| 方式 | 执行路径 | 认证与安装 |
|---|---|---|
| 远程 MCP | 客户端 → EvoLink 托管 MCP → 平台 API | Streamable HTTP + 浏览器 OAuth，无需安装本地服务 |
| 本地 stdio | 客户端 → 本机 MCP 进程 → 平台 API | Node.js 20+、npx 启动、个人 API Key |

远程端点为 `https://mcp.evolink.ai/mcp`。Passport 负责 OAuth；服务请求 `https://api.evolink.ai` 和文件服务。MCP URL、平台 `/v1` 路径、文档地址和 llms.txt 是不同入口，不相互替代。

### 初始化与调用

由宿主或 MCP SDK 处理 initialize、协议版本、Accept、认证、会话和内容块。初始化后读取 `tools/list`，再用 `tools/call` 调用工具：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"check_balance","arguments":{}}}
```

本页示例中的 name / arguments 是工具输入，不是 REST 请求体。工具可能返回文本、结构化数据、资源链接和缩略图；宿主决定如何展示。检查工具错误和任务 status，不能只看 HTTP 成功。

### 工具与后台能力

| MCP 工具 | 后台接口或实现 |
|---|---|
| search_models | `GET /v1/models` 与别名、可用性和参考整合 |
| get_model、recommend_models、search_docs | 版本化模型参考与账户目录，不是同名 REST 接口 |
| estimate_cost | `GET /v1/catalog/models/{model_id}/pricing-rules?view=full` 与服务内估价规则（1.7.0 起） |
| get_pricing_rules | `GET /v1/catalog/pricing-rules` 与 `GET /v1/catalog/models/{model_id}/pricing-rules`（view=full） |
| generate_image | `POST /v1/images/generations` |
| generate_video | `POST /v1/videos/generations` |
| generate_audio | `POST /v1/audios/generations` |
| get_task | `GET /v1/tasks/{task_id}` |
| list_tasks，指定 task_ids | `POST /v1/tasks/batch` |
| list_tasks、get_task_usage | `GET /v1/tasks`，分页与有界汇总 |
| check_balance | `GET /v1/credits` |
| 上传授权 | `POST /v1/files/upload-token` |
| upload_file | 文件服务 /url 或 /base64；本地 stdio 可读允许目录 |
| prepare_upload、get_upload | 托管 MCP 的一次性 PUT 地址与状态；回执恢复依文件服务支持 |

模型参数放在 `arguments.input`；服务按模型生成 REST 请求。`media_seconds` 只提示计费，`max_cost_usd` 只做提交前估价检查。登录或使用 API Key 时，MCP 按你账户自己的价格估价；否则按公开默认价格规则估价（参考价，不含账户折扣）。仍没有最终结算硬上限。

### 上传、恢复与权限

一次性 PUT 地址由 prepare_upload 返回，只在有文件读取能力的环境使用，上传后通过 get_upload 查询。远程服务不能读取用户电脑路径，网页附件也未必能提供原件字节。具体步骤见[素材与上传](/cn/mcp/overview#files)。

付费提交保存 `client_request_id`、规范输入、账户和返回 task_id；未知结果先查询原任务及历史，不换编号重发。不能仅凭客户端保存编号承诺后端所有异常都不会重复扣费。

OAuth 只开放受限媒体能力，不能借工具调用任意 Key 管理或后台接口。当前没有可用的取消工具；停止等待不代表任务取消。CLI 使用独立命令与执行路径，说明见[CLI 参考](/cn/cli/reference#api)。
