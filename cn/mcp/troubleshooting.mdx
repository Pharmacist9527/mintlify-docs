## 先确认用的是哪种方式

- **CLI**：`evolink --version`、`evolink auth status --json`、`evolink balance --json`。客户端没有原生 MCP 工具并不表示 CLI 失败。
- **原生 MCP**：确认服务 URL 是 `https://mcp.evolink.ai/mcp`，已登录，并实际调用 `check_balance`。
- **文档检索 MCP**：文档站的 `/docs/mcp` 只检索文档，不提供生成工具。不要把它当作媒体服务。

## 安装了 CLI，智能体仍找不到

| 现象 | 怎么做 |
|---|---|
| `evolink: command not found` | 确认 npm 全局可执行目录在当前智能体的 PATH 中；检查是否安装到了另一台机器或容器 |
| Node 版本不足 | 使用 Node.js 22+，检查智能体实际执行环境的版本 |
| 技能文件存在但未被发现 | `evolink skills install --agent NAME`，新开对话并确认发现 `evolink-cli` |
| 只发现 `evolink-mcp` | 那是原生 MCP 技能；CLI 要发现 `evolink-cli`，不要混用命令 |
| 智能体拒绝运行命令 | 按宿主的权限规则处理；不要更换调用路径绕过拒绝 |

## 登录失败或浏览器没打开

CLI 会打印本次授权链接，可以自行打开；需要回调到 CLI 所在机器，SSH 情况见 [CLI 登录](/cn/mcp/cli#linux-与-ssh)。`--no-browser` 不等于设备码，也不支持粘贴回调地址。

- `credential_store_unavailable`：Linux 检查 Secret Service、D-Bus 和同一用户会话；不写明文令牌替代。
- `login_timeout` 或同意页失效：重新发起登录，不复用旧授权链接。CLI 的本地等待约 3 分钟，同意页事务有效期可能更长。
- 登录了错误账户：CLI 退出重登；原生 MCP 在对应客户端断开重连。
- Claude 或 ChatGPT 不显示添加入口：检查客户端版本、账户与工作区权限，按各自接入页和官方说明处理。
- 原生 MCP 已登录但看不到工具：先尝试在当前对话验证；缺工具时新开对话，仍缺再重启客户端。

## 模型或参数问题

| 问题 | 下一步 |
|---|---|
| 搜索不到旧型号，如 Topaz | 查当前可用模型；不沿用历史参数索引中的停用型号 |
| 价格或参数缺失 | 查 `get_model`、模型文章或选信息完整的型号，不编造总价 |
| Wan 时长、GPT 图片尺寸被拒 | 按返回的范围、像素及组合限制修改后重新报价 |
| Seed Audio 要时长、加 duration 又被拒 | 不加 `input.duration`；使用独立 `media_seconds` 估价提示，并说明输出总时长未知 |
| 音频参考图片与参考音频同时传 | 查看互斥规则，仅保留所选模型允许的组合 |

## 报价被拒或实际费用不同

原生 MCP `max_cost_usd` 与 CLI 的预算都是估价保护，不能保证最终结算金额。参考视频、未补齐倍率、Token 和未知音频时长见[费用与上限](/cn/mcp/billing)。

CLI 可能返回 `invalid_input`、`estimate_unavailable`、`uncheckable_cap`、`cost_exceeds_cap`、`price_changed`、`quote_expired` 或 `quote_session_changed`。先看 JSON 的 `error` 与说明，保留原预算，修改请求后重新报价并确认。不要自行去掉预算、换成起价或声称失败报价可提交。

## 任务超时、状态未知或重复提交

- 有任务 ID：查同一任务，或 `evolink tasks wait TASK_ID --json`。
- 提交结果未知且原报价尚可恢复：`evolink tasks resume --quote QUOTE_ID --json`，沿用原请求 ID。
- 原报价失效或本地记录丢失：先查近期任务，核对模型与时间。
- 不要通过再次生成刷新预览或进度；新任务会再次计费。

## 下载返回 403

公开媒体文件可能按客户端特征限制访问。已观察到默认 Python urllib 返回 HTTP 403、正文 `error code: 1010`，使用明确的产品 User-Agent 后可下载。只在您确实需要程序下载时设置请求头，例如您自己的应用可使用 `YourApp/1.0`；EvoLink 客户端示例为 `EvoLinkClient/1.0`：

```python
import urllib.request

request = urllib.request.Request(
    result_url,
    headers={"User-Agent": "EvoLinkClient/1.0"},
)
with urllib.request.urlopen(request, timeout=60) as response:
    content_type = response.headers.get("Content-Type", "")
    # Check status and media type before saving the response in your application.
```

此处 `result_url` 是任务返回的原链接。不要把 EvoLink 的认证头转发给媒体域名。User-Agent 的一次通过不保证所有网络出口可用；仍失败时记录 HTTP 状态、内容类型和时间，联系支持，不公开凭据或私密素材链接。

## 原链接可看，缩略图是灰框

这通常应先查客户端预览，而不是重新生成。MCP 已提供小预览兼容处理，但旧消息不会自动更新，客户端也可能缓存失败。重新查询已有任务并保留原文件链接，见[结果与下载](/cn/mcp/tasks)。

## 下载或上传的本地路径错误

检查文件存在、可读、格式支持及大小；下载父目录要存在，目标不能已存在。0.5.0 的部分文件错误可能归为 `request_failed`，请结合命令和系统路径排查。收到“下载成功”但文件打不开时，检查实际文件类型和 HTTP 返回；不要把 HTML 错误页改扩展名当图片。不要把尚未发布的文件头验证功能当作现有保证。

## 联系支持时准备什么

提供 CLI/客户端版本、连接方式、脱敏后的命令和错误码、任务 ID、时间以及原文件是否能打开。不要提供 API Key、令牌、验证码、授权回调或一次性上传地址。
