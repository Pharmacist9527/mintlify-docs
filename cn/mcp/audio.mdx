## 先区分任务

- **音乐或歌曲**：可以先查询 Suno 等音乐型号，检查简单模式、自定义歌词、风格和是否纯音乐。
- **配音或语音**：查询适合的语音型号，检查文本字段、语言、声音与参考素材；不要直接用音乐模型替代。
- **参考声音或多模态输入**：必须由具体模型支持，遵守参考图片与参考音频等互斥规则。

使用 `search_models` / `get_model`；CLI 对应 `models search --type audio` 和 `models show`。

## 示例需求

```text
用 EvoLink 为产品介绍生成一段自然、清楚的中文配音。
文本是“欢迎使用 EvoLink，开始你的创作”。先查适合的语音模型，报价后等我确认。
```

```text
用 EvoLink 做一首轻快的夏日公路旅行歌曲。先查 Suno 的模式和输入参数，
告诉我预计费用与输出数量，等我确认后再生成。
```

模型可能用 `prompt`、文本或歌词字段，不能把一个模型的输入模板套给所有音频型号。

## 为什么不能随便加 duration

有些按秒计费音频模型不允许指定输出时长，例如 Seed Audio。不能为了估价把 `duration` 加进 `input`：参数校验会拒绝它。

`media_seconds`（CLI 的 `--media-seconds`）是独立的估价提示，不发给模型。对于生成时长未知的音频，它只能说明“假设生成这么长时的费用”，不是总价或上限；实际费用按生成后的测量时长计算。

因此这类请求不能靠填写 `media_seconds` 建立 `max_cost_usd`。智能体需要说明未知时长和费用，保留用户预算，并请用户决定是否接受无法给出事前总价的方案。见[费用与上限](/cn/mcp/billing)。

## 提交、查询和保存

批准后调用 `generate_audio`；CLI 用保存的音频报价：

```bash
evolink generate audio --quote QUOTE_ID --confirm --wait --json
evolink tasks get TASK_ID --json
evolink download TASK_ID --output ./audio.mp3 --index 1 --json
```

下载扩展名要匹配实际结果格式，不能只改扩展名转换格式。音乐任务可能返回多条音轨、封面等结果；查看 `results`，逐项交付并用正确 `--index` 保存。出现多个文件不代表可以自动再生成新的任务。

任务完成后报告实际费用和原链接；客户端是否能内嵌播放取决于客户端。结果一般 24 小时有效，参考素材一般 72 小时保留。
