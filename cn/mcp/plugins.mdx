插件可把远程 MCP 配置和调用指导一起交给助手。不同客户端的插件不是同一种安装包；先选当前宿主，再完成它自己的授权。

| 入口 | 安装内容 | 执行媒体任务 |
|---|---|---|
| ChatGPT 自定义 MCP 插件 | 在 ChatGPT 中创建服务器连接 | ChatGPT 调用远程 MCP |
| Codex 仓库插件 | EvoLink 远程 MCP 配置与 evolink-mcp 技能 | Codex 调用远程 MCP |
| Claude Code 仓库插件 | EvoLink 远程 MCP 配置与 evolink-mcp 技能 | Claude Code 调用远程 MCP |
| CLI 随包技能 | evolink-cli 指令与参考资料 | 助手执行 CLI，CLI 直连 API |
| 单独安装 evolink-mcp | 只有 MCP 调用指导 | 仍需另行配置 MCP 和授权 |

## ChatGPT 自定义 MCP 插件

按 [ChatGPT 接入](/cn/mcp/chatgpt)添加自定义 MCP，服务器地址为：

```text
https://mcp.evolink.ai/mcp
```

选择 OAuth，完成浏览器登录和同意，再在对话中启用 EvoLink。ChatGPT 不使用下面的 Codex marketplace 命令，也不需要 npm 安装本地 CLI。

创建自定义连接不代表 EvoLink 已在公共插件目录上架。入口是否开放、能否调用生成工具，由账户、客户端版本和工作区权限决定。参见 [OpenAI 自定义 MCP 说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)。

## Codex 仓库插件

先确认当前 Codex 版本支持 `plugin` 命令。插件用于原生远程 MCP；官网的 CLI 提示词是另一种接入方式，安装 CLI 的用户不必为了生成再装插件。

<Steps>

<Step title="添加来源并安装插件">

在 Codex 实际运行的机器与用户终端执行：

```bash
codex plugin marketplace add Evolink-AI/mcp-plugin
codex plugin add evolink@evolink
codex plugin list --json
```

确认插件列表有 EvoLink。它带来远程 MCP 配置与 `evolink-mcp` 技能，不安装 EvoLink CLI。

</Step>

<Step title="加载插件并完成授权">

刷新插件或新开 Codex 对话，确认 EvoLink 服务已加载。宿主要求认证时通过它自己的浏览器 OAuth 登录；支持下方命令且服务已注册的环境可执行：

```bash
codex mcp login evolink
```

保持命令等待，登录并同意后回到 Codex。已有手动 MCP 配置时先选一种连接来源，避免同名重复。

</Step>

<Step title="验证工具与技能">

```text
请确认已读取 evolink-mcp，并使用 EvoLink 查询余额和可用图片模型，先不要生成。
```

成功标志是技能被读取且 `check_balance`、`search_models` 实际返回结果；插件列表本身不证明授权已成功。

</Step>

</Steps>

更新来源后在宿主刷新插件并核对实际版本：

```bash
codex plugin marketplace upgrade evolink
```

命令形式见 [Codex CLI 官方参考](https://learn.chatgpt.com/docs/cli/reference)。手工 MCP 配置见 [Codex 接入](/cn/mcp/codex)；命令与技能安装见[独立 CLI 指南](/cn/cli/codex)。

## Claude Code 仓库插件

先确认当前 Claude Code 支持插件。以下是 **Claude Code 对话内命令**，不要放普通终端执行。

<Steps>

<Step title="安装仓库插件">

```text
/plugin marketplace add Evolink-AI/mcp-plugin
/plugin install evolink@evolink
```

等待来源与插件安装完成，确认当前用户/项目启用了 EvoLink；保留其他插件。

</Step>

<Step title="授权远程 MCP">

```text
/mcp
```

刷新插件后选择 EvoLink 并完成浏览器认证。与手动注册的同名连接不要重复使用。

</Step>

<Step title="免费验证">

让助手确认已读取 `evolink-mcp`，实际查询余额和模型，先不生成。手工 MCP 配置见 [Claude Code 接入](/cn/mcp/claude-code)；CLI 安装见[独立 CLI 指南](/cn/cli/claude-code)。

</Step>

</Steps>

## 只安装 MCP 技能

已配置原生 MCP、只需要调用指导时，可选安装仓库技能：

```bash
npx skills add Evolink-AI/mcp-plugin -g -y
```

这条命令通过 skills 安装器取得仓库中的技能，不安装 EvoLink CLI、不启动本地 MCP，也不替用户完成 OAuth。确认技能安装到当前宿主可发现的位置，并让助手读取 evolink-mcp。

## 插件提供哪些指导

来源是 [Evolink-AI/mcp-plugin](https://github.com/Evolink-AI/mcp-plugin)。配置指向托管远程 MCP；技能说明模型查询、参数检查、报价确认、素材上传、生成、任务查询、失败恢复与原件交付。它不把代码开发、任意文件编辑或完整视频剪辑变成 EvoLink MCP 工具。

CLI 和 MCP 技能可遵守相同的媒体规则，但命令和工具不同。一次任务选择一个入口；提交超时且结果未知时查询原请求或原 task_id，不自动换入口重新生成。技能内容与安装目录见 [Agent 可读资料](/cn/cli-mcp/agent-resources#skills)，工具参数见 [MCP 工具参考](/cn/mcp/tools)。

费用、额度及撤销授权见 [费用与保留期](/cn/mcp/billing)。安装插件、安装技能或完成 OAuth，都不代替用户对本次付费生成的批准。

## 插件安装遇到问题

| 现象 | 下一步 |
|---|---|
| plugin / marketplace 命令不存在 | 核对宿主版本与官方安装说明，或选择对应客户端页的手工 MCP 方式或[独立 CLI 安装](/cn/cli/setup) |
| 仓库获取失败 | 检查 GitHub 网络访问与宿主来源设置，保留原错误 |
| 安装成功但看不到工具 | 刷新实际会话，确认启用插件并完成 OAuth |
| 同名服务或技能重复 | 先备份，确认各自来源，保留需要的一种，不删除其他服务 |
| 工具能列出但调用失败 | 用免费余额检查授权；按 [MCP 排错](/cn/mcp/billing#mcp-connection)处理 |

安装插件不会为任何付费测试授权。技能加载问题与更多排错集中在[费用与排错](/cn/mcp/billing#faq)。
