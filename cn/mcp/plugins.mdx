## 两种技能，选对应入口

| 技能 | 用在哪里 | 安装方式 |
|---|---|---|
| `evolink-cli` | 通过 `evolink` 命令执行媒体任务 | 安装 `@evolinkai/cli` 后运行 `evolink skills install` |
| `evolink-mcp` | 通过客户端原生 MCP 工具调用 | MCP 插件，或从 `Evolink-AI/mcp-plugin` 单独安装技能 |

两种技能都要求先查模型、参数和报价，等明确确认后生成，保存任务 ID 并交付原文件。技能不是账户登录，也不是客户端工具连接；文件安装成功后还要确认智能体发现它。

## CLI 随包技能

```bash
evolink skills install
evolink skills install --agent codex
```

更新 CLI 包后再次安装，才会同步最新随包技能。支持的智能体与环境见 [CLI 安装](/cn/mcp/cli)。

## 原生 MCP 插件

公开仓库：[Evolink-AI/mcp-plugin](https://github.com/Evolink-AI/mcp-plugin)。插件组合远程 MCP 连接和 `evolink-mcp` 技能。

Claude Code 可在会话中运行：

```text
/plugin marketplace add Evolink-AI/mcp-plugin
/plugin install evolink@evolink
```

按客户端提示刷新插件，再在 `/mcp` 中选择 EvoLink 并认证。Codex 可在其插件管理入口添加该仓库/市场并安装 EvoLink；具体入口与安装命令以当前客户端版本为准，参见 [Codex 接入](/cn/mcp/codex)。

插件和手动添加的 MCP 使用同一个服务。先检查是否已连接，避免重复工具；不用为安装 CLI 再装一份原生 MCP 插件。

## 只安装原生 MCP 技能

```bash
npx skills add Evolink-AI/mcp-plugin -g -y
npx skills ls -g -a codex
```

验证输出中存在 `evolink-mcp`，其他智能体按其技能发现机制核对。技能本身没有生成连接，仍需添加远程 MCP 并调用 `check_balance` 验证。

旧技能名 `evolink-media` 已改为 `evolink-mcp`。先确认新技能被发现，备份个人修改，再移除旧技能，避免重复规则。`evolink-cli` 是另一条执行入口，不是再次改名。
