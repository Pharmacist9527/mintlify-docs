Kimi K3.1 Pro 和 Highspeed 共用请求格式，支持 1,048,576 tokens 上下文、始终开启的思考、流式输出、函数工具、严格 JSON Schema 和上下文缓存。Highspeed 提供更快的生成速度，输入、输出与缓存写入使用独立单价。

<Note>
推荐 BaseURL：`https://direct.evolink.ai`，支持文本模型长连接；备用地址：`https://api.evolink.ai`。请求使用 EvoLink API Key：`Authorization: Bearer YOUR_API_KEY`。
</Note>

## 思考与输出上限

原生思考强度为 `low`、`high`、`max`，默认 `max`。两个模型始终思考；思考 Token 已包含在输出 Token 和输出上限中。若输出预算过小，可能只有思考内容而没有最终回答。

| API | 思考字段 | 输出上限字段 |
| --- | --- | --- |
| Chat Completions | `reasoning_effort` | `max_completion_tokens` |
| Messages | `output_config.effort` | `max_tokens`（必填） |
| Responses | `reasoning.effort` | `max_output_tokens` |

Chat / Responses 默认输出上限为 131,072，最大为 1,048,576，同时受剩余上下文限制。对于需要快速响应的短问题，可以显式选择 `low` 并给出合理的输出预算。

为兼容通用客户端，下列档位会转换为原生档位：

| 客户端取值 | 实际档位 |
| --- | --- |
| `medium` | `high` |
| `xhigh` | `max` |
| `minimal`、`none` | `low` |

`none` 不会关闭思考。无需传入 K2 的 `thinking` / `enable_thinking` 开关。采样使用固定配置：`temperature=1`、`top_p=0.95`、`n=1`、`presence_penalty=frequency_penalty=0`，无需自行设置。

多轮对话时保留完整的思考与工具历史：Chat 保留 assistant 的 `reasoning_content` 和 `tool_calls`；Messages 保留 `thinking`、`signature` 与工具块；Responses 将完整 `output` 按原顺序回填。仅保留最终文本可能破坏后续推理或工具续答。

## 上下文缓存

重复前缀自动参与缓存，默认写入 5m 档。请求 TTL 控制写入策略，实际命中和写入分类以返回用量及账单为准；缓存读取与缓存写入分别计费。

Chat / Responses 在顶层传入：

```json
{
  "prompt_cache_options": {"mode": "implicit", "ttl": "1h"}
}
```

Messages 在顶层传入：

```json
{
  "cache_control": {"type": "ephemeral", "ttl": "1h"}
}
```

Messages 的消息块内缓存标记不能代替顶层 `cache_control`。

| API | 输入用量口径 |
| --- | --- |
| Chat | `prompt_tokens` 包含普通输入、缓存读取和缓存写入；细分在 `prompt_tokens_details`。 |
| Responses | `input_tokens` 包含普通输入、缓存读取和缓存写入；细分在 `input_tokens_details`。 |
| Messages | `input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens` 三段互斥；写入由 `cache_creation` 拆为 5m / 1h。 |

Chat / Responses 的普通输入量需从总输入中扣除缓存读取及缓存写入；Messages 的 `input_tokens` 已经排除两者。不要重复计算缓存写入，也不要把思考 Token 再加一次输出费。

## 联网搜索

仅按实际调用计费，声明工具但没有调用不会产生搜索工具费。搜索结果进入后续模型上下文时，也会按输入 Token 计费；普通自定义函数不产生搜索工具费。

<Tabs>
  <Tab title="Chat Completions">
    推荐统一写法：

    ```json
    {"tools": [{"type": "web_search"}]}
    ```

    也支持 Moonshot 原生声明：

    ```json
    {"tools": [{"type": "builtin_function", "function": {"name": "$web_search"}}]}
    ```

    内置搜索返回 `function.name=$web_search` 的工具调用，`arguments` 包含搜索结果引用。将完整 assistant 消息放回历史，再将每个调用的 `arguments` 作为同一 `tool_call_id` 的 tool 消息内容回填，继续请求以生成最终回答。请勿仅显示第一轮的空 `content`。

    ```python
    import os
    from openai import OpenAI

    client = OpenAI(
        api_key=os.environ["EVOLINK_API_KEY"],
        base_url="https://direct.evolink.ai/v1",
    )
    messages = [{"role": "user", "content": "Use web search to find the official Kimi homepage URL."}]

    while True:
        result = client.chat.completions.create(
            model="kimi-k3.1-pro",
            messages=messages,
            reasoning_effort="low",
            max_completion_tokens=4096,
            tools=[{"type": "builtin_function", "function": {"name": "$web_search"}}],
        )
        message = result.choices[0].message
        if not message.tool_calls:
            print(message.content)
            break
        messages.append(message.model_dump(exclude_none=True))
        for call in message.tool_calls:
            if call.function.name != "$web_search":
                raise RuntimeError(f"Unexpected tool: {call.function.name}")
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "name": call.function.name,
                "content": call.function.arguments,
            })
    ```

    返回的内置调用类型可能是 `builtin_function`，完整回填即可，服务会兼容处理。流式搜索用量也会补充到标准 `usage`，以便 SDK 读取真实 Token 数。
  </Tab>
  <Tab title="Messages">
    ```json
    {"tools": [{"type": "web_search_20250305", "name": "web_search", "max_uses": 1}]}
    ```

    服务端返回 `server_tool_use` 和 `web_search_tool_result` 等内容块，并可继续生成回答。多轮对话需保留这些块。上游可能省略 `usage.server_tool_use` 汇总字段，实际成功搜索仍会计费。
  </Tab>
  <Tab title="Responses">
    ```json
    {"tools": [{"type": "web_search"}]}
    ```

    搜索通过 `web_search_call` 输出项返回，服务端可继续生成最终消息。请同时处理 reasoning、工具输出和最终 message，不要假设 `output[0]` 一定是答案文本。
  </Tab>
</Tabs>

<Note>
Moonshot 已在[官方内置搜索文档](https://platform.kimi.ai/docs/guide/use-web-search)标注旧 `$web_search` 的退役计划；2026-10-24 两款模型的国内、海外渠道仍已实测可用。本页描述模型内置工具，不包含独立 REST Search / Search Pro / Fetch 产品。
</Note>

## 流式响应与结构化输出

Chat 使用 `stream=true`，需要用量时同时传 `stream_options.include_usage=true`，以 `[DONE]` 判断结束。Messages 使用 Anthropic SSE 事件，处理 `message_start`、`content_block_delta`、`message_delta` 和 `message_stop`。

Responses 使用语义化事件，处理 `response.output_text.delta` 与推理事件，并检查 `response.completed`、`response.incomplete` 或 `response.failed`。输出上限导致 `incomplete` 时，可增加输出预算重试，不能将其当作完整答案。

严格 JSON Schema 的字段按协议选择：Chat 使用 `response_format.json_schema`，Messages 使用 `output_config.format`，Responses 使用 `text.format`。最终文本与思考内容应分别处理，只解析最终答案中的 JSON。各入口的完整请求示例见对应参数页。
