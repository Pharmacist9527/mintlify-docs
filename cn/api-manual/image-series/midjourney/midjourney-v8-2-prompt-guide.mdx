## 与 V8.1 的差异

Midjourney V8.2 于 **2026 年 7 月 24 日** 成为默认版本。官方定位是一次聚焦美学、画质与个性化的更新：结果更有创意、更大胆、更精致，低质量的离群结果明显减少。在本平台上，V8.2 与 V8.1 使用**相同的七个模型 ID、相同的接口和相同的价格**，迁移只需改一行：把 `model` 字段里的 `mj-v8.1` 换成 `mj-v8.2`，提示词无需重写。

| 项目 | V8.1 | V8.2 |
|------|------|------|
| 模型 ID | `mj-v8.1`、`mj-v8.1-variation`、`-remix`、`-edit`、`-retexture`、`-upload-paint`、`-remove-bg` | 同样七个，前缀改为 `mj-v8.2` |
| 精细度 `--q` / `--quality` | 仅 `1` 或 `4` | `1` – `4` |
| `turbo` 速度（2 倍） | 不接受 | 生图及 remix / edit / retexture / upload-paint 均接受 |
| 不支持的标志 | 静默剥离 | 原样透传；上游以明确报错拒绝，预扣积分退还 |
| `--oref` / `--ow` | 接受 | 不支持（被上游拒绝） |
| 价格与倍率 | 5.4 / 8.1 积分，`turbo` x2，`hd` x1.5 | 完全相同 |
| 派生任务（变化 / 重塑 / 编辑） | 上游由 V7 引擎渲染 | 相同 |

<Note>
Midjourney 官方的 V8.2 发布同时引入了 **Edit Model**（基于指令的编辑，可从最多 4 张参考图生成，取代 Omni Reference、Character Reference 和 Retexture 工具）。本路由暂未开放 Edit Model。`mj-v8.2-edit` 与 `mj-v8.2-upload-paint` 是画布编辑（`canvas` + `img_pos` + 可选 `mask`），`mj-v8.2-retexture` 是经典的转绘工具。
</Note>

## 参数总览

| 参数 | 写法 | 类型 | 取值范围 | 默认值 | 说明 |
|------|------|------|---------|--------|------|
| 宽高比 | `--ar W:H` | 整数比 | 任意正整数比，不支持小数 | 1:1 | 图像宽高比 |
| 混沌 | `--c N` | int | 0 - 100 | 0 | 生成结果的多样性 |
| 种子 | `--seed N` | int | 0 - 4294967295 | 随机 | 固定种子可复现结果 |
| 风格化 | `--s N` | int | 0 - 1000 | 100 | 艺术风格强度 |
| 实验参数 | `--exp N` | int | 0 - 100 | 0 | 美学效果，可与风格化叠加 |
| 质量（精细度） | `--quality N` / `--q N` | int | 1 - 4 | 1 | 渲染精细度；不加价。V8.1 仅接受 1 / 4 |
| 原始模式 | `--raw` | 标志 | — | 关闭 | 禁用默认美化 |
| 反向提示词 | `--no 元素1, 元素2` | 文本 | — | — | 图中不希望出现的元素 |
| 图像权重 | `--iw N` | float | 0 - 3 | 1 | 垫图影响力 |
| 风格参考 | `--sref [URL]` | URL | — | — | 匹配视觉风格 |
| 风格权重 | `--sw N` | int | 0 - 1000 | 100 | 风格参考强度 |
| 个性化 | `--p [code]` | 代码 | — | — | 应用 Midjourney 个性化配置代码，原样透传 |
| 平铺 | `--tile` | 标志 | — | 关 | 生成无缝重复图案 |
| 怪异 | `--weird N` / `--w N` | int | 0 - 3000 | 0 | 非常规、实验性的美学效果 |

<Note>
以下两项设置**不**写在 prompt 里，而是通过 API 参数控制（写在 prompt 中无效，会被剥离）：

- **速度**（`draft` / `fast` / `turbo`）→ `model_params.speed`
- **输出质量**（`standard` / `hd`）→ 顶层 `quality` 参数

`--v` / `--version` 固定为 V8.2，不支持 `--niji`。详见下文[速度模式](#速度模式)与[输出质量](#输出质量)。
</Note>

## 基础参数

### 宽高比 `--ar`

设置图像的宽高比，仅支持整数比，小数会被拒绝（请写 `139:100`，不要写 `1.39:1`）。

```
一只猫 --ar 16:9
```

常见值：`1:1`、`4:3`、`3:2`、`16:9`、`9:16`、`2:3`。极端比例可能产生不可预测的结果。各比例对应的像素尺寸见[输出质量](#输出质量)。

### 混沌 `--chaos` / `--c`

控制生成结果的多样性。值越高，4 张图之间差异越大。

```
一只猫 --c 50
```

| 范围 | 效果 |
|------|------|
| 0 | 4 张图非常相似（默认） |
| 1-50 | 适度多样性 |
| 50-100 | 高度随机，适合创意探索 |

### 风格化 `--stylize` / `--s`

调节写实与艺术之间的平衡。

```
一只猫 --s 500
```

| 范围 | 效果 |
|------|------|
| 0-250 | 写实风格，忠实于提示词 |
| 250-750 | 平衡 |
| 750-1000 | 强烈艺术性，大胆色彩构图 |

### 实验参数 `--exp`

与 `--stylize` 类似但可叠加，生成更详细、动态、创意的图像。

```
一只猫 --exp 25
```

- 推荐值：5、10、25、50、100
- 5-50 效果变化明显，50-100 变化较小
- 超过 25-50 时可能覆盖 `--stylize` 的效果

### 质量 `--quality` / `--q`

设置渲染精细度。取值 1 - 4，默认 1。该标志会原样透传给上游，**不改变价格**。

```
一只猫 --q 3
```

- V8.2 接受 `1` / `2` / `3` / `4`；V8.1 仅接受 `1` / `4`。超出范围的值会被上游拒绝（`quality: should in [1 2 3 4]`），任务失败，预扣积分退还
- Midjourney 官方的参数表中并未为 V8 列出 `--q`，因此视觉效果由上游尽力提供——依赖它之前，请先用自己的提示词对比几个取值
- 仅生图接口可用；派生任务（变化、重塑、编辑等）继承源图

### 原始模式 `--raw`

禁用默认美化，更严格地遵循提示词细节。适用于追求真实感或精确控制的场景。

```
产品照片 --raw
```

### 反向提示词 `--no`

列出不希望出现在图中的元素，多个元素用逗号分隔。在描述里写"没有水果"或"不要水果"无效——Midjourney 会把这些词当作内容处理——请改用该标志。

```
静物水粉画 --no fruit, flowers
```

### 种子 `--seed`

固定初始随机状态，用于对比测试。

```
一只猫 --seed 23453422
```

- 范围：0 - 4294967295
- 相同种子 + 相同提示词 → 在 V8.x 上结果约 99% 一致（官方数据）；参数的细微改动仍会改变图像
- 请勿将种子与 `turbo` 速度组合：turbo 以吞吐量为优化目标，种子锁定在该模式下不可靠

## 图像引用参数

### 图像提示（垫图）

在提示词**开头**放置图片 URL，用图片影响生成内容。

```
https://example.com/ref.jpg 文本描述 --iw 1.5
```

**有效组合规则：**

| 组合方式 | 是否有效 |
|---------|---------|
| 1 张图 + 无文字 | 无效（会报错） |
| 1 张图 + 文字描述 | 有效 |
| 2+ 张图 + 无文字 | 有效 |
| 2+ 张图 + 文字描述 | 有效 |

- 最多 20 张垫图
- 支持格式：`.png`、`.gif`、`.webp`、`.jpg`、`.jpeg`
- 不支持 `draft` 速度（请改用 `fast`）
- URL 必须能在几秒内公开访问，详见[输入图片要求](#输入图片要求)

### 图像权重 `--iw`

控制垫图对结果的影响力。范围 0 - 3，默认 1，值越高越接近参考图。

```
https://example.com/ref.jpg 水彩风景 --iw 2.0
```

### 风格参考 `--sref`

匹配参考图的视觉风格（颜色、纹理、光照），不复制内容。**必须配合文本提示词使用**。

```
一只猫 --sref https://example.com/style.jpg
```

- 支持多张：`--sref URL1 URL2`
- 支持随机风格：`--sref random`（生成后返回数字代码，可重用）
- 最多 20 个 sref
- 文本提示词只描述内容，不写指令（写"一只猫"，不要写"让它看起来像参考图"）

### 风格权重 `--sw`

控制风格参考的影响程度。范围 0 - 1000，默认 100。

```
一只猫 --sref https://example.com/style.jpg --sw 500
```

### 个性化 `--p`

应用 Midjourney 的个性化配置或情绪板（moodboard）代码。该标志原样透传。配置需在 midjourney.com 上创建并评分，API 无法创建或列出它们，因此只使用你已有的代码，并先在小批量上验证效果。

```
一只猫 --p abc123
```

## 速度模式

速度模式通过 API 的 `model_params.speed` 字段控制（请勿在提示词中写 `--draft` / `--fast` / `--turbo`）。

| 模式 | 说明 | 费用 |
|------|------|------|
| `draft` | 单次运行返回 24 张轻量级 512 px 草图。仅限生图接口。 | 与 fast 同倍率 |
| `fast` | 标准模式（默认），每次生成 4 张图 | 标准 |
| `turbo` | 极速模式，生成更快，每次生成 4 张图 | 2 倍 |

<Note>
与 V7 不同，V8.2 的 `draft` 模式**不**减半收费——它与 `fast` 使用相同倍率。草图模式单次运行返回 24 张小图，挑出喜欢的再以完整质量重跑。草图模式不能与 `hd` 质量组合使用，`draft` + `turbo` 也不能组合（`speed` 只能取一个值）。
</Note>

<Note>
Midjourney 公开文档标注 Turbo 在 V8 上不可用。本平台使用的上游渠道对 V8.2 确实接受 `turbo`（已在生产环境验证，按 2 倍计费）。若上游某次拒绝了 turbo 请求，任务会失败并返回上游报错，预扣积分退还。
</Note>

## 输出质量

输出分辨率通过顶层 `quality` 参数控制，**而非**提示词标志。请勿在提示词中写 `--hd`。

| 值 | 分辨率 | 费用 |
|----|--------|------|
| `standard` | 标准分辨率，约 1 MP（默认） | 1 倍 |
| `hd` | 原生高清输出，约 4 MP | 1.5 倍 |

各宽高比下的大致输出尺寸（V8.2 官方数据；HD 的精确尺寸可能略有出入）：

| 宽高比 | `standard` | `hd` |
|--------|-----------|------|
| 1:1 | 1024 x 1024 | 2048 x 2048 |
| 4:3 | 1232 x 928 | 2464 x 1856 |
| 2:3 | 896 x 1344 | 1792 x 2688 |
| 16:9 | 1456 x 816 | 2912 x 1632 |

- 质量倍率与速度倍率是**相乘**关系：`turbo` + `hd` = 3 倍
- `hd` 与 `draft` 速度**不兼容**
- V8.2 没有独立的放大接口；需要 2K 输出时请使用 `hd`

## 提示词长度限制

| 接口 | 限制 | 说明 |
|------|------|------|
| `mj-v8.2`（生图） | 上游限制**文本描述 1024 字符**；API 整体最多接受 2048 字符 | 上游只统计去掉图片 URL 和 `--标志` 后的描述部分，多出的空间留给 URL 和参数 |
| `mj-v8.2-remix` / `-edit` / `-retexture` / `-upload-paint` | 8100 字符 | 提示词作为编辑指令发送，不适用 1024 规则 |
| `mj-v8.2-variation` / `-remove-bg` | — | `prompt` 会被忽略 |

描述过长会被上游以 `v8系列模型提示词长度限制为1024` 拒绝，任务失败，预扣积分退还。

## 冲突关系

| 参数 A | 参数 B | 说明 |
|--------|--------|------|
| `draft` 速度 | `hd` 质量 | 草图模式不能与 HD 组合 |
| `draft` 速度 | `turbo` 速度 | `speed` 只能取一个值；无法以 turbo 速度出 24 张草图 |
| `draft` 速度 | 图像提示 / `--sref` | 图像引用需要 `fast` |
| 纯图像提示 | `--stylize` / `--exp` | 无文字时不兼容 |
| `--exp` > 25 | `--stylize` | 高 `--exp` 可能压制 `--stylize`；组合使用时请调低 `--exp` |
| `--seed` | `turbo` 速度 | turbo 模式下种子锁定不可靠 |

## V8.2 不支持的参数

V8.2 只剥离会破坏版本锁定或计费的标志，**其余标志一律原样透传给上游**。若上游不支持某个标志，任务会失败并返回上游的报错原文，预扣积分全额退还——不会再静默丢弃。

| 参数 | 处理方式 |
|------|----------|
| `--v` / `--version` / `--niji` | 剥离——版本固定为 V8.2 |
| `--fast` / `--turbo` / `--draft` / `--relax` | 剥离——请使用 `model_params.speed` |
| `--hd` | 剥离——请使用顶层 `quality` 参数 |
| `--bs` / `--batchsize` | 剥离——批量张数不可配置 |
| `--edit` | 不可用——本路由未开放官方 Edit Model；画布编辑请使用 `mj-v8.2-edit` / `mj-v8.2-upload-paint` |
| `--oref` / `--ow` | 上游拒绝（V8.2 不支持） |
| `--cref` / `--cw` | 上游拒绝（V8.2 不支持） |
| `--stop` | 上游拒绝 |
| 多提示词 `::` | 上游拒绝 |
| `--sv` | 仅接受 `--sv 6`，且须与 `--sref` 搭配 |
| `--repeat` / `--r`、`{}` 排列组合、`--stealth` / `--public` | API 不支持 |

## 输入图片要求

以下规则适用于垫图、`--sref` URL，以及 retexture / upload-paint / remove-bg 的 `image_urls` 字段。

- **仅接受公开的 HTTP(S) URL。** 不接受 Base64 和 data URL。
- **上游在创建任务时同步拉取图片，约 10 秒后放弃。** 若无法在时限内下载文件，请求以 `400` 失败，不会创建任务。实际使用中，中国大陆以外的图床（imgur、ibb、raw.githubusercontent、pinimg、picsum 等）几乎每次都会失败。请把图片放在快速 CDN 上，或先通过[文件上传 API](/cn/api-manual/file-series/upload-url)上传并使用返回的 URL。
- 支持格式：`.png`、`.gif`、`.webp`、`.jpg`、`.jpeg`。文件请保持适中大小；即使图床可达，过大的文件也可能超出拉取时限。
- `mj-v8.2-remove-bg` 不接受本平台 Midjourney 任务返回的带签名结果链接（URL 中含 `Expires` / `Signature`）。请重新托管图片或使用无签名 URL。retexture 与 upload-paint 接受这类链接。
- `draft` 速度下不可使用图像引用。

## 提示词格式规范

### 基本结构

```
[图片URL] 文本描述 --参数1 值1 --参数2 值2
```

### 书写规则

- 参数放在文本提示**末尾**
- `--` 前必须有**空格**
- 参数中不使用标点符号
- 参数后面不能再写文本
- 要在图中渲染文字，请用双引号包住：`a neon sign that says "OPEN" --ar 3:2`

### 示例

<CodeGroup>
```text 正确
a yellow Persian cat --ar 1:2 --s 500
```

```text 错误
a yellow Persian cat--ar 2:3          ← --前缺空格
a yellow Persian cat - - ar 2:3       ← --间有空格
a yellow Persian cat --ar 2:3, --s 50 ← 参数中有标点
a yellow Persian cat --ar 2:3 more description ← 参数后有文本
```
</CodeGroup>

## 任务流程

V8.2 的七个模型均为异步任务，按次计费。

1. **提交** —— `POST /v1/images/generations` 立即返回任务 `id`、`status: processing` 和 `usage.credits_reserved`，上游任务在后台创建。
2. **轮询** —— `GET /v1/tasks/{task_id}`（[查询任务状态](/cn/api-manual/task-management/get-task-detail)）。每 3–5 秒轮询一次，客户端超时建议设为约 20 分钟；任务仍为 `processing` 时不要重复提交同一提示词。
3. **读取结果** —— `status` 为 `completed` 时，`results` 中为图片 URL：`fast` / `turbo` 为 4 张，`draft` 为 24 张。`usage.cost` 为最终扣费。
4. **保存图片** —— 结果链接有效期 **30 天**，需要保留的图片请自行下载或重新托管。
5. **可选回调** —— 传入 `callback_url`（HTTPS、公网可达）即可在 `completed` / `failed` / `cancelled` 时收到通知。回调会退避重试 3 次；请把回调当作提示，并以任务查询为准。

| 状态 | 含义 | 是否终态 |
|------|------|---------|
| `pending` | 已受理，等待上游队列 | 否 |
| `processing` | 渲染中 | 否 |
| `completed` | 图片已就绪，见 `results` | 是 |
| `failed` | 上游错误、参数被拒、内容审核或图片拉取失败；报错信息在 `error` 中，预扣积分退还 | 是 |
| `cancelled` | 用户已取消 | 是 |

失败任务全额退款，包括上游参数拒绝（`--oref`、超范围的 `--q`、描述过长）和图片拉取失败。唯一例外是内容审核，见下文。错误码与重试建议见[错误码](/cn/api-manual/task-management/error-codes)页面。

### 派生任务使用 V7 引擎

基于 V8.2 源图的变化、重塑和画布编辑任务，上游由 Midjourney 的 V7 引擎渲染（这是 Midjourney 对基于 V8 的派生任务的官方行为）。结果在风格上可能与源图略有差异，价格不变。源任务必须是同一账号下已完成的 `mj-v8.2` 系列任务；不接受 V8.1 源任务。

## 常见问题

**从 V8.1 迁移需要改提示词吗？**
不需要。只改 `model` 的值即可，提示词、`model_params` 和价格均不变。仅 `--oref` / `--ow` 不再可用，且 `--q` 在 `1` 和 `4` 之外还接受 `2` 和 `3`。

**为什么垫图请求在创建任务之前就返回 400？**
上游未能在拉取时限内下载图片。请把文件放到快速、公网可达的图床上，或使用文件上传 API，然后重试。

**能以 turbo 速度出 24 张草图吗？**
不能。`speed` 只能取一个值，草图模式始终按 fast 倍率运行。

**`--q 4` 会更慢或更贵吗？**
计费没有差别。渲染时间可能略长，视觉上的提升取决于提示词。

**V8.2 的图片可以放大吗？**
V8.2 没有放大接口。请改用 `quality: "hd"` 生成原生 2K 输出。

## 内容审核说明

<Note>
Midjourney 内置内容审核机制。如果生成的部分图像触发了审核过滤，该次请求已消耗的积分将无法退还，请留意提示词的内容合规性。
</Note>
