このページでは、タスクとファイルに関する共通ルールをまとめています。実行手順については [CLI のワークフロー](/ja/cli/workflows)と [MCP のワークフロー](/ja/mcp/overview#workflows)を参照してください。

<span id="tasks" />
## 一度だけ送信し、タスク ID を控える

生成は、出力を直接返すことも、task_id を返すこともあります。ID、モデル、入力、報告された状態を控えたうえで、完了するか失敗が確定するまで、元のタスクを照会してください。実際に返された状態に基づいて判断してください。ツールの待機がタイムアウトしても、生成が失敗したわけではありません。

| 状況 | 対応 |
|---|---|
| task_id がある | 元のタスクを照会するか、完了を待ちます。複数の ID はまとめて照会します |
| まだキューで待機中、または実行中 | 照会を続けます。待機をやめてもタスクはキャンセルされません |
| 状態を検証できない：`task_response_invalid`、`task_identity_mismatch`、`task_status_unknown` のいずれかで、`status_check: unverified` が付く | 元のタスク ID を保持し、もう一度照会します。照会は無料です。これは失敗でも、課金ゼロでも、返金でもないため、生成し直さないでください |
| 受け付け済み（`submission_state: accepted`）だが、まだ状態がない | タスクは存在します。生成し直すのではなく、その task_id を照会します |
| 完了 | すべてのオリジナルファイルを保存します。数、形式、判明している料金、有効期限を報告します |
| 失敗が確定 | エラーコード（`error.code`）、その説明（`error.message`）、時刻を報告します。タスクは課金されず、送信時に仮押さえされたクレジットは自動的に返還されます |
| ID がなく、送信結果が不明 | 下記のとおり、元のルートで復旧します |

バッチ照会と一覧照会では、検証できたタスクはそのまま返され、残りには印が付きます（`partial`、`missing`、`details_missing`）。詳細が欠けていても、そのタスクが存在しなかったという意味ではありません。それらの ID をもう一度照会してください。状態、結果、アカウントの記録を確認する必要がある場合、レスポンスには `dashboard_url` と英語の `dashboard_guidance` が含まれます。同じ EvoLink アカウントで [EvoLink ダッシュボード](https://evolink.ai/dashboard)にログインし、元のタスク ID を保持してください。リンクだけでは、完了、課金、返金のいずれも確認できません。通知、リンクのラベル、生成の確認メッセージは、デフォルトでは英語です。別の言語を希望する場合は、アシスタントに伝えてください。

リリース済みの CLI と MCP には、現在、利用できる公開のキャンセル手段がありません。ターミナル、会話、接続を閉じても、タスクはキャンセルされず、課金されないことの根拠にもなりません。

## タイムアウトや結果不明から復旧する

<Steps>
  <Step title="元のアカウントと送信記録を保持する">
    CLI では quote_id とその復旧用の記録を保持し、MCP では client_request_id、元の入力、エラーを保持します。生成し直すよりも、既存の task_id を照会することを優先してください。
  </Step>
  <Step title="元のルートで復旧する">
    [CLI での復旧](/ja/cli/billing#tasks-and-recovery)または [MCP での復旧](/ja/mcp/billing#tasks-and-recovery)に従ってください。元のアカウント、入力、リクエスト ID を維持します。アカウント、キー、CLI/MCP のルートを変えて再送信しないでください。EvoLink はリクエスト ID を24時間保持します。その間は、同じリクエスト ID と同じ入力であれば元のタスクが返され、新たな課金は発生しません。CLI の `tasks resume` は、最初の送信から23時間以内で、見積書の有効期限が切れておらず、価格も上がっていない場合に、そのリクエスト ID で再送します。それ以外の場合は何も送信しません。24時間を過ぎると、そのリクエスト ID があっても重複するタスクの作成は防げなくなるため、もう一度送信する前に最近のタスクを確認してください。
  </Step>
  <Step title="タスクと課金の事実を確かめる">
    完了した出力は保存し、失敗が確定した場合は課金を確認します。それでも不明な場合は、エラーと時刻を記録して、サポートに連絡してください。不明であることは、何も生成されなかった、あるいは課金されなかったという意味ではありません。
  </Step>
</Steps>

## 参照素材をモデルが読めるようにする

1. 受け付けられる画像・動画・音声の種類、数、サイズ、参照素材の組み合わせを確認します。
2. 実行環境で読み取れるファイル、またはサーバーからアクセスできる URL を使います。チャットの添付ファイルやデスクトップ上のパスが、そのままリモートから読み取れるわけではありません。
3. アップロードのレシートとファイル URL を確認してから、それをモデルの入力に追加し、もう一度見積もります。
4. 結果が不明な場合は、元の upload_id を保持してください。代わりのアップロードを要求するのは、失敗または失効が確定してからにします。レシートに対応しているかどうかは、デプロイ環境によって異なります。

| ルート | 入力の場所と制限 | 手順 |
|---|---|---|
| CLI のローカルファイル | CLI から読み取れること。最大 95 MiB で、モデルによってはさらに厳しい場合があります | [CLI の参照素材](/ja/cli/workflows#files) |
| リモート MCP の URL／インラインデータ | サーバーから読み取れる URL。base64 は最大 1 MiB です | [MCP のアップロードツール](/ja/mcp/tools) |
| リモート MCP の1回限りのアップロード | prepare_upload を呼び出し、ファイルを扱える環境からアップロードしてから、get_upload を呼び出します。上限は 95 MiB です | [MCP の参照素材](/ja/mcp/overview#files) |
| ローカル stdio | MCP プロセスが動作するマシン上の file_path。モデルとファイルサービスの制限が適用されます | [ローカル MCP](/ja/mcp/other-clients#local-mcp) |

## 有効期限と保存

| 項目 | 現在のデフォルト |
|---|---|
| 生成されたオリジナルの URL | 通常24時間。早めに保存してください |
| アップロードした参照素材 | 通常72時間。失効後は再アップロードしてください |
| 見積書の承認（CLI の `quote_id`、MCP の `pricing_quote`） | 同じ入力で、承認済みの価格以下である限り、見積もりから24時間有効です。有効期限が切れた場合（`quote_expired`）、価格が上がった場合（`price_changed`）、入力が変わった場合（`quote_input_changed`）は、新しい見積もりと承認が必要です |
| リクエスト ID（`client_request_id`） | 最初の送信から24時間、EvoLink が保持します。CLI の `tasks resume` は、見積書の有効期限が切れておらず、価格が上がっていない場合に限り、23時間以内であればこのリクエスト ID で再送します |
| リモートの1回限りのアップロード許可 | 通常15分で、一度だけ使用できます |
| リモートアップロードの状態確認用 URL | 通常1時間。元の upload_id を保持してください |

実際に返された値が優先されます。レシートの互換性は、ファイルサービスのデプロイ環境によって異なります。ダウンロードしたオリジナルファイルは、ユーザー側のストレージに残ります。一時 URL、ドキュメント、チャットの添付ファイルは、恒久的な保存先ではありません。失効した参照素材は再アップロードし、変更した入力は改めて確認してください。

## ダウンロードとプレビューのトラブルシューティング

1. 元のタスクを照会し、完了していることを確認します。そのタスクのオリジナルの URL を使ってください。失効したリンク、非公開のリンク、無効なリンクは、ヘッダーを付けても直せません。
2. CLI の場合は download を使えます。MCP の場合は、オリジナルファイルをブラウザで開くか、ファイルを扱える環境から保存できます。[CLI でのダウンロード](/ja/cli/reference)と [MCP での受け渡し](/ja/mcp/overview#delivery)を参照してください。
3. HTTP ステータス、Content-Type、実際の形式を確認します。エラーの HTML や JSON はメディアではありません。すべての画像を PNG という名前に変えるのではなく、拡張子を実際の形式に合わせてください。
4. プレビューがグレーになっている場合や、リンクしか表示されない場合は、オリジナルファイルを開いてください。問題なく開ければ、それを渡すか保存します。ホストのプレビューを理由に、承認のない再生成や編集を行ってはいけません。

### Python のデフォルトのリクエストが拒否される場合

有効なオリジナルファイルがブラウザや curl では取得できるのに、デフォルト設定の Python では失敗する場合は、自分で管理しているコードで製品の User-Agent を設定できます。次の画像の例は、result_url がすでに有効なオリジナルの URL であることを前提としています：

```python
from urllib.request import Request, urlopen
from shutil import copyfileobj

request = Request(result_url, headers={"User-Agent": "EvoLinkClient/1.0"})
with urlopen(request, timeout=60) as response:
    if not response.headers.get_content_type().startswith("image/"):
        raise ValueError("Expected an image response")
    with open("result.png", "xb") as output:
        copyfileobj(response, output)
```

この例は、画像以外のレスポンスを拒否し、上書きを避けます。実際の形式が PNG でない場合は、拡張子を変更してください。動画や音声では、それぞれに合った MIME チェック、ファイル名、個別の検証が必要です。この方法は、特定のメタデータと画像のケースでのみ検証されたもので、あらゆるクライアント、ファイル、ネットワークで検証されたわけではありません。CLI のダウンロードでは、製品の UA がすでに設定されています。

## サポートに伝える情報

OS、エージェントとそのバージョン、CLI/MCP のバージョン、ルート、失敗した段階、時刻、エラーコード、期待した動作と実際の動作、既存の task_id、quote_id/client_request_id、upload_id、機密情報を伏せた診断情報を提供してください。SSH、コンテナ、プロキシを使っている場合は、その旨も伝えてください。

OAuth トークン、キー、認証リンクの全体、1回限りのアップロード URL、署名付きの非公開 URL、非公開ファイルは伏せてください。認証情報ファイルや、環境情報の完全なダンプは共有しないでください。まず [CLI のトラブルシューティング](/ja/cli/billing#faq)または [MCP のトラブルシューティング](/ja/mcp/billing#faq)で、どの段階の問題かを特定してください。
