## V8.1 からの変更点

Midjourney V8.2 は **2026 年 7 月 24 日**にデフォルトバージョンになりました。公式には美的表現、画質、パーソナライゼーションに重点を置いたアップデートで、結果はより創造的で大胆かつ洗練され、低品質な外れ値が大幅に減っています。本プラットフォームでは V8.2 は V8.1 と**同じ 7 つのモデル ID、同じエンドポイント、同じ価格**を使用するため、移行は 1 行の変更で済みます。`model` フィールドの `mj-v8.1` を `mj-v8.2` に置き換えるだけです。プロンプトを書き直す必要はありません。

| 項目 | V8.1 | V8.2 |
|------|------|------|
| モデル ID | `mj-v8.1`、`mj-v8.1-variation`、`-remix`、`-edit`、`-retexture`、`-upload-paint`、`-remove-bg` | 同じ 7 つ、プレフィックスは `mj-v8.2` |
| 精細度 `--q` / `--quality` | `1` または `4` のみ | `1` – `4` |
| `turbo` 速度（2 倍） | 受け付けない | 画像生成および remix / edit / retexture / upload-paint で受け付け |
| 非サポートのフラグ | 黙って除去 | そのまま透過。上流が明示的なエラーで拒否し、予約されたクレジットは返金 |
| `--oref` / `--ow` | 受け付け | 非サポート（上流で拒否） |
| 価格と倍率 | 5.4 / 8.1 クレジット、`turbo` 2 倍、`hd` 1.5 倍 | 同一 |
| 派生タスク（variation / remix / edit） | 上流の V7 エンジンでレンダリング | 同じ |

<Note>
Midjourney 公式の V8.2 リリースでは **Edit Model**（最大 4 枚の参照画像からの指示ベースの編集と生成。Omni Reference、Character Reference、Retexture ツールを置き換えるもの）も導入されました。Edit Model はまだこのルートでは公開されていません。`mj-v8.2-edit` と `mj-v8.2-upload-paint` はキャンバス編集（`canvas` + `img_pos` + 任意の `mask`）であり、`mj-v8.2-retexture` は従来のリテクスチャツールです。
</Note>

- **速度**（`draft` / `fast` / `turbo`）→ `model_params.speed`

`--v` / `--version` は V8.2 に固定されており、`--niji` はサポートされていません。下記の[速度モード](#速度モード)と[出力品質](#出力品質)を参照してください。
</Note>

## 基本パラメータ

### アスペクト比 `--ar`

画像のアスペクト比を設定します。整数比のみサポートされており、小数は拒否されます（`1.39:1` ではなく `139:100` と書いてください）。

```
a cat --ar 16:9
```

よく使う値：`1:1`、`4:3`、`3:2`、`16:9`、`9:16`、`2:3`。極端な比率は予測不能な結果を生む可能性があります。各比率で生成されるピクセルサイズは[出力品質](#出力品質)を参照してください。

### カオス `--chaos` / `--c`

生成結果の多様性を制御します。値が高いほど、4 枚の画像間の差異が大きくなります。

```
a cat --c 50
```

| 範囲 | 効果 |
|-------|--------|
| 0 | 4 枚の画像が非常に似ている（デフォルト） |
| 1-50 | 適度な多様性 |
| 50-100 | 高度にランダム、創造的な探索に適する |

### スタイライズ `--stylize` / `--s`

写実性とアートスタイルのバランスを調整します。

```
a cat --s 500
```

| 範囲 | 効果 |
|-------|--------|
| 0-250 | 写実的なスタイル、プロンプトに忠実 |
| 250-750 | バランス型 |
| 750-1000 | 強い芸術表現、大胆な色彩と構図 |

### 実験パラメータ `--exp`

`--stylize` に似ていますが併用可能で、より詳細でダイナミックかつ創造的な画像を生成します。

```
a cat --exp 25
```

- 推奨値：5、10、25、50、100
- 5-50 で効果の変化が顕著、50-100 では効果が頭打ちになります
- 25-50 を超えると `--stylize` の効果を上書きする可能性があります

### クオリティ `--quality` / `--q`

レンダリングの精細度を設定します。範囲 1 - 4、デフォルト 1。このフラグはそのまま上流に透過され、**価格は変わりません**。

```
a cat --q 3
```

- V8.2 は `1` / `2` / `3` / `4` を受け付けます。V8.1 は `1` / `4` のみ受け付けます。範囲外の値は上流で拒否され（`quality: should in [1 2 3 4]`）、タスクは失敗し、予約されたクレジットは返金されます
- Midjourney 公式のパラメータ表には V8 の `--q` が記載されていないため、視覚的な効果は上流がベストエフォートで提供するものです。頼りにする前に、ご自身のプロンプトでいくつかの値を比較してください
- 画像生成エンドポイント専用。派生タスク（バリエーション、リミックス、編集など）はソース画像を継承します

### Raw モード `--raw`

デフォルトの美化を無効化し、プロンプトの細部により厳密に従います。フォトリアリズムや精密な制御が必要なシーンに適しています。

```
product photo --raw
```

### ネガティブプロンプト `--no`

画像に含めたくない要素を列挙します。複数の項目はカンマで区切ります。説明文に「no fruit」や「without fruit」と書いても効果はありません。Midjourney はそれらの語を内容として扱うため、代わりにこのフラグを使用してください。

```
still life gouache painting --no fruit, flowers
```

### シード `--seed`

比較テストのために初期のランダム状態を固定します。

```
a cat --seed 23453422
```

- 範囲：0 - 4294967295
- 同じシード + 同じプロンプト → V8.x では約 99% 同一の結果（公式の数値）。パラメータをわずかに変えても画像は変化します
- シードを `turbo` 速度と組み合わせないでください。turbo はスループット最適化のため、シードの固定が確実に機能しません

## 画像参照パラメータ

### 画像プロンプト

プロンプトの**先頭**に画像 URL を配置し、生成内容に影響を与えます。

```
https://example.com/ref.jpg text description --iw 1.5
```

**有効な組み合わせのルール：**

| 組み合わせ | 有効か？ |
|-------------|--------|
| 画像 1 枚 + テキストなし | 無効（エラーになります） |
| 画像 1 枚 + テキスト説明 | 有効 |
| 画像 2 枚以上 + テキストなし | 有効 |
| 画像 2 枚以上 + テキスト説明 | 有効 |

- 画像プロンプトは最大 20 枚
- 対応フォーマット：`.png`、`.gif`、`.webp`、`.jpg`、`.jpeg`
- `draft` 速度では利用できません（`fast` を使用してください）
- URL は数秒以内に公開アクセスできる必要があります。[入力画像の要件](#入力画像の要件)を参照してください

### 画像ウェイト `--iw`

画像プロンプトの結果への影響度を制御します。範囲 0 - 3、デフォルト 1。値が高いほど参照画像に近い結果になります。

```
https://example.com/ref.jpg watercolor landscape --iw 2.0
```

### スタイル参照 `--sref`

参照画像のビジュアルスタイル（色、テクスチャ、ライティング）を一致させ、内容はコピーしません。**テキストプロンプトと併用する必要があります**。

```
a cat --sref https://example.com/style.jpg
```

- 複数指定をサポート：`--sref URL1 URL2`
- ランダムスタイルをサポート：`--sref random`（生成後に数値コードを返し、再利用可能）
- sref は最大 20 個
- テキストプロンプトは指示ではなく内容を記述してください（「make this look like the reference」ではなく「a cat」）

### スタイルウェイト `--sw`

スタイル参照の影響度を制御します。範囲 0 - 1000、デフォルト 100。

```
a cat --sref https://example.com/style.jpg --sw 500
```

### パーソナライゼーション `--p`

Midjourney のパーソナライゼーションプロファイルまたはムードボードのコードを適用します。このフラグは変更されずに透過されます。プロファイルは midjourney.com で作成・評価するもので、API から作成や一覧取得はできません。すでにお持ちのコードのみを使用し、まず少量のバッチで効果を検証してください。

```
a cat --p abc123
```

## 速度モード

速度モードは API の `model_params.speed` フィールドで制御します（プロンプトに `--draft` / `--fast` / `--turbo` を書かないでください）。

| モード | 説明 | 費用 |
|------|-------------|------|
| `draft` | 1 回の実行で 24 枚の軽量な 512 px スケッチ画像を返します。画像生成エンドポイント専用。 | fast と同じ倍率 |
| `fast` | 標準モード（デフォルト）、1 回の生成で 4 枚 | 標準 |
| `turbo` | ターボモード。生成がより高速、1 回の生成で 4 枚 | 2 倍 |

<Note>
V7 とは異なり、V8.2 の `draft` モードは**半額になりません**——`fast` と同じ倍率を使用します。draft は 1 回の実行で 24 枚の小さなスケッチを返すので、気に入ったものを選んでフル品質で再実行してください。draft は `hd` 品質と組み合わせることはできません。また、`draft` + `turbo` の組み合わせもできません（`speed` は単一の値です）。
</Note>

<Note>
Midjourney の公開ドキュメントでは Turbo は V8 で利用不可とされています。本プラットフォームが使用する上流チャネルは V8.2 で `turbo` を受け付けます（本番環境で検証済み、2 倍で課金）。上流が turbo リクエストを拒否した場合は、タスクは上流のメッセージとともに失敗し、予約されたクレジットは返金されます。
</Note>

## 出力品質

出力解像度はトップレベルの `quality` パラメータで制御し、プロンプトのフラグ**ではありません**。プロンプトに `--hd` を書かないでください。

| 値 | 解像度 | 費用 |
|-------|-----------|------|
| `standard` | 標準解像度、約 1 MP（デフォルト） | 1 倍 |
| `hd` | ネイティブ HD 出力、約 4 MP | 1.5 倍 |

アスペクト比ごとのおおよその出力サイズ（V8.2 公式の数値。HD の正確な寸法は多少異なる場合があります）：

| アスペクト比 | `standard` | `hd` |
|--------------|-----------|------|
| 1:1 | 1024 x 1024 | 2048 x 2048 |
| 4:3 | 1232 x 928 | 2464 x 1856 |
| 2:3 | 896 x 1344 | 1792 x 2688 |
| 16:9 | 1456 x 816 | 2912 x 1632 |

- 品質倍率は速度倍率と**掛け合わされます（乗算）**：`turbo` + `hd` = 3 倍
- `hd` は `draft` 速度と**互換性がありません**
- V8.2 には独立したアップスケールエンドポイントがありません。2K 出力が必要な場合は `hd` を使用してください

## プロンプトの文字数制限

| エンドポイント | 制限 | 備考 |
|----------|-------|-------|
| `mj-v8.2`（画像生成） | 上流が適用する**テキスト説明 1024 文字**。API 全体では最大 2048 文字を受け付けます | 上流は画像 URL と `--flags` を除いた説明文のみをカウントします。余裕分は URL とパラメータ用です |
| `mj-v8.2-remix` / `-edit` / `-retexture` / `-upload-paint` | 8100 文字 | プロンプトは編集指示として送信され、1024 のルールは適用されません |
| `mj-v8.2-variation` / `-remove-bg` | — | `prompt` は無視されます |

説明文が長すぎる場合、上流は `v8系列模型提示词长度限制为1024` で拒否し、タスクは失敗して予約されたクレジットは返金されます。

## 依存関係

以下のパラメータは効果を発揮するために他のパラメータを必要とします：

| パラメータ | 前提条件 |
|-----------|-------------|
| `--sw` | `--sref` が必要 |
| `--iw` | 画像プロンプトが必要 |
| `--sref` | テキストプロンプトが必要 |
| 単一の画像プロンプト | テキストプロンプトが必要 |

## 競合関係

| パラメータ A | パラメータ B | 説明 |
|-------------|-------------|-------------|
| `draft` 速度 | `hd` 品質 | draft モードは HD と組み合わせられません |
| `draft` 速度 | `turbo` 速度 | `speed` は単一の値です。turbo 速度での 24 枚スケッチは利用できません |
| `draft` 速度 | 画像プロンプト / `--sref` | 画像参照には `fast` が必要 |
| 画像のみのプロンプト | `--stylize` / `--exp` | テキストがないと互換性がありません |
| `--exp` > 25 | `--stylize` | 高い `--exp` は `--stylize` を抑制する可能性があります。併用時は `--exp` を下げてください |
| `--seed` | `turbo` 速度 | turbo ではシードの固定が確実に機能しません |

## V8.2 でサポートされていないパラメータ

V8.2 が除去するのは、バージョン固定や課金を狂わせるフラグだけです。**それ以外のフラグはすべてそのまま上流に透過されます**。上流がフラグをサポートしていない場合、タスクは上流のエラーメッセージとともに失敗し、予約されたクレジットは返金されます。黙って破棄されることはありません。

| パラメータ | 扱い |
|-----------|------|
| `--v` / `--version` / `--niji` | 除去 — バージョンは V8.2 に固定 |
| `--fast` / `--turbo` / `--draft` / `--relax` | 除去 — `model_params.speed` を使用 |
| `--hd` | 除去 — トップレベルの `quality` パラメータを使用 |
| `--bs` / `--batchsize` | 除去 — バッチサイズは設定不可 |
| `--edit` | 利用不可 — 公式の Edit Model はこのルートでは公開されていません。キャンバス編集には `mj-v8.2-edit` / `mj-v8.2-upload-paint` を使用してください |
| `--oref` / `--ow` | 上流で拒否（V8.2 では非サポート） |
| `--cref` / `--cw` | 上流で拒否（V8.2 では非サポート） |
| `--stop` | 上流で拒否 |
| マルチプロンプト `::` | 上流で拒否 |
| `--sv` | `--sv 6` のみ受け付け、かつ `--sref` との併用が必要 |
| `--repeat` / `--r`、`{}` 順列、`--stealth` / `--public` | API ではサポートされていません |

## 入力画像の要件

以下のルールは、画像プロンプト、`--sref` の URL、および retexture / upload-paint / remove-bg の `image_urls` フィールドに適用されます。

- **公開 HTTP(S) URL のみ。** Base64 と data URL は受け付けません。
- **上流はタスク作成時に画像を同期的に取得し、約 10 秒で諦めます。** 時間内にファイルをダウンロードできない場合、リクエストは `400` で失敗し、タスクは作成されません。中国本土外の画像ホスティング（imgur、ibb、raw.githubusercontent、pinimg、picsum など）は実際にはほぼ毎回失敗します。画像を高速な CDN に置くか、先に[ファイルアップロード API](/ja/api-manual/file-series/upload-url)でアップロードして、返された URL を使用してください。
- 対応フォーマット：`.png`、`.gif`、`.webp`、`.jpg`、`.jpeg`。ファイルサイズは適度に抑えてください。非常に大きなファイルは、到達可能なホストからでも取得時間の予算を超えることがあります。
- `mj-v8.2-remove-bg` は、本プラットフォームの Midjourney タスクが返す署名付き結果リンク（`Expires` / `Signature` を含む URL）を受け付けません。画像を再ホストするか、署名なしの URL を使用してください。retexture と upload-paint はこれらのリンクを受け付けます。
- `draft` 速度では画像参照は利用できません。

## プロンプトのフォーマット規則

### 基本構造

```
[image URL] text description --param1 value1 --param2 value2
```

### 記述ルール

- パラメータはテキストプロンプトの**末尾**に置きます
- `--` の前には**スペース**が必要です
- パラメータに句読点を使用しないでください
- パラメータの後にテキストを続けることはできません
- 画像内に文字を描画するには、二重引用符で囲みます：`a neon sign that says "OPEN" --ar 3:2`

### 例

<CodeGroup>
```text Correct
a yellow Persian cat --ar 1:2 --s 500
```

```text Incorrect
a yellow Persian cat--ar 2:3          ← -- の前にスペースがない
a yellow Persian cat - - ar 2:3       ← -- の間にスペースがある
a yellow Persian cat --ar 2:3, --s 50 ← パラメータに句読点がある
a yellow Persian cat --ar 2:3 more description ← パラメータの後にテキストがある
```
</CodeGroup>

## タスクのワークフロー

V8.2 の 7 つのモデルはすべて非同期で、呼び出しごとに課金されます。

1. **送信** — `POST /v1/images/generations` は即座にタスク `id`、`status: processing`、`usage.credits_reserved` を返します。上流のジョブはバックグラウンドで作成されます。
2. **ポーリング** — `GET /v1/tasks/{task_id}`（[タスクステータスの照会](/ja/api-manual/task-management/get-task-detail)）。3〜5 秒ごとにポーリングし、クライアント側で約 20 分の上限を設けてください。タスクがまだ `processing` の間に同じプロンプトを再送信しないでください。
3. **結果の読み取り** — `status` が `completed` になると、`results` に画像 URL が格納されます。`fast` / `turbo` では 4 枚、`draft` では 24 枚です。`usage.cost` に最終的な課金額が表示されます。
4. **画像の保存** — 結果リンクの有効期間は **30 日**です。保持したいものはダウンロードするか再ホストしてください。
5. **任意のコールバック** — `callback_url`（HTTPS、公開ホスト）を渡すと、`completed` / `failed` / `cancelled` 時に通知されます。コールバックはバックオフ付きで 3 回リトライされます。あくまで補助的な通知として扱い、タスク照会で確認してください。

| ステータス | 意味 | 最終状態？ |
|--------|---------|--------|
| `pending` | 受理済み、上流のキュー待ち | いいえ |
| `processing` | レンダリング中 | いいえ |
| `completed` | `results` に画像が用意された | はい |
| `failed` | 上流エラー、パラメータ拒否、コンテンツ審査、または取得失敗。メッセージは `error` にあり、予約されたクレジットは返金されます | はい |
| `cancelled` | ユーザーによりキャンセル | はい |

失敗したタスクは、上流によるパラメータ拒否（`--oref`、範囲外の `--q`、長すぎる説明文）や画像取得の失敗を含めて全額返金されます。唯一の例外はコンテンツ審査です（下記参照）。エラーコードとリトライの指針は[エラーコードリファレンス](/ja/api-manual/task-management/error-codes)ページに記載されています。

### 派生タスクは V7 エンジンを使用

V8.2 のソース画像を元にしたバリエーション、リミックス、キャンバス編集のタスクは、上流では Midjourney の V7 エンジンでレンダリングされます（V8 ベースの派生ジョブに対する Midjourney 公式の挙動）。結果はソース画像とスタイルがわずかに異なる場合があります。価格は変わりません。ソースタスクは同一アカウントに属する完了済みの `mj-v8.2` シリーズのタスクである必要があり、V8.1 のソースは受け付けられません。

## よくある質問

**V8.1 から移行する際にプロンプトを変更する必要はありますか？**
いいえ。`model` の値を変更するだけで、プロンプト、`model_params`、価格は変わりません。`--oref` / `--ow` が使えなくなる点と、`--q` が `1` と `4` に加えて `2` と `3` を受け付けるようになる点だけが異なります。

**画像プロンプトがタスク作成前に 400 で失敗するのはなぜですか？**
上流が取得時間の予算内に画像をダウンロードできなかったためです。ファイルを高速で公開アクセス可能なホストに移すか、ファイルアップロード API を使用してから再試行してください。

**turbo 速度で 24 枚の draft スケッチを取得できますか？**
いいえ。`speed` は単一の値であり、draft は常に fast の倍率で実行されます。

**`--q 4` は遅くなったり高くなったりしますか？**
課金は変わりません。レンダリング時間がわずかに長くなる場合があり、視覚的な向上はプロンプトによって異なります。

**V8.2 の画像をアップスケールできますか？**
V8.2 にはアップスケールエンドポイントがありません。代わりに `quality: "hd"` で生成し、ネイティブ 2K 出力を取得してください。

## コンテンツ審査に関する注意

<Note>
Midjourneyにはコンテンツ審査機能が組み込まれています。生成された画像の一部が審査でフィルタリングされた場合、そのリクエストで消費されたクレジットは返金されません。プロンプトの内容がガイドラインに準拠しているかご確認ください。
</Note>
