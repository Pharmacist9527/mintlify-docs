## パラメータ一覧

| パラメータ | 書き方 | 型 | 範囲 | デフォルト | 説明 |
|-----------|--------|------|-------|---------|-------------|
| アスペクト比 | `--ar W:H` | 整数比 | 任意の正の整数比、小数不可 | 1:1 | 画像のアスペクト比 |
| カオス | `--c N` | int | 0 - 100 | 0 | 生成結果の多様性 |
| シード | `--seed N` | int | 0 - 4294967295 | ランダム | シードを固定して結果を再現 |
| スタイライズ | `--s N` | int | 0 - 1000 | 100 | アートスタイルの強度 |
| 実験パラメータ | `--exp N` | int | 0 - 100 | 0 | 美的効果、スタイライズと併用可能 |
| クオリティ（精細度） | `--quality N` / `--q N` | int | 1 - 4 | 1 | レンダリングの精細度。4 は高品質モード。追加料金なし。V8.1 は 1 / 4 のみ受け付けます |
| Raw モード | `--raw` | スイッチ | — | オフ | デフォルトの美化を無効化 |
| ネガティブプロンプト | `--no item1, item2` | テキスト | — | — | 画像に含めない要素 |
| 画像ウェイト | `--iw N` | float | 0 - 3 | 1 | 画像プロンプトの影響度 |
| スタイル参照 | `--sref [URL]` | URL | — | — | ビジュアルスタイルを一致させる |
| スタイルウェイト | `--sw N` | int | 0 - 1000 | 100 | スタイル参照の強度 |
| パーソナライゼーション | `--p [code]` | コード | — | — | パーソナライゼーションプロファイルまたはムードボードのコードを適用。そのまま透過 |
| タイル | `--tile` | スイッチ | — | オフ | シームレスな繰り返しパターンを生成 |
| ウィアード | `--weird N` / `--w N` | int | 0 - 3000 | 0 | 型破りで実験的な美的表現 |

<Note>
以下の 2 つの設定は prompt に**書かず**、API で制御します（prompt に書いても効果はなく、パラメータは除去されます）：

- **速度**（`draft` / `fast`）→ `model_params.speed`
- **出力品質**（`standard` / `hd`）→ トップレベルの `quality` パラメータ

`--v` / `--version` は V8.2 に固定されており、`--niji` はサポートされていません。下記の[速度モード](#速度モード)と[出力品質](#出力品質)を参照してください。
</Note>

## 基本パラメータ

### アスペクト比 `--ar`

画像のアスペクト比を設定します。整数比のみサポートされており、小数は拒否されます（`1.39:1` ではなく `139:100` と書いてください）。極端な比率は実験的なもので、予測不能な結果を生む可能性があります。

```
a cat --ar 16:9
```

よく使う値：`1:1`、`4:3`、`3:2`、`16:9`、`9:16`、`2:3`。ピクセルサイズは[出力品質](#出力品質)を参照してください。

### カオス `--chaos` / `--c`

生成結果の多様性を制御します。値が高いほど、4 枚の画像間の差異が大きくなります。

```
a cat --c 50
```

| 範囲 | 効果 |
|-------|--------|
| 0 | 4 枚の画像が高度に一致（デフォルト） |
| 1-30 | わずかな差異 |
| 30-70 | 適度な多様性 |
| 70-100 | 顕著な差異、創造的な探索に適する |

### スタイライズ `--stylize` / `--s`

写実性とアートスタイルのバランスを調整します。

```
a cat --s 500
```

| 範囲 | 効果 |
|-------|--------|
| 0-250 | 写実的なスタイル、プロンプトに忠実 |
| 250-750 | バランス型 |
| 750-1000 | 強い芸術表現、大胆な色彩と構図 |

### 実験パラメータ `--exp`

`--stylize` に似ていますが併用可能で、より詳細でダイナミックかつ創造的な画像を生成します。

```
a cat --exp 25
```

- 推奨値：5、10、25、50、100
- 5-50 で効果の変化が顕著、50-100 では効果が頭打ちになります
- 25-50 を超えると `--stylize` と `--p` の効果を上書きする可能性があります。併用時は低めの値を使用してください

### クオリティ `--quality` / `--q`

レンダリングの精細度を設定します。範囲 1 - 4、デフォルト 1。`4` は高品質モードです。このパラメータはそのまま上流に透過され、**価格は変わりません**。

```
a cat --q 3
```

- V8.2 は `1` / `2` / `3` / `4` を受け付けます。V8.1 は `1` / `4` のみ受け付けます。範囲外の値は上流で拒否され（`quality: should in [1 2 3 4]`）、タスクは失敗し、予約されたクレジットは返金されます
- 値が高いほどレンダリングに時間がかかります
- 画像生成エンドポイント専用。派生タスク（バリエーション、リミックス、編集など）はソース画像を継承します

### Raw モード `--raw`

デフォルトの美化を無効化し、プロンプトの細部により厳密に従います。フォトリアリズムや精密な制御が必要なシーンに適しています。

```
product photo --raw
```

### ネガティブプロンプト `--no`

画像に含めたくない要素を列挙します。複数の項目はカンマで区切ります。これは、それらの要素に -0.5 のウェイトを与えるのと同等です。説明文に「no fruit」や「without fruit」と書いても効果はありません。Midjourney はそれらの語を内容として扱うため、代わりにこのパラメータを使用してください。

```
still life gouache painting --no fruit, flowers
```

### シード `--seed`

比較テストのために初期のランダム状態を固定します。

```
a cat --seed 23453422
```

- 範囲：0 - 4294967295
- シードは初期状態を固定するだけで、同一の出力を保証するものではありません。プロンプト、パラメータ、モデルバージョンのいずれかを変更すると結果は変わります
- テスト時は固定シードを、本番では多様性のためにランダムなシードを使用してください

## 画像参照パラメータ

### 画像プロンプト

プロンプトの**先頭**に画像 URL を配置し、生成内容に影響を与えます。

```
https://example.com/ref.jpg text description --iw 1.5
```

**有効な組み合わせのルール：**

| 組み合わせ | 有効か？ |
|-------------|--------|
| 画像 1 枚 + テキストなし | 無効（エラーになります） |
| 画像 1 枚 + テキスト説明 | 有効 |
| 画像 2 枚以上 + テキストなし | 有効 |
| 画像 2 枚以上 + テキスト説明 | 有効 |

- 画像プロンプトは最大 20 枚
- 対応フォーマット：`.png`、`.gif`、`.webp`、`.jpg`、`.jpeg`。1 ファイルあたり最大 20 MB、1 辺あたり最大 16k ピクセル
- 画像のみのプロンプト（テキストなし）は `--stylize` および `--weird` と互換性がありません
- `draft` 速度でも利用できます（本プラットフォームで検証済み）。`draft` と併用できないのは `--tile` のみです
- URL は数秒以内に公開アクセスできる必要があります。[入力画像の要件](#入力画像の要件)を参照してください

### 画像ウェイト `--iw`

画像プロンプトの結果への影響度を制御します。範囲 0 - 3、デフォルト 1。値が高いほど参照画像に近い結果になります。

```
https://example.com/ref.jpg watercolor landscape --iw 2.0
```

### スタイル参照 `--sref`

参照画像のビジュアルスタイル（色、テクスチャ、ライティング）を一致させ、内容はコピーしません。**テキストプロンプトと併用する必要があります**。

```
a cat --sref https://example.com/style.jpg
```

- 複数指定をサポート：`--sref URL1 URL2`。相対ウェイトは `--sref URL1::2 URL2::1` の形で指定できます（上流のドキュメントに記載。本プラットフォームでは未検証）
- ランダムスタイルをサポート：`--sref random`（生成後に数値コードを返し、再利用可能）
- sref は最大 20 個
- テキストプロンプトは指示ではなく内容を記述してください（「make this look like the reference」ではなく「a cat」）

### スタイルウェイト `--sw`

スタイル参照の影響度を制御します。範囲 0 - 1000、デフォルト 100。

```
a cat --sref https://example.com/style.jpg --sw 500
```

### パーソナライゼーション `--p`

Midjourney のパーソナライゼーションプロファイルまたはムードボードのコードを適用します。このパラメータは変更されずに透過されます。プロファイルは midjourney.com で作成・評価するもので、API から作成や一覧取得はできません。すでにお持ちのコードのみを使用し、まず少量のバッチで効果を検証してください。`--p` は `--weird` と併用できません。

```
a cat --p abc123
```

## 速度モード

速度モードは API の `model_params.speed` フィールドで制御します（プロンプトに `--draft` / `--fast` を書かないでください）。

ルートごとの取りうる値：画像生成は `draft` / `fast`、リミックス・キャンバス編集・リテクスチャ・アップロードペイントは `fast` のみ、バリエーションと背景除去には speed フィールドがありません。

| モード | 説明 | 費用 |
|------|-------------|------|
| `draft` | 1 回の実行で 24 枚の軽量な 512 px スケッチ画像を返します。画像生成エンドポイント専用。 | fast と同じ倍率 |
| `fast` | 標準モード（デフォルト）、1 回の生成で 4 枚 | 標準 |

<Note>
V7 とは異なり、V8.2 の `draft` モードは**半額になりません**——`fast` と同じ倍率を使用します。draft は 1 回の実行で 24 枚の小さなスケッチを返すので、気に入ったものを選んでフル品質で再実行してください。draft は `hd` 品質または `--tile` と組み合わせることはできません（`--oref` は V8.2 ではそもそもサポートされていません）。

**V8.2 では turbo は利用できません。** 上流チャネルのドキュメントでは V8 は turbo モード非対応とされているため、`speed: "turbo"` は V8.2 のすべてのエンドポイントで `400` で拒否されます（V8.1 と同様）。
</Note>

## 出力品質

出力解像度はトップレベルの `quality` パラメータで制御し、プロンプトのパラメータ**ではありません**。プロンプトに `--hd` を書かないでください。

| 値 | 解像度 | 費用 |
|-------|-----------|------|
| `standard` | 標準解像度、1:1 では長辺約 1024 px（デフォルト） | 1 倍 |
| `hd` | ネイティブ 2K 出力、1:1 では約 2048 x 2048 | 1.5 倍 |

- 品質倍率は速度倍率と**掛け合わされます（乗算）**
- `hd` は `draft` 速度と**互換性がありません**
- V8.2 には独立したアップスケールエンドポイントがありません。上流は V8 の「アップスケール」を `hd` での新規生成として実装しているため、2K 出力が必要な場合は `quality: "hd"` を使用してください

## プロンプトの文字数制限

| エンドポイント | 制限 | 備考 |
|----------|-------|-------|
| `mj-v8.2`（画像生成） | 上流が適用する**テキスト説明 1024 文字**。API 全体では最大 2048 文字を受け付けます | 上流は画像 URL と `--パラメータ` を除いた説明文のみをカウントします。余裕分は URL とパラメータ用です |
| `mj-v8.2-remix` / `-edit` / `-retexture` / `-upload-paint` | 8100 文字 | プロンプトは編集指示として送信され、1024 のルールは適用されません |
| `mj-v8.2-variation` / `-remove-bg` | — | `prompt` は無視されます |

説明文が長すぎる場合、上流は `v8系列模型提示词长度限制为1024` で拒否し、タスクは失敗して予約されたクレジットは返金されます。

|-----------|-------------|
| `--sw` | `--sref` が必要 |
| `--iw` | 画像プロンプトが必要 |

| 単一の画像プロンプト | テキストプロンプトが必要 |

## 競合関係

| パラメータ A | パラメータ B | 説明 |
|-------------|-------------|-------------|
| `draft` 速度 | `hd` 品質 | draft モードは HD と組み合わせられません |
| `draft` 速度 | `--tile` | 併用できません |
| `--weird` | `--p` | 併用できません |
| 画像のみのプロンプト | `--stylize` / `--weird` | テキストがないと互換性がありません |
| `--exp` > 25 | `--stylize` / `--p` | 高い `--exp` はこれらを抑制する可能性があります。併用時は `--exp` を下げてください |

## V8.2 でサポートされていないパラメータ

V8.2 が除去するのは、バージョン固定や課金を狂わせるパラメータだけです。**それ以外のパラメータはすべてそのまま上流に透過されます**。上流がパラメータをサポートしていない場合、タスクは上流のエラーメッセージとともに失敗し、予約されたクレジットは返金されます。黙って破棄されることはありません。

| パラメータ | 扱い |
|-----------|------|
| `--v` / `--version` / `--niji` | 除去 — バージョンは V8.2 に固定 |
| `--fast` / `--turbo` / `--draft` / `--relax` | 除去 — `model_params.speed` を使用（`draft` / `fast`。V8.2 では turbo は利用不可） |
| `--hd` | 除去 — トップレベルの `quality` パラメータを使用 |
| `--bs` / `--batchsize` | 除去 — バッチサイズは設定不可 |
| `--edit` | 上流の指示ベース編集エンドポイント用に予約されており、本プラットフォームではまだ公開されていません。現在のすべてのエンドポイントで上流に拒否されます |
| `--oref` / `--ow` | 上流で拒否（V8.2 では非サポート） |
| `--cref` / `--cw` | 上流で拒否（V8.2 では非サポート） |
| `--stop` | 上流で拒否 |
| マルチプロンプト `::` | 上流で拒否 |
| `--sv` | `--sv 6` のみ受け付け、かつ `--sref` との併用が必要 |
| `--repeat` / `--r`、`{}` 順列、`--stealth` / `--public` | API ではサポートされていません |

<Note>
上流チャネルは V8.1 / V8.2 向けに**指示ベースの編集**エンドポイント（Midjourney Edit Model：`--edit`、最大 4 枚の参照画像、任意で透明マスクによる再描画）も公開しています。本プラットフォームではまだ公開されておらず、提供時期を調整中です。`mj-v8.2-edit` と `mj-v8.2-upload-paint` はキャンバス編集（`canvas` + `img_pos` + 任意の `mask`）であり、`mj-v8.2-retexture` はリテクスチャツールです。現在のいずれのエンドポイントでも、プロンプトに `--edit` を書くと上流で拒否されます。
</Note>

## 入力画像の要件

以下のルールは、画像プロンプト、`--sref` の URL、および retexture / upload-paint / remove-bg の `image_urls` フィールドに適用されます。

- **公開 HTTP(S) URL のみ。** Base64 と data URL は受け付けません。URL 自体は 1024 文字以内である必要があります。
- **上流はタスク作成時に画像を同期的に取得し、約 10 秒で諦めます**（本プラットフォームでの実測値）。時間内にファイルをダウンロードできない場合、リクエストは `400` で失敗し、タスクは作成されません。中国本土外の画像ホスティング（imgur、ibb、raw.githubusercontent、pinimg、picsum など）は実際にはほぼ毎回失敗します。画像を高速な CDN に置くか、先に[ファイルアップロード API](/ja/api-manual/file-series/upload-url)でアップロードして、返された URL を使用してください。
- 対応フォーマット：`.png`、`.gif`、`.webp`、`.jpg`、`.jpeg`（`mj-v8.2-remove-bg` は `.png`、`.jpg`、`.jpeg` のみ受け付けます）。1 ファイルあたり最大 20 MB、1 辺あたり最大 16k ピクセル。非常に大きなファイルは、到達可能なホストからでも取得時間の予算を超えることがあります。
- `mj-v8.2-remove-bg` は、本プラットフォームの Midjourney タスクが返す署名付き結果リンク（`Expires` / `Signature` を含む URL）を受け付けません。画像を再ホストするか、署名なしの URL を使用してください。retexture と upload-paint はこれらのリンクを受け付けます。
- 画像プロンプトと `--sref` の URL は `draft` 速度でも受け付けられます（本プラットフォームで検証済み）。`draft` と併用して拒否されるのは `--tile` のみです。

## プロンプトのフォーマット規則

### 基本構造

```
[image URL] text description --param1 value1 --param2 value2
```

### 記述ルール

- パラメータはテキストプロンプトの**末尾**に置きます
- `--` の前には**スペース**が必要です
- パラメータに句読点を使用しないでください
- パラメータの後にテキストを続けることはできません
- 画像内に文字を描画するには、二重引用符で囲みます：`a neon sign that says "OPEN" --ar 3:2`

### 例

<CodeGroup>
```text Correct
a yellow Persian cat --ar 1:2 --s 500
```

```text Incorrect
a yellow Persian cat--ar 2:3          ← -- の前にスペースがない
a yellow Persian cat - - ar 2:3       ← -- の間にスペースがある
a yellow Persian cat --ar 2:3, --s 50 ← パラメータに句読点がある
a yellow Persian cat --ar 2:3 more description ← パラメータの後にテキストがある
```
</CodeGroup>

## タスクのワークフロー

V8.2 の 7 つのモデルはすべて非同期で、呼び出しごとに課金されます。

1. **送信** — `POST /v1/images/generations` は即座にタスク `id`、`status: processing`、`usage.credits_reserved` を返します。上流のジョブはバックグラウンドで作成されます。
2. **ポーリング** — `GET /v1/tasks/{task_id}`（[タスクステータスの照会](/ja/api-manual/task-management/get-task-detail)）。上流の報告では生成と編集の平均所要時間は約 40 秒です。3〜5 秒ごとにポーリングし、クライアント側で約 20 分の上限を設けてください。タスクがまだ `processing` の間に同じプロンプトを再送信しないでください。
3. **結果の読み取り** — `status` が `completed` になると、`results` に画像 URL が格納されます。`fast` では 4 枚、`draft` では 24 枚です。`usage.cost` に最終的な課金額が表示されます。
4. **画像の保存** — 結果リンクの有効期間は **30 日**です。保持したいものはダウンロードするか再ホストしてください。
5. **任意のコールバック** — `callback_url`（HTTPS、公開ホスト）を渡すと、`completed` / `failed` 時に通知されます。コールバックはバックオフ付きで 3 回リトライされます。あくまで補助的な通知として扱い、タスク照会で確認してください。

| ステータス | 意味 | 最終状態？ |
|--------|---------|--------|
| `pending` | 受理済み、上流のキュー待ち | いいえ |
| `processing` | レンダリング中 | いいえ |
| `completed` | `results` に画像が用意された | はい |
| `failed` | 上流エラー、パラメータ拒否、コンテンツ審査、または取得失敗。メッセージは `error` にあり、予約されたクレジットは返金されます | はい |

失敗したタスクは、上流によるパラメータ拒否（`--oref`、範囲外の `--q`、長すぎる説明文）や画像取得の失敗を含めて全額返金されます。唯一の例外はコンテンツ審査です（下記参照）。エラーコードとリトライの指針は[エラーコードリファレンス](/ja/api-manual/task-management/error-codes)ページに記載されています。

### 派生タスク

バリエーション、リミックス、キャンバス編集は、同一アカウントの完了済み `mj-v8.2` シリーズのタスクをソース（`task_id` + `image_number`）として使用します。上流チャネルのドキュメントに記載され、本プラットフォームで検証済みのルール：

- これらの派生操作では、ソースタスクは上流の Midjourney V7 エンジンでレンダリングされるため、結果はソース画像とスタイルがわずかに異なる場合があります。価格は変わりません。V8.1 のソースは受け付けられません。
- `image_number` でソース画像を選択します：`fast` のソースタスクは `0`〜`3`、`draft` のソースタスクは `0`〜`23`（24 枚のスケッチすべてをバリエーション、リミックス、編集のソースにできます）。
- `mj-v8.2-upload-paint`、`mj-v8.2-retexture`、`mj-v8.2-remove-bg` の結果は、バリエーション、リミックス、編集のソースとして**使用できません**。上流はこれらのアップスケールのみを許可しており、本ルートでは公開していません。代わりに画像生成、バリエーション、リミックス、編集のタスクをソースにしてください。

## よくある質問

**V8.1 から移行する際にプロンプトを変更する必要はありますか？**
いいえ。`model` の値を変更するだけで、プロンプト、`model_params`、価格は変わりません。`--oref` / `--ow` が使えなくなる点と、`--q` が `1` と `4` に加えて `2` と `3` を受け付けるようになる点だけが異なります。

**画像プロンプトがタスク作成前に 400 で失敗するのはなぜですか？**
上流が取得時間の予算内に画像をダウンロードできなかったためです。ファイルを高速で公開アクセス可能なホストに移すか、ファイルアップロード API を使用してから再試行してください。

**turbo 速度はありますか？**
いいえ。上流のドキュメントでは V8 は turbo 非対応とされているため、V8.2 は V8.1 と同様に `draft` と `fast` のみ提供します。

**`--q 4` は遅くなったり高くなったりしますか？**
課金は変わりません。上流は `4` を高品質モードとしており、レンダリングに時間がかかります。

**V8.2 の画像をアップスケールできますか？**
V8.2 にはアップスケールエンドポイントがありません。代わりに `quality: "hd"` で生成し、ネイティブ 2K 出力を取得してください。

## コンテンツ審査に関する注意

<Note>
Midjourneyにはコンテンツ審査機能が組み込まれています。審査は画像ごとに個別に行われます。生成された画像の一部がフィルタリングされた場合、その枠は空で返され、残りの画像は通常どおり配信されますが、そのリクエストで消費されたクレジットは返金されません。プロンプトの内容がガイドラインに準拠しているかご確認ください。
</Note>
