プラグインは、リモート MCP の設定とエージェント向けのガイダンスをまとめてパッケージ化できます。インストールと認証の仕組みは、ホストごとに異なります。

| 入口 | インストールされる内容 | メディアの実行 |
|---|---|---|
| ChatGPT のカスタム MCP プラグイン | ChatGPT で作成されるサーバー接続 | ChatGPT がリモート MCP を呼び出します |
| Codex のリポジトリプラグイン | EvoLink のリモート MCP 設定と evolink-mcp スキル | Codex がリモート MCP を呼び出します |
| Claude Code のリポジトリプラグイン | EvoLink のリモート MCP 設定と evolink-mcp スキル | Claude Code がリモート MCP を呼び出します |
| CLI 同梱のスキル | evolink-cli の指示とリファレンス | エージェントが CLI を実行し、CLI が API を直接呼び出します |
| 単体の evolink-mcp スキル | MCP の呼び出し方のガイダンスのみ | MCP の設定と認証は、別途必要です |

## ChatGPT のカスタム MCP プラグイン

[ChatGPT の設定](/ja/mcp/chatgpt)に従って、カスタム MCP サーバーを追加します：

```text
https://mcp.evolink.ai/mcp
```

OAuth を選択し、ブラウザでのログインと承認を完了してから、会話で EvoLink を有効にします。ChatGPT は、下記の Codex の marketplace コマンドを使わず、npm によるローカルへの CLI のインストールも必要としません。

カスタム接続を作成できても、EvoLink が公開のプラグインディレクトリに掲載されているという意味ではありません。接続を作成できるかどうか、生成ツールを使えるかどうかは、お使いのアカウント、ホストのバージョン、ワークスペースの権限によって決まります。[OpenAI のカスタム MCP に関するガイダンス](https://developers.openai.com/api/docs/guides/custom-mcp-server)を参照してください。

## Codex のリポジトリプラグイン

お使いの Codex のバージョンが `plugin` に対応していることを確認してください。このプラグインは、ネイティブのリモート MCP を使います。公式サイトの CLI 用プロンプトは、別の方法です。CLI を使っている場合は、生成のためにプラグインを追加でインストールする必要はありません。

<Steps>

<Step title="ソースを追加してプラグインをインストールする">

Codex を実行するマシンとユーザーのターミナルで、次を実行します：

```bash
codex plugin marketplace add Evolink-AI/mcp-plugin
codex plugin add evolink@evolink
codex plugin list --json
```

プラグインの一覧に EvoLink が表示されることを確認してください。このプラグインが提供するのは、リモート MCP の設定と `evolink-mcp` スキルであり、EvoLink CLI ではありません。

</Step>

<Step title="プラグインを読み込んで認証する">

プラグインを再読み込みするか、Codex で新しい会話を開いて、EvoLink サーバーが読み込まれていることを確認します。求められたら、ホストのブラウザ OAuth を完了してください。サーバーが登録済みで、次のコマンドに対応している場合は、これを使います：

```bash
codex mcp login evolink
```

ログインと承認が終わるまでコマンドを実行したままにし、そのあとで Codex に戻ります。手動の MCP 設定がすでにある場合は、単一の登録元を選んでください。

</Step>

<Step title="ツールとスキルを検証する">

```text
evolink-mcp を読んだことを確認してから、EvoLink で残高と利用可能な画像モデルを確認してください。まだ生成しないでください。
```

スキルが読み込まれ、`check_balance` と `search_models` の実際の呼び出しが成功すれば、成功です。プラグインの一覧だけでは、認証は検証できません。

</Step>

</Steps>

ソースを更新するには、次を実行し、ホストでプラグインを再読み込みして、実際のバージョンを確認します：

```bash
codex plugin marketplace upgrade evolink
```

手動での MCP 設定については、[Codex CLI リファレンス](https://learn.chatgpt.com/docs/cli/reference)と [Codex の設定](/ja/mcp/codex)を参照してください。CLI の手順は、[別の CLI ガイド](/ja/cli/codex)にあります。

## Claude Code のリポジトリプラグイン

プラグインに対応したバージョンの Claude Code を使ってください。以下は **Claude Code の会話内コマンド**であり、通常のシェルコマンドではありません。

<Steps>

<Step title="リポジトリプラグインをインストールする">

```text
/plugin marketplace add Evolink-AI/mcp-plugin
/plugin install evolink@evolink
```

インストールが終わるのを待ち、現在のユーザーまたはプロジェクトで EvoLink が有効になっていることを確認します。ほかのプラグインは、そのまま残してください。

</Step>

<Step title="リモート MCP を認証する">

```text
/mcp
```

プラグインを再読み込みしたら、EvoLink を選択し、ブラウザでの認証を完了します。手動で登録した接続と重複しないようにしてください。

</Step>

<Step title="無料で検証する">

アシスタントに、`evolink-mcp` を読んだことを確認してもらい、生成は行わずに、残高とモデルを実際に照会してもらいます。手動での MCP 設定については、[Claude Code の設定](/ja/mcp/claude-code)を参照してください。CLI の手順は、[別の CLI ガイド](/ja/cli/claude-code)にあります。

</Step>

</Steps>

## MCP スキルだけをインストールする

ネイティブ MCP がすでに設定されていて、エージェント向けのガイダンスだけが必要な場合：

```bash
npx skills add Evolink-AI/mcp-plugin -g -y
```

このコマンドは、skills インストーラーを通じて、リポジトリのスキルを取得します。EvoLink CLI をインストールしたり、ローカル MCP を起動したり、OAuth を完了したりはしません。ホストがインストール先を検出し、evolink-mcp を読み込むことを確認してください。

## プラグインが案内する内容

ソースは [Evolink-AI/mcp-plugin](https://github.com/Evolink-AI/mcp-plugin) です。設定は、ホスト型のリモート MCP を指しています。このスキルは、モデルの探索、パラメータの検証、見積もりと承認、参照素材のアップロード、生成、タスク、失敗からの復旧、オリジナルファイルの受け渡しを扱います。EvoLink MCP のツールに、コード開発、任意のファイル編集、本格的な動画編集の機能を加えるものではありません。

CLI のスキルと MCP のスキルは、メディアに関する方針を共有できますが、使うコマンドとツールは異なります。タスクごとに1つの経路を選んでください。送信がタイムアウトして結果が不明な場合は、別の入口から生成し直すのではなく、元のリクエストまたは task_id を復旧してください。内容とディレクトリについては[エージェント向けリソース](/ja/cli-mcp/agent-resources#skills)を、パラメータについては[プラットフォームのリファレンス](/ja/mcp/tools)を参照してください。

上限と認証の取り消しについては、[料金と保持期間](/ja/mcp/billing)を参照してください。プラグインのインストール、スキルのインストール、OAuth の認証は、有料生成のリクエストを承認するものではありません。

## プラグインのインストールに関する問題

| 症状 | 次の手順 |
|---|---|
| plugin / marketplace コマンドが見つからない | ホストのバージョンと公式の設定手順を確認するか、そのホストの手動 MCP ガイド、または[別の CLI セットアップ](/ja/cli/setup)を使います |
| リポジトリを取得できない | GitHub への接続と、ホストのソース設定を確認します。元のエラーは残しておいてください |
| インストールしたのにツールがない | 実際に使っているセッションを再読み込みし、プラグインを有効にして、OAuth を完了します |
| サーバーまたはスキルが重複している | 設定をバックアップし、それぞれのソースを確認して、使うものだけを残します。ほかのサービスは、そのまま残してください |
| ツールは一覧に表示されるのに、呼び出しが失敗する | 無料の残高照会で、認証を検証します。[MCP のトラブルシューティング](/ja/mcp/billing#mcp-connection)を参照してください |

プラグインをインストールしても、有料のテストが承認されたことにはなりません。検出やそのほかの問題については、[総合トラブルシューティング](/ja/mcp/billing#faq)を参照してください。
