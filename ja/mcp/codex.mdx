このページでは、Codex でのネイティブ MCP を扱います。リモートのサービスは Streamable HTTP とブラウザの OAuth を使い、EvoLink CLI は必要ありません。コマンドやスキルを実行する場合は、別の [CLI ガイド](/ja/cli/codex)を使ってください。

## リモート MCP を接続する

ネイティブツールを使う場合は、**Streamable HTTP + OAuth** と、次のサーバー URL を使います：

```text
https://mcp.evolink.ai/mcp
```

CLI のインストールは必要ありません。既存の設定をバックアップし、EvoLink の部分だけをマージして、ほかのサービスはそのまま残してください。コマンドによる登録か、手動での登録のどちらかを選びます。

<Steps>

<Step title="リモートサーバーを追加する">

Codex CLI がインストールされているターミナルで、次を実行します：

```bash
codex mcp add evolink --url https://mcp.evolink.ai/mcp
```

設定に `evolink` が含まれていることを確認してください。追加する前に、既存の項目がないかを確認します。手動での登録とプラグインによる登録が重複しないようにしてください。

</Step>

<Step title="MCP を別途認証する">

```bash
codex mcp login evolink
```

ブラウザで EvoLink にログインし、承認して、完了を待ちます。追加の時点で認証がすでに完了している場合は、ログインを繰り返す必要はありません。`evolink auth login` では、このネイティブ接続は認証されません。

</Step>

<Step title="接続を確認し、残高を照会する">

```bash
codex mcp list
```

Codex で新しいセッションを開くか、`/mcp` を使ってから、下記の、無料で検証するためのプロンプトを送信します。実際のアカウント残高と利用可能なモデルが返されれば、成功です。

</Step>

</Steps>

手動で設定する場合は、ユーザーの `~/.codex/config.toml`、または信頼できるプロジェクトの `.codex/config.toml` に、次のセクションだけをマージします：

```toml
[mcp_servers.evolink]
url = "https://mcp.evolink.ai/mcp"
```

Codex App には、同じ URL と OAuth を使う、独自のプラグインまたはカスタム MCP 接続があります。ターミナルの CLI にログインしても、App が自動的に接続されるわけではありません。[Codex のドキュメント](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)を参照してください。

認証が済んだら、エージェントのチャットで次を送信します：

```text
EvoLink でアカウントの残高を確認し、利用可能な画像モデルを検索してください。まだ生成しないでください。
```

**成功の目安**：`check_balance` と `search_models` の実際の呼び出しが結果を返すこと。これらのツールは、実際の MCP 接続で検証してください。

## アップデート、切断、トラブルシューティング

ホスト型の MCP サーバーは、EvoLink が更新します。設定を変更したら、実際に使っているクライアントのセッションを再読み込みしてください。必要に応じて、そのクライアントの OAuth 操作から再認証します。切断するには、ホストの MCP 設定で EvoLink を無効にするか、ログアウトするか、削除してください。ほかのサーバーはそのまま残します。

| 症状 | 対処 |
|---|---|
| URL を追加したのにツールがない | 接続を有効にし、認証を完了して、再読み込みし、組織のポリシーを確認します |
| 401、または認証を求められる | この MCP 接続を再認証し、元のタスク ID を保持します |
| 403、またはツールが拒否される | ホストの権限、アカウントやキーの状態、ネットワークのエラーを確認します |
| タイムアウト、またはレスポンスを受け取れない | 生成し直すのではなく、元の操作を照会して復旧します |
| リンクだけが表示される、またはプレビューがグレーになる | 自動的に作り直さずに、オリジナルファイルを開いて渡します |

[MCP の料金、アクセス、トラブルシューティング](/ja/mcp/billing#faq)を参照してください。送信の前に、[制作のワークフロー](/ja/mcp/overview#workflows)を読んでください。呼び出しの形は、[MCP ツールリファレンス](/ja/mcp/tools)にあります。
