## MCP の料金と承認

このページは、リリース済みの MCP 1.12.1 を対象としています。`estimate_cost` を呼び出してから、モデル、最終的な入力、出力の数、見積もり額を示してください。生成ツールを呼び出すのは、このタスクが明確に承認されてからにしてください。ユーザーが、このタスク、バッチ、または会話の残り全体について、見積もりや確認は不要だと明確に述べた場合、アシスタントは代わりに `skip_estimate: true` を付けて送信します。[見積もりなしで生成する](/ja/mcp/tools#skip-estimate)を参照してください。

見積もりの状態、公開価格に基づくことによる制限、承認、予算については、[モデル、料金、クォータ](/ja/cli-mcp/models-and-billing#pricing)を参照してください。リリース済みの max_cost_usd は、送信前の見積もりと比較するだけで、最終的な請求額に上限を設けるものではありません。

estimate_cost は max_cost_usd を受け付けません。生成ツールは受け付けます。

ネイティブ MCP には、CLI のようなローカルの `quote_id` と `--confirm` コマンドも、セッション単位のサーバー側承認ボタンもありません。エージェントは、このタスクのモデル、入力、見積もり、承認を保持する必要があります。入力が変わった場合、価格が上がった場合、承認の有効期限が切れた場合は、改めて承認が必要です。承認（`pricing_quote`）は、承認済みの価格以下である限り、見積もりから24時間有効です。生成ツールはもう一度見積もりを行い、価格が変わっていないか下がっていれば、その後に価格ルールが変更されていても送信します。価格が上がっていれば `price_changed`、入力が変わっていれば `quote_input_changed`、承認が `expires_at` を過ぎていれば `quote_expired` が返されます。ホストのツール権限、アカウントの認証、購入の承認は、互いに代わりになるものではありません。

モデル、残高、タスクの照会では、生成は送信されません。生成は課金されます。ファイルサービスの制限は、別途適用されます。失敗したタスクは課金されず、送信時に仮押さえされたクレジットは自動的に返還されます。タイムアウトしたことやチャットを閉じたことは、課金が発生しなかったことや、返金が完了したことの根拠にはなりません。使用量の照会は、完全な精算の領収書ではありません。

[共通のアクセスルール](/ja/cli-mcp/models-and-billing#authorization)を参照してください。このページには、このルートでのログインとログアウトの操作を記載しています。

## 認証、権限、クォータ

リモート MCP は、Passport によるブラウザの OAuth を使います。接続用の認証情報はホストが保存し、サービスは OAuth に紐付いた既存のキーを使います。リモート MCP と CLI は、アカウントへのアクセス、キーのクォータ、権限を共有できます。共有されているキーを一時停止すると、それを使うすべての利用元に影響します。ホストのセッションからのログアウトは、別の操作です。

ローカル stdio は、その MCP プロセスに渡された個人用の API Key を使い、そのキーの権限とクォータに従います。キーをチャットに貼り付けないでください。また、CLI にログインしていることを、ネイティブ MCP が認証済みであることの証拠として扱わないでください。

切断やログアウトは、ホストの MCP 設定またはコネクタ設定から行ってください。必要に応じて、アカウントの認証管理から、アカウントの認証を取り消してください。ウィンドウを閉じても、アクセスが取り消されるとは限りません。残高不足、1日のクォータや合計クォータ、モデルの権限の問題は、アカウント設定で解決してください。

## 保存と有効期限

見積書、参照素材、アップロード許可、オリジナルの URL のデフォルトの有効期間は、[タスク、参照素材、結果](/ja/cli-mcp/tasks-and-files#retention)にまとめています。実際に返された値が優先されます。レシートに対応しているかどうかは、ファイルサービスのデプロイ環境によって異なります。

## MCP のトラブルシューティング：接続の種類を特定する

リモート MCP は、`https://mcp.evolink.ai/mcp`、Streamable HTTP、ホストでの OAuth ログインを使います。ローカル stdio は、ホストで設定された `@evolinkai/mcp` プロセスと、プラットフォームのキーを使います。実際に使っている接続について、認証情報とツールの検出を確認してください。

| 症状 | トラブルシューティングのセクション |
|---|---|
| ブラウザでの認証が失敗する、または繰り返される | [ログイン](#login) |
| スキルはあるのに、実際のツールがない | [スキルと権限](#skills-discovery) |
| MCP が見つからない、テキストだけの返答になる、ツールが拒否される | [接続とツールの検出](#mcp-connection) |
| モデルが見つからない、入力が無効、価格が不完全 | [モデルと価格](#models-and-pricing) |
| 生成がタイムアウトした、または結果が不明 | [タスクと復旧](#tasks-and-recovery) |
| 添付ファイルを読み取れない、またはアップロードに失敗した | [アップロード](#uploads) |
| オリジナルファイルが 403 になる、プレビューがグレー、結果がリンクだけ | [ダウンロード](#download) |
| 問題が解決しない | [サポートに伝える情報](#support) |

このホストの接続が有効で認証済みであること、ツールが表示されていることを確認してから、実際に `check_balance` を呼び出してください。リモート MCP は16個、ローカル stdio は14個のツールを提供します。CLI が成功しても、ネイティブ MCP にアクセスできることの証明にはなりません。また、MCP のトラブルシューティングに CLI のインストールは必要ありません。

<span id="login" />

### ブラウザでのログインと認証

<Steps>
  <Step title="ホストから認証を開始する">
    この MCP またはコネクタの項目にある、ログインまたは認証の操作を使います。ホストのコマンドやメニューは、そのホスト専用のガイドで確認してください。別の CLI にログインしても、この接続は認証されません。
  </Step>
  <Step title="ブラウザでアカウントの承認を完了する">
    正しい EvoLink アカウントにログインし、スコープを確認して、承認します。ホストの認証フローは、待機させたままにしてください。認証 URL の全体や、コールバックのパラメータを共有しないでください。フローが失敗した場合は、元のホストからやり直します。
  </Step>
  <Step title="ホストに戻って検証する">
    接続のツールを再読み込みし、`check_balance` と `search_models` があることを確認して、実際に残高を照会します。401 の場合は、再認証してください。403 の場合は、アカウントの権限、キーの状態、ホストのツール権限も確認してください。
  </Step>
</Steps>

ローカル stdio は、このブラウザのフローを使いません。プロセスが受け取ったプラットフォームのキー、起動環境、stderr を確認してください。リモートの OAuth と個人用のキーを混在させないでください。[その他のクライアント](/ja/mcp/other-clients)を参照してください。

### スキルはインストールされているのに、ツールが使えない

1. `evolink-mcp` のツール向けの説明を読んでください。ネイティブ MCP は、CLI スキルにあるターミナルコマンドを実行できません。
2. ホストで、実際のサーバー設定とツールを確認してください。スキルを読んでもサーバーは登録されず、プラグインをインストールしても OAuth が自動的に完了するわけではありません。
3. セッションまたはプラグインを再読み込みし、ツールの権限を確認してください。説明があっても、ツール呼び出しの記録がなければ、アクセスできることの証明にはなりません。
4. ツールが一覧に表示されるのに呼び出しが失敗する場合は、ツールのエラーと元の接続を確認してください。有料生成を接続テストとして使わないでください。

<span id="mcp-connection" />
### MCP の接続とアクセス：ツールがない、接続の失敗、401/403

1. 接続の種類を確認します。リモートは、`https://mcp.evolink.ai/mcp`、Streamable HTTP、OAuth を使います。ローカル stdio は、起動コマンドと個人用のキーを使います。ドキュメントのページ、`llms.txt`、REST のエンドポイントは、MCP サーバーではありません。
2. EvoLink を有効にし、このホストでのブラウザ認証を完了してから、再読み込みするか、新しいセッションを開きます。既存の設定をバックアップし、EvoLink の部分だけをマージしてください。ほかのサービスの設定を上書きせずに、JSON の引用符とカンマ、YAML の空白、設定のスコープを確認します。
3. `check_balance` と `search_models` を呼び出します。ツールが一覧に表示されるのに呼び出しが失敗する場合は、認証を確認してください。残高の照会はできるのに生成ツールがない場合は、ツールのオン／オフの設定と、ワークスペースのポリシーを確認してください。

| 症状 | 対処 |
|---|---|
| サーバー名が重複している | 既存の項目を確認し、いずれか一方の登録元を選びます。手動での登録とプラグインによる登録が重複しないようにしてください |
| 401 / 認証の期限切れ | タスク ID を保持したまま、該当するホストから再認証します |
| 403 / ツールの拒否 | ホストのポリシー、アカウントやキーの制限、ネットワークでの拒否のいずれなのかを切り分けます。UA を変えればすべての 403 が解決すると決めつけず、失敗した段階を記録してください |
| ローカルプロセスを起動できない | Node 20 以上であること、npx のパス、ホストの環境、起動時のエラーを確認します。再読み込みして検証してください |
| ローカルのキーが無効、または権限がない | ダッシュボードでそのキーの状態とスコープを確認し、チャットではなく、ホストのシークレット設定を更新します |
| 設定を変更しても反映されない | その接続を持つプロセスを再読み込みします。リモートの Gateway は、手元のノート PC のターミナルを再読み込みしても更新されません |

設定ページ：[ChatGPT](/ja/mcp/chatgpt)、[Claude](/ja/mcp/claude)、[Claude Code](/ja/mcp/claude-code)、[Codex](/ja/mcp/codex)、[Cursor](/ja/mcp/cursor)、[OpenClaw](/ja/mcp/openclaw)、[Hermes](/ja/mcp/hermes-agent)、[その他のクライアント](/ja/mcp/other-clients)。

### モデルと価格：検索結果が空、パラメータが無効、見積もりが不完全

1. 現在提供されているモデルを検索し、返された正式な ID を使います。シリーズ名、表示名、エイリアスは、有効な送信用 ID ではない場合があります。必要な参照素材への対応という条件は外さずに、検索の言い回しを広げてください。
2. このモデルについて、MCP の `get_model` を確認します。必須項目、スペル、列挙値、数値の制限、同時に指定できない参照素材を確認してください。ほかのモデルの `duration`、`size`、`quality` フィールドをコピーしないでください。
3. 見積もりをやり直し、`input_valid`、`problems`、`estimate.status`、`basis`、`warnings` を確認します。入力またはアカウントが変わった場合、価格が上がった場合、承認の有効期限が切れた場合は、新しい見積もりと承認が必要です。

`needs_input` の場合は、不足している入力を補うか、`missing_usage` と `usage_help` に示された課金使用量を `media_seconds` または `pricing_parameters` で指定してください。`no_price` は利用できず、`partial` は合計額ではありません。長さや参照素材の倍率が不明な場合に、開始価格で埋めることはできません。予算は維持してください。拒否を回避するために、断りなく上限を外したり、キーを切り替えたり、仕様を下げたりしないでください。

`search_models`、`get_model`、`recommend_models` のどのモデルにも価格がなく、`pricing_warning` に `Public pricing rules are unavailable or invalid` と表示される場合、サーバーは 1.8.1 以前のバージョンです。これらのバージョンでは、段階制ルールに `multiplier` がないと、すべての価格が表示されなくなります。リモート MCP ではより新しいバージョンが動作しているため、ツールをもう一度呼び出してください。`npx -y @evolinkai/mcp@latest` で設定されたローカル stdio は、クライアントを再起動すると新しいバージョンを取得します。1.8.2 以降では、ルールを読み取れないモデルは除外されて `pricing_warning` に示され、ほかのモデルの価格はそのまま表示されます。

`estimate_cost` または `get_pricing_rules` が、秒数とともに `rate_limited`（`pricing_calls_per_minute`）を返した場合は、その秒数だけ待ってから、もう一度呼び出してください。ホスト型サービスでは、ログイン中のアカウントごとに、これら2つのツールのそれぞれについて、価格ルールを毎分30回まで読み取れます。直前に読み取ったルールから返された回答は、回数に数えられません。同じモデルの複数の入力は、入力ごとに呼び出すのではなく、`inputs` を使って一度の呼び出しで見積もってください。プラットフォーム自体が価格の読み取りを制限している場合、見積もりには過去10分以内に読み取ったルールが使われ、それがいつ読み取られたものかが示されます。ローカル stdio には、このような制限はありません。

リリース済みバージョンの、公開デフォルト価格に基づく見積もりは、アカウント固有の正式な見積書（Quote）ではなく、`max_cost_usd` も最終的な精算額の上限ではありません。[料金](/ja/mcp/billing)と[コマンド／ツールのリファレンス](/ja/mcp/tools)を参照してください。

### タイムアウト、実行中のタスク、結果不明

<Steps>
  <Step title="元のタスクを保持して照会する">
    既存の `task_id` に対して `get_task` を呼び出します。時間を区切って待機するには、`wait_seconds` を 0–45 に設定します。ID が複数ある場合は、`list_tasks` を使います。タイムアウトで終了するのはその待機だけで、生成は終了しません。読み取りが `status_check: unverified` を返した場合（`task_response_invalid`、`task_identity_mismatch`、`task_status_unknown`、`task_query_timeout` のいずれか、または待機中のあとの読み取りが失敗したときの `last_known_status`）は、同じタスクをもう一度照会してください。これは失敗ではありません。`submission_state: accepted` の generate の結果には、すでに `task_id` があります。
  </Step>
  <Step title="結果不明の送信を、元のリクエスト ID で復旧する">
    タスク ID が返されなかった場合は、`client_request_id`、入力、アカウント、エラーを保持してください。同じツールと同じリクエスト ID で復旧します。アカウントやリクエスト ID を変えて生成し直さないでください。EvoLink はリクエスト ID を24時間保持します。その間は、同じリクエスト ID と同じ入力であれば元のタスクが返され、新たな課金は発生しません。バッチの場合は、結果の中で完了させるべきものとして示された項目だけが送信されます。その時点で承認の有効期限が切れている場合は、同じ入力をもう一度見積もり、新しい `pricing_quote` を同じリクエスト ID とともに渡してください。24時間を過ぎると、そのリクエスト ID があっても重複するタスクの作成は防げなくなります。まず `list_tasks` で確認し、通らなかったものだけを、新しい見積もりと新しいリクエスト ID で送信してください。`list_tasks` が受け付けるのは、ドキュメントに記載されたパラメータだけです。勝手に作ったフィルターは受け付けません。
  </Step>
  <Step title="失敗とアカウント上の結果を、別々に確かめる">
    実際のエラーと時刻を記録し、元のタスクとアカウントの使用量を照会してください。失敗したタスクは課金されず、送信時に仮押さえされたクレジットは自動的に返還されます。結果不明の送信は失敗ではなく、課金されていないことの証明にもなりません。キューをキャンセルするための、利用できる公開ツールはありません。MCP を切断したりページを閉じたりしても、タスクはキャンセルされません。
  </Step>
</Steps>

まだ送信していないタスクで、入力が変わった場合、価格が上がった場合、承認の有効期限が切れた場合は、新しい見積もりと承認が必要です。送信済み、または結果が不明なリクエストは、先に復旧してください。パラメータと例については、[タスクのツール](/ja/mcp/tools#task-progress-and-results)を参照してください。

### 添付ファイルを読み取れない、アップロードの失敗、結果不明

1. 渡されたファイルをホストが読み取れることを確認してください。リモート MCP はデスクトップ上のパスを直接読み取れず、チャットの添付ファイルが、そのままモデル用の URL になるわけでもありません。
2. アクセス可能な URL には、`upload_file.file_url` を使います。リモートの base64 は、1 MiB までです。それより大きなファイルは、`prepare_upload` を呼び出し、ファイルにアクセスできる環境からアップロードしてから、`get_upload` を呼び出します。1回限りのアップロードでは、最大 95 MiB まで扱えます。許可の有効期間は約15分、状態の保持期間は約1時間です。
3. ローカル stdio では、MCP プロセスが動作するマシン上の `upload_file.file_path` を使えます。パス、権限、形式、ファイルサービスの制限、モデルの制限を確認してください。デスクトップ上のパスが、クラウドのホストからそのまま読み取れるわけではありません。
4. 元の `upload_id` を保持し、それを照会してください。結果が不明であることは、何もアップロードされなかったという意味ではありません。レシートの互換性は、ファイルサービスのデプロイ環境によって異なります。代わりのアップロードは、失敗または失効が確定してから要求してください。参照素材の有効期間は、通常72時間です。失効した入力は、再アップロードしてください。

パラメータについては[アップロードツール](/ja/mcp/tools)を、手順の全体については[参照素材のワークフロー](/ja/mcp/overview#files)を参照してください。ホストにファイルを扱う機能がない場合は、アクセス可能な URL を使ってください。アップロードの失敗を、生成し直すことで解決しようとしないでください。

<span id="download" />

### ダウンロードとプレビュー

元のタスクを照会し、完了していることを確認して、そのオリジナルの URL を使ってください。オリジナルファイルは、ブラウザで開くか、ファイルを扱える環境から保存します。[MCP での受け渡し](/ja/mcp/overview#delivery)を参照してください。

HTTP と形式のチェック、Python で製品の User-Agent を設定する例、失効したリンク、グレーのプレビューについては、[ダウンロードのトラブルシューティング](/ja/cli-mcp/tasks-and-files#download)にまとめています。結果が不明なタスクは、生成し直したりプレビューを編集したりするのではなく、復旧してください。

### サポートに伝える情報

[サポート用チェックリスト](/ja/cli-mcp/tasks-and-files#support)に従い、バージョン、失敗した段階、ID、機密情報を伏せたエラーを伝えてください。このルートの診断情報は残しておいてください。キー、トークン、非公開 URL、環境情報のダンプは共有しないでください。

### CLI のインストールのトラブルシューティングをお探しの場合

CLI のコマンド、安全な認証情報ストア、SSH コールバック、スキルの検出については、現在は [CLI のトラブルシューティング](/ja/cli/billing#cli-install)と [CLI のセットアップガイド](/ja/cli/setup)にまとめています。この項目は、古いリンクとの互換性を保つためのものです。ネイティブ MCP の設定には、このページと、お使いのクライアントのガイドを使ってください。
