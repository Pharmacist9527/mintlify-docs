## CLI のインストール、ログイン、検証

CLI は、**Node.js 22 以上**を導入した macOS、Windows、Linux に対応しています。エージェントがコマンドを実行するマシンとユーザー環境にインストールしてください。ターミナルを使う場合は、手動の手順に従えます。

### エージェントに EvoLink のインストールを依頼する

次のプロンプト全体を、エージェントの**チャット入力欄**に貼り付けてください。公式サイトのプロンプトと同じ内容です。ブラウザでのログインと権限の承認は、ご自身で完了してください。

```text
ここで画像・動画・音声を直接生成できるように、EvoLink を設定してください。
1. CLI をインストール：`npm install -g @evolinkai/cli` を実行してください。
2. ログイン：`evolink auth login` を実行してください。
3. 対応スキルをインストール：`evolink skills install` を実行してください。
4. 接続を確認し、成功したら利用を開始できると伝えてください。
```

エージェントがターミナルのコマンドを実行できない場合は、下記の手動の手順に従ってください。`bash` のブロックは**ターミナル**で、ステップごとに順に実行します。両方のインストール方法を行う必要はありません。

### 手動インストール：5つのステップ

<Steps>

<Step title="Node.js と実行環境を確認する">

エージェントを実行するマシンで、エージェントを実行するのと同じユーザーとしてターミナルを開きます。macOS ではターミナル、Windows では PowerShell またはコマンドプロンプト、あるいは Cursor の統合ターミナルを使います。

```bash
node --version
npm --version
```

**成功の目安**：どちらのコマンドもバージョンを表示し、Node.js が 22 以降であること。インストールされていない場合やバージョンが古い場合は、[Node.js](https://nodejs.org/en/download) から適切なバージョンをインストールし、ターミナルを開き直して、もう一度確認します。WSL、SSH ホスト、コンテナ、お使いのデスクトップは、それぞれ別の環境です。エージェントがコマンドを実行する環境にインストールしてください。

</Step>

<Step title="CLI をインストールして確認する">

```bash
npm install -g @evolinkai/cli
evolink --version
```

**成功の目安**：インストールがエラーなく終了し、`evolink --version` で CLI のバージョンが表示されること。`-g` は、現在の Node/npm のグローバルディレクトリにコマンドをインストールします。MCP やプラグインのリポジトリをクローンする必要はありません。先に進む前に、[インストールの問題](/ja/cli/billing#cli-install)を解決してください。

</Step>

<Step title="EvoLink にログインする">

```bash
evolink auth login
```

1. コマンドは実行したままにします。ブラウザが開くか、今回の試行用のログインリンクが表示されます。
2. EvoLink にログインし、アカウント、クライアント、要求されている権限を確認して、承認します。
3. 元のターミナルに戻り、完了を待ってから、次を実行します：

```bash
evolink auth status --json
```

**成功の目安**：`authenticated: true`。CLI は、オペレーティングシステムの安全な認証情報ストアを使います。API Key を作成したり貼り付けたりする必要はありません。ブラウザのコールバックだけでは、ターミナル側のログインは完了しません。残高照会による接続確認は、最後のステップで行います。ブラウザ、タイムアウト、Linux の認証情報ストアに関するエラーについては、[ログインのトラブルシューティング](/ja/cli/billing#login)を参照してください。

</Step>

<Step title="スキルをインストールし、エージェントが検出できることを確認する">

```bash
evolink skills install
evolink skills status --json
```

`--agent` を付けない場合、対応しているすべてのスキルディレクトリがインストール先になります。それらのエージェント自体がインストールされるわけではありません。特定のホストだけを対象にするには、下記の一覧にある agent の値を指定します。

**成功の目安**：`current: true`。エージェントのチャットで、次を送信します：

```text
このセッションで evolink-cli スキルを検出して読み込めることを確認してください。まず接続を検証し、メディアは生成しないでください。
```

このスキルは、モデルの探索、パラメータ、見積もりと承認、参照素材、タスク、オリジナルファイルのダウンロードの進め方を案内します。ネイティブ MCP を登録したり、ログインを代行したりはしません。`assistant_discovery: not_checked` の場合は、ホスト側での確認が必要です。必要に応じて、スキルを再読み込みするか、新しい会話を開いてください。[スキルの検出](/ja/cli/billing#skills-discovery)を参照してください。

</Step>

<Step title="無料で検証し、準備ができたことを確認する">

```bash
evolink balance --json
evolink doctor --json
```

**成功の目安**：balance がアカウントのデータを返し、doctor が `ok`、`connection_verified`、`model_discovery_verified` を `true` と報告し、エージェントがスキルを読んだことを確認すること。残高がゼロでも接続は確認できますが、生成には十分な残高が必要です。

これらのステップでは、有料のメディアタスクは作成されません。すべて完了すれば、アシスタントは準備ができたと伝えてかまいません。`failed` になったチェックがあれば、先に進む前に解決してください。接続テストのために画像を生成しないでください。

</Step>

</Steps>

### 単一のエージェント向けにスキルをインストールする

公式サイトで案内している `evolink skills install` は、対応しているすべてのディレクトリを対象にします。単一のホストだけを対象にする場合は、下記の `AGENT_NAME` を次の表の値に置き換えてください：

| クライアント | AGENT_NAME | スキルディレクトリ |
|---|---|---|
| Codex CLI | `codex` | `~/.agents/skills/evolink-cli` |
| Claude Code | `claude-code` | `~/.claude/skills/evolink-cli` |
| Cursor | `cursor` | `~/.agents/skills/evolink-cli` |
| OpenClaw | `openclaw` | `~/.openclaw/skills/evolink-cli` |
| Hermes | `hermes` | `~/.hermes/skills/evolink-cli` |
| Gemini CLI | `gemini` | `~/.agents/skills/evolink-cli` |
| OpenCode | `opencode` | `~/.agents/skills/evolink-cli` |
| GitHub Copilot CLI | `copilot` | `~/.agents/skills/evolink-cli` |

```text
evolink skills install --agent AGENT_NAME
evolink doctor --agent AGENT_NAME --json
```

たとえば、Gemini では次のようになります：

```bash
evolink skills install --agent gemini
evolink doctor --agent gemini --json
```

これらは CLI のインストール先であり、ホストのすべてのバージョンがこのディレクトリを自動的に検出することを保証するものではありません。ホスト側でコマンドの実行が許可され、スキルが読み込まれる必要があります。[スキルと権限のトラブルシューティング](/ja/cli/billing#skills-discovery)を参照してください。一覧にないアシスタントは、[エージェントが読めるリソース](/ja/cli/skills)を読むことができます。agent の値を勝手に作らないでください。

### CLI とスキルを更新する

```bash
npm install -g @evolinkai/cli@latest
evolink --version
evolink skills install
evolink skills status --json
```

`current: true` を確認し、エージェントにスキルを読み直してもらいます。ローカルでの編集は保持されます。`--replace-modified` は、編集内容を置き換えると決めた場合にだけ使ってください。以前の内容は `~/.evolink-media/skill-backups/` にバックアップされます。新規のインストールには、古い `@evolinkai/media-cli` / `evolink-media` を使わないでください。

### 新しいバージョンがあることを知る方法

CLI 0.10.0 以降では、CLI が自分で npm の最新リリースを確認します：

- `evolink setup`、`doctor`、`auth login` は毎回確認を行い、`update_available`、`latest_version`、アップグレード用のコマンドを含む `update` を報告します。利用できるアップデートがあっても、それは通知にすぎず、コマンドが失敗することはありません。
- オフラインで動作する `auth status` を除くそのほかのコマンドは、オンラインでの確認を多くても1日1回だけ行います。新しいリリースがある場合は、コマンド自体の出力のあとに、stderr へ1行を出力します。同じリリースについての出力は、多くても1日1回です。`--json` の stdout と終了コードは変わりません。
- 確認の際は、アカウント情報を含まないリクエストを1件、公開の npm レジストリ（registry.npmjs.org）に送信します。待機時間は最大3秒で、レジストリに到達できない場合は何も表示しません。
- 確認をオフにするには、`EVOLINK_CLI_UPDATE_CHECK=0` を設定します。`NO_UPDATE_NOTIFIER` に何らかの値が設定されている場合や、CI 環境でも、確認はオフになります。

通知は次の1行です：

```text
EvoLink CLI 0.10.1 is available (installed 0.10.0). Update with npm install -g @evolinkai/cli@latest, then run evolink skills install.
```

この通知が表示されたら、上記のコマンドでアップグレードし、スキルを同期してください。0.10.0 より前のバージョンでは通知されません。`evolink --version` と `npm view @evolinkai/cli version` の結果を比べるか、[CLI の GitHub Releases](https://github.com/deeplearning-goethe/evolink-cli/releases) を開き、Watch → Custom → Releases を選んで購読してください。

ブラウザでの承認が、サイトに戻らずに、二か国語表示の 127.0.0.1 のページで終わる場合は、インストールされている CLI が 0.9.1 より古いバージョンです。先に進む前にアップグレードしてください。

### ログイン状態の確認とログアウト

現在のセッションを確認します：

```bash
evolink auth status --json
```

ログアウトしたい場合にだけ、次を別途実行します：

```bash
evolink auth logout
```

これにより、現在の CLI セッションが取り消されます。ネイティブ MCP の認証は、それぞれのホスト側で管理してください。アカウントを切り替える前に、既存のタスク ID を保存しておいてください。古い見積書を、新しいアカウントとして送信することはできません。

### Linux と SSH：ブラウザが別のマシンにある場合

Linux でログイン状態を保持するには、現在のユーザーセッションで **D-Bus とロック解除済みの Secret Service** が必要です。まずこれを確認してください。これがない場合は、`credential_store_unavailable` になるのが想定どおりの動作です。root 権限はその代わりになりません。安全な認証情報ストアを設定するか、それを備えた環境でローカルに CLI を実行してください。

<Steps>

<Step title="リモートホストでログインを開始する">

```bash
evolink auth login --no-browser --timeout 600
```

このコマンドは実行したままにし、今回の認証リンクを使います。`--no-browser` はブラウザの起動を抑止しますが、コールバックは引き続き待ちます。これは**デバイスコードによるログインではありません**。指定できる範囲は 30–900秒で、デフォルトは180秒です。

</Step>

<Step title="ローカルのターミナルからコールバックポートを転送する">

今回の試行の `redirect_uri` から、実際のポートを確認します。両方の `CALLBACK_PORT` と、`USER` および `HOST` を置き換えてください。`http://127.0.0.1:54321/callback` の場合は、両方の位置に `54321` を指定します。認証リンクの全体を公開しないでください。

```bash
ssh -N -L CALLBACK_PORT:127.0.0.1:CALLBACK_PORT USER@HOST
```

転送用のターミナルは実行したままにします。プロンプトが表示されず、何も動いていないように見えるのは正常です。ポートが競合した場合は、認証リンクのポートを書き換えずに解決してください。

</Step>

<Step title="このリンクを開き、リモート側で検証する">

最初のステップのリンクをローカルのブラウザで開き、ログインして承認したら、リモート側のコマンドが終了するのを待ちます。その同じリモートのユーザー環境で、次を実行します：

```bash
evolink auth status --json
evolink balance --json
```

成功したら、この転送セッションを停止します。タイムアウトした場合は、新しいログインを開始し、その実際のポートを転送してください。古いリンクは再利用できません。ネイティブ MCP のコールバックはホスト側のもので、EvoLink CLI のフラグは使いません。

</Step>

</Steps>

## インストール後

[はじめての生成ワークフロー](/ja/cli/workflows#workflows)に従ってください。タスクを説明し、エージェントに利用可能なモデル、パラメータ、料金を確認してもらい、送信の前に確認します。インストール、ログイン、権限、ダウンロードについては、[CLI コマンドリファレンス](/ja/cli/reference#cli-reference)と[総合トラブルシューティング](/ja/cli/billing#faq)を参照してください。

ネイティブのリモート MCP やローカル stdio については、[その他の MCP クライアントのガイド](/ja/mcp/other-clients)を使ってください。CLI のログイン用オプションでは、MCP 接続は設定されません。
