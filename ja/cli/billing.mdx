## CLI の料金と承認

このページは、リリース済みの CLI 0.14.1 を対象としています。CLI はプラットフォームの API を直接呼び出し、コマンドと保存済みの見積もりをローカルで管理します。ログインには Passport を使います。まずは[ワークフロー全体](/ja/cli/workflows)から始めてください。

1. 最終的なモデルと入力で `evolink estimate` を実行し、見積もり額を示します。
2. このモデル、パラメータ、料金が承認されたら、保存された `quote_id` と `--confirm` を使って生成します。
3. 入力またはログインが変わった場合、価格が上がった場合、見積書の有効期限が切れた場合は、見積もりをやり直して承認を得ます。別の見積書を使い回さないでください。ユーザーが、見積もりや確認は不要だと明確に述べた場合は、ステップ 1–2 の代わりに `generate --skip-estimate` を使います。
4. 元のタスクとアカウントの使用量を照会します。見積もりは、実際の課金や返金を裏付けるものではありません。

見積もりの状態、公開価格に基づくことによる制限、承認、予算については、[モデル、料金、クォータ](/ja/cli-mcp/models-and-billing#pricing)を参照してください。リリース済みの max_cost_usd は、送信前の見積もりと比較するだけで、最終的な請求額に上限を設けるものではありません。

見積書は、見積もった時点から24時間有効で、元のアカウント、モデル、入力に紐付けられます。生成では、送信前にもう一度見積もりが行われます。同じ入力で、承認済みの価格以下であれば、その後に価格ルールが変更されていても送信されます。一方、価格が上がった場合（`price_changed`）、入力が変わった場合（`quote_input_changed`）、見積書の有効期限が切れた場合（`quote_expired`）は、何も送信されず、新しい見積もりと承認が必要です。見積書は、支払いの領収書ではありません。`--confirm` は、このタスクに対する承認を表すもので、ログインやホストでの実行権限の代わりにはなりません。モデル、残高、タスクの照会では、生成は送信されません。生成は課金されます。ファイルサービスのサイズ制限と保持期間の制限は、別途適用されます。換算の目安は $1 あたり約 68 クレジットです。実際に返された値とアカウントの記録を使ってください。

[共通のアクセスルール](/ja/cli-mcp/models-and-billing#authorization)を参照してください。このページには、このルートでのログインとログアウトの操作を記載しています。

## ログイン、権限、クォータ

ブラウザでのログインは Passport が処理し、CLI の認証情報はシステムの安全なストアに保存されます。業務リクエストには、OAuth に紐付いた既存のキーが使われます。CLI とリモート MCP は、アカウントへのアクセス、キーのクォータ、権限を共有できます。共有されているキーを一時停止したり変更したりすると、それを使うすべての利用元に影響します。OAuth セッションは、それぞれ個別にログアウトします。

```bash
evolink auth status --json
```

このローカルの CLI からログアウトするには、次を別途実行します：

```bash
evolink auth logout
```

個人用の API Key で設定されたローカル MCP は、そのキーの権限を使います。CLI にログインしても、別の MCP プロセスが認証されるわけではありません。残高、1日のクォータと合計クォータ、モデルへのアクセス、ツールの権限によって、送信できないことがあります。失敗したタスクは課金されず、送信時に仮押さえされたクレジットは自動的に返還されます。切断やログアウトは、返金が完了したことの根拠にはなりません。

<span id="retention" />

## 保存と有効期限

見積書、参照素材、アップロード許可、オリジナルの URL のデフォルトの有効期間は、[タスク、参照素材、結果](/ja/cli-mcp/tasks-and-files#retention)にまとめています。実際に返された値が優先されます。レシートに対応しているかどうかは、ファイルサービスのデプロイ環境によって異なります。

## CLI のトラブルシューティング：失敗した段階を特定する

CLI を実行するのと同じマシン、OS ユーザー、ターミナルで、バージョンとアクセスを確認します。これらの照会では、生成は送信されません：

```bash
evolink --version
evolink auth status --json
evolink doctor --json
```

| 症状 | トラブルシューティングのセクション |
|---|---|
| `node`、`npm`、`evolink` のいずれかが見つからない | [環境とインストール](#cli-install) |
| ログイン、SSH コールバック、安全なストアのいずれかで失敗する | [ログイン](#login) |
| スキルをインストールしたのに、エージェントが使えない | [スキルの検出](#skills-discovery) |
| モデルが見つからない、入力が拒否される、価格が不完全 | [モデルと価格](#models-and-pricing) |
| 生成がタイムアウトした、送信結果が不明 | [タスクと復旧](#tasks-and-recovery) |
| アップロードに失敗した、または結果が不明 | [アップロード](#uploads) |
| ダウンロードで 403 になる、プレビューがグレー、結果がリンクだけ | [ダウンロード](#download) |
| これらを確認しても問題が解決しない | [サポートに伝える情報](#support) |

先に進む前に、現在の段階の問題を解決してください。接続の検証に有料生成は必要ありません。インストールを試すために、生成を繰り返さないでください。

<span id="cli-install" />
### 環境とインストール：コマンドが見つからない、権限、タイムアウト

**ステップ 1**：実際の実行環境を確認します。エージェントが使うターミナルで、次を実行します：

```bash
node --version
npm --version
```

CLI には Node.js 22 以上が必要です。`command not found` と表示される場合や、Windows でコマンドが認識されない場合は、[Node.js](https://nodejs.org/en/download) をインストールして、ターミナルを開き直してください。デスクトップにインストールしても、SSH、WSL、コンテナの中に CLI がインストールされるわけではありません。

**ステップ 2**：npm のインストール先を確認します。

```bash
npm config get prefix
```

| 症状 | 対処 |
|---|---|
| npm は成功したのに evolink が見つからない | 新しいターミナルを開き、同じ Node/npm 環境であることを確認して、そのグローバルコマンド用ディレクトリが PATH に含まれているかを確認します |
| EACCES / permission denied | [npm の権限に関するガイダンス](https://docs.npmjs.com/resolving-eacces-permissions-errors-when-installing-packages-globally/)に従って、ユーザーが書き込める Node/npm 環境を使い、CLI を再インストールしてから、そのパスとバージョンを確認します |
| タイムアウト、DNS、証明書、プロキシのエラー | 公式の npm レジストリへのアクセスと、プロキシの設定を確認します。エラーの内容を残し、証明書の検証は有効のままにしてください |
| PowerShell がスクリプトをブロックする | 同じ Windows 環境でコマンドプロンプトを使うか、所属する組織のデバイスポリシーに従います |
| 古い evolink コマンドがある、または evolink コマンドが複数ある | エージェントが使っているコマンドを特定し、それに対応する Node 環境を更新します |

お使いのシステムに合った、パス確認用のコマンドを選んでください：

<Tabs>
  <Tab title="macOS / Linux">

```bash
command -v node
command -v npm
command -v evolink
```

  </Tab>
  <Tab title="Windows PowerShell">

```powershell
Get-Command node
Get-Command npm
Get-Command evolink
```

  </Tab>
</Tabs>

**ステップ 3**：もう一度検証します。該当する問題を修正したら、インストールまたは更新を行い、`evolink --version` を実行します。このコマンドが動作する場合にだけ、ログインに進んでください。[インストール手順の全体](/ja/cli/setup#cli-install)を参照してください。

<span id="login" />
### ログインとコールバック：ブラウザが開かない、ログインが完了しない

1. `evolink auth login` または `setup` は実行したままにします。ブラウザが開かない場合は、今回の試行のリンクを手動で開き、アカウントを確認して、承認します。
2. 元のターミナルに戻り、完了を待ちます。承認後、ブラウザは「承認を受け取りました」という通知のある EvoLink MCP のページに移動します。これは、コールバックが届いたことを意味するだけで、アカウントへの接続が検証されたことを意味するわけではありません。コマンドを途中で終了しないでください。
3. 保存されている認証と、実際のアカウントへのアクセスを、別々に確認します：

```bash
evolink auth status --json
evolink balance --json
```

それぞれ、`authenticated: true` と、実際の残高データが返ることを確認します。タイムアウトした場合は、認可コードを使い回さず、新しいリンクで新しい試行を開始してください。待ち時間を長くするには、次のようにします：

```bash
evolink auth login --timeout 600
```

| 症状 | 対処 |
|---|---|
| 127.0.0.1 / localhost のコールバックに接続できない | login がまだ実行中であること、およびブラウザと CLI がそれぞれどこで実行されているかを確認します。リモートの場合は、[SSH コールバックの転送](/ja/cli/setup#ssh-login)を使います |
| credential_store_unavailable | Linux では、同じユーザーの D-Bus、Secret Service、ロック解除の状態を確認します。先に安全な認証情報ストアを設定してください |
| ユーザー、コンテナ、サーバーを切り替えたあと、ログイン状態がなくなる | セッションは元の環境のものです。認証情報ファイルをコピーせずに、新しい環境で改めて認証してください |
| キーが一時停止中、期限切れ、または上限超過 | ダッシュボードで共有キーを確認します。再認証しても、一時停止は解除されず、上限も引き上げられません |
| エージェントがログイントークンの期限切れを報告する、または `auth status` の `access_token_expires_at` が過ぎている | それは、有効期間の短いアクセストークンの期限にすぎません。CLI は次のコマンドの前にトークンを更新するため、新たなログインは不要です。`evolink balance --json` で検証してください。`auth login` をやり直すのは、`login_required` または `login_expired` になった場合だけです |
| 承認後、ブラウザがサイトに戻らず、二か国語表示の 127.0.0.1 のページのままになる | インストールされている CLI が 0.9.1 より古いバージョンです。`npm install -g @evolinkai/cli@latest` でアップグレードしてから、`evolink skills install` を実行してください。0.10.0 以降は、CLI が自分で新しいリリースを知らせます。[新しいバージョンがあることを知る方法](/ja/cli/setup#update-check)を参照してください |
| 出力に `EvoLink CLI X is available` と表示される | これは新しいリリースの通知で、エラーではありません。コマンド自体は完了しています。表示された方法でアップグレードし、`evolink skills install` を実行してください。確認をオフにするには、`EVOLINK_CLI_UPDATE_CHECK=0` を設定します |

`--no-browser` でも、ブラウザのコールバックは必要です。これは、デバイスコードによる認証でも、ブラウザを使わない認証でもありません。API Key を、リモートの OAuth トークンとして入力しないでください。

<span id="skills-discovery" />
### スキルと権限：インストールしたファイルをエージェントが使わない

1. エージェントを実行するユーザーのディレクトリを確認します。対応する `--agent` を使ってください。Codex の場合：

```bash
evolink skills status --agent codex --json
```

2. `current: true` は、インストールされているファイルが CLI と一致していることを意味します。ファイルがない場合や古い場合は、`evolink skills install --agent codex` を使ってください。`modified` の場合は、ローカルでの編集を保持してください。`conflict` の場合は、skills ディレクトリ全体を削除するのではなく、競合しているスキルまたは無効なメタデータを解消してください。
3. エージェントに、`evolink-cli` を検出して読み込めることを確認してもらいます。必要に応じて、再読み込みするか、新しい会話を開いてください。ホスト側で、必要なコマンドの実行権限を確認します。組織による制限は、ホスト側の設定で対応する必要があります。

`assistant_discovery: not_checked` は、ホストでの読み込みがまだ検証されていないことを意味します。`SKILL.md` ファイルがあることや、ドキュメントのページを読んだことは、エージェントが CLI を実行できることの証明にはなりません。

CLI を更新したら、スキルを同期してください。`--replace-modified` は、ローカルでの変更を置き換えると決めた場合にだけ使ってください。バックアップは `~/.evolink-media/skill-backups/` に保存されます。ディレクトリと内容は、[エージェントが読めるリソース](/ja/cli/skills#skills)に一覧があります。

<span id="models-and-pricing" />
### モデルと価格：検索結果が空、パラメータが無効、見積もりが不完全

1. 現在提供されているモデルを検索し、返された正式な ID を使います。シリーズ名、表示名、エイリアスは、有効な送信用 ID ではない場合があります。必要な参照素材への対応という条件は外さずに、検索の言い回しを広げてください。
2. このモデルについて、`models show` / `models schema` を確認します。必須項目、スペル、列挙値、数値の制限、同時に指定できない参照素材を確認してください。ほかのモデルの `duration`、`size`、`quality` フィールドをコピーしないでください。
3. 見積もりをやり直し、`input_valid`、`problems`、`estimate.status`、`basis`、`warnings` を確認します。入力またはアカウントが変わった場合、価格が上がった場合、見積書の有効期限が切れた場合は、新しい見積もりと承認が必要です。

`needs_input` の場合は、不足している入力を補うか、`missing_usage` と `usage_help` に示された課金使用量を `--media-seconds` または `--pricing-parameters` で指定してください。`no_price` は利用できず、`partial` は合計額ではありません。長さや参照素材の倍率が不明な場合に、開始価格で埋めることはできません。予算は維持してください。拒否を回避するために、断りなく上限を外したり、キーを切り替えたり、仕様を下げたりしないでください。

検索、`models show`、`models recommend` のどのモデルにも価格がなく、`pricing_warning` に `Public pricing rules are unavailable or invalid` と表示される場合、CLI は 0.10.1 以前のバージョンです。これらのバージョンでは、モデル一覧に `multiplier` のない段階制ルールが含まれていると、すべての価格が表示されなくなります。このようなルールは、10月12日から公開されています。`npm install -g @evolinkai/cli@latest` で 0.10.2 以降にアップグレードしてから、`evolink skills install` を実行してください。0.10.2 以降では、ルールを読み取れないモデルは除外されて `pricing_warning` に示され、ほかのモデルの価格はそのまま表示されます。

リリース済みバージョンの、公開デフォルト価格に基づく見積もりは、アカウント固有の正式な見積書（Quote）ではなく、`max_cost_usd` も最終的な精算額の上限ではありません。[料金](/ja/cli/billing)と[コマンドリファレンス](/ja/cli/reference)を参照してください。

<span id="tasks-and-recovery" />

### 生成のタイムアウト、実行中のタスク、結果不明の送信

<Steps>
  <Step title="ID がある場合は元のタスクを照会する">
    ```bash
    evolink tasks get TASK_ID --json
    evolink tasks wait TASK_ID --timeout 600 --json
    ```
    待機がタイムアウトしても、生成はキャンセルされません。複数のタスクには batch または list を使い、完了後にオリジナルファイルをダウンロードしてください。照会が `status_check: unverified`（`task_response_invalid`、`task_identity_mismatch`、`task_status_unknown` のいずれか）を返した場合は、最新の状態を検証できなかったことを意味します。生成するのではなく、同じタスクをもう一度照会してください。`submission_state: accepted` の `generate` の結果には、状態がない場合でも、すでにタスク ID があります。
  </Step>
  <Step title="タスク ID が返されなかった場合は元の見積書から復旧する">
    ```bash
    evolink tasks resume --quote QUOTE_ID --json
    ```
    元のアカウント、見積書、リクエスト ID を保持してください。アカウント、見積書、リクエスト ID を切り替えて生成し直さないでください。結果が不明であることは、何も送信されなかった、あるいは課金されなかったという意味ではありません。
  </Step>
  <Step title="失敗に対処する前に証拠を残す">
    元のタスク ID、エラーコード、時刻を記録してください。失敗が確定したタスクは課金されず、送信時に仮押さえされたクレジットは自動的に返還されます。利用できる公開のキャンセルコマンドはありません。ターミナルを閉じたり待機を止めたりしても、サーバー側のタスクはキャンセルされません。
  </Step>
</Steps>

まだ送信しておらず、有効期限が切れた見積書や、入力が変わったり価格が上がったりした見積書は、見積もりと承認をやり直してください。既存のタスクや結果不明の送信は、先に復旧してください。[タスクコマンドのリファレンス](/ja/cli/reference#cli-reference)を参照してください。

<span id="uploads" />

### アップロードの失敗、サイズ超過、結果不明

1. エージェントを実行するマシン上で、絶対パス、権限、実際の形式を確認します。リモートホストやコンテナは、デスクトップ上のパスを直接読み取れません。
2. ローカルの CLI からのアップロードは、95 MiB までです。モデルによっては、形式、数、サイズについて、より厳しい制限がある場合があります。先にモデルのドキュメントを確認してください。チャットの添付ファイルは、読み取り可能なファイルか、アクセス可能な URL にする必要があります。
3. 結果が不明な場合は、元の `upload_id` を保持し、それを照会します：

```bash
evolink uploads get UPLOAD_ID --json
```

4. レシートを照会できるかどうかは、ファイルサービスのデプロイ環境によって異なります。`outcome_unknown` は、何もアップロードされなかったことの根拠にはなりません。代わりのアップロードを要求するのは、失敗または失効が確定してからにしてください。参照素材の有効期間は、通常72時間です。失効した入力は再アップロードし、リクエストを更新して、生成の前に見積もりと承認をやり直してください。

アップロードの方法については[参照素材のワークフロー](/ja/cli/workflows#files)を、レシートのフィールドについては[コマンドリファレンス](/ja/cli/reference)を参照してください。1回限りのアップロード URL、非公開の署名付き URL、キーをチャットで共有しないでください。

<span id="download" />

### ダウンロードとプレビュー

元のタスクを照会し、完了していることを確認して、そのオリジナルの URL を使ってください。CLI の download を優先して使ってください。[CLI リファレンス](/ja/cli/reference)を参照してください。ダウンロードでは、製品の UA がすでに使われています。

HTTP と形式のチェック、Python で製品の User-Agent を設定する例、失効したリンク、グレーのプレビューについては、[ダウンロードのトラブルシューティング](/ja/cli-mcp/tasks-and-files#download)にまとめています。結果が不明なタスクは、生成し直したりプレビューを編集したりするのではなく、復旧してください。

### サポートに伝える情報

[サポート用チェックリスト](/ja/cli-mcp/tasks-and-files#support)に従い、バージョン、失敗した段階、ID、機密情報を伏せたエラーを伝えてください。このルートの診断情報は残しておいてください。キー、トークン、非公開 URL、環境情報のダンプは共有しないでください。

<span id="mcp-connection" />

### ネイティブ MCP 接続のトラブルシューティング

CLI と MCP は別々の入口です。ネイティブの OAuth、ツールの検出、ローカル stdio については、[MCP のトラブルシューティング](/ja/mcp/billing#mcp-connection)を参照してください。CLI のインストールに成功しても、MCP へのアクセスが確認されたことにはなりません。この項目は、古いリンクを維持するための互換用です。CLI のコマンド、ログイン、スキルについては、上記で説明しています。
