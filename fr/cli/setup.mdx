## Installation de la CLI, connexion et vérification

La CLI prend en charge macOS, Windows et Linux avec **Node.js 22+**. Installez-la sur la machine et dans l’environnement utilisateur où votre agent exécute les commandes. Les utilisateurs du terminal peuvent suivre les étapes manuelles.

### Demander à votre agent d’installer EvoLink

Collez l’intégralité de ce prompt dans la **zone de conversation** de l’agent. Il est identique au prompt du site web. Effectuez vous-même la connexion dans le navigateur et accordez vous-même les permissions demandées.

```text
Configure EvoLink pour que je puisse créer directement ici des images, des vidéos et de l’audio.
1. Installe la CLI : exécute `npm install -g @evolinkai/cli`.
2. Connecte-toi : exécute `evolink auth login`.
3. Installe la compétence associée : exécute `evolink skills install`.
4. Vérifie la connexion et confirme que je peux commencer une fois la vérification réussie.
```

Si l’agent ne peut pas exécuter de commandes dans un terminal, suivez les étapes manuelles ci-dessous. Exécutez les blocs `bash` dans un **terminal**, une étape à la fois. Il n’est pas nécessaire d’effectuer les deux méthodes d’installation.

### Installation manuelle : cinq étapes

<Steps>

<Step title="Vérifier Node.js et l’environnement d’exécution">

Ouvrez un terminal sur la machine et sous l’utilisateur qui exécutent l’agent. Utilisez Terminal sous macOS, PowerShell ou l’Invite de commandes sous Windows, ou le terminal intégré de Cursor.

```bash
node --version
npm --version
```

**Réussite** : les deux commandes affichent une version, avec Node.js 22 ou une version ultérieure. S’il est absent ou trop ancien, installez une version adaptée depuis [Node.js](https://nodejs.org/en/download), rouvrez le terminal et vérifiez à nouveau. WSL, les hôtes SSH, les conteneurs et votre ordinateur local sont des environnements distincts ; installez la CLI là où l’agent exécute les commandes.

</Step>

<Step title="Installer et vérifier la CLI">

```bash
npm install -g @evolinkai/cli
evolink --version
```

**Réussite** : l’installation se termine sans erreur et `evolink --version` affiche une version de la CLI. `-g` installe une commande dans le répertoire global du Node/npm actuel. Il n’est pas nécessaire de cloner un dépôt MCP ou de plugin. Corrigez les [problèmes d’installation](/fr/cli/billing#cli-install) avant de continuer.

</Step>

<Step title="Se connecter à EvoLink">

```bash
evolink auth login
```

1. Laissez la commande s’exécuter. Elle ouvre un navigateur ou affiche le lien de connexion propre à cette tentative.
2. Connectez-vous à EvoLink, vérifiez le compte, le client et les permissions demandées, puis autorisez l’accès.
3. Revenez au terminal d’origine, attendez la fin de la commande, puis exécutez :

```bash
evolink auth status --json
```

**Réussite** : `authenticated: true`. La CLI utilise le stockage sécurisé des identifiants de connexion du système d’exploitation ; vous n’avez pas besoin de créer ni de coller une clé API. Le rappel du navigateur ne suffit pas à terminer la connexion dans le terminal. L’accès au solde est vérifié à la dernière étape. Consultez le [dépannage de la connexion](/fr/cli/billing#login) pour les erreurs liées au navigateur, à l’expiration du délai et au stockage sous Linux.

</Step>

<Step title="Installer la compétence et confirmer sa détection par l’agent">

```bash
evolink skills install
evolink skills status --json
```

Sans `--agent`, l’installation cible tous les répertoires de compétences pris en charge ; elle n’installe pas ces agents. Utilisez l’une des valeurs d’agent indiquées plus bas pour sélectionner un seul hôte.

**Réussite** : `current: true`. Dans la conversation de l’agent, envoyez :

```text
Confirme que cette session peut détecter et lire la compétence evolink-cli. Vérifie d’abord la connexion ; ne génère aucun média.
```

La compétence guide la recherche de modèles, les paramètres, les estimations et l’accord, les références, les tâches et le téléchargement des originaux. Elle n’enregistre pas le MCP natif et ne vous connecte pas. `assistant_discovery: not_checked` exige une confirmation de la part de l’hôte. Actualisez les compétences ou ouvrez une nouvelle conversation si nécessaire. Consultez [Détection des compétences](/fr/cli/billing#skills-discovery).

</Step>

<Step title="Vérifier gratuitement et confirmer que tout est prêt">

```bash
evolink balance --json
evolink doctor --json
```

**Réussite** : balance renvoie les données du compte ; doctor indique `true` pour `ok`, `connection_verified` et `model_discovery_verified` ; l’agent confirme avoir lu la compétence. Un solde nul permet tout de même d’établir que la connexion fonctionne, mais la génération nécessite des fonds suffisants.

Ces étapes ne créent aucune tâche média payante. Une fois qu’elles sont terminées, l’assistant peut vous dire que vous êtes prêt. Corrigez toute vérification `failed` avant de poursuivre ; ne générez pas d’image pour tester la connexion.

</Step>

</Steps>

### Installer la compétence pour un seul agent

La commande `evolink skills install` du site web cible tous les répertoires pris en charge. Pour un seul hôte, remplacez `AGENT_NAME` ci-dessous par une valeur de ce tableau :

| Client | AGENT_NAME | Répertoire de la compétence |
|---|---|---|
| Codex CLI | `codex` | `~/.agents/skills/evolink-cli` |
| Claude Code | `claude-code` | `~/.claude/skills/evolink-cli` |
| Cursor | `cursor` | `~/.agents/skills/evolink-cli` |
| OpenClaw | `openclaw` | `~/.openclaw/skills/evolink-cli` |
| Hermes | `hermes` | `~/.hermes/skills/evolink-cli` |
| Gemini CLI | `gemini` | `~/.agents/skills/evolink-cli` |
| OpenCode | `opencode` | `~/.agents/skills/evolink-cli` |
| GitHub Copilot CLI | `copilot` | `~/.agents/skills/evolink-cli` |

```text
evolink skills install --agent AGENT_NAME
evolink doctor --agent AGENT_NAME --json
```

Par exemple, Gemini utilise :

```bash
evolink skills install --agent gemini
evolink doctor --agent gemini --json
```

Il s’agit des cibles d’installation de la CLI, et non d’une garantie que chaque version d’un hôte détecte automatiquement le répertoire. L’hôte doit autoriser les commandes et charger les compétences ; consultez le [dépannage des compétences et des permissions](/fr/cli/billing#skills-discovery). Les assistants qui ne figurent pas dans la liste peuvent lire les [ressources lisibles par les agents](/fr/cli/skills) ; n’inventez pas de valeurs d’agent.

### Mettre à jour la CLI et la compétence

```bash
npm install -g @evolinkai/cli@latest
evolink --version
evolink skills install
evolink skills status --json
```

Vérifiez `current: true` et demandez à l’agent de relire la compétence. Les modifications locales sont conservées. N’utilisez `--replace-modified` qu’après avoir décidé de les remplacer ; le contenu précédent est sauvegardé dans `~/.evolink-media/skill-backups/`. N’utilisez pas les anciens `@evolinkai/media-cli` / `evolink-media` pour de nouvelles installations.

### Comment savoir qu’une nouvelle version existe

À partir de la CLI 0.10.0, la CLI vérifie elle-même sur npm quelle est la dernière version publiée :

- `evolink setup`, `doctor` et `auth login` vérifient à chaque exécution et renvoient `update` avec `update_available`, `latest_version` et la commande de mise à niveau. Une mise à jour disponible n’est qu’un avis ; elle ne fait jamais échouer la commande.
- Les autres commandes, à l’exception de `auth status` qui fonctionne hors ligne, vérifient en ligne au plus une fois par jour. Lorsqu’une version plus récente existe, elles affichent une ligne sur stderr après leur propre sortie, au plus une fois par jour pour une même version. La sortie stdout de `--json` et le code de sortie restent inchangés.
- Une vérification envoie une seule requête, sans information de compte, au registre npm public (registry.npmjs.org), attend au plus 3 secondes et reste silencieuse si le registre est injoignable.
- Pour désactiver les vérifications, définissez `EVOLINK_CLI_UPDATE_CHECK=0`. Elles sont également désactivées lorsque `NO_UPDATE_NOTIFIER` est défini avec n’importe quelle valeur, ou en CI.

L’avis tient en une ligne :

```text
EvoLink CLI 0.10.1 is available (installed 0.10.0). Update with npm install -g @evolinkai/cli@latest, then run evolink skills install.
```

Lorsque vous le voyez, effectuez la mise à niveau avec les commandes ci-dessus et synchronisez la compétence. Les versions antérieures à 0.10.0 ne vous avertissent pas : comparez `evolink --version` avec `npm view @evolinkai/cli version`, ou ouvrez [les GitHub Releases de la CLI](https://github.com/deeplearning-goethe/evolink-cli/releases) et choisissez Watch → Custom → Releases pour vous abonner.

Si l’autorisation dans le navigateur se termine sur une page bilingue à l’adresse 127.0.0.1 au lieu de revenir au site, la CLI installée est antérieure à 0.9.1 ; effectuez la mise à niveau avant de continuer.

### Vérifier la connexion ou se déconnecter

Vérifiez la session en cours :

```bash
evolink auth status --json
```

N’exécutez cette commande, séparément, que lorsque vous voulez vous déconnecter :

```bash
evolink auth logout
```

Cette commande révoque la session CLI en cours. Gérez l’autorisation du MCP natif dans son propre hôte. Enregistrez les identifiants de tâche existants avant de changer de compte ; les anciens devis ne peuvent pas être soumis avec un nouveau compte.

### Linux et SSH : navigateur sur une autre machine

Sous Linux, une connexion persistante nécessite **D-Bus et un Secret Service déverrouillé** dans la session de l’utilisateur en cours. Vérifiez d’abord ce point. Sans cela, l’erreur `credential_store_unavailable` est attendue ; un accès root ne le remplace pas. Configurez le stockage sécurisé ou exécutez la CLI en local dans un environnement qui le fournit.

<Steps>

<Step title="Démarrer la connexion sur l’hôte distant">

```bash
evolink auth login --no-browser --timeout 600
```

Laissez cette commande s’exécuter et utilisez le lien d’autorisation en cours. `--no-browser` empêche l’ouverture du navigateur mais attend tout de même un rappel ; ce n’est **pas une connexion par code d’appareil**. La plage autorisée va de 30 à 900 secondes, avec 180 par défaut.

</Step>

<Step title="Transférer le port de rappel depuis un terminal local">

Repérez le port réel dans le `redirect_uri` de cette tentative. Remplacez les deux valeurs `CALLBACK_PORT`, ainsi que `USER` et `HOST`. Pour `http://127.0.0.1:54321/callback`, utilisez `54321` aux deux emplacements. Ne publiez pas le lien d’autorisation complet.

```bash
ssh -N -L CALLBACK_PORT:127.0.0.1:CALLBACK_PORT USER@HOST
```

Laissez le terminal de transfert ouvert ; un terminal inactif, sans invite de commande, est normal. Résolvez un conflit de port sans modifier le port du lien d’autorisation.

</Step>

<Step title="Ouvrir ce lien et vérifier à distance">

Ouvrez le lien de la première étape dans votre navigateur local, connectez-vous et autorisez l’accès, puis attendez que la commande distante se termine. Dans ce même environnement utilisateur distant, exécutez :

```bash
evolink auth status --json
evolink balance --json
```

Arrêtez cette session de transfert une fois la connexion réussie. En cas d’expiration du délai, lancez une nouvelle connexion et transférez son port réel ; l’ancien lien ne peut pas être réutilisé. Les rappels du MCP natif relèvent de l’hôte et n’utilisent pas les options d’EvoLink CLI.

</Step>

</Steps>

## Après l’installation

Suivez le [flux de travail de la première génération](/fr/cli/workflows#workflows) : décrivez la tâche, demandez à l’agent de vérifier les modèles disponibles, les paramètres et le coût, puis confirmez avant la soumission. Consultez la [référence des commandes de la CLI](/fr/cli/reference#cli-reference) et le [dépannage centralisé](/fr/cli/billing#faq) pour l’installation, la connexion, les permissions et les téléchargements.

Pour le MCP distant natif ou le stdio local, utilisez le [guide des autres clients MCP](/fr/mcp/other-clients). Les options de connexion de la CLI ne configurent pas une connexion MCP.
