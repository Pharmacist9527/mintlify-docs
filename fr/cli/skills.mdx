## Installer et gérer la compétence de la CLI

Cette page couvre les cibles, les répertoires, la détection par l’hôte et les mises à jour d’evolink-cli. Consultez les [ressources communes](/fr/cli-mcp/agent-resources) pour le périmètre, les notions de CLI, de MCP et de plugin, et les règles communes.

## Installer et vérifier la détection

```bash
evolink skills install
evolink skills status --json
```

L’installation par défaut couvre les répertoires cibles pris en charge, sans installer les agents. Pour sélectionner un seul hôte :

```bash
evolink skills install --agent codex
evolink skills status --agent codex --json
evolink doctor --agent codex --json
```

Vérifiez current:true, puis envoyez ceci dans la conversation de l’agent :

```text
Confirme que cette session peut détecter et lire evolink-cli. Consulte d’abord le solde et les modèles ; ne génère aucun média.
```

assistant_discovery:not_checked signifie que la CLI ne peut pas vérifier la détection à la place de l’hôte. Si les fichiers existent mais ne sont pas utilisés, actualisez les compétences ou ouvrez une nouvelle session, puis vérifiez les permissions de commande. La simple lecture d’un document ne prouve pas l’accès au compte.

## Cibles et répertoires pris en charge

| --agent | Client | Répertoire |
|---|---|---|
| codex | Codex | ~/.agents/skills/evolink-cli |
| claude-code | Claude Code | ~/.claude/skills/evolink-cli |
| cursor | Cursor | ~/.agents/skills/evolink-cli |
| openclaw | OpenClaw | ~/.openclaw/skills/evolink-cli |
| hermes | Hermes | ~/.hermes/skills/evolink-cli |
| gemini | Gemini CLI | ~/.agents/skills/evolink-cli |
| opencode | OpenCode | ~/.agents/skills/evolink-cli |
| copilot | GitHub Copilot CLI | ~/.agents/skills/evolink-cli |

Gemini, OpenCode et Copilot peuvent suivre l’[installation générale en cinq étapes](/fr/cli/setup#cli-install) avec leur valeur d’agent. Installez la CLI dans l’environnement réel : SSH, WSL, conteneur ou Gateway. Il s’agit de cibles d’installation, et non de garanties de détection dans chaque version d’un hôte. La politique de l’hôte et le chargement des compétences restent de la responsabilité de l’hôte.

## Mises à jour et modifications personnelles

```bash
npm install -g @evolinkai/cli@latest
evolink skills install
evolink skills status --json
```

Synchronisez les compétences après avoir mis à jour la CLI et demandez à l’agent de les relire. Les modifications personnelles sont conservées par défaut. Examinez d’abord les états modified/conflict. N’utilisez --replace-modified qu’après avoir décidé de remplacer le contenu personnel ; les fichiers d’origine sont sauvegardés dans ~/.evolink-media/skill-backups/. Consultez le [dépannage des compétences](/fr/cli/billing#skills-discovery).

À partir de la CLI 0.10.0, `evolink doctor` sans `--agent` inspecte aussi les copies de la compétence installées pour chaque agent. Lorsqu’une copie est plus ancienne que la CLI, `guidance` vous demande d’exécuter `evolink skills install` ; les modifications personnelles et les conflits sont signalés, jamais remplacés. Ces constats ne modifient pas `ok`. Pour savoir comment la CLI annonce les nouvelles versions, voir [Comment savoir qu’une nouvelle version existe](/fr/cli/setup#update-check).

## Ressources pour les agents

Fournissez à l’agent les [règles communes et les ressources lisibles](/fr/cli-mcp/agent-resources#agent-rules), la [référence CLI](/fr/cli/reference) et les [flux de travail média](/fr/cli/workflows).
