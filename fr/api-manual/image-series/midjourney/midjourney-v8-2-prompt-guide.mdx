## Aperçu des paramètres

| Paramètre | Syntaxe | Type | Plage | Par défaut | Description |
|-----------|---------|------|-------|------------|-------------|
| Rapport d'aspect | `--ar W:H` | Ratio entier | Tout ratio d'entiers positifs, sans décimales | 1:1 | Rapport d'aspect de l'image |
| Chaos | `--c N` | int | 0 - 100 | 0 | Diversité des résultats générés |
| Seed | `--seed N` | int | 0 - 4294967295 | Aléatoire | Fixer le seed pour des résultats reproductibles |
| Stylisation | `--s N` | int | 0 - 1000 | 100 | Intensité du style artistique |
| Expérimental | `--exp N` | int | 0 - 100 | 0 | Effet esthétique, cumulable avec la stylisation |
| Qualité (niveau de détail) | `--quality N` / `--q N` | int | 1 - 4 | 1 | Niveau de détail de l'image ; 4 est le mode haute qualité. Sans surcoût. V8.1 n'accepte que 1 / 4 |
| Mode Raw | `--raw` | Interrupteur | — | Désactivé | Désactiver l'embellissement par défaut |
| Prompt négatif | `--no item1, item2` | Texte | — | — | Éléments à exclure de l'image |
| Poids de l'image | `--iw N` | float | 0 - 3 | 1 | Influence du prompt image |
| Référence de style | `--sref [URL]` | URL | — | — | Correspondre au style visuel |
| Poids du style | `--sw N` | int | 0 - 1000 | 100 | Force de la référence de style |
| Personnalisation | `--p [code]` | Code | — | — | Appliquer un profil de personnalisation ou un code de moodboard, transmis tel quel |
| Mosaïque | `--tile` | Interrupteur | — | Désactivé | Générer des motifs répétitifs sans couture |
| Weird | `--weird N` / `--w N` | int | 0 - 3000 | 0 | Esthétique non conventionnelle et expérimentale |

<Note>
Deux réglages ne s'écrivent **pas** dans le prompt — ils sont contrôlés via l'API (les écrire dans le prompt n'a aucun effet, les paramètres sont retirés) :

- **Vitesse** (`draft` / `fast`) → `model_params.speed`
- **Qualité de sortie** (`standard` / `hd`) → paramètre de premier niveau `quality`

`--v` / `--version` est verrouillé sur V8.2 et `--niji` n'est pas pris en charge. Voir ci-dessous [Modes de vitesse](#modes-de-vitesse) et [Qualité de sortie](#qualité-de-sortie).
</Note>

## Paramètres de base

### Rapport d'aspect `--ar`

Définit le rapport d'aspect de l'image. Seuls les ratios entiers sont pris en charge ; les décimales sont rejetées (écrivez `139:100`, pas `1.39:1`). Les ratios extrêmes sont expérimentaux et peuvent produire des résultats imprévisibles.

```
un chat --ar 16:9
```

Valeurs courantes : `1:1`, `4:3`, `3:2`, `16:9`, `9:16`, `2:3`. Voir [Qualité de sortie](#qualité-de-sortie) pour la taille en pixels.

### Chaos `--chaos` / `--c`

Contrôle la diversité des résultats générés. Des valeurs plus élevées produisent de plus grandes différences entre les 4 images.

```
un chat --c 50
```

| Plage | Effet |
|-------|-------|
| 0 | Les 4 images sont très homogènes (par défaut) |
| 1-30 | Différences subtiles |
| 30-70 | Diversité modérée |
| 70-100 | Différences marquées, adapté à l'exploration créative |

### Stylisation `--stylize` / `--s`

Ajuste l'équilibre entre réalisme et style artistique.

```
un chat --s 500
```

| Plage | Effet |
|-------|-------|
| 0-250 | Style réaliste, fidèle au prompt |
| 250-750 | Équilibré |
| 750-1000 | Expression artistique forte, couleurs et composition audacieuses |

### Expérimental `--exp`

Similaire à `--stylize` mais cumulable, génère des images plus détaillées, dynamiques et créatives.

```
un chat --exp 25
```

- Valeurs recommandées : 5, 10, 25, 50, 100
- Changements d'effet notables de 5 à 50, rendements décroissants de 50 à 100
- Au-dessus de 25-50, il peut supplanter l'effet de `--stylize` et de `--p` ; utilisez des valeurs plus basses lors de leur combinaison

### Qualité `--quality` / `--q`

Définit le niveau de détail de l'image. Plage 1 - 4, par défaut 1 ; `4` est le mode haute qualité. Le paramètre est transmis tel quel au fournisseur et **ne change pas le prix**.

```
un chat --q 3
```

- V8.2 accepte `1` / `2` / `3` / `4` ; V8.1 n'accepte que `1` / `4`. Les valeurs hors plage sont rejetées par le fournisseur (`quality: should in [1 2 3 4]`), la tâche échoue et les crédits réservés sont remboursés
- Les valeurs plus élevées prennent plus de temps à rendre
- Uniquement pour le point de terminaison de génération d'images ; les tâches dérivées (variation, remix, édition, etc.) héritent de l'image source

### Mode Raw `--raw`

Désactive l'embellissement par défaut pour une adhérence plus stricte aux détails du prompt. Adapté au photoréalisme ou aux scénarios de contrôle précis.

```
photo de produit --raw
```

### Prompt négatif `--no`

Liste les éléments qui ne doivent pas apparaître dans l'image. Séparez plusieurs éléments par des virgules. Cela équivaut à attribuer à ces éléments un poids de -0.5. Écrire « pas de fruits » ou « sans fruits » dans la description ne fonctionne pas — Midjourney traite ces mots comme du contenu — ; utilisez donc le paramètre à la place.

```
still life gouache painting --no fruit, flowers
```

### Seed `--seed`

Fixe l'état aléatoire initial pour les tests comparatifs.

```
un chat --seed 23453422
```

- Plage : 0 - 4294967295
- Le seed ne fixe que l'état initial ; il ne garantit pas une sortie identique, et toute modification du prompt, des paramètres ou de la version du modèle change le résultat
- Utilisez un seed fixe pendant les tests et un seed aléatoire en production pour plus de variété

## Paramètres de référence d'image

### Prompt image

Placez les URL d'images au **début** du prompt pour influencer le contenu généré.

```
https://example.com/ref.jpg description textuelle --iw 1.5
```

**Règles de combinaison valides :**

| Combinaison | Valide ? |
|-------------|----------|
| 1 image + pas de texte | Invalide (provoquera une erreur) |
| 1 image + description textuelle | Valide |
| 2+ images + pas de texte | Valide |
| 2+ images + description textuelle | Valide |

- Maximum 20 prompts image
- Formats pris en charge : `.png`, `.gif`, `.webp`, `.jpg`, `.jpeg` ; au maximum 20 Mo par fichier et 16k pixels par côté
- Les prompts composés uniquement d'images (sans texte) sont incompatibles avec `--stylize` et `--weird`
- Fonctionne aussi en vitesse `draft` (vérifié sur cette plateforme) ; seul `--tile` ne peut pas être combiné avec `draft`
- Les URL doivent être accessibles publiquement en quelques secondes, voir [Exigences relatives aux images en entrée](#exigences-relatives-aux-images-en-entrée)

### Poids de l'image `--iw`

Contrôle l'influence des prompts image sur le résultat. Plage 0 - 3, par défaut 1. Des valeurs plus élevées produisent des résultats plus proches de l'image de référence.

```
https://example.com/ref.jpg paysage aquarelle --iw 2.0
```

### Référence de style `--sref`

Correspond au style visuel (couleurs, textures, éclairage) de l'image de référence sans copier le contenu. **Doit être utilisé avec un prompt textuel**.

```
un chat --sref https://example.com/style.jpg
```

- Plusieurs prises en charge : `--sref URL1 URL2` ; des poids relatifs peuvent être indiqués avec `--sref URL1::2 URL2::1` (documenté par le fournisseur, pas encore vérifié sur cette plateforme)
- Style aléatoire pris en charge : `--sref random` (renvoie un code numérique après génération, réutilisable)
- Maximum 20 srefs
- Le prompt textuel doit décrire le contenu, pas donner des instructions (« un chat », pas « fais ressembler ceci à la référence »)

### Poids du style `--sw`

Contrôle l'influence de la référence de style. Plage 0 - 1000, par défaut 100.

```
un chat --sref https://example.com/style.jpg --sw 500
```

### Personnalisation `--p`

Applique un profil de personnalisation Midjourney ou un code de moodboard. Le paramètre est transmis sans modification. Les profils et les moodboards sont créés sur midjourney.com ; l'API ne peut ni les créer ni les lister. N'utilisez donc que des codes que vous possédez déjà et validez d'abord l'effet sur un petit lot. `--p` ne peut pas être combiné avec `--weird`.

```
un chat --p abc123
```

## Modes de vitesse

Le mode de vitesse est contrôlé via le champ API `model_params.speed` (n'écrivez pas `--draft` / `--fast` dans le prompt).

Routes concernées : la génération d’image accepte `draft` / `fast` ; remix, édition de canevas, retexture et upload paint n’acceptent que `fast` ; variation et suppression d’arrière-plan n’ont pas de champ speed.

| Mode | Description | Coût |
|------|-------------|------|
| `draft` | Renvoie 24 images d'esquisse légères en 512 px en une seule exécution. Uniquement pour le point de terminaison de génération d'images. | Même multiplicateur que fast |
| `fast` | Mode standard (par défaut), 4 images par génération | Standard |

<Note>
Contrairement à V7, le mode `draft` de V8.2 n'est **pas** à moitié prix — il utilise le même multiplicateur que `fast`. Le mode draft renvoie 24 petites esquisses en une seule exécution ; choisissez celles que vous préférez et relancez-les en pleine qualité. Le mode draft ne peut pas être combiné avec la qualité `hd` ni `--tile` (`--oref` n'est pas du tout pris en charge sur V8.2).

**Turbo n'est pas disponible sur V8.2.** Le canal fournisseur documente V8 comme ne prenant pas en charge le mode turbo ; `speed: "turbo"` est donc rejeté avec `400` sur tous les points de terminaison V8.2 (comme sur V8.1).
</Note>

## Qualité de sortie

La résolution de sortie est contrôlée via le paramètre de premier niveau `quality`, et **non** par un paramètre de prompt. N'écrivez pas `--hd` dans le prompt.

| Valeur | Résolution | Coût |
|--------|------------|------|
| `standard` | Résolution standard, environ 1024 px sur le grand côté pour 1:1 (par défaut) | 1x |
| `hd` | Sortie 2K native, environ 2048 x 2048 pour 1:1 | 1.5x |

- Le multiplicateur de qualité est **combiné (multiplié)** avec le multiplicateur de vitesse
- `hd` est **incompatible** avec la vitesse `draft`
- Il n'existe pas de point de terminaison d'upscale distinct sur V8.2 ; le fournisseur implémente l'« upscale » de V8 comme une nouvelle génération en `hd`, utilisez donc `quality: "hd"` lorsque vous avez besoin de la sortie 2K

## Limites de longueur du prompt

| Point de terminaison | Limite | Remarques |
|----------------------|--------|-----------|
| `mj-v8.2` (génération d'images) | **1024 caractères de description textuelle**, imposés par le fournisseur ; l'API accepte jusqu'à 2048 caractères au total | Le fournisseur ne compte que la description, une fois les URL d'images et les `--paramètres` retirés. La marge supplémentaire est destinée aux URL et aux paramètres |
| `mj-v8.2-remix` / `-edit` / `-retexture` / `-upload-paint` | 8100 caractères | Le prompt est envoyé comme instruction d'édition ; la règle des 1024 ne s'applique pas |
| `mj-v8.2-variation` / `-remove-bg` | — | `prompt` est ignoré |

Une description trop longue est rejetée par le fournisseur avec `v8系列模型提示词长度限制为1024` ; la tâche échoue et les crédits réservés sont remboursés.

## Paramètres non pris en charge dans V8.2

V8.2 ne retire que les paramètres qui fausseraient le verrouillage de version ou la facturation ; **tous les autres paramètres sont transmis tels quels au fournisseur**. Si le fournisseur ne prend pas en charge un paramètre, la tâche échoue avec le message d'erreur du fournisseur et les crédits réservés sont remboursés — rien n'est ignoré silencieusement.

| Paramètre | Traitement |
|-----------|------------|
| `--v` / `--version` / `--niji` | Retiré — la version est verrouillée sur V8.2 |
| `--fast` / `--turbo` / `--draft` / `--relax` | Retiré — utilisez `model_params.speed` (`draft` / `fast` ; turbo n'est pas disponible sur V8.2) |
| `--hd` | Retiré — utilisez le paramètre de premier niveau `quality` |
| `--bs` / `--batchsize` | Retiré — la taille de lot n'est pas configurable |
| `--edit` | Réservé au point de terminaison d'édition par instructions du fournisseur, qui n'est pas encore exposé sur cette plateforme ; rejeté par le fournisseur sur tous les points de terminaison actuels |
| `--oref` / `--ow` | Rejeté par le fournisseur (non pris en charge sur V8.2) |
| `--cref` / `--cw` | Rejeté par le fournisseur (non pris en charge sur V8.2) |
| `--stop` | Rejeté par le fournisseur |
| Multi-prompt `::` | Rejeté par le fournisseur |
| `--sv` | Seul `--sv 6` est accepté, et uniquement avec `--sref` |
| `--repeat` / `--r`, permutations `{}`, `--stealth` / `--public` | Non pris en charge via API |

<Note>
Le canal fournisseur a également ouvert un point de terminaison d'**édition par instructions** pour V8.1 / V8.2 (le Midjourney Edit Model : `--edit` avec jusqu'à 4 images de référence, repeinture facultative par masque transparent). Il n'est pas encore exposé sur cette plateforme et est en cours de planification. `mj-v8.2-edit` et `mj-v8.2-upload-paint` sont des éditions sur canevas (`canvas` + `img_pos` + `mask` facultatif), et `mj-v8.2-retexture` est l'outil retexture. Écrire `--edit` dans un prompt sur l'un des points de terminaison actuels est rejeté par le fournisseur.
</Note>

## Exigences relatives aux images en entrée

Ces règles s'appliquent aux prompts image, aux URL `--sref` et au champ `image_urls` de retexture / upload-paint / remove-bg.

- **URL HTTP(S) publique uniquement.** Les données Base64 et les URL data ne sont pas acceptées pour les images en entrée. L'URL elle-même ne doit pas dépasser 1024 caractères.
- **Le fournisseur télécharge l'image de manière synchrone lors de la création de la tâche et abandonne après environ 10 secondes** (mesuré sur cette plateforme). S'il ne parvient pas à télécharger le fichier à temps, la requête échoue avec `400` et aucune tâche n'est créée. Les hébergeurs d'images situés hors de Chine continentale (imgur, ibb, raw.githubusercontent, pinimg, picsum et similaires) échouent presque systématiquement en pratique. Hébergez les images sur un CDN rapide ou téléversez-les d'abord avec l'[API de téléversement de fichiers](/fr/api-manual/file-series/upload-url) et utilisez l'URL renvoyée.
- Formats pris en charge : `.png`, `.gif`, `.webp`, `.jpg`, `.jpeg` (`mj-v8.2-remove-bg` n'accepte que `.png`, `.jpg`, `.jpeg`). Au maximum 20 Mo par fichier et 16k pixels par côté ; les fichiers très volumineux peuvent dépasser le délai de récupération même depuis un hôte accessible.
- `mj-v8.2-remove-bg` n'accepte pas les liens de résultat signés renvoyés par les tâches Midjourney sur cette plateforme (URL contenant `Expires` / `Signature`). Réhébergez l'image ou utilisez une URL non signée. Retexture et upload-paint acceptent ces liens.
- Les prompts image et les URL `--sref` sont aussi acceptés en vitesse `draft` (vérifié sur cette plateforme) ; seul `--tile` est rejeté avec `draft`.

## Directives de format de prompt

### Structure de base

```
[URL d'image] description textuelle --param1 valeur1 --param2 valeur2
```

### Règles d'écriture

- Les paramètres se placent à la **fin** du prompt textuel
- Un **espace** est requis avant `--`
- Ne pas utiliser de ponctuation dans les paramètres
- Aucun texte ne peut suivre après les paramètres
- Pour faire apparaître des mots dans l'image, entourez-les de guillemets doubles : `a neon sign that says "OPEN" --ar 3:2`

### Exemples

<CodeGroup>
```text Correct
a yellow Persian cat --ar 1:2 --s 500
```

```text Incorrect
a yellow Persian cat--ar 2:3          ← espace manquant avant --
a yellow Persian cat - - ar 2:3       ← espace entre --
a yellow Persian cat --ar 2:3, --s 50 ← ponctuation dans les paramètres
a yellow Persian cat --ar 2:3 more description ← texte après les paramètres
```
</CodeGroup>

## Flux de travail des tâches

Les sept modèles V8.2 sont asynchrones et facturés à l'appel.

1. **Soumettre** — `POST /v1/images/generations` répond immédiatement avec un `id` de tâche, `status: processing` et `usage.credits_reserved`. Le job fournisseur est créé en arrière-plan.
2. **Interroger** — `GET /v1/tasks/{task_id}` ([Interroger l'état d'une tâche](/fr/api-manual/task-management/get-task-detail)). Le fournisseur indique une durée moyenne d'environ 40 secondes pour la génération et les éditions ; interrogez toutes les 3 à 5 secondes avec un plafond côté client d'environ 20 minutes, et ne resoumettez pas le même prompt tant qu'une tâche est encore en `processing`.
3. **Lire le résultat** — lorsque `status` vaut `completed`, `results` contient les URL des images : 4 pour `fast`, 24 pour `draft`. `usage.cost` indique le montant final facturé.
4. **Sauvegarder les images** — les liens de résultat sont valides **30 jours**. Téléchargez ou réhébergez tout ce que vous souhaitez conserver.
5. **Callback facultatif** — passez `callback_url` (HTTPS, hôte public) pour être notifié lors de `completed` / `failed`. Les callbacks sont réessayés 3 fois avec backoff ; considérez-les comme une indication et confirmez par l'interrogation de la tâche.

| Statut | Signification | Final ? |
|--------|---------------|---------|
| `pending` | Acceptée, en attente de la file du fournisseur | Non |
| `processing` | Rendu en cours | Non |
| `completed` | Images prêtes dans `results` | Oui |
| `failed` | Erreur du fournisseur, rejet de paramètre, modération ou échec de récupération ; le message figure dans `error` et les crédits réservés sont remboursés | Oui |

Les tâches échouées sont intégralement remboursées, y compris les rejets de paramètres par le fournisseur (`--oref`, `--q` hors plage, description trop longue) et les échecs de récupération d'image. La seule exception est la modération de contenu, voir ci-dessous. Les codes d'erreur et les conseils de nouvelle tentative sont listés sur la page [Codes d'erreur](/fr/api-manual/task-management/error-codes).

### Tâches dérivées

La variation, le remix et l'édition sur canevas prennent comme source une tâche terminée de la série `mj-v8.2` appartenant au même compte (`task_id` + `image_number`). Règles documentées par le canal fournisseur et vérifiées sur cette plateforme :

- Pour ces opérations dérivées, les tâches sources sont rendues chez le fournisseur par le moteur V7 de Midjourney ; le résultat peut donc différer légèrement en style de l'image source. La tarification est inchangée. Les sources V8.1 ne sont pas acceptées.
- `image_number` sélectionne l'image source : `0`–`3` pour une tâche source `fast`, `0`–`23` pour une tâche source `draft` (les 24 esquisses peuvent toutes servir de source à une variation, un remix ou une édition).
- Les résultats de `mj-v8.2-upload-paint`, `mj-v8.2-retexture` et `mj-v8.2-remove-bg` ne peuvent **pas** servir de source à une variation, un remix ou une édition ; le fournisseur n'autorise que leur upscale, que cette interface n'expose pas. Utilisez plutôt une tâche de génération d'images, de variation, de remix ou d'édition comme source.

## FAQ

**Dois-je modifier mes prompts en passant de V8.1 ?**
Non. Changez la valeur de `model` ; les prompts, `model_params` et les prix sont inchangés. Seuls `--oref` / `--ow` ne fonctionnent plus, et `--q` accepte `2` et `3` en plus de `1` et `4`.

**Pourquoi mon prompt image échoue-t-il avec un 400 avant même qu'une tâche soit créée ?**
Le fournisseur n'a pas pu télécharger l'image dans le délai imparti. Déplacez le fichier vers un hôte rapide et accessible publiquement, ou utilisez l'API de téléversement de fichiers, puis réessayez.

**Existe-t-il une vitesse turbo ?**
Non. Le fournisseur documente V8 comme ne prenant pas en charge turbo ; V8.2 ne propose donc que `draft` et `fast`, comme V8.1.

**`--q 4` est-il plus lent ou plus cher ?**
Il n'est pas facturé différemment. Le fournisseur décrit `4` comme le mode haute qualité, dont le rendu prend plus de temps.

**Puis-je upscaler une image V8.2 ?**
Il n'y a pas de point de terminaison d'upscale sur V8.2. Générez plutôt avec `quality: "hd"` pour une sortie 2K native.

## Avis de modération de contenu

<Note>
Midjourney dispose d'un système de modération de contenu intégré. Chaque image est modérée individuellement : si certaines images générées sont filtrées, leurs emplacements sont renvoyés vides tandis que les autres images sont livrées normalement, et les crédits consommés pour cette requête ne sont pas remboursés. Veuillez vous assurer que vos prompts respectent les directives de contenu.
</Note>
