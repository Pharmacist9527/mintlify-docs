Utilisez EvoLink depuis votre agent pour générer des images, des vidéos, de la musique et de la voix, trouver des modèles et vérifier les coûts, importer des références, suivre les tâches et enregistrer les originaux. Choisissez une méthode de connexion, puis suivez le guide d’installation et de vérification gratuite correspondant.

## Choisir une méthode de connexion

| Où vous travaillez | Voie recommandée | Installation et authentification |
|---|---|---|
| Conversation Claude ou ChatGPT | [MCP distant](/fr/mcp/overview) | Ajoutez une connexion et autorisez-la via OAuth dans le navigateur ; aucune installation de la CLI |
| Codex, Claude Code, Cursor, OpenClaw ou Hermes avec exécution dans un terminal | [CLI](/fr/cli/setup) | Installez la CLI, connectez-vous, puis installez et chargez la compétence |
| Terminal, SSH ou scripts | [CLI](/fr/cli/setup) | Installez la CLI dans l’environnement d’exécution ; SSH comporte des étapes de rappel distinctes |
| Un agent de terminal qui utilise les outils MCP natifs | [Guide du client MCP](/fr/mcp/overview#choose-your-assistant) | Configurez et autorisez directement la connexion de l’hôte |
| Un client qui ne prend en charge que le stdio local | [MCP local](/fr/mcp/other-clients#local-mcp) | Configurez un processus local, Node.js et une clé API personnelle |

Codex CLI est votre client d’agent ; EvoLink CLI est l’outil média qu’il appelle. Ce sont deux produits différents. Chaque carte recommande une seule voie ; les guides CLI par client renvoient aussi vers l’alternative MCP native.

## Vérifier avant de générer

<Steps>
  <Step title="Installer la voie choisie et s’authentifier">
    Suivez l’[installation de la CLI](/fr/cli/setup) en cinq étapes ou votre [guide du client MCP](/fr/mcp/overview#choose-your-assistant). Effectuez vous-même la connexion dans le navigateur. Ne communiquez ni clés ni jetons dans la conversation.
  </Step>
  <Step title="Consulter le solde et les modèles, puis vérifier les compétences ou les outils">
    Les utilisateurs de la CLI consultent le solde, exécutent doctor et demandent à l’agent de confirmer qu’il détecte la compétence. Les utilisateurs de MCP appellent réellement check_balance et search_models. Des fichiers installés ou une liste d’outils ne prouvent pas que l’exécution réussit. Ces vérifications ne soumettent aucune tâche média payante.
  </Step>
  <Step title="Examiner le plan et le coût estimé avant d’approuver la génération">
    Vérifiez le modèle exact et les entrées, préparez les références, puis examinez le plan et l’estimation. Après un accord explicite, soumettez une seule fois, conservez l’identifiant de tâche et enregistrez les originaux. Consultez les [flux de travail CLI](/fr/cli/workflows) ou les [flux de travail MCP](/fr/mcp/overview#workflows).
  </Step>
</Steps>

## Comment les voies s’articulent

Les requêtes média de la CLI suivent le chemin `Agent / terminal → CLI → API de la plateforme`. Le MCP natif suit le chemin `Agent → MCP distant ou local → API de la plateforme`. L’exécution des médias par la CLI ne dépend pas du MCP distant. La connexion au compte passe par Passport ; les importations et les téléchargements d’originaux utilisent des points de terminaison de fichiers distincts.

L’installation, les sessions et les vérifications de connexion se font séparément pour chaque voie. Pour un même compte, OAuth peut actuellement partager les permissions et les quotas de la clé interne. Utilisez une seule voie pour la tâche. Reprenez les soumissions à l’issue inconnue par la voie initiale plutôt que de générer à nouveau par l’autre.
