Utilisez la [présentation CLI/MCP](/fr/cli-mcp/overview) pour choisir selon votre client. Les ressources communes de cette section couvrent les coûts, les tâches, les fichiers et les instructions destinées aux agents.

EvoLink MCP expose la recherche de modèles, les estimations, la génération de médias, les références, les tâches et le solde sous forme d’outils natifs pour les agents. Cette section traite de MCP ; les commandes de terminal et evolink-cli se trouvent dans la [section CLI distincte](/fr/cli/overview).

Ce guide décrit la version publiée **MCP 1.12.1**. Le MCP distant propose 16 outils avec OAuth dans le navigateur ; le stdio local propose 14 outils avec une clé API personnelle. Interrogez les modèles et les entrées actuels du compte avant toute exécution.

## Choisir votre assistant

Établissez la connexion en Streamable HTTP à l’adresse `https://mcp.evolink.ai/mcp`. Autorisez l’accès depuis le point d’entrée propre au client, et non depuis une URL de documentation.

## Démarrage rapide : MCP distant

<Steps>
<Step title="Ajouter le serveur">
Ajoutez un MCP ou un connecteur personnalisé nommé EvoLink, à l’adresse https://mcp.evolink.ai/mcp. Suivez le guide du client ci-dessus ; aucun paquet MCP local n’est nécessaire.
</Step>
<Step title="Se connecter et autoriser l’accès dans le navigateur">
Sélectionnez OAuth, connectez-vous à EvoLink, vérifiez le compte et les permissions, autorisez l’accès, puis revenez au client. Activez la connexion et les outils. La connexion de la CLI ne remplace pas l’autorisation MCP de l’hôte.
</Step>
<Step title="Vérifier gratuitement les outils réels">
Envoyez ce message et confirmez que vous obtenez des résultats réels pour le solde et les modèles :

```text
Utilise EvoLink pour vérifier mon solde et rechercher les modèles d’image disponibles. Ne génère rien pour le moment.
```

Des appels réussis à check_balance et search_models prouvent l’accès ; une simple liste d’outils ne le prouve pas. Cette vérification ne crée aucune tâche média payante.
</Step>
</Steps>

Pour les clients limités à stdio, suivez la [configuration du MCP local](/fr/mcp/other-clients#local-mcp). Configurez séparément son démarrage et son authentification.

## Votre première génération

Une fois la connexion établie, décrivez votre objectif :

<Tabs>
  <Tab title="Image">
```text
Utilise EvoLink pour créer une publicité pour une marque de café, avec une lumière chaude, une tasse en céramique crème et un espace réservé au texte de la marque en haut.
Compare les modèles adaptés et présente les spécifications de sortie, l’estimation et les limites. Attends mon accord.
Renvoie le lien de l’image originale et le montant final facturé qui est indiqué. Ne régénère pas et ne modifie pas le résultat automatiquement.
```
  </Tab>
  <Tab title="Vidéo">
```text
Utilise EvoLink pour créer une courte vidéo d’un coucher de soleil sur l’océan. Présente d’abord les modèles adaptés, les durées prises en charge, la qualité, les options audio et l’estimation.
Après mon accord, soumets une seule fois, enregistre l’identifiant de tâche et interroge la tâche jusqu’à ce qu’elle soit terminée. Renvoie le lien de la vidéo originale et le montant facturé qui est indiqué.
```
  </Tab>
  <Tab title="Audio">
```text
Utilise EvoLink pour générer un message vocal d’accueil en chinois qui dit “欢迎来到我们的咖啡店”.
Choisis un modèle vocal, vérifie la voix et les exigences d’entrée, explique la facturation, puis attends mon accord avant de générer et de renvoyer l’audio original.
```
  </Tab>
</Tabs>

La génération consomme des crédits EvoLink. Ces prompts demandent à l’assistant d’attendre l’accord. L’autorisation du compte, la permission d’outil de l’hôte et l’accord sur le coût de la tâche sont distincts. Le MCP natif ne fournit pas de bouton d’accord côté serveur dans la conversation ; l’agent doit obtenir un accord explicite pour cette tâche. Lisez [Facturation et autorisation](/fr/mcp/billing).

## Fonctionnement

Le MCP distant suit le chemin `votre assistant → EvoLink MCP → API de la plateforme`. L’hôte gère la connexion OAuth ; le service distant exécute les outils. Les clients de conversation dans le navigateur n’ont besoin ni de Node.js ni d’EvoLink CLI.

Le stdio local suit le chemin `votre assistant → processus MCP local → API de la plateforme`. Installez Node.js 20+ sur la machine qui exécute l’assistant, laissez l’hôte lancer le processus et fournissez une clé API de la plateforme. Consultez [Autres clients MCP](/fr/mcp/other-clients#local-mcp) pour la configuration.

Les deux modes exposent les principaux outils de modèles, d’estimation, de génération et de tâches. Le MCP distant expose en plus `prepare_upload` et `get_upload`. Les compétences et les plugins, facultatifs, fournissent des instructions d’utilisation ; ils ne remplacent ni l’enregistrement du serveur, ni l’autorisation du compte, ni les permissions d’outils de l’hôte.

| Objectif | Outils |
|---|---|
| Vérifier le solde et l’accès au compte | `check_balance` |
| Trouver des modèles, des paramètres et de la documentation | `search_models`, `get_model`, `search_docs` |
| Comparer des modèles candidats pour une tâche | `recommend_models` |
| Estimer le coût | `estimate_cost` |
| Générer des images, des vidéos ou de l’audio | `generate_image`, `generate_video`, `generate_audio` |
| Interroger, attendre et lister les tâches | `get_task`, `list_tasks` |
| Examiner l’usage du compte | `get_task_usage` |
| Importer des références | `upload_file` ; le MCP distant propose aussi `prepare_upload`, `get_upload` |

Ces outils ne permettent ni le développement de code, ni le montage vidéo local, ni la création de sites web. Un hôte d’agent peut disposer lui-même de ces capacités ; attribuez-les à l’hôte lorsque vous décrivez EvoLink.

<span id="models" />

## Étape 1 : sélectionner un modèle et valider ses entrées

Utilisez `search_models` ou `recommend_models` pour obtenir les modèles candidats actuels, puis `get_model` pour les identifiants exacts, les capacités prises en charge, les champs obligatoires et les limites. Utilisez `search_docs` pour des indications complémentaires. Un nom de famille de modèles n’est pas forcément un identifiant de soumission valide.

Consultez [Modèles, coûts et quotas](/fr/cli-mcp/models-and-billing#models) pour l’ordre de sélection, les familles récentes à comparer et les règles tarifaires. Vérifiez le catalogue et les entrées actuels du compte ; les modèles cités en exemple ne sont pas des recommandations par défaut.

L’exemple suivant utilise `z-image-turbo`. Vérifiez les paramètres avant d’utiliser un modèle, quel qu’il soit :

```json
{"name":"get_model","arguments":{"model":"z-image-turbo"}}
```

<span id="files" />

## Étape 2 : préparer les références

Aucune importation n’est nécessaire pour des entrées uniquement textuelles. Pour des images, des vidéos ou de l’audio de référence, vérifiez d’abord les types pris en charge, les nombres autorisés et les limites de taille.

1. **URL accessible** : appelez `upload_file` avec `file_url`. Le serveur doit pouvoir récupérer l’URL ; un chemin sur l’ordinateur de l’utilisateur n’est pas une URL publique.
2. **Petit fichier intégré** : avec le MCP distant, `upload_file` accepte jusqu’à 1 MiB de contenu en base64 et exige un type MIME correspondant. Ne placez pas de fichiers volumineux dans les messages d’outils.
3. **Fichier local pour le MCP distant** : appelez `prepare_upload`, importez le fichier depuis un environnement disposant d’un accès aux fichiers et de capacités HTTP, puis consultez le reçu avec `get_upload`. La limite d’importation est de 95 MiB, sous réserve des restrictions du modèle. L’autorisation d’importation est à usage unique et expire au bout d’environ 15 minutes ; les URL d’état restent valables environ une heure.
4. **stdio local** : `upload_file` accepte un `file_path` local. Il s’agit d’un chemin absolu sur la machine du processus MCP, qui n’est pas automatiquement l’ordinateur de l’utilisateur de la conversation. Les limites du service de fichiers et du modèle s’appliquent toujours.

```json
{"name":"prepare_upload","arguments":{"file_name":"reference.png"}}
```

```json
{"name":"get_upload","arguments":{"upload_id":"UPLOAD_ID"}}
```

Une pièce jointe d’une conversation ne devient pas automatiquement une URL utilisable par le modèle. Si l’hôte ne peut ni lire ni importer de fichiers, demandez une URL accessible. Conservez l’`upload_id` d’origine lorsque l’issue est inconnue ; ne relancez pas immédiatement l’importation. La compatibilité des reçus dépend du déploiement du service de fichiers. Les références sont généralement conservées 72 heures ; réimportez les entrées expirées et mettez à jour la requête.

<span id="images" />

## Étape 3 : estimer, approuver et générer une image

Préparez les entrées finales avant d’estimer. Présentez le modèle, le nombre d’images, la taille, le contenu et le coût estimé. Une estimation n’est pas une garantie du règlement final. Consultez [Coûts](/fr/mcp/billing#pricing) pour connaître la couverture et les limites de la tarification dans la version publiée.

```json
{"name":"estimate_cost","arguments":{"model":"z-image-turbo","input":{"prompt":"A minimalist coffee advertisement with a ceramic cup"}}}
```

N’appelez la génération qu’après un accord explicite sur ce plan et sur le coût estimé. `client_request_id` est un identifiant de requête stable de 16 à 96 caractères ; les nouvelles tentatives d’une même soumission doivent conserver cet identifiant et les mêmes entrées. Le budget ci-dessous ne sert qu’à illustrer le paramètre ; définissez-le d’après le budget explicite de l’utilisateur :

```json
{"name":"generate_image","arguments":{"model":"z-image-turbo","input":{"prompt":"A minimalist coffee advertisement with a ceramic cup"},"client_request_id":"coffee-image-demo-001","max_cost_usd":1}}
```

`max_cost_usd` est une vérification avant la soumission, et non un plafond appliqué au montant final facturé. `estimate_cost` ne l’accepte pas. La permission donnée par l’hôte d’appeler un outil ne vaut pas, à elle seule, accord pour l’achat.

Si vous demandez à l’assistant de ne pas estimer ni confirmer (par exemple « génère directement »), il transmet `skip_estimate: true` et soumet sans vous demander de confirmation, dans la portée que vous avez indiquée ; voir [Générer sans estimation](/fr/mcp/tools#skip-estimate). Pour plusieurs images ou tâches d’un même modèle, il transmet `inputs` (jusqu’à 50) à `estimate_cost` et à l’outil de génération : une seule estimation, un seul accord et un seul appel qui renvoie tous les task_id en une fois. Voir [Lots](/fr/mcp/tools#batches).

<span id="video" />

## Vidéo : vérifier la durée, la résolution, le son et les références

Utilisez `get_model` pour trouver l’identifiant exact du modèle texte-vers-vidéo ou image-vers-vidéo. La durée, la résolution, les options de son et la vidéo de référence peuvent influer sur le prix ; ne réutilisez pas une estimation établie pour d’autres entrées. Les tâches d’une même famille peuvent utiliser des identifiants différents.

Validez les paramètres → importez les références → appelez `estimate_cost` avec les entrées finales → présentez le plan et obtenez un accord explicite → appelez `generate_video` avec ces mêmes entrées → interrogez la tâche initiale → livrez la vidéo originale.

Lorsque `media_seconds` est nécessaire, utilisez la durée mesurée de l’entrée. Suspendez l’opération lorsque les mesures requises sont inconnues, que la tarification est incomplète ou qu’une comparaison avec le budget ne peut pas être menée à bien. Ne corrigez pas une vignette grise en modifiant ou en régénérant automatiquement la vidéo terminée.

<span id="audio" />

## Audio : distinguer la musique de la voix

Pour la musique, comparez les modèles Suno v6 disponibles ; pour la narration ou la voix off, utilisez un modèle vocal adapté. Vérifiez les paramètres du modèle, préparez le texte, la langue, la voix, les paroles, la durée ou l’audio de référence, puis estimez les entrées finales, obtenez l’accord et appelez `generate_audio`.

Une tarification audio incomplète ne signifie pas que l’usage est gratuit. Livrez les URL d’origine de l’audio issues de la tâche terminée, conservez toutes les sorties renvoyées et expliquez leur format réel ainsi que la manière de les enregistrer.

<span id="tasks" />

## Étape 4 : attendre, interroger et reprendre la tâche initiale

La génération peut renvoyer un résultat ou un `task_id`. Interrogez cette tâche au lieu de soumettre à nouveau la génération. `get_task.wait_seconds` attend au sein d’un même appel et accepte de 0 à 45 secondes. L’expiration du délai d’attente met fin à cette attente uniquement.

```json
{"name":"get_task","arguments":{"task_id":"TASK_ID","wait_seconds":30}}
```

Utilisez `list_tasks` avec `task_ids` pour les requêtes par lot, ou ses filtres pour l’historique. Si la soumission dépasse le délai avant de renvoyer un identifiant, conservez l’identifiant de requête, les entrées, les identifiants de connexion et l’erreur d’origine en vue de la reprise. Ne changez ni d’identité ni d’identifiant pour générer à nouveau à des fins de dépannage.

Il n’existe actuellement aucun outil public utilisable d’annulation de file d’attente. Arrêter l’attente d’un agent, fermer une page ou déconnecter le MCP n’annule pas la tâche côté serveur et ne prouve ni l’absence de facturation ni qu’un remboursement a été effectué.

<span id="delivery" />

## Étape 5 : livrer les résultats originaux

Une fois la tâche terminée, renvoyez les URL d’origine accessibles, avec le modèle, le nombre de sorties, les informations de coût connues et l’expiration. Les originaux générés sont généralement conservés 24 heures ; enregistrez-les rapidement. Un hôte peut aussi afficher des aperçus. Pour un résultat réduit à un lien ou une vignette grise, vérifiez d’abord l’URL d’origine.

Vérifiez le code d’état HTTP, le type de contenu et le format réel du fichier avant d’enregistrer. Une page d’erreur n’est pas un média. Du code de téléchargement Python que vous contrôlez peut définir un User-Agent de produit lorsque sa requête par défaut est bloquée ; voir le [dépannage des téléchargements](/fr/mcp/billing#download).

Ne corrigez pas des problèmes de livraison ou d’aperçu par une nouvelle génération non approuvée. Si l’utilisateur demande séparément une modification, utilisez les capacités correspondantes de l’hôte et obtenez tout accord requis sur le coût.

Consultez la [référence des outils MCP](/fr/mcp/tools) pour les arguments et les résultats, et [Compétences et ressources lisibles](/fr/cli-mcp/agent-resources) pour les instructions complètes destinées aux agents.
