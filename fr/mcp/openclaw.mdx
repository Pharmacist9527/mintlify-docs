Cette page traite du MCP natif dans OpenClaw. Le service distant utilise Streamable HTTP et OAuth dans le navigateur, sans nécessiter EvoLink CLI. Pour l’exécution par commandes et par compétence, utilisez le [guide CLI](/fr/cli/openclaw) distinct.

## Connecter le MCP distant

Pour les outils natifs, utilisez **Streamable HTTP + OAuth** avec cette URL de serveur :

```text
https://mcp.evolink.ai/mcp
```

L’installation de la CLI n’est pas nécessaire. Sauvegardez la configuration existante, ne fusionnez que la partie EvoLink et préservez les autres services. Choisissez l’enregistrement par commande ou l’enregistrement manuel.

<Steps>

<Step title="Vérifier la prise en charge du MCP distant">

```bash
openclaw mcp --help
```

La version réelle du Gateway doit prendre en charge Streamable HTTP et OAuth. Si ces commandes sont absentes, suivez les indications de mise à niveau de cette version ou utilisez le [guide CLI distinct](/fr/cli/openclaw) ; n’inventez pas d’options pour un hôte plus ancien.

</Step>

<Step title="Ajouter le serveur et définir OAuth">

```bash
openclaw mcp add evolink --url https://mcp.evolink.ai/mcp --transport streamable-http
```

Dans le fichier `~/.openclaw/openclaw.json` du Gateway ou dans sa configuration réelle, définissez `auth` sur `"oauth"` dans `mcp.servers.evolink`, en conservant les autres champs générés. Les versions de Control UI qui le prennent en charge permettent de l’ajouter et de l’activer dans Settings → MCP.

</Step>

<Step title="Autoriser, sonder et interroger">

```bash
openclaw mcp login evolink
openclaw mcp doctor evolink --probe
```

Après l’autorisation dans le navigateur, utilisez l’agent qui appartient au Gateway réel pour envoyer le prompt ci-dessous. Si les modifications ne sont pas prises en compte, actualisez le Gateway auquel appartient la connexion ; actualiser le terminal d’un ordinateur portable n’actualise pas un Gateway distant.

</Step>

</Steps>

La politique d’outils d’OpenClaw détermine aussi la disponibilité. Consultez la [documentation d’OpenClaw](https://docs.openclaw.ai/tools/mcp) pour la version, l’autorisation et l’appartenance de la connexion.

Après l’autorisation, envoyez ceci dans la conversation de l’agent :

```text
Utilise EvoLink pour vérifier le solde de mon compte et rechercher les modèles d’image disponibles. Ne génère rien pour le moment.
```

**Réussite** : des appels réels à `check_balance` et `search_models` renvoient des résultats. Vérifiez ces outils dans la connexion MCP réellement utilisée.

## Mises à jour, déconnexion et dépannage

EvoLink met à jour le serveur MCP hébergé. Après une modification de la configuration, actualisez la session réelle du client. Si nécessaire, renouvelez l’autorisation au moyen de l’action OAuth de ce client. Pour déconnecter EvoLink, désactivez-le, déconnectez-vous ou supprimez-le dans les paramètres MCP de l’hôte ; conservez les autres serveurs.

| Symptôme | Action |
|---|---|
| URL ajoutée mais aucun outil | Activez la connexion, terminez l’autorisation, actualisez et vérifiez la politique de l’organisation |
| 401 ou authentification requise | Renouvelez l’autorisation de cette connexion MCP et conservez les identifiants des tâches initiales |
| 403 ou outil refusé | Vérifiez les permissions de l’hôte, l’état du compte ou de la clé et les erreurs réseau |
| Délai dépassé ou réponse perdue | Interrogez et reprenez l’opération initiale au lieu de générer à nouveau |
| Résultat réduit à un lien ou aperçu gris | Ouvrez et livrez l’original sans le refaire automatiquement |

Consultez [Coûts, accès et dépannage MCP](/fr/mcp/billing#faq). Lisez le [flux de travail de création](/fr/mcp/overview#workflows) avant de soumettre ; la forme des appels est décrite dans la [référence des outils MCP](/fr/mcp/tools).
