Les plugins peuvent regrouper la configuration du MCP distant et des instructions destinées aux agents. Chaque hôte utilise son propre mécanisme d’installation et d’autorisation.

| Point d’entrée | Contenu installé | Exécution des médias |
|---|---|---|
| Plugin MCP personnalisé pour ChatGPT | Une connexion au serveur créée dans ChatGPT | ChatGPT appelle le MCP distant |
| Plugin de dépôt pour Codex | Configuration du MCP distant EvoLink et compétence evolink-mcp | Codex appelle le MCP distant |
| Plugin de dépôt pour Claude Code | Configuration du MCP distant EvoLink et compétence evolink-mcp | Claude Code appelle le MCP distant |
| Compétence fournie avec la CLI | Instructions et documents de référence evolink-cli | L’agent exécute la CLI, qui appelle directement l’API |
| Compétence evolink-mcp autonome | Instructions d’appel de MCP uniquement | La configuration et l’autorisation de MCP restent nécessaires |

## Plugin MCP personnalisé pour ChatGPT

Suivez [Configuration de ChatGPT](/fr/mcp/chatgpt) pour ajouter un serveur MCP personnalisé :

```text
https://mcp.evolink.ai/mcp
```

Choisissez OAuth, autorisez l’accès lors de la connexion dans le navigateur, puis activez EvoLink dans votre conversation. ChatGPT n’utilise pas les commandes de marketplace de Codex décrites ci-dessous et ne nécessite pas d’installer la CLI en local avec npm.

Une connexion personnalisée ne signifie pas qu’EvoLink figure dans le répertoire public des plugins. La création et l’accès aux outils de génération dépendent de votre compte, de la version de l’hôte et des permissions de l’espace de travail. Consultez les [recommandations d’OpenAI sur les MCP personnalisés](https://developers.openai.com/api/docs/guides/custom-mcp-server).

## Plugin de dépôt pour Codex

Confirmez que votre version de Codex prend en charge `plugin`. Ce plugin utilise le MCP distant natif ; le prompt CLI du site web est une autre méthode. Les utilisateurs de la CLI n’ont pas besoin, en plus, d’un plugin pour générer.

<Steps>

<Step title="Ajouter la source et installer le plugin">

Exécutez dans le terminal de la machine et de l’utilisateur qui exécutent Codex :

```bash
codex plugin marketplace add Evolink-AI/mcp-plugin
codex plugin add evolink@evolink
codex plugin list --json
```

Confirmez qu’EvoLink apparaît dans la liste des plugins. Il fournit la configuration du MCP distant et la compétence `evolink-mcp`, et non EvoLink CLI.

</Step>

<Step title="Charger le plugin et autoriser l’accès">

Actualisez les plugins ou ouvrez une nouvelle conversation Codex, puis confirmez que le serveur EvoLink est chargé. Terminez l’autorisation OAuth de l’hôte dans le navigateur lorsque vous y êtes invité. Si le serveur est enregistré et que cette commande est prise en charge, utilisez :

```bash
codex mcp login evolink
```

Laissez-la s’exécuter pendant la connexion et l’autorisation, puis revenez à Codex. Choisissez une seule source d’enregistrement lorsqu’une configuration MCP manuelle existe déjà.

</Step>

<Step title="Vérifier les outils et la compétence">

```text
Confirme que tu as lu evolink-mcp, puis utilise EvoLink pour vérifier le solde et les modèles d’image disponibles. Ne génère rien pour le moment.
```

La vérification est réussie lorsque la compétence a été lue et que des appels réels à `check_balance` et `search_models` ont abouti ; une simple liste de plugins ne prouve pas l’autorisation.

</Step>

</Steps>

Pour mettre à jour la source, exécutez cette commande et actualisez le plugin dans l’hôte, en vérifiant sa version réelle :

```bash
codex plugin marketplace upgrade evolink
```

Consultez la [référence de Codex CLI](https://learn.chatgpt.com/docs/cli/reference) et [Configuration MCP pour Codex](/fr/mcp/codex) pour la configuration manuelle de MCP ; les instructions pour la CLI se trouvent dans le [guide CLI distinct](/fr/cli/codex).

## Plugin de dépôt pour Claude Code

Utilisez une version de Claude Code qui prend en charge les plugins. Ce sont des **commandes de conversation Claude Code**, et non des commandes shell ordinaires.

<Steps>

<Step title="Installer le plugin de dépôt">

```text
/plugin marketplace add Evolink-AI/mcp-plugin
/plugin install evolink@evolink
```

Attendez la fin de l’installation et confirmez qu’EvoLink est activé pour l’utilisateur ou le projet en cours. Préservez les autres plugins.

</Step>

<Step title="Autoriser le MCP distant">

```text
/mcp
```

Après avoir actualisé le plugin, sélectionnez EvoLink et effectuez l’authentification dans le navigateur. Évitez un doublon avec une connexion enregistrée manuellement.

</Step>

<Step title="Vérifier gratuitement">

Demandez à l’assistant de confirmer qu’il a lu `evolink-mcp` et de consulter réellement le solde et les modèles, sans générer. Consultez [Configuration MCP pour Claude Code](/fr/mcp/claude-code) pour la configuration manuelle de MCP ; les instructions pour la CLI se trouvent dans le [guide CLI distinct](/fr/cli/claude-code).

</Step>

</Steps>

## Installer uniquement la compétence MCP

Si le MCP natif est déjà configuré et que vous n’avez besoin que des instructions destinées aux agents :

```bash
npx skills add Evolink-AI/mcp-plugin -g -y
```

Cette commande récupère les compétences du dépôt au moyen du programme d’installation skills. Elle n’installe pas EvoLink CLI, ne démarre pas le MCP local et ne termine pas l’autorisation OAuth. Vérifiez que l’hôte détecte la destination et lit evolink-mcp.

## Ce que le plugin enseigne

La source est [Evolink-AI/mcp-plugin](https://github.com/Evolink-AI/mcp-plugin). La configuration pointe vers le MCP distant hébergé. Sa compétence couvre la recherche de modèles, la validation des paramètres, les estimations et l’accord, l’importation des références, la génération, les tâches, la reprise après échec et la livraison des originaux. Elle n’ajoute aux outils EvoLink MCP ni développement de code, ni modification de fichiers arbitraires, ni montage vidéo complet.

Les compétences CLI et MCP peuvent partager des règles relatives aux médias, mais utilisent des commandes et des outils différents. Choisissez une seule voie par tâche. Si la soumission dépasse le délai et que l’issue est inconnue, reprenez la requête initiale ou le task_id au lieu de générer à nouveau par un autre point d’entrée. Consultez [Ressources pour les agents](/fr/cli-mcp/agent-resources#skills) pour le contenu et les répertoires, et la [référence de la plateforme](/fr/mcp/tools) pour les paramètres.

Consultez [Coûts et conservation](/fr/mcp/billing) pour les limites et la révocation. L’installation d’un plugin, l’installation d’une compétence et l’autorisation OAuth ne valent pas accord pour une demande de génération payante.

## Problèmes d’installation du plugin

| Symptôme | Prochaine étape |
|---|---|
| Commandes plugin / marketplace absentes | Vérifiez la version de l’hôte et la configuration officielle, ou utilisez son guide MCP manuel ou la [configuration distincte de la CLI](/fr/cli/setup) |
| Impossible de récupérer le dépôt | Vérifiez la connectivité à GitHub et les paramètres de source de l’hôte ; conservez l’erreur d’origine |
| Plugin installé mais outils absents | Actualisez la session réelle, activez le plugin et terminez l’autorisation OAuth |
| Serveur ou compétence en double | Sauvegardez la configuration, examinez les sources, gardez celle que vous voulez et préservez les autres services |
| Les outils sont listés mais les appels échouent | Vérifiez l’autorisation avec des consultations gratuites du solde ; voir le [dépannage MCP](/fr/mcp/billing#mcp-connection) |

L’installation d’un plugin ne vaut pas accord pour des tests payants. Consultez le [dépannage centralisé](/fr/mcp/billing#faq) pour la détection et les autres problèmes.
