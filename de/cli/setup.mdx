## CLI installieren, anmelden und prüfen

Die CLI unterstützt macOS, Windows und Linux mit **Node.js 22+**. Installieren Sie sie auf dem Rechner und in der Benutzerumgebung, in der Ihr Agent Befehle ausführt. Terminalbenutzer können den manuellen Schritten folgen.

### Den Agenten EvoLink installieren lassen

Fügen Sie diesen Prompt vollständig in das **Chatfeld** des Agenten ein. Er entspricht dem Prompt der Website. Die Anmeldung im Browser und die Zustimmung zu den Berechtigungen erledigen Sie selbst.

```text
Richte EvoLink ein, damit ich hier direkt Bilder, Videos und Audio erzeugen kann.
1. Installiere die CLI: führe `npm install -g @evolinkai/cli` aus.
2. Melde dich an: führe `evolink auth login` aus.
3. Installiere den zugehörigen Skill: führe `evolink skills install` aus.
4. Prüfe die Verbindung und sage mir nach erfolgreicher Prüfung, dass ich loslegen kann.
```

Kann der Agent keine Terminalbefehle ausführen, folgen Sie den manuellen Schritten unten. Führen Sie `bash`-Blöcke in einem **Terminal** aus, einen Schritt nach dem anderen. Sie müssen nicht beide Installationsmethoden durchführen.

### Manuelle Installation: fünf Schritte

<Steps>

<Step title="Node.js und die Ausführungsumgebung prüfen">

Öffnen Sie ein Terminal auf dem Rechner und unter dem Benutzer, unter dem der Agent läuft. Verwenden Sie unter macOS das Terminal, unter Windows PowerShell oder die Eingabeaufforderung oder das integrierte Terminal von Cursor.

```bash
node --version
npm --version
```

**Erfolg**: Beide Befehle zeigen Versionen an, Node.js in Version 22 oder neuer. Fehlt Node.js oder ist es veraltet, installieren Sie eine passende Version von [Node.js](https://nodejs.org/en/download), öffnen Sie das Terminal erneut und prüfen Sie noch einmal. WSL, SSH-Hosts, Container und Ihr Desktop sind getrennte Umgebungen; installieren Sie dort, wo der Agent Befehle ausführt.

</Step>

<Step title="CLI installieren und prüfen">

```bash
npm install -g @evolinkai/cli
evolink --version
```

**Erfolg**: Die Installation endet ohne Fehler, und `evolink --version` zeigt eine CLI-Version an. `-g` installiert einen Befehl in das globale Verzeichnis der aktuellen Node/npm-Umgebung. Dafür muss kein MCP- oder Plugin-Repository geklont werden. Beheben Sie [Installationsprobleme](/de/cli/billing#cli-install), bevor Sie fortfahren.

</Step>

<Step title="Bei EvoLink anmelden">

```bash
evolink auth login
```

1. Lassen Sie den Befehl laufen. Er öffnet einen Browser oder gibt den Anmeldelink für diesen Versuch aus.
2. Melden Sie sich bei EvoLink an, prüfen Sie Konto, Client und angeforderte Berechtigungen und stimmen Sie zu.
3. Kehren Sie zum ursprünglichen Terminal zurück, warten Sie auf den Abschluss und führen Sie dann aus:

```bash
evolink auth status --json
```

**Erfolg**: `authenticated: true`. Die CLI verwendet den sicheren Anmeldedatenspeicher des Betriebssystems; Sie müssen keinen API Key erstellen oder einfügen. Ein Browser-Callback allein schließt die Anmeldung im Terminal nicht ab. Die Verbindung für die Guthabenabfrage wird im letzten Schritt geprüft. Zu Browser-, Zeitüberschreitungs- und Linux-Speicherfehlern siehe [Fehlerbehebung bei der Anmeldung](/de/cli/billing#login).

</Step>

<Step title="Skill installieren und Erkennung durch den Agenten bestätigen">

```bash
evolink skills install
evolink skills status --json
```

Ohne `--agent` zielt die Installation auf alle unterstützten Skill-Verzeichnisse; sie installiert diese Agenten nicht. Verwenden Sie einen der unten aufgeführten Agent-Werte, um einen einzelnen Host auszuwählen.

**Erfolg**: `current: true`. Senden Sie im Chat des Agenten:

```text
Bestätige, dass diese Sitzung den Skill evolink-cli erkennen und lesen kann. Prüfe zuerst die Verbindung; generiere keine Medien.
```

Der Skill leitet bei Modellsuche, Parametern, Kostenschätzungen und Zustimmung, Referenzen, Aufträgen und dem Download der Originale an. Er registriert kein natives MCP und meldet Sie nicht an. `assistant_discovery: not_checked` erfordert eine Bestätigung durch den Host. Aktualisieren Sie bei Bedarf die Skills oder öffnen Sie eine neue Unterhaltung. Siehe [Skill-Erkennung](/de/cli/billing#skills-discovery).

</Step>

<Step title="Kostenlos prüfen und Bereitschaft bestätigen">

```bash
evolink balance --json
evolink doctor --json
```

**Erfolg**: balance liefert Kontodaten; doctor meldet `ok`, `connection_verified` und `model_discovery_verified` als `true`; der Agent bestätigt, dass er den Skill gelesen hat. Auch ein Guthaben von null kann die Verbindung belegen, für die Generierung ist aber ausreichendes Guthaben nötig.

Diese Schritte erstellen keine kostenpflichtigen Medienaufträge. Sind sie abgeschlossen, kann der Assistent sagen, dass Sie startklar sind. Klären Sie jede Prüfung mit `failed`, bevor Sie fortfahren; generieren Sie kein Bild als Verbindungstest.

</Step>

</Steps>

### Skill für einen einzelnen Agenten installieren

Der Befehl `evolink skills install` von der Website zielt auf alle unterstützten Verzeichnisse. Für einen einzelnen Host ersetzen Sie `AGENT_NAME` unten durch einen Wert aus dieser Tabelle:

| Client | AGENT_NAME | Skill-Verzeichnis |
|---|---|---|
| Codex CLI | `codex` | `~/.agents/skills/evolink-cli` |
| Claude Code | `claude-code` | `~/.claude/skills/evolink-cli` |
| Cursor | `cursor` | `~/.agents/skills/evolink-cli` |
| OpenClaw | `openclaw` | `~/.openclaw/skills/evolink-cli` |
| Hermes | `hermes` | `~/.hermes/skills/evolink-cli` |
| Gemini CLI | `gemini` | `~/.agents/skills/evolink-cli` |
| OpenCode | `opencode` | `~/.agents/skills/evolink-cli` |
| GitHub Copilot CLI | `copilot` | `~/.agents/skills/evolink-cli` |

```text
evolink skills install --agent AGENT_NAME
evolink doctor --agent AGENT_NAME --json
```

Für Gemini lautet das zum Beispiel:

```bash
evolink skills install --agent gemini
evolink doctor --agent gemini --json
```

Dies sind Installationsziele der CLI und keine Garantie, dass jede Host-Version das Verzeichnis automatisch erkennt. Der Host muss Befehle zulassen und Skills laden; siehe [Fehlerbehebung bei Skills und Berechtigungen](/de/cli/billing#skills-discovery). Nicht aufgeführte Assistenten können die [für Agenten lesbaren Ressourcen](/de/cli/skills) lesen; erfinden Sie keine Agent-Werte.

### CLI und Skill aktualisieren

```bash
npm install -g @evolinkai/cli@latest
evolink --version
evolink skills install
evolink skills status --json
```

Prüfen Sie `current: true` und bitten Sie den Agenten, den Skill erneut zu lesen. Lokale Änderungen bleiben erhalten. Verwenden Sie `--replace-modified` erst, wenn Sie entschieden haben, sie zu ersetzen; der bisherige Inhalt wird unter `~/.evolink-media/skill-backups/` gesichert. Verwenden Sie das alte `@evolinkai/media-cli` / `evolink-media` nicht für neue Installationen.

<span id="update-check" />
### So erfahren Sie von einer neuen Version

Ab CLI 0.10.0 prüft die CLI selbst bei npm, welche Version die neueste ist:

- `evolink setup`, `doctor` und `auth login` prüfen jedes Mal und melden `update` mit `update_available`, `latest_version` und dem Upgrade-Befehl. Ein verfügbares Update ist nur ein Hinweis; es lässt den Befehl nie fehlschlagen.
- Andere Befehle, außer dem offline arbeitenden `auth status`, prüfen höchstens einmal am Tag online. Gibt es eine neuere Version, geben sie nach ihrer eigenen Ausgabe eine Zeile auf stderr aus, für dieselbe Version höchstens einmal am Tag. Die stdout-Ausgabe von `--json` und der Exit-Code bleiben unverändert.
- Eine Prüfung sendet eine Anfrage ohne Kontoinformationen an die öffentliche npm-Registry (registry.npmjs.org), wartet höchstens 3 Sekunden und bleibt still, wenn die Registry nicht erreichbar ist.
- Um die Prüfungen auszuschalten, setzen Sie `EVOLINK_CLI_UPDATE_CHECK=0`. Sie sind auch ausgeschaltet, wenn `NO_UPDATE_NOTIFIER` auf einen beliebigen Wert gesetzt ist, sowie in CI.

Der Hinweis besteht aus einer Zeile:

```text
EvoLink CLI 0.10.1 is available (installed 0.10.0). Update with npm install -g @evolinkai/cli@latest, then run evolink skills install.
```

Wenn Sie ihn sehen, führen Sie das Upgrade mit den Befehlen oben durch und synchronisieren Sie den Skill. Versionen vor 0.10.0 erinnern Sie nicht: Vergleichen Sie `evolink --version` mit `npm view @evolinkai/cli version`, oder öffnen Sie [die GitHub Releases der CLI](https://github.com/deeplearning-goethe/evolink-cli/releases) und wählen Sie Watch → Custom → Releases, um sie zu abonnieren.

Endet die Zustimmung im Browser auf einer zweisprachigen 127.0.0.1-Seite, statt zur Website zurückzukehren, ist die installierte CLI älter als 0.9.1; führen Sie das Upgrade durch, bevor Sie fortfahren.

### Anmeldung prüfen oder abmelden

Prüfen Sie die aktuelle Sitzung:

```bash
evolink auth status --json
```

Führen Sie dies nur dann gesondert aus, wenn Sie sich abmelden möchten:

```bash
evolink auth logout
```

Dies widerruft die aktuelle CLI-Sitzung. Die Autorisierung für natives MCP verwalten Sie im jeweiligen Host. Speichern Sie vorhandene Auftragskennungen, bevor Sie das Konto wechseln; alte Preisangebote können nicht unter einem neuen Konto abgesendet werden.

### Linux und SSH: Browser auf einem anderen Rechner

Eine dauerhafte Anmeldung unter Linux braucht **D-Bus und einen entsperrten Secret Service** in der aktuellen Benutzersitzung. Prüfen Sie das zuerst. Ohne diese Voraussetzung ist `credential_store_unavailable` zu erwarten; Root-Zugriff ist kein Ersatz. Richten Sie einen sicheren Speicher ein oder führen Sie die CLI lokal in einer Umgebung aus, die ihn bereitstellt.

<Steps>

<Step title="Anmeldung auf dem Remote-Host starten">

```bash
evolink auth login --no-browser --timeout 600
```

Lassen Sie diesen Befehl laufen und verwenden Sie den aktuellen Autorisierungslink. `--no-browser` unterdrückt den Start des Browsers, wartet aber weiterhin auf einen Callback; es ist **keine Anmeldung per Gerätecode**. Der Bereich beträgt 30–900 Sekunden, Standard ist 180.

</Step>

<Step title="Callback-Port von einem lokalen Terminal weiterleiten">

Suchen Sie den tatsächlichen Port in der `redirect_uri` dieses Versuchs. Ersetzen Sie beide Werte `CALLBACK_PORT` sowie `USER` und `HOST`. Bei `http://127.0.0.1:54321/callback` verwenden Sie `54321` an beiden Stellen. Veröffentlichen Sie den vollständigen Autorisierungslink nicht.

```bash
ssh -N -L CALLBACK_PORT:127.0.0.1:CALLBACK_PORT USER@HOST
```

Lassen Sie das Terminal mit der Weiterleitung laufen; ein untätiges Terminal ohne Eingabeaufforderung ist normal. Lösen Sie einen Portkonflikt, ohne den Port im Autorisierungslink zu ändern.

</Step>

<Step title="Diesen Link öffnen und remote prüfen">

Öffnen Sie den Link aus dem ersten Schritt in Ihrem lokalen Browser, melden Sie sich an und stimmen Sie zu, und warten Sie dann, bis der Remote-Befehl beendet ist. Führen Sie in derselben Remote-Benutzerumgebung aus:

```bash
evolink auth status --json
evolink balance --json
```

Beenden Sie diese Weiterleitungssitzung nach dem Erfolg. Starten Sie bei einer Zeitüberschreitung eine neue Anmeldung und leiten Sie deren tatsächlichen Port weiter; der alte Link lässt sich nicht wiederverwenden. Callbacks von nativem MCP gehören zum Host und verwenden keine Flags der EvoLink CLI.

</Step>

</Steps>

## Nach der Installation

Folgen Sie dem [Ablauf der ersten Generierung](/de/cli/workflows#workflows): Beschreiben Sie den Auftrag, lassen Sie den Agenten verfügbare Modelle, Parameter und Kosten prüfen und bestätigen Sie dann vor dem Absenden. Zu Installation, Anmeldung, Berechtigungen und Downloads siehe die [CLI-Befehlsreferenz](/de/cli/reference#cli-reference) und die [zentrale Fehlerbehebung](/de/cli/billing#faq).

Für natives Remote-MCP oder lokales stdio nutzen Sie die [Anleitung für weitere MCP-Clients](/de/mcp/other-clients). Die Anmeldeoptionen der CLI konfigurieren keine MCP-Verbindung.
