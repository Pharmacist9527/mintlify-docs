## MCP-Verbindung wählen

| Verbindung | Installieren oder verbinden | Authentifizierung | Geeignet für |
|---|---|---|---|
| Remote-MCP | https://mcp.evolink.ai/mcp | Browser-OAuth | Web-Chat und native MCP-Clients |
| Lokales MCP | npx startet @evolinkai/mcp | API Key der Plattform | stdio-Clients und erlaubte lokale Uploads |

Remote-MCP benötigt das lokale MCP-Paket nicht. Die Installation der CLI registriert keinen nativen MCP-Server. Die Installation eines Skills meldet nicht an und verbindet keine Werkzeuge.

## Separate CLI-Anleitungen für Terminal-Agenten

Für Terminals, Skripte, Gemini CLI, OpenCode und GitHub Copilot CLI folgen Sie der [Einrichtung von EvoLink CLI](/de/cli/setup#cli-install) für Installation, Anmeldung, Skill-Ziele und kostenlose Prüfung. Agenten, die Befehle ausführen, können die CLI verwenden; natives MCP konfigurieren Sie mit den Anleitungen für Remote-MCP oder lokales MCP weiter unten.

<span id="ssh-login" />

### Anmeldung unter Linux und über SSH

Läuft die CLI remote, Ihr Browser aber lokal, folgen Sie der [Weiterleitung des SSH-Callbacks](/de/cli/setup#ssh-login), nachdem die Anforderungen an den sicheren Anmeldedatenspeicher unter Linux erfüllt sind. Callbacks des Remote-MCP werden vom Host verwaltet und nutzen nicht die Weiterleitungsschritte der CLI.

## Lokales stdio-MCP mit einem API Key

Ein Client, der nur stdio unterstützt, kann einen lokalen MCP-Prozess starten. Er braucht **Node.js 20+** und einen persönlichen API Key statt des Browser-OAuth des Remote-MCP.

<Steps>

<Step title="Node und einen eigenen Key vorbereiten">

```bash
node --version
npx --version
```

Beide Befehle müssen funktionieren, mit Node 20 oder neuer. Erstellen Sie einen eigenen persönlichen Key mit Limits unter [API Keys](https://evolink.ai/dashboard/keys). Stellen Sie `EVOLINK_API_KEY` über die sichere Umgebung oder die Secret-Einstellungen des Clients bereit, nicht über den Chat des Agenten, geteilte Screenshots oder ein Repository.

</Step>

<Step title="Lokalen Start konfigurieren">

Wählen Sie in den MCP-Einstellungen des Clients lokal/stdio:

```text
command: npx
args: -y @evolinkai/mcp@latest
```

Beim ersten Start ruft npx das Paket ab. Der Host kommuniziert über stdio, und der lokale Prozess ruft die Plattform-API auf. Stellen Sie sicher, dass der Host npx findet; eine GUI-Anwendung kann eine andere Umgebung haben als Ihr Terminal. `YOUR_API_KEY` unten ist ein Platzhalter für die private lokale Konfiguration. Bevorzugen Sie die Vererbung aus der Umgebung, sofern sie unterstützt wird.

```json
{
  "mcpServers": {
    "evolink": {
      "command": "npx",
      "args": ["-y", "@evolinkai/mcp@latest"],
      "env": {"EVOLINK_API_KEY": "YOUR_API_KEY"}
    }
  }
}
```

</Step>

<Step title="Verzeichnisse erlauben, wenn lokale Dateien benötigt werden">

Setzen Sie für Uploads über lokale Pfade `EVOLINK_UPLOAD_ALLOWED_DIRS` in der Prozessumgebung auf die erlaubten absoluten Verzeichnisse. Trennen Sie mehrere Verzeichnisse unter macOS/Linux mit `:` und unter Windows mit `;`. Ohne diese Einstellung sind Uploads über lokale Pfade deaktiviert. Remote-MCP akzeptiert `file_path` nie.

Dies steuert den Zugriff auf lokale Dateien, nicht die Grenzen des Modells für Format, Dauer oder Größe. Die Verwendung von URL oder base64 braucht keinen Zugriff auf lokale Verzeichnisse.

</Step>

<Step title="Neu laden und kostenlose Werkzeuge prüfen">

Speichern Sie die Konfiguration, aktivieren Sie EvoLink und laden Sie neu oder öffnen Sie eine neue Sitzung, je nachdem, was Ihr Host verlangt. Bitten Sie ihn, `check_balance` und `search_models` aufzurufen, und prüfen Sie, ob echte Ergebnisse zurückkommen. Das Starten eines Prozesses oder das Auflisten von Werkzeugen allein ist keine erfolgreiche Kontoprüfung.

Lokales stdio bietet nicht die Werkzeuge `prepare_upload` / `get_upload` für einmalige Remote-Uploads. Prüfen Sie das tatsächliche `tools/list`. Für den persönlichen Key gelten eigene Limits, nicht die Limits des OAuth-Keys.

</Step>

</Steps>

### Konfiguration für Claude Code und Codex

Ist der Key bereits über die sichere Umgebung bereitgestellt, kann Claude Code mit diesem Befehl anstelle des JSON-Beispiels registrieren:

```bash
claude mcp add --scope user evolink -- npx -y @evolinkai/mcp@latest
```

Codex kann diesen Abschnitt einfügen, um Variablen aus seiner Startumgebung zu übernehmen:

```toml
[mcp_servers.evolink]
command = "npx"
args = ["-y", "@evolinkai/mcp@latest"]
env_vars = ["EVOLINK_API_KEY", "EVOLINK_UPLOAD_ALLOWED_DIRS"]
```

Laden Sie nach dem Aktualisieren neu und prüfen Sie die tatsächliche Version. `@latest` ersetzt keinen bereits laufenden Prozess. Zu Fehlern bei Start, Key und lokalen Pfaden siehe die [zentrale Fehlerbehebung](/de/mcp/billing#mcp-connection).

## Weitere Remote-MCP-Clients

Der Client braucht Streamable HTTP, OAuth und Browser-Callbacks. Ein Client, der auf statische Keys oder stdio beschränkt ist, sollte das lokale MCP oben verwenden.

<Steps>

<Step title="Server hinzufügen">

Erstellen Sie eine MCP-Verbindung mit dem Namen EvoLink, mit Streamable HTTP und dieser URL:

```text
https://mcp.evolink.ai/mcp
```

Geben Sie keine URL der Dokumentation, keine `/v1`-URL der Plattform und keinen npx-Befehl ein.

</Step>

<Step title="OAuth abschließen und Werkzeuge aktivieren">

Wählen Sie OAuth, verwenden Sie die Anmeldeaktion des Clients, stimmen Sie im Browser zu und kehren Sie zurück. Prüfen Sie, ob die Verbindung und die Werkzeuge aktiviert sind. Ein statischer API Key ist nicht das OAuth-Token dieser Verbindung.

</Step>

<Step title="Kostenlos prüfen">

```text
Prüfe mit EvoLink mein Guthaben und suche verfügbare Bildmodelle. Generiere noch nichts.
```

Folgen Sie dem [Ablauf für den ersten Medienauftrag](/de/mcp/overview#workflows), sobald tatsächliche Guthaben- und Modellergebnisse zurückkommen. Eine Werkzeugliste ohne erfolgreiche Aufrufe erfordert weiterhin eine Fehlerbehebung bei der Autorisierung.

</Step>

</Steps>
