## Was sich gegenüber V8.1 geändert hat

Midjourney V8.2 wurde am **24. Juli 2026** zur Standardversion. Offiziell ist es ein Update mit Schwerpunkt auf Ästhetik, Bildqualität und Personalisierung: Die Ergebnisse sind kreativer, mutiger und ausgefeilter, und Ausreißer mit niedriger Qualität sind deutlich seltener. Auf dieser Plattform verwendet V8.2 **dieselben sieben Modell-IDs, dieselben Endpunkte und dieselben Preise** wie V8.1, die Migration ist also eine Einzeiler-Änderung: Ersetzen Sie `mj-v8.1` im Feld `model` durch `mj-v8.2`. Prompts müssen nicht umgeschrieben werden.

| Punkt | V8.1 | V8.2 |
|-------|------|------|
| Modell-IDs | `mj-v8.1`, `mj-v8.1-variation`, `-remix`, `-edit`, `-retexture`, `-upload-paint`, `-remove-bg` | Dieselben sieben, mit dem Präfix `mj-v8.2` |
| Detailstufe `--q` / `--quality` | Nur `1` oder `4` | `1` – `4` |
| `turbo`-Geschwindigkeit (2x) | Nicht akzeptiert | Akzeptiert bei der Bildgenerierung sowie bei Remix / Edit / Retexture / Upload-Paint |
| Nicht unterstützte Flags | Stillschweigend entfernt | Durchgereicht; der Upstream lehnt sie mit einer expliziten Fehlermeldung ab und die reservierten Credits werden erstattet |
| `--oref` / `--ow` | Akzeptiert | Nicht unterstützt (vom Upstream abgelehnt) |
| Preise und Multiplikatoren | 5,4 / 8,1 Credits, `turbo` x2, `hd` x1,5 | Identisch |
| Abgeleitete Aufgaben (Variation / Remix / Edit) | Upstream von der V7-Engine gerendert | Gleich |

<Note>
Mit dem offiziellen V8.2-Release hat Midjourney außerdem das **Edit Model** eingeführt (anweisungsbasierte Bearbeitung und Generierung aus bis zu 4 Referenzbildern, das Omni Reference, Character Reference und das Retexture-Werkzeug ersetzt). Das Edit Model ist auf dieser Route noch nicht verfügbar. `mj-v8.2-edit` und `mj-v8.2-upload-paint` sind Canvas-Bearbeitungen (`canvas` + `img_pos` + optionale `mask`), und `mj-v8.2-retexture` ist das klassische Retexture-Werkzeug.
</Note>

<Note>
Zwei Einstellungen werden **nicht** in den Prompt geschrieben, sondern über die API gesteuert (im Prompt haben sie keine Wirkung, die Flags werden entfernt):

- **Geschwindigkeit** (`draft` / `fast` / `turbo`) → `model_params.speed`
- **Ausgabequalität** (`standard` / `hd`) → Top-Level-Parameter `quality`

`--v` / `--version` ist auf V8.2 festgelegt und `--niji` wird nicht unterstützt. Siehe unten [Geschwindigkeitsmodi](#geschwindigkeitsmodi) und [Ausgabequalität](#ausgabequalität).
</Note>

## Grundlegende Parameter

### Seitenverhältnis `--ar`

Legt das Bildseitenverhältnis fest. Es werden nur Ganzzahlverhältnisse unterstützt; Dezimalzahlen werden abgelehnt (schreiben Sie `139:100`, nicht `1.39:1`).

```
eine Katze --ar 16:9
```

Gängige Werte: `1:1`, `4:3`, `3:2`, `16:9`, `9:16`, `2:3`. Extreme Verhältnisse können unvorhersehbare Ergebnisse erzeugen. Die Pixelgrößen, die jedes Verhältnis erzeugt, finden Sie unter [Ausgabequalität](#ausgabequalität).

### Chaos `--chaos` / `--c`

Steuert die Vielfalt der generierten Ergebnisse. Höhere Werte erzeugen größere Unterschiede zwischen den 4 Bildern.

```
eine Katze --c 50
```

| Bereich | Effekt |
|---------|--------|
| 0 | 4 Bilder sind sehr ähnlich (Standard) |
| 1-50 | Mäßige Vielfalt |
| 50-100 | Hochgradig zufällig, geeignet für kreative Erkundung |

### Stilisierung `--stylize` / `--s`

Passt die Balance zwischen Realismus und künstlerischem Stil an.

```
eine Katze --s 500
```

| Bereich | Effekt |
|---------|--------|
| 0-250 | Realistischer Stil, dem Prompt treu |
| 250-750 | Ausgewogen |
| 750-1000 | Starker künstlerischer Ausdruck, kräftige Farben und Komposition |

### Experimentell `--exp`

Ähnlich wie `--stylize`, aber stapelbar, erzeugt detailliertere, dynamischere und kreativere Bilder.

```
eine Katze --exp 25
```

- Empfohlene Werte: 5, 10, 25, 50, 100
- Spürbare Effektänderungen von 5-50, abnehmende Wirkung von 50-100
- Kann die Wirkung von `--stylize` über 25-50 überschreiben

### Qualität `--quality` / `--q`

Legt die Render-Detailstufe fest. Bereich 1 - 4, Standard 1. Das Flag wird unverändert an den Upstream durchgereicht und **ändert den Preis nicht**.

```
eine Katze --q 3
```

- V8.2 akzeptiert `1` / `2` / `3` / `4`; V8.1 akzeptiert nur `1` / `4`. Werte außerhalb des Bereichs werden vom Upstream abgelehnt (`quality: should in [1 2 3 4]`), die Aufgabe schlägt fehl und reservierte Credits werden erstattet
- Midjourneys eigene Parametertabelle führt `--q` für V8 nicht auf, die visuelle Wirkung wird daher vom Upstream nach bestem Bemühen bereitgestellt — vergleichen Sie einige Werte mit Ihren eigenen Prompts, bevor Sie sich darauf verlassen
- Nur für den Bildgenerierungs-Endpunkt; abgeleitete Aufgaben (Variation, Remix, Bearbeitung usw.) übernehmen das Quellbild

### Raw-Modus `--raw`

Deaktiviert die Standard-Verschönerung für eine strengere Einhaltung der Prompt-Details. Geeignet für Fotorealismus oder präzise Kontrollszenarien.

```
Produktfoto --raw
```

### Negativ-Prompt `--no`

Listet Elemente auf, die im Bild nicht erscheinen sollen. Mehrere Elemente werden durch Kommas getrennt. „kein Obst" oder „ohne Obst" in der Beschreibung zu schreiben funktioniert nicht — Midjourney behandelt diese Wörter als Inhalt —, verwenden Sie daher stattdessen das Flag.

```
still life gouache painting --no fruit, flowers
```

### Seed `--seed`

Fixiert den anfänglichen Zufallszustand für Vergleichstests.

```
eine Katze --seed 23453422
```

- Bereich: 0 - 4294967295
- Gleicher Seed + gleicher Prompt → Ergebnisse sind auf V8.x zu etwa 99 % identisch (offizielle Angabe); kleine Parameteränderungen verändern das Bild dennoch
- Kombinieren Sie Seeds nicht mit der `turbo`-Geschwindigkeit: Turbo ist auf Durchsatz optimiert, und die Seed-Fixierung ist dort nicht zuverlässig

## Bildreferenz-Parameter

### Bildprompt

Platzieren Sie Bild-URLs am **Anfang** des Prompts, um den generierten Inhalt zu beeinflussen.

```
https://example.com/ref.jpg Textbeschreibung --iw 1.5
```

**Gültige Kombinationsregeln:**

| Kombination | Gültig? |
|-------------|---------|
| 1 Bild + kein Text | Ungültig (erzeugt Fehler) |
| 1 Bild + Textbeschreibung | Gültig |
| 2+ Bilder + kein Text | Gültig |
| 2+ Bilder + Textbeschreibung | Gültig |

- Maximal 20 Bildprompts
- Unterstützte Formate: `.png`, `.gif`, `.webp`, `.jpg`, `.jpeg`
- Nicht verfügbar mit `draft`-Geschwindigkeit (verwenden Sie `fast`)
- URLs müssen innerhalb weniger Sekunden öffentlich erreichbar sein, siehe [Anforderungen an Eingabebilder](#anforderungen-an-eingabebilder)

### Bildgewicht `--iw`

Steuert den Einfluss des Bildprompts auf das Ergebnis. Bereich 0 - 3, Standard 1. Höhere Werte erzeugen Ergebnisse näher am Referenzbild.

```
https://example.com/ref.jpg Aquarelllandschaft --iw 2.0
```

### Stilreferenz `--sref`

Gleicht den visuellen Stil (Farben, Texturen, Beleuchtung) des Referenzbilds ab, ohne den Inhalt zu kopieren. **Muss mit einem Textprompt verwendet werden**.

```
eine Katze --sref https://example.com/style.jpg
```

- Mehrere unterstützt: `--sref URL1 URL2`
- Zufälliger Stil unterstützt: `--sref random` (gibt nach der Generierung einen Zahlencode zurück, wiederverwendbar)
- Maximal 20 Srefs
- Beschreiben Sie im Textprompt den Inhalt, keine Anweisungen („eine Katze", nicht „lass das wie die Referenz aussehen")

### Stilgewicht `--sw`

Steuert den Einfluss der Stilreferenz. Bereich 0 - 1000, Standard 100.

```
eine Katze --sref https://example.com/style.jpg --sw 500
```

### Personalisierung `--p`

Wendet ein Midjourney-Personalisierungsprofil oder einen Moodboard-Code an. Das Flag wird unverändert durchgereicht. Profile werden auf midjourney.com erstellt und bewertet; die API kann sie weder erstellen noch auflisten. Verwenden Sie daher nur Codes, die Sie bereits besitzen, und prüfen Sie die Wirkung zunächst an einer kleinen Charge.

```
eine Katze --p abc123
```

## Geschwindigkeitsmodi

Der Geschwindigkeitsmodus wird über das API-Feld `model_params.speed` gesteuert (schreiben Sie nicht `--draft` / `--fast` / `--turbo` in den Prompt).

| Modus | Beschreibung | Kosten |
|-------|-------------|--------|
| `draft` | Liefert 24 leichtgewichtige 512-px-Skizzenbilder in einem einzigen Durchlauf. Nur für Bildgenerierungs-Endpunkt. | Gleicher Multiplikator wie fast |
| `fast` | Standardmodus (Standard), 4 Bilder pro Generierung | Standard |
| `turbo` | Turbo-Modus, schnellere Generierung, 4 Bilder pro Generierung | 2x |

<Note>
Anders als bei V7 ist der `draft`-Modus von V8.2 **nicht** zum halben Preis – er verwendet denselben Multiplikator wie `fast`. Draft liefert 24 kleine Skizzen in einem Durchlauf; wählen Sie die gewünschten aus und führen Sie sie in voller Qualität erneut aus. Draft kann nicht mit `hd`-Qualität kombiniert werden, und auch `draft` + `turbo` lässt sich nicht kombinieren (`speed` ist ein einzelner Wert).
</Note>

<Note>
Midjourneys öffentliche Dokumentation führt Turbo für V8 als nicht verfügbar. Der von dieser Plattform verwendete Upstream-Kanal akzeptiert `turbo` für V8.2 jedoch (in der Produktion verifiziert, abgerechnet mit 2x). Sollte der Upstream eine Turbo-Anfrage einmal ablehnen, schlägt die Aufgabe mit der Upstream-Meldung fehl und die reservierten Credits werden erstattet.
</Note>

## Ausgabequalität

Die Ausgabeauflösung wird über den Top-Level-Parameter `quality` gesteuert, **nicht** über ein Prompt-Flag. Schreiben Sie nicht `--hd` in den Prompt.

| Wert | Auflösung | Kosten |
|------|-----------|--------|
| `standard` | Standardauflösung, etwa 1 MP (Standard) | 1x |
| `hd` | Native HD-Ausgabe, etwa 4 MP | 1,5x |

Ungefähre Ausgabegrößen nach Seitenverhältnis (offizielle V8.2-Angaben; die genauen HD-Abmessungen können geringfügig abweichen):

| Seitenverhältnis | `standard` | `hd` |
|------------------|-----------|------|
| 1:1 | 1024 x 1024 | 2048 x 2048 |
| 4:3 | 1232 x 928 | 2464 x 1856 |
| 2:3 | 896 x 1344 | 1792 x 2688 |
| 16:9 | 1456 x 816 | 2912 x 1632 |

- Der Qualitätsmultiplikator wird mit dem Geschwindigkeitsmultiplikator **kombiniert (multipliziert)**: `turbo` + `hd` = 3x
- `hd` ist **inkompatibel** mit `draft`-Geschwindigkeit
- Auf V8.2 gibt es keinen separaten Upscale-Endpunkt; verwenden Sie `hd`, wenn Sie die 2K-Ausgabe benötigen

## Prompt-Längenbegrenzungen

| Endpunkt | Limit | Hinweise |
|----------|-------|----------|
| `mj-v8.2` (Bildgenerierung) | **1024 Zeichen Textbeschreibung**, durchgesetzt vom Upstream; die API akzeptiert insgesamt bis zu 2048 Zeichen | Der Upstream zählt nur die Beschreibung, nachdem Bild-URLs und `--flags` entfernt wurden. Der zusätzliche Platz ist für URLs und Parameter vorgesehen |
| `mj-v8.2-remix` / `-edit` / `-retexture` / `-upload-paint` | 8100 Zeichen | Der Prompt wird als Bearbeitungsanweisung gesendet; die 1024-Regel gilt nicht |

Eine zu lange Beschreibung wird vom Upstream mit `v8系列模型提示词长度限制为1024` abgelehnt; die Aufgabe schlägt fehl und reservierte Credits werden erstattet.

## Konflikte

| Parameter A | Parameter B | Beschreibung |
|-------------|-------------|-------------|
| `draft` Geschwindigkeit | `hd` Qualität | Draft-Modus kann nicht mit HD kombiniert werden |
| `draft` Geschwindigkeit | `turbo` Geschwindigkeit | `speed` ist ein einzelner Wert; 24 Skizzen mit Turbo-Geschwindigkeit sind nicht verfügbar |
| `draft` Geschwindigkeit | Bildprompt / `--sref` | Bildreferenzen erfordern `fast` |

| `--exp` > 25 | `--stylize` | Hohes `--exp` kann `--stylize` unterdrücken; senken Sie `--exp` bei Kombination |
| `--seed` | `turbo` Geschwindigkeit | Seed-Fixierung ist im Turbo-Modus nicht zuverlässig |

## Nicht unterstützte Parameter in V8.2

V8.2 entfernt nur die Flags, die Versionssperre oder Abrechnung verfälschen würden; **alle anderen Flags werden unverändert an den Upstream durchgereicht**. Unterstützt der Upstream ein Flag nicht, schlägt die Aufgabe mit der Upstream-Fehlermeldung fehl und reservierte Credits werden erstattet — nichts wird stillschweigend verworfen.

| Parameter | Behandlung |
|-----------|------------|
| `--v` / `--version` / `--niji` | Entfernt — Version ist auf V8.2 festgelegt |
| `--fast` / `--turbo` / `--draft` / `--relax` | Entfernt — verwenden Sie `model_params.speed` |
| `--hd` | Entfernt — verwenden Sie den Top-Level-Parameter `quality` |
| `--bs` / `--batchsize` | Entfernt — Batch-Größe nicht konfigurierbar |
| `--edit` | Nicht verfügbar — das offizielle Edit Model ist auf dieser Route nicht verfügbar; verwenden Sie `mj-v8.2-edit` / `mj-v8.2-upload-paint` für Canvas-Bearbeitungen |
| `--oref` / `--ow` | Vom Upstream abgelehnt (auf V8.2 nicht unterstützt) |
| `--cref` / `--cw` | Vom Upstream abgelehnt (auf V8.2 nicht unterstützt) |
| `--stop` | Vom Upstream abgelehnt |
| Multi-Prompt `::` | Vom Upstream abgelehnt |
| `--sv` | Nur `--sv 6` wird akzeptiert, und nur zusammen mit `--sref` |
| `--repeat` / `--r`, `{}`-Permutationen, `--stealth` / `--public` | Über API nicht unterstützt |

## Anforderungen an Eingabebilder

Diese Regeln gelten für Bildprompts, `--sref`-URLs und das Feld `image_urls` von Retexture / Upload-Paint / Remove-BG.

- **Nur öffentliche HTTP(S)-URLs.** Base64 und Data-URLs werden nicht akzeptiert.
- **Der Upstream lädt das Bild beim Erstellen der Aufgabe synchron herunter und bricht nach etwa 10 Sekunden ab.** Kann die Datei nicht rechtzeitig heruntergeladen werden, schlägt die Anfrage mit `400` fehl und es wird keine Aufgabe erstellt. Bildhoster außerhalb Festlandchinas (imgur, ibb, raw.githubusercontent, pinimg, picsum und ähnliche) scheitern in der Praxis fast immer. Hosten Sie Bilder auf einem schnellen CDN oder laden Sie sie zuerst mit der [Datei-Upload-API](/de/api-manual/file-series/upload-url) hoch und verwenden Sie die zurückgegebene URL.
- Unterstützte Formate: `.png`, `.gif`, `.webp`, `.jpg`, `.jpeg`. Halten Sie die Dateien angemessen klein; sehr große Dateien können das Zeitbudget für den Download selbst von einem erreichbaren Host aus überschreiten.
- `mj-v8.2-remove-bg` akzeptiert nicht die signierten Ergebnislinks, die Midjourney-Aufgaben auf dieser Plattform zurückgeben (URLs mit `Expires` / `Signature`). Hosten Sie das Bild neu oder verwenden Sie eine unsignierte URL. Retexture und Upload-Paint akzeptieren diese Links.
- Bildreferenzen sind bei `draft`-Geschwindigkeit nicht verfügbar.

## Prompt-Format-Richtlinien

### Grundstruktur

```
[Bild-URL] Textbeschreibung --param1 Wert1 --param2 Wert2
```

### Schreibregeln

- Parameter stehen am **Ende** des Textprompts
- Ein **Leerzeichen** ist vor `--` erforderlich
- Keine Satzzeichen in Parametern verwenden
- Nach Parametern darf kein Text folgen
- Um Wörter im Bild darzustellen, setzen Sie sie in doppelte Anführungszeichen: `a neon sign that says "OPEN" --ar 3:2`

### Beispiele

<CodeGroup>
```text Richtig
a yellow Persian cat --ar 1:2 --s 500
```

```text Falsch
a yellow Persian cat--ar 2:3          ← fehlendes Leerzeichen vor --
a yellow Persian cat - - ar 2:3       ← Leerzeichen zwischen --
a yellow Persian cat --ar 2:3, --s 50 ← Satzzeichen in Parametern
a yellow Persian cat --ar 2:3 more description ← Text nach Parametern
```
</CodeGroup>

## Aufgaben-Workflow

Alle sieben V8.2-Modelle sind asynchron und werden pro Aufruf abgerechnet.

1. **Absenden** — `POST /v1/images/generations` antwortet sofort mit einer Aufgaben-`id`, `status: processing` und `usage.credits_reserved`. Der Upstream-Job wird im Hintergrund erstellt.
2. **Abfragen** — `GET /v1/tasks/{task_id}` ([Aufgabenstatus abfragen](/de/api-manual/task-management/get-task-detail)). Fragen Sie alle 3–5 Sekunden ab, mit einer clientseitigen Obergrenze von etwa 20 Minuten; senden Sie denselben Prompt nicht erneut, solange eine Aufgabe noch `processing` ist.
3. **Ergebnis lesen** — wenn `status` gleich `completed` ist, enthält `results` die Bild-URLs: 4 bei `fast` / `turbo`, 24 bei `draft`. `usage.cost` zeigt die endgültige Belastung.
4. **Bilder speichern** — Ergebnislinks sind **30 Tage** gültig. Laden Sie alles herunter oder hosten Sie es neu, was Sie behalten möchten.
5. **Optionaler Callback** — übergeben Sie `callback_url` (HTTPS, öffentlicher Host), um bei `completed` / `failed` / `cancelled` benachrichtigt zu werden. Callbacks werden 3-mal mit Backoff wiederholt; betrachten Sie sie als Hinweis und bestätigen Sie den Status über die Aufgabenabfrage.

| Status | Bedeutung | Endgültig? |
|--------|-----------|------------|
| `pending` | Angenommen, wartet auf die Upstream-Warteschlange | Nein |
| `processing` | Wird gerendert | Nein |
| `completed` | Bilder in `results` bereit | Ja |
| `failed` | Upstream-Fehler, Parameterablehnung, Moderation oder fehlgeschlagener Download; die Meldung steht in `error` und reservierte Credits werden erstattet | Ja |
| `cancelled` | Vom Benutzer abgebrochen | Ja |

Fehlgeschlagene Aufgaben werden vollständig erstattet, einschließlich Parameterablehnungen durch den Upstream (`--oref`, `--q` außerhalb des Bereichs, zu lange Beschreibung) und fehlgeschlagener Bild-Downloads. Die einzige Ausnahme ist die Inhaltsmoderation, siehe unten. Fehlercodes und Hinweise zu Wiederholungsversuchen finden Sie auf der Seite [Fehlercodes](/de/api-manual/task-management/error-codes).

### Abgeleitete Aufgaben verwenden die V7-Engine

Variations-, Remix- und Canvas-Bearbeitungsaufgaben, die auf einem V8.2-Quellbild aufbauen, werden upstream von Midjourneys V7-Engine gerendert (offizielles Midjourney-Verhalten für V8-basierte abgeleitete Jobs). Das Ergebnis kann sich stilistisch geringfügig vom Quellbild unterscheiden. Die Preise bleiben unverändert. Quellaufgaben müssen abgeschlossene Aufgaben der `mj-v8.2`-Serie sein, die zum selben Konto gehören; V8.1-Quellen werden nicht akzeptiert.

## FAQ

**Muss ich meine Prompts beim Wechsel von V8.1 ändern?**
Nein. Ändern Sie den Wert von `model`; Prompts, `model_params` und Preise bleiben unverändert. Nur `--oref` / `--ow` funktionieren nicht mehr, und `--q` akzeptiert zusätzlich zu `1` und `4` auch `2` und `3`.

**Warum schlägt mein Bildprompt mit einem 400 fehl, bevor überhaupt eine Aufgabe erstellt wird?**
Der Upstream konnte das Bild nicht innerhalb seines Zeitbudgets herunterladen. Verschieben Sie die Datei auf einen schnellen, öffentlich erreichbaren Host oder verwenden Sie die Datei-Upload-API, und versuchen Sie es dann erneut.

**Kann ich 24 Draft-Skizzen mit Turbo-Geschwindigkeit erhalten?**
Nein. `speed` ist ein einzelner Wert; Draft läuft immer mit dem Fast-Multiplikator.

**Ist `--q 4` langsamer oder teurer?**
Es wird nicht anders abgerechnet. Die Renderzeit kann etwas länger sein; der visuelle Gewinn hängt vom Prompt ab.

**Kann ich ein V8.2-Bild hochskalieren?**
Auf V8.2 gibt es keinen Upscale-Endpunkt. Generieren Sie stattdessen mit `quality: "hd"` für eine native 2K-Ausgabe.

## Hinweis zur Inhaltsmoderation

<Note>
Midjourney verfügt über ein integriertes Moderationssystem. Wenn einige generierte Bilder durch die Moderation gefiltert werden, können die für diese Anfrage verbrauchten Credits nicht erstattet werden. Bitte achten Sie darauf, dass Ihre Prompts den Inhaltsrichtlinien entsprechen.
</Note>
