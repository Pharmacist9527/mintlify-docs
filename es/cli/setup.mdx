## Instalación, inicio de sesión y verificación de la CLI

La CLI es compatible con macOS, Windows y Linux con **Node.js 22+**. Instálala en el equipo y en el entorno de usuario donde tu agente ejecuta los comandos. Si trabajas directamente en la terminal, puedes seguir los pasos manuales.

### Pide a tu agente que instale EvoLink

Pega este prompt completo en el **cuadro de chat** del agente. Coincide con el prompt del sitio web. Completa tú mismo el inicio de sesión en el navegador y la aprobación de permisos.

```text
Configura EvoLink para que pueda generar imágenes, vídeos y audio directamente aquí.
1. Instala la CLI: ejecuta `npm install -g @evolinkai/cli`.
2. Inicia sesión: ejecuta `evolink auth login`.
3. Instala la habilidad complementaria: ejecuta `evolink skills install`.
4. Verifica la conexión y, cuando funcione, dime que puedo empezar.
```

Si el agente no puede ejecutar comandos de terminal, sigue los pasos manuales de abajo. Ejecuta los bloques `bash` en una **terminal**, un paso cada vez. No hace falta que completes los dos métodos de instalación.

### Instalación manual: cinco pasos

<Steps>

<Step title="Comprueba Node.js y el entorno de ejecución">

Abre una terminal en el equipo y con el usuario que ejecuta el agente. Usa Terminal en macOS, PowerShell o el Símbolo del sistema en Windows, o la terminal integrada de Cursor.

```bash
node --version
npm --version
```

**Éxito**: ambos comandos muestran una versión, y la de Node.js es la 22 o posterior. Si falta o está desactualizado, instala una versión adecuada desde [Node.js](https://nodejs.org/en/download), vuelve a abrir la terminal y comprueba de nuevo. WSL, los servidores SSH, los contenedores y tu equipo de escritorio son entornos distintos; instala donde el agente ejecuta los comandos.

</Step>

<Step title="Instala y comprueba la CLI">

```bash
npm install -g @evolinkai/cli
evolink --version
```

**Éxito**: la instalación termina sin errores y `evolink --version` muestra una versión de la CLI. `-g` instala un comando en el directorio global del Node/npm actual. No requiere clonar ningún repositorio de MCP ni de plugins. Resuelve los [problemas de instalación](/es/cli/billing#cli-install) antes de continuar.

</Step>

<Step title="Inicia sesión en EvoLink">

```bash
evolink auth login
```

1. Mantén el comando en ejecución. El comando abre un navegador o muestra el enlace de inicio de sesión de este intento.
2. Inicia sesión en EvoLink, revisa la cuenta, el cliente y los permisos solicitados, y autoriza.
3. Vuelve a la terminal original, espera a que termine y después ejecuta:

```bash
evolink auth status --json
```

**Éxito**: `authenticated: true`. La CLI usa el almacén seguro de credenciales del sistema operativo; no necesitas crear ni pegar ninguna clave API. El callback del navegador por sí solo no completa el inicio de sesión en la terminal. La conexión con el saldo se comprueba en el último paso. Consulta la [solución de problemas de inicio de sesión](/es/cli/billing#login) para los errores del navegador, de tiempo de espera y del almacenamiento en Linux.

</Step>

<Step title="Instala la habilidad y confirma que el agente la detecta">

```bash
evolink skills install
evolink skills status --json
```

Sin `--agent`, la instalación se dirige a todos los directorios de habilidades admitidos; no instala esos agentes. Usa uno de los valores de agente que se indican más abajo para elegir un solo host.

**Éxito**: `current: true`. En el chat del agente, envía:

```text
Confirma que esta sesión puede detectar y leer la habilidad evolink-cli. Verifica primero la conexión; no generes contenido multimedia.
```

La habilidad guía la búsqueda de modelos, los parámetros, las estimaciones y la aprobación, las referencias, las tareas y la descarga de originales. No registra el MCP nativo ni inicia sesión por ti. `assistant_discovery: not_checked` requiere la confirmación del host. Si hace falta, vuelve a cargar las habilidades o abre una conversación nueva. Consulta [Detección de habilidades](/es/cli/billing#skills-discovery).

</Step>

<Step title="Verifica gratis y confirma que todo está listo">

```bash
evolink balance --json
evolink doctor --json
```

**Éxito**: balance devuelve los datos de la cuenta; doctor indica `ok`, `connection_verified` y `model_discovery_verified` con valor `true`; el agente confirma que ha leído la habilidad. Un saldo de cero también demuestra la conexión, pero para generar hace falta saldo suficiente.

Estos pasos no crean tareas multimedia de pago. Cuando terminen, el asistente puede decirte que ya puedes empezar. Corrige cualquier comprobación `failed` antes de seguir; no generes una imagen como prueba de conexión.

</Step>

</Steps>

### Instala la habilidad para un solo agente

El comando `evolink skills install` del sitio web se dirige a todos los directorios admitidos. Para un solo host, sustituye `AGENT_NAME` en los comandos de abajo por un valor de esta tabla:

| Cliente | AGENT_NAME | Directorio de la habilidad |
|---|---|---|
| Codex CLI | `codex` | `~/.agents/skills/evolink-cli` |
| Claude Code | `claude-code` | `~/.claude/skills/evolink-cli` |
| Cursor | `cursor` | `~/.agents/skills/evolink-cli` |
| OpenClaw | `openclaw` | `~/.openclaw/skills/evolink-cli` |
| Hermes | `hermes` | `~/.hermes/skills/evolink-cli` |
| Gemini CLI | `gemini` | `~/.agents/skills/evolink-cli` |
| OpenCode | `opencode` | `~/.agents/skills/evolink-cli` |
| GitHub Copilot CLI | `copilot` | `~/.agents/skills/evolink-cli` |

```text
evolink skills install --agent AGENT_NAME
evolink doctor --agent AGENT_NAME --json
```

Por ejemplo, Gemini usa:

```bash
evolink skills install --agent gemini
evolink doctor --agent gemini --json
```

Estos son destinos de instalación de la CLI, no una garantía de que todas las versiones de cada host detecten el directorio automáticamente. El host debe permitir los comandos y cargar las habilidades; consulta la [solución de problemas de habilidades y permisos](/es/cli/billing#skills-discovery). Los asistentes que no aparecen en la lista pueden leer los [recursos legibles para agentes](/es/cli/skills); no inventes valores de agente.

### Actualiza la CLI y la habilidad

```bash
npm install -g @evolinkai/cli@latest
evolink --version
evolink skills install
evolink skills status --json
```

Comprueba `current: true` y pide al agente que vuelva a leer la habilidad. Los cambios locales se conservan. Usa `--replace-modified` solo cuando hayas decidido sustituirlos; el contenido anterior se guarda como copia de seguridad en `~/.evolink-media/skill-backups/`. No uses los antiguos `@evolinkai/media-cli` / `evolink-media` para instalaciones nuevas.

<span id="update-check" />
### Cómo saber si hay una versión nueva

A partir de la CLI 0.10.0, la propia CLI comprueba en npm cuál es la versión más reciente:

- `evolink setup`, `doctor` y `auth login` lo comprueban siempre e informan en `update` con `update_available`, `latest_version` y el comando de actualización. Una actualización disponible es solo un aviso; nunca hace que el comando falle.
- Los demás comandos, salvo `auth status`, que funciona sin conexión, lo comprueban en línea como máximo una vez al día. Cuando hay una versión más reciente, imprimen una línea en stderr después de su propia salida, como máximo una vez al día para la misma versión. El stdout de `--json` y el código de salida no cambian.
- Cada comprobación envía una sola solicitud, sin información de la cuenta, al registro público de npm (registry.npmjs.org), espera como máximo 3 segundos y no muestra nada si no se puede acceder al registro.
- Para desactivar las comprobaciones, define `EVOLINK_CLI_UPDATE_CHECK=0`. También se desactivan cuando `NO_UPDATE_NOTIFIER` tiene cualquier valor, o en CI.

El aviso es una sola línea:

```text
EvoLink CLI 0.10.1 is available (installed 0.10.0). Update with npm install -g @evolinkai/cli@latest, then run evolink skills install.
```

Cuando lo veas, actualiza con los comandos de arriba y sincroniza la habilidad. Las versiones anteriores a la 0.10.0 no avisan: compara `evolink --version` con `npm view @evolinkai/cli version`, o abre [GitHub Releases de la CLI](https://github.com/deeplearning-goethe/evolink-cli/releases) y elige Watch → Custom → Releases para suscribirte.

Si, al autorizar en el navegador, terminas en una página bilingüe de 127.0.0.1 en lugar de volver al sitio web, la CLI instalada es anterior a la 0.9.1; actualízala antes de continuar.

### Consulta el inicio de sesión o cierra sesión

Comprueba la sesión actual:

```bash
evolink auth status --json
```

Ejecuta esto por separado solo cuando quieras cerrar sesión:

```bash
evolink auth logout
```

Esto revoca la sesión actual de la CLI. La autorización del MCP nativo se gestiona en su propio host. Guarda los identificadores de las tareas existentes antes de cambiar de cuenta; las cotizaciones antiguas no se pueden enviar con una cuenta nueva.

### Linux y SSH: el navegador está en otro equipo

El inicio de sesión persistente en Linux necesita **D-Bus y un Secret Service desbloqueado** en la sesión del usuario actual. Compruébalo primero. Sin ello, lo esperable es `credential_store_unavailable`; el acceso root no lo sustituye. Configura el almacenamiento seguro o ejecuta la CLI en local, en un entorno que lo proporcione.

<Steps>

<Step title="Empieza el inicio de sesión en el equipo remoto">

```bash
evolink auth login --no-browser --timeout 600
```

Mantén este comando en ejecución y usa el enlace de autorización actual. `--no-browser` evita que se abra el navegador, pero sigue esperando un callback; **no es un inicio de sesión con código de dispositivo**. El rango es de 30–900 segundos, y el valor predeterminado es 180.

</Step>

<Step title="Reenvía el puerto del callback desde una terminal local">

Busca el puerto real en el `redirect_uri` de este intento. Sustituye los dos valores `CALLBACK_PORT`, además de `USER` y `HOST`. Para `http://127.0.0.1:54321/callback`, usa `54321` en las dos posiciones. No publiques el enlace de autorización completo.

```bash
ssh -N -L CALLBACK_PORT:127.0.0.1:CALLBACK_PORT USER@HOST
```

Mantén abierta la terminal del reenvío; es normal que se quede inactiva y sin mostrar el indicador de comandos. Si hay un conflicto de puertos, resuélvelo sin modificar el puerto del enlace de autorización.

</Step>

<Step title="Abre este enlace y verifica en el equipo remoto">

Abre el enlace del primer paso en tu navegador local, inicia sesión y autoriza, y espera a que termine el comando remoto. En ese mismo entorno de usuario remoto, ejecuta:

```bash
evolink auth status --json
evolink balance --json
```

Cuando haya funcionado, detén esta sesión de reenvío. Si se agota el tiempo de espera, empieza un nuevo inicio de sesión y reenvía su puerto real; el enlace antiguo no se puede reutilizar. Los callbacks del MCP nativo corresponden al host y no usan las opciones de EvoLink CLI.

</Step>

</Steps>

## Después de la instalación

Sigue el [flujo de trabajo de la primera generación](/es/cli/workflows#workflows): describe la tarea, pide al agente que compruebe los modelos disponibles, los parámetros y el costo, y confirma antes de enviar. Consulta la [referencia de comandos de la CLI](/es/cli/reference#cli-reference) y la [solución de problemas centralizada](/es/cli/billing#faq) para la instalación, el inicio de sesión, los permisos y las descargas.

Para el MCP remoto nativo o el stdio local, usa la [guía de otros clientes MCP](/es/mcp/other-clients). Las opciones de inicio de sesión de la CLI no configuran una conexión MCP.
