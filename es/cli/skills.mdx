## Instala y gestiona la habilidad de la CLI

Esta página trata los destinos de evolink-cli, sus directorios, la detección en el host y las actualizaciones. Consulta los [recursos comunes](/es/cli-mcp/agent-resources) para conocer el alcance, los conceptos de CLI, MCP y plugins, y las reglas comunes.

## Instala y verifica la detección

```bash
evolink skills install
evolink skills status --json
```

La instalación predeterminada abarca los directorios de destino admitidos sin instalar los agentes. Para elegir un solo host:

```bash
evolink skills install --agent codex
evolink skills status --agent codex --json
evolink doctor --agent codex --json
```

Comprueba current:true y envía esto en el chat del agente:

```text
Confirma que esta sesión puede detectar y leer evolink-cli. Consulta primero el saldo y los modelos; no generes contenido multimedia.
```

assistant_discovery:not_checked significa que la CLI no puede verificar la detección en nombre del host. Si los archivos existen pero no se usan, vuelve a cargar las habilidades o abre una sesión nueva y comprueba los permisos de comandos. Leer un documento, por sí solo, no demuestra el acceso a la cuenta.

## Destinos y directorios admitidos

| --agent | Cliente | Directorio |
|---|---|---|
| codex | Codex | ~/.agents/skills/evolink-cli |
| claude-code | Claude Code | ~/.claude/skills/evolink-cli |
| cursor | Cursor | ~/.agents/skills/evolink-cli |
| openclaw | OpenClaw | ~/.openclaw/skills/evolink-cli |
| hermes | Hermes | ~/.hermes/skills/evolink-cli |
| gemini | Gemini CLI | ~/.agents/skills/evolink-cli |
| opencode | OpenCode | ~/.agents/skills/evolink-cli |
| copilot | GitHub Copilot CLI | ~/.agents/skills/evolink-cli |

Gemini, OpenCode y Copilot pueden seguir la [instalación general en cinco pasos](/es/cli/setup#cli-install) con su propio valor de agente. Instala en el entorno real de SSH, WSL, contenedor o Gateway. Estos son destinos de instalación, no garantías de detección en todas las versiones de cada host. Las políticas del host y la carga de habilidades siguen siendo responsabilidad del host.

## Actualizaciones y cambios personales

```bash
npm install -g @evolinkai/cli@latest
evolink skills install
evolink skills status --json
```

Después de actualizar la CLI, sincroniza las habilidades y pide al agente que vuelva a leerlas. Los cambios personales se conservan de forma predeterminada. Revisa primero los estados modified/conflict. Usa --replace-modified solo cuando hayas decidido sustituir el contenido personal; el contenido anterior se guarda como copia de seguridad en ~/.evolink-media/skill-backups/. Consulta la [solución de problemas de habilidades](/es/cli/billing#skills-discovery).

A partir de la CLI 0.10.0, `evolink doctor` sin `--agent` también revisa las copias de la habilidad instaladas para cada agente. Cuando una copia es más antigua que la CLI, `guidance` te pide que ejecutes `evolink skills install`; los cambios personales y los conflictos se notifican, nunca se sustituyen. Estos resultados no cambian `ok`. Para saber cómo avisa la CLI de las versiones nuevas, consulta [Cómo saber si hay una versión nueva](/es/cli/setup#update-check).
