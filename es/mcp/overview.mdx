Usa el [resumen de CLI/MCP](/es/cli-mcp/overview) para elegir según tu cliente. Los recursos comunes de esta sección tratan los costos, las tareas, los archivos y las instrucciones para agentes.

EvoLink MCP ofrece la búsqueda de modelos, las estimaciones, la generación multimedia, las referencias, las tareas y el saldo como herramientas nativas del agente. Esta sección trata MCP; los comandos de terminal y evolink-cli están en la [sección aparte de la CLI](/es/cli/overview).

Esta guía describe la versión publicada **MCP 1.12.1**. El MCP remoto tiene 16 herramientas con OAuth en el navegador; el stdio local tiene 14 herramientas con una clave API personal. Consulta los modelos y las entradas actuales de la cuenta antes de ejecutar.

## Inicio rápido: MCP remoto

<Steps>
<Step title="Añade el servidor">
Añade un MCP o conector personalizado llamado EvoLink con la URL https://mcp.evolink.ai/mcp. Sigue la guía de tu cliente, más arriba; no hace falta ningún paquete MCP local.
</Step>
<Step title="Inicia sesión y autoriza en el navegador">
Selecciona OAuth, inicia sesión en EvoLink, revisa la cuenta y los permisos, autoriza y vuelve. Activa la conexión y las herramientas. El inicio de sesión de la CLI no sustituye a la autorización de MCP en el host.
</Step>
<Step title="Verifica gratis las herramientas reales">
Envía esto y confirma que recibes resultados reales de saldo y de modelos:

```text
Usa EvoLink para consultar mi saldo y buscar los modelos de imagen disponibles. No generes nada todavía.
```

Las llamadas correctas a check_balance y search_models demuestran el acceso; una lista de herramientas por sí sola, no. Esta comprobación no crea ninguna tarea multimedia de pago.
</Step>
</Steps>

Para los clientes que solo admiten stdio, sigue la [configuración del MCP local](/es/mcp/other-clients#local-mcp). Configura por separado su inicio y su autenticación.

## Tu primera generación

Una vez conectado, describe tu objetivo:

<Tabs>
  <Tab title="Imagen">
```text
Usa EvoLink para crear un anuncio de una marca de café con luz cálida, una taza de cerámica color crema y espacio en la parte superior para el texto de la marca.
Compara los modelos adecuados y muestra las especificaciones de salida, la estimación y las limitaciones. Espera mi aprobación.
Devuelve el enlace de la imagen original y el cargo final informado. No regeneres ni modifiques el resultado automáticamente.
```
  </Tab>
  <Tab title="Video">
```text
Usa EvoLink para crear un video corto de un atardecer en el mar. Muestra primero los modelos adecuados, la duración admitida, la calidad, las opciones de audio y la estimación.
Tras mi aprobación, envía una sola vez, guarda el identificador de la tarea y consúltala hasta que se complete. Devuelve el enlace del video original y el cargo informado.
```
  </Tab>
  <Tab title="Audio">
```text
Usa EvoLink para generar una voz de bienvenida en chino que diga “欢迎来到我们的咖啡店”.
Elige un modelo de voz, comprueba los requisitos de voz y de entrada, explica la facturación y espera mi aprobación antes de generar y devolver el audio original.
```
  </Tab>
</Tabs>

La generación consume créditos de EvoLink. Estos prompts piden al asistente que espere la aprobación. La autorización de la cuenta, el permiso de herramientas del host y la aprobación del costo de la tarea son cosas distintas. El MCP nativo no ofrece en el servidor un botón de aprobación para la conversación; el agente debe obtener la aprobación explícita para esta tarea. Lee [Facturación y autorización](/es/mcp/billing).

<span id="workflows" />

## Cómo funciona

El MCP remoto sigue `tu asistente → EvoLink MCP → API de la plataforma`. El host gestiona el inicio de sesión OAuth; el servicio remoto ejecuta las herramientas. Los clientes de chat en el navegador no necesitan Node.js ni EvoLink CLI.

El stdio local sigue `tu asistente → proceso MCP local → API de la plataforma`. Instala Node.js 20+ en el equipo que ejecuta el asistente, deja que el host inicie el proceso y proporciona una clave API de la plataforma. Consulta [Otros clientes MCP](/es/mcp/other-clients#local-mcp) para la configuración.

Los dos modos ofrecen las herramientas principales de modelos, estimación, generación y tareas. El MCP remoto ofrece además `prepare_upload` y `get_upload`. Las habilidades y los plugins opcionales aportan instrucciones de uso; no sustituyen al registro del servidor, a la autorización de la cuenta ni a los permisos de herramientas del host.

| Objetivo | Herramientas |
|---|---|
| Consultar el saldo y el acceso a la cuenta | `check_balance` |
| Buscar modelos, parámetros y documentación | `search_models`, `get_model`, `search_docs` |
| Comparar modelos candidatos para una tarea | `recommend_models` |
| Estimar el costo | `estimate_cost` |
| Generar imágenes, video o audio | `generate_image`, `generate_video`, `generate_audio` |
| Consultar, esperar y listar tareas | `get_task`, `list_tasks` |
| Revisar el uso de la cuenta | `get_task_usage` |
| Subir referencias | `upload_file`; el MCP remoto tiene además `prepare_upload`, `get_upload` |

Estas herramientas no ofrecen desarrollo de código, edición local de video ni creación de sitios web. El host de un agente puede tener esas capacidades por su cuenta; atribúyeselas al host cuando describas EvoLink.

<span id="models" />

## Paso 1: elige un modelo y valida sus entradas

Usa `search_models` o `recommend_models` para ver los candidatos actuales y después `get_model` para conocer los IDs exactos, las capacidades admitidas, los campos obligatorios y los límites. Usa `search_docs` para obtener más orientación. El nombre de una familia no es necesariamente un ID válido para enviar.

Consulta [Modelos, costos y cuotas](/es/cli-mcp/models-and-billing#models) para conocer el orden de elección, las familias más recientes que conviene comparar y las reglas de precios. Comprueba el catálogo y las entradas actuales de la cuenta; los modelos de ejemplo no son recomendaciones predeterminadas.

El siguiente ejemplo usa `z-image-turbo`. Comprueba los parámetros antes de usar cualquier modelo:

```json
{"name":"get_model","arguments":{"model":"z-image-turbo"}}
```

<span id="files" />

## Paso 2: prepara las referencias

Con entradas de solo texto, omite las subidas. Para imágenes, video o audio de referencia, comprueba primero los tipos admitidos, las cantidades y los límites de tamaño.

1. **URL accesible**: llama a `upload_file` con `file_url`. El servidor debe poder acceder a la URL; una ruta en la computadora del usuario no es una URL pública.
2. **Archivo pequeño incrustado**: `upload_file` en remoto acepta hasta 1 MiB de contenido en base64 y necesita un tipo MIME que coincida. No pongas archivos grandes en los mensajes de las herramientas.
3. **Archivo local para el MCP remoto**: llama a `prepare_upload`, sube el archivo desde un entorno con acceso a archivos y capacidad HTTP, y revisa el comprobante con `get_upload`. El límite de subida es de 95 MiB, sujeto a las restricciones del modelo. La autorización de subida es de un solo uso y caduca al cabo de unos 15 minutos; las URLs de estado duran aproximadamente una hora.
4. **stdio local**: `upload_file` admite un `file_path` local. Es una ruta absoluta en el equipo donde se ejecuta el proceso MCP, no automáticamente una ruta de la computadora del usuario del chat. Se siguen aplicando los límites del servicio de archivos y del modelo.

```json
{"name":"prepare_upload","arguments":{"file_name":"reference.png"}}
```

```json
{"name":"get_upload","arguments":{"upload_id":"UPLOAD_ID"}}
```

Un archivo adjunto del chat no se convierte automáticamente en una URL que el modelo pueda usar. Si el host no puede leer ni subir archivos, pide una URL accesible. Conserva el `upload_id` original cuando el resultado sea desconocido; no vuelvas a subir de inmediato. La compatibilidad con los comprobantes depende del despliegue del servicio de archivos. Las referencias suelen conservarse 72 horas; vuelve a subir las entradas caducadas y actualiza la solicitud.

<span id="images" />

## Paso 3: estima, aprueba y genera una imagen

Prepara las entradas finales antes de estimar. Muestra el modelo, la cantidad de imágenes, el tamaño, el contenido y el costo estimado. Una estimación no garantiza la liquidación final. Consulta [costos](/es/mcp/billing#pricing) para conocer la cobertura y las limitaciones de los precios en la versión publicada.

```json
{"name":"estimate_cost","arguments":{"model":"z-image-turbo","input":{"prompt":"A minimalist coffee advertisement with a ceramic cup"}}}
```

Llama a la generación solo después de la aprobación explícita de este plan y de su costo estimado. `client_request_id` es un identificador de solicitud estable de 16–96 caracteres; los reintentos de un mismo envío deben mantener su identificador y sus entradas. El presupuesto de abajo solo ilustra el parámetro; defínelo a partir del presupuesto explícito del usuario:

```json
{"name":"generate_image","arguments":{"model":"z-image-turbo","input":{"prompt":"A minimalist coffee advertisement with a ceramic cup"},"client_request_id":"coffee-image-demo-001","max_cost_usd":1}}
```

`max_cost_usd` es una comprobación previa al envío, no un tope garantizado del cargo final. `estimate_cost` no lo acepta. El permiso del host para llamar a una herramienta no aprueba la compra por sí solo.

Si le dices al asistente que no hace falta estimar ni confirmar (por ejemplo, "genera directamente"), este pasa `skip_estimate: true` y envía sin preguntar, dentro del alcance que hayas indicado; consulta [Generar sin estimación](/es/mcp/tools#skip-estimate). Para varias imágenes o tareas de un mismo modelo, pasa `inputs` (hasta 50) a `estimate_cost` y a la herramienta de generación: una estimación, una aprobación y una sola llamada que devuelve todos los task_id a la vez. Consulta [Lotes](/es/mcp/tools#batches).

<span id="video" />

## Video: comprueba la duración, la resolución, el sonido y las referencias

Usa `get_model` para encontrar el ID exacto del modelo de texto a video o de imagen a video. La duración, la resolución, las opciones de sonido y el video de referencia pueden afectar al precio; no reutilices una estimación hecha con otras entradas. Las tareas de una misma familia pueden usar IDs distintos.

Valida los parámetros → sube las referencias → llama a `estimate_cost` con las entradas finales → muestra el plan y obtén la aprobación explícita → llama a `generate_video` con esas mismas entradas → consulta la tarea original → entrega el video original.

Cuando haga falta `media_seconds`, usa la duración medida de la entrada. Detente cuando no se conozcan las mediciones necesarias, el precio esté incompleto o no se pueda completar la comparación con el presupuesto. No intentes arreglar una miniatura gris editando o regenerando automáticamente el video terminado.

<span id="audio" />

## Audio: distingue la música de la voz

Para música, compara los modelos Suno v6 disponibles; para narración o locución, usa un modelo de voz adecuado. Comprueba los parámetros del modelo, prepara el texto, el idioma, la voz, la letra, la duración o el audio de referencia, y después estima las entradas finales, obtén la aprobación y llama a `generate_audio`.

Que el precio del audio esté incompleto no significa que el uso sea gratis. Entrega las URLs del audio original de la tarea completada, conserva todos los resultados devueltos y explica su formato real y cómo guardarlos.

<span id="tasks" />

## Paso 4: espera, consulta y recupera la tarea original

La generación puede devolver un resultado o un `task_id`. Consulta esa tarea en lugar de volver a enviar la generación. `get_task.wait_seconds` espera dentro de una misma llamada y acepta 0–45 segundos. Cuando se agota el tiempo de espera, solo termina esa espera.

```json
{"name":"get_task","arguments":{"task_id":"TASK_ID","wait_seconds":30}}
```

Usa `list_tasks` con `task_ids` para las consultas en lote, o usa sus filtros para el historial. Si el envío agota el tiempo de espera antes de devolver un identificador, conserva el identificador de solicitud original, las entradas, las credenciales y el error para la recuperación. No cambies de identidad ni de identificador para volver a generar como forma de diagnosticar el problema.

Actualmente no existe ninguna herramienta pública utilizable para cancelar tareas en cola. Detener la espera de un agente, cerrar una página o desconectar MCP no cancela la tarea en el servidor, ni demuestra que no haya habido cargo o que se haya completado un reembolso.

<span id="delivery" />

## Paso 5: entrega los resultados originales

Cuando la tarea se complete, devuelve las URLs originales accesibles junto con el modelo, la cantidad de resultados, la información de costo conocida y la caducidad. Los originales generados suelen conservarse 24 horas; guárdalos cuanto antes. El host también puede mostrar vistas previas. Si el resultado solo muestra un enlace o una miniatura gris, verifica primero la URL original.

Comprueba el estado HTTP, el tipo de contenido y el formato real del archivo antes de guardar. Una página de error no es contenido multimedia. Un código de descarga en Python que controles puede definir un User-Agent de producto cuando su solicitud predeterminada se bloquea; consulta la [solución de problemas de descarga](/es/mcp/billing#download).

No intentes arreglar los problemas de entrega o de vista previa con una regeneración no aprobada. Si el usuario pide aparte una edición, usa las capacidades correspondientes del host y obtén la aprobación de costos que haga falta.

Consulta la [referencia de herramientas de MCP](/es/mcp/tools) para los argumentos y los resultados, y [Habilidades y recursos legibles](/es/cli-mcp/agent-resources) para las instrucciones completas para agentes.
