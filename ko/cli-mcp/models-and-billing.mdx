이 페이지는 CLI와 MCP가 공유하는 비즈니스 규칙을 정리합니다. 정확한 입력은 [CLI 레퍼런스](/ko/cli/reference)와 [MCP 레퍼런스](/ko/mcp/tools)를 참고하세요. 정식 출시된 CLI 0.14.1과 MCP 1.12.1을 기준으로 합니다. 검색 요금은 실제로 반환된 `search_charges`를 확인하세요.

<span id="models" />
## 모델 선택

1. 작업 유형을 정하세요: 이미지 생성/편집, 텍스트/이미지-영상 생성, 음악 또는 음성. 수량, 품질, 길이, 참조 파일, 예산을 명시하세요.
2. 계정에서 사용할 수 있는 모델 목록을 조회하고, 목록에 나온 정확한 모델 ID를 사용하며, 스키마를 확인하세요. 계열 이름, 별칭, 표시 이름이 곧바로 제출용 ID가 되는 것은 아닙니다.
3. 적합한 최신 계열이나 권장 계열을 비교한 뒤 품질, 참조 파일 지원, 비용, 예상 대기 시간을 설명하세요. 플랫폼 통계 없이 인기도를 측정한 것처럼 말하지 마세요.
4. 최종 요청의 예상 비용을 산정하기 전에 필수 항목, 범위, 상호 배타적인 입력을 확인하세요. 모델이나 입력을 바꾼 뒤에는 다시 확인하세요.

비교해 볼 만한 계열로는 이미지용 GPT Image 2.5/2.0과 Seedream 5.0, 영상용 Seedance 2.5/2.0과 Wan 3.0, 음악용 Suno v6이 있습니다. 이는 검색 방향일 뿐, 계정에서 사용할 수 있다는 보장은 아닙니다. 내레이션에는 음성 모델을 선택하세요. 예시 모델은 작업 흐름을 보여 주기 위한 것이며 기본 권장 모델이 아닙니다.

| 정보 | CLI | MCP |
|---|---|---|
| 사용 가능한 모델 | `models search`, `models recommend` | `search_models`, `recommend_models` |
| 매개변수와 제한 | `models show`, `models schema` | `get_model` |
| 모델 문서 | `docs search` | `search_docs` |
| 최종 입력의 예상 비용 | `estimate` | `estimate_cost` |

## 예상 비용 읽는 법

| 상태 | 의미 | 조치 |
|---|---|---|
| `estimated` | 예상 금액입니다. 실제 청구는 정산 결과를 따릅니다 | 계획, 금액, 알려진 제한 사항을 제시한 뒤 승인을 받으세요 |
| `partial` | 가격 산정 요소 일부가 빠져 있습니다 | 완전한 합계로 취급하지 마세요. 빠진 요소를 찾아 해결하세요 |
| `token_billed` | GPT Image, Gemini Omni Flash, Qwen TTS 토큰 과금 모델의 참고 가격으로, 제출 시 EvoLink가 선차감하는 금액입니다. 과금은 실제 토큰 수를 기준으로 합니다 | 확정 합계가 아니라 참고 가격으로 보여 주세요. 작업은 실제 토큰 수로 정산되며 차액은 환불되거나 추가로 청구됩니다 |
| `needs_input` | 필수 입력 또는 과금 사용량이 빠져 있습니다 | `missing_usage`와 `usage_help`를 읽고 거기에 명시된 값을 제공한 뒤 예상 비용을 다시 산정하세요 |
| `no_price` | 사용할 수 있는 가격이 없습니다 | 무료라고 설명하거나 자동으로 제출하지 마세요 |

GPT Image 토큰 과금 모델(`gpt-image-1.5`, `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`, `gpt-image-2.6-flare`, `gpt-image-2.6-sunburst`)은 `token_billed`와 함께 참고 가격을 반환합니다. 참고 가격은 해당 입력에 대해 EvoLink가 제출 시 선차감하는 크레딧입니다. 크기와 품질에 따른 출력 토큰, 프롬프트 토큰, 참조 이미지 또는 마스크마다 1,536 토큰을 합산한 뒤 `n`을 곱해 계산합니다. `size`가 `auto`이면 2048×2048 출력으로 계산하므로, 크기를 지정하면 참고 가격이 실제에 더 가까워집니다. `gpt-image-2.6` GIF는 모든 프레임이 그려지는 이미지 한 장을 기준으로 계산합니다(`size`가 `auto`이면 512×512 프레임). 작업은 실제로 사용한 토큰 수로 정산되므로 최종 청구액은 더 낮거나 약간 더 높을 수 있습니다. 이 모델들에는 `pricing_parameters`의 토큰 수를 사용하지 않습니다. `max_cost_usd`를 명시하는 경우 그 값이 참고 가격의 1.5배 이상이어야 합니다.

Gemini Omni Flash 영상 모델(`gemini-omni-flash-*`, `gemini-omni-1.1-flash-*`, `gemini-omni-1.2-flash-*`)도 `token_billed`와 함께 참고 가격을 반환하며, EvoLink가 제출 시 선차감하는 방식 그대로 계산합니다. 즉 출력 해상도와 길이에 따른 영상 출력 토큰, 프롬프트 토큰, 입력 이미지마다 2,020 토큰, 그리고 입력 영상이나 참조 영상의 토큰을 합산합니다. 입력 영상이나 참조 영상이 있으면 그 길이를 `media_seconds`(MCP) 또는 `--media-seconds`(CLI)로 알려 주세요. 참조 영상이 여러 개라면 가장 긴 영상의 길이를 입력하세요. 이 값이 없으면 참고 가격이 나오지 않으며, 예상 비용 결과가 이 값을 요구합니다. 요청에는 영상의 해상도가 담기지 않고 EvoLink가 제출 시점에 읽어 들이므로, 참고 가격은 영상을 4k로 계산하며 예상 비용 결과에는 입력 해상도별 가격(360p, 720p, 1080p, 4k)도 함께 나옵니다(`reference_usage.input_resolution_prices`). 이 가격들을 사용자에게 보여 주세요. 이 모델들에도 `pricing_parameters`의 토큰 수를 사용하지 않으며, `max_cost_usd`는 참고 가격의 1.5배와 비교합니다. 작업은 실제로 사용한 토큰 수로 정산됩니다.

`qwen-audio-3.1-tts-flash`도 `token_billed`와 함께 참고 가격을 반환하며, EvoLink가 제출 시 선차감하는 방식 그대로 텍스트를 기준으로 계산합니다. `pricing_parameters`의 토큰 수는 사용하지 않고, `max_cost_usd`는 참고 가격의 1.5배와 비교하며, 작업은 실제로 사용한 토큰 수로 정산됩니다. `hot_fix: null`은 `hot_fix`가 없는 것으로 처리합니다.

사용량을 0으로 입력해 생성 가격이 0이 되는 경우에는 사용량이 빠진 것으로 봅니다. 무료인 미디어 생성은 없습니다.

<span id="missing-usage" />

모델 가격이 참조 영상의 길이처럼 입력에 없는 사용량에 따라 달라지는 경우, 예상 비용 결과는 금액도 승인 정보도 반환하지 않습니다. `total_known`은 `false`이고, `missing_usage`에는 빠진 값이 하나씩 나열되며, `usage_help`는 그 값을 제공하는 방법을 알려 줍니다. MCP에서는 `media_seconds` 또는 `pricing_parameters`를, CLI에서는 `--media-seconds` 또는 `--pricing-parameters`를 사용합니다. 생성 단계에서는 이런 요청을 제출하기 전에 거부합니다(`quote_usage_required`). `partial` 예상 비용은 가격이 산정된 부분을 유지하고, 합계가 그 밖에 무엇에 따라 달라지는지 알려 줍니다. `get_model`과 `models show`는 모델 가격 산정에 필요한 사용량을 `billing_usage`에 표시합니다. 측정한 값이나 명시적으로 예상한 값을 제공하고, 값을 지어내지 마세요.

예상 비용은 EvoLink가 과금 기준으로 삼는 설정을 읽어 산정합니다. Midjourney의 `speed`와 `type`은 `model_params`에서 가져옵니다. Seedream 5.0 Pro는 `size` 또는 `quality` 때문에 출력이 2K가 되면 2K 가격으로 산정합니다. MiniMax H3와 H3 Max의 참조-영상 생성은 무료 제공분을 넘는 참조 이미지를 계산에 포함합니다. Tencent 영상 업스케일은 `model_params.max_fps`가 `"30"`이 아니면 원본 프레임 레이트를 `pricing_parameters.output_fps`로 입력해야 합니다. Seedance 드래프트-영상 변환은 `pricing_parameters.content_filter`가 `true`가 아니면 드래프트가 콘텐츠 필터 없이 만들어졌다고 가정합니다.

`input_valid`, `problems`, `basis`, `warnings`를 확인하세요. 모델 목록에 표시된 시작 가격은 요청 전체에 대한 견적이 아닙니다. 해상도, 사운드, 참조 파일, 실제 입력 길이, 오디오 과금 방식이 비용에 영향을 줄 수 있습니다.

Seedance 2.5 생성에서 `quality`를 생략하고 `draft: true`를 지정하면 `480p`가 사용됩니다. 예상 비용 결과가 `effective_input`과 `defaults_applied`를 반환하면, 승인을 받기 전에 실제로 적용되는 이 설정을 보여 주세요. 생성에도 같은 설정이 사용됩니다. 드래프트-영상 변환에는 별도의 입력이 있습니다. 특정 모델에 대한 검사는 다른 모델 ID나 다른 동작에 그대로 적용되지 않습니다.

`seedance-2.5-video-edit`에서는 `input.duration: -1`이 편집을 선택합니다. 가격 산정에 쓸 예상 출력 길이(초)는 `pricing_parameters.duration_seconds`에 넣으세요. 이 값은 생성 설정을 대체하지 않으며 최종 사용량을 확정하지도 않습니다.

검색은 다음 일곱 가지 미디어 모델 경로에서 기본적으로 꺼져 있습니다: `doubao-seedream-5.0-lite`, `gemini-3-pro-image-preview`, `gemini-3.1-flash-image-preview`, `gemini-nano-banana-2.1`, `seedance-2.0-text-to-video`, `seedance-2.0-fast-text-to-video`, `seedance-2.5-text-to-video`. Seedream은 `model_params.tools: [{"type":"web_search"}]`로 검색을 켜고, 나머지는 `model_params.web_search: true`를 사용합니다. Gemini 3.1 Flash Image와 Nano Banana 2.1은 이와 별개로 `model_params.image_search: true`도 지원합니다.

사용자가 명시적으로 요청하거나 승인하지 않는 한 모델의 웹 검색과 이미지 검색은 꺼 두세요. 임의로 검색을 켜거나, 복사한 예시에 검색이 켜져 있다는 이유만으로 켜서는 안 됩니다. 에이전트가 검색이 필요하다고 판단하면 먼저 검색할 때마다 추가로 부과되는 단가를 알려 주고 합계는 알 수 없다는 점을 설명한 뒤, 명시적인 동의를 받고 나서 켜세요. 검색이 없는 작업에 대한 승인은 검색 추가까지 허용하는 것이 아닙니다. 검색 설정이 바뀌면 예상 비용을 새로 산정하고 다시 승인받아야 합니다. 이는 어시스턴트를 위한 지침이며, 서버는 대화에서 이루어진 동의를 검증하지 않습니다.

검색이 꺼져 있을 때는 검색 요금 경고를 덧붙이지 마세요. 최종 입력에서 검색이 켜져 있으면, 사용자가 요청한 경우라도 생성 승인을 받기 전에 켜진 검색 유형별 현재 단가를 알려 주세요. 검색 횟수가 빠져 있으면 검색이 한 번도 없다고 가정하고 검색 요금을 제외한, 확인된 비용만의 `partial` 소계가 나옵니다. 텍스트/사고 토큰처럼 알 수 없는 다른 사용량도 제외됩니다. 작업 하나가 검색을 전혀 하지 않을 수도, 여러 번 할 수도 있습니다. 실제 횟수는 작업과 모델의 전략에 따라 달라지므로 생성 전에는 총 검색 요금을 알 수 없습니다. 웹 검색과 이미지 검색은 따로 과금됩니다.

`pricing_parameters.search_count`와 `image_search_count`는 예상 사용량을 나타낼 뿐 실행 횟수를 제한하지 않습니다. 예상 횟수를 0으로 지정해도 검색이 꺼지지는 않습니다. 불완전한 예상 비용으로는 사용자가 명시한 예산을 검증할 수 없습니다. 알 수 없는 사용량을 없애려고 횟수를 지어내지 마세요. 구버전 클라이언트가 검색이 켜져 있고 예상 횟수가 없는 요청을 완전한 예상 비용으로 처리한다면, 그 견적을 승인하기 전에 클라이언트를 업데이트하세요.

정식 출시된 클라이언트는 주로 공개 기본 가격을 사용하며, 계정 할인 전체나 측정된 사용량, 계정 정산 기준의 견적(Quote)을 반영하지 않습니다. 새 엔드포인트나 코드 후보가 있다고 해서 프로덕션에 적용되었다는 뜻은 아닙니다. 가격 산정이나 예산 비교가 불완전하면 진행을 멈추세요. 참고 환산 비율은 $1당 약 68 크레딧입니다. 실제 응답과 계정 기록을 기준으로 하세요.

<span id="approval" />
## 승인과 예산

정확한 모델, 최종 입력, 출력 사양/수량, 예상 비용, 제한 사항을 보여 주세요. 이번 생성에 대한 명시적인 승인을 받으세요. 승인은 예상 비용을 산정한 시점부터 24시간 동안, 같은 입력에 대해 승인된 가격 이하일 때 유효합니다. 생성 단계에서는 제출하기 전에 예상 비용을 다시 산정하며, 가격이 그대로이거나 더 낮으면 진행합니다. 그사이 가격 규칙이 바뀐 경우에도 마찬가지입니다. 가격이 오른 경우(`price_changed`), 모델, 입력 또는 참조 파일이 바뀐 경우(`quote_input_changed`), 계정이 다른 경우, 승인이 만료된 경우(`quote_expired`)에는 예상 비용을 새로 산정하고 다시 승인받아야 합니다.

| 제약 | 현재 의미 |
|---|---|
| 계정 로그인 | 계정 서비스에 대한 접근 권한 |
| 호스트의 명령/도구 권한 | 에이전트가 해당 동작을 실행할 수 있는 권한 |
| 작업별 비용 승인 | 이번 계획과 예상 비용에 대한 수락 |
| 명시적인 `max_cost_usd` | 정식 출시된 클라이언트에서 제출 전에 예상 비용과 비교하는 값입니다(참고 가격에 대해서는 그 1.5배 이상이어야 합니다). **최종 청구액의 상한이 아닙니다** |
| 플랫폼 키 할당량 | 계정의 일일/총 한도와 접근 정책 |

이들은 서로 별개의 확인 절차입니다. 로그인과 호스트 권한은 요금 부과에 대한 승인이 아닙니다. 거부를 우회하려고 예산을 없애거나, 키를 바꾸거나, 경로를 전환하지 마세요. 최종 상한을 두려면 서버가 이를 지원해야 합니다. 현재 문서로는 정산 금액이 예상 비용 단계에서 정한 예산을 절대 넘지 않는다고 약속할 수 없습니다.

CLI는 로컬 `quote_id`를 저장하고 `--confirm`으로 제출합니다. 네이티브 MCP는 입력, 예상 비용, 명시적인 승인을 에이전트의 작업 흐름 안에서 관리하며, CLI 견적 파일이나 세션 단위의 서버 승인 버튼이 없습니다. [CLI 승인](/ko/cli/billing#pricing)과 [MCP 승인](/ko/mcp/billing#pricing)을 참고하세요.

<span id="skip-estimate" />
### 예상 비용 산정 없이 생성하기

사용자가 예상 비용 산정이나 확인을 하지 말라고 명시적으로 말하면(예: "바로 생성해 주세요") 에이전트는 견적 없이 제출합니다. MCP에서는 `skip_estimate: true`, CLI에서는 `--skip-estimate`를 사용합니다. 적용 범위는 사용자가 말한 그대로입니다. 이번 작업, 이번 배치, 또는 이 대화에서 이후에 하는 모든 생성일 수 있습니다. 에이전트는 사용자의 침묵, 잔액, 자신의 제안을 근거로 이를 추론해서는 안 됩니다. 사용자가 대화의 남은 부분 전체에 대해 생략하기로 하면, 에이전트는 이후 생성은 묻지 않고 제출된다는 점을 한 번 알립니다. 새 대화를 시작하거나 예상 비용 산정을 다시 해 달라고 요청하면 원래대로 돌아갑니다. 예상 비용 산정을 생략해도 유효하지 않은 입력과 명시된 예산은 그대로 검사하고, 검색은 여전히 승인이 필요하며, 작업 요금은 실제 사용량에 따라 부과됩니다. 예상 비용 산정이 실패했거나 합계가 없는데 사용자가 생략을 선택하지 않은 경우, 에이전트는 실제 사용량 기준 요금으로 그래도 생성할지 한 번 묻습니다.

<span id="batches" />
### 한 모델로 여러 작업 실행하기

예상 비용 산정 한 번으로 한 모델의 입력을 최대 50개까지 다룰 수 있습니다(MCP `inputs`, CLI `--inputs-file`). 입력별 가격, 합계, 그리고 정확히 그 배치에 대한 승인 하나를 반환합니다. 승인 후에는 호출 한 번으로 모든 입력을 한꺼번에 제출하고, 기다리지 않고 작업 ID를 반환합니다. 결과는 `list_tasks` 또는 `tasks batch`로 수집하세요. 일부 입력이 제출되지 않았다면 같은 요청 ID와 완전히 같은 입력으로 배치를 마무리하세요. MCP에서는 첫 제출 후 24시간 이내에 같은 `client_request_id`로 다시 호출합니다(승인이 만료되었다면 먼저 예상 비용을 다시 산정하세요). CLI에서는 첫 제출 후 23시간 이내에, 견적이 만료되지 않았고 가격이 오르지 않은 동안 `tasks resume --quote`를 실행합니다. 이미 접수된 입력은 새로 과금되지 않고 원래 작업을 반환합니다. 이 기간 안에는 접수된 입력, 제출되지 않은 입력, 결과를 알 수 없는 입력을 새 요청 ID로 다시 제출해서는 안 됩니다. 이 기간이 지난 뒤에는 어떤 작업이 존재하는지 확인하고(`list_tasks`, `tasks batch` 또는 `tasks list`), 접수되지 않은 입력만 새 예상 비용과 새 요청 ID를 사용해 새 배치로 제출하세요. GPT Image 같은 일부 모델은 `n`보다 적은 수의 이미지를 반환하는 경우가 많으므로, 이미지 한 장마다 입력을 하나씩 사용하세요.

<span id="authorization" />
## 권한, 잔액, 할당량

현재 같은 계정의 CLI와 원격 MCP OAuth는 내부 키의 권한, 할당량, 일시 중지 상태를 공유할 수 있습니다. 변경 사항은 이 키를 사용하는 쪽 모두에 영향을 주지만, CLI 세션과 호스트 세션은 서로 분리되어 있습니다. 로컬 stdio는 설정된 개인 API Key를 사용합니다.

모델, 잔액, 작업 조회는 미디어 생성을 제출하지 않습니다. 생성에는 요금이 부과되며, 업로드에는 파일 서비스의 별도 제한이 적용됩니다. 잔액 부족, 할당량, 접근 권한 문제는 해당 계정 설정에서 해결하세요. 다시 인증한다고 잔액이 충전되거나 키의 일시 중지가 해제되지는 않습니다.

실패한 작업(`status: failed`)에는 요금이 부과되지 않으며, 제출 시 선차감된 크레딧은 자동으로 반환됩니다. 시간 초과, 로그아웃, 페이지 닫기는 요금이 부과되지 않았다거나 환불되었다는 근거가 되지 않습니다. 환불이 들어왔다는 말은 명확한 과금 증빙이 있을 때에만 하세요. 사용량 조회는 완전한 명세서가 아닙니다.

<span id="troubleshooting" />
## 검색 결과 없음, 유효하지 않은 입력, 불완전한 가격 정보

1. 작업/참조 파일에 필요한 기능 조건은 유지하면서 검색어를 넓히고, 계정과 권한을 확인하세요.
2. 해당 모델의 스키마를 다시 읽고 필드, 열거형 값, 범위, 상호 배타적인 참조 입력을 확인하세요.
3. 최종 입력으로 예상 비용을 산정하고 상태 표를 따르세요. 알 수 없는 요소를 시작 가격으로 채우지 마세요.
4. 아직 제출하지 않은 요청은 다시 확인하세요. 제출했거나 제출 여부를 알 수 없는 요청은 [먼저 복구하세요](/ko/cli-mcp/tasks-and-files#recovery).

경로별 조치는 [CLI 모델 문제 해결](/ko/cli/billing#models-and-pricing)과 [MCP 모델 문제 해결](/ko/mcp/billing#models-and-pricing)을 참고하세요.
