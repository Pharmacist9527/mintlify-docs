## MCP 연결 방식 선택

| 연결 | 설치 또는 연결 | 인증 | 대상 |
|---|---|---|---|
| 원격 MCP | https://mcp.evolink.ai/mcp | 브라우저 OAuth | 웹 채팅 및 네이티브 MCP 클라이언트 |
| 로컬 MCP | npx로 @evolinkai/mcp 실행 | 플랫폼 API Key | stdio 클라이언트 및 허용된 로컬 업로드 |

원격 MCP에는 로컬 MCP 패키지가 필요 없습니다. CLI를 설치해도 네이티브 MCP 서버가 등록되지는 않습니다. 스킬을 설치해도 로그인이 되거나 도구가 연결되지는 않습니다.

## 전용 가이드 선택

[Claude](/ko/mcp/claude), [Codex](/ko/mcp/codex), [Claude Code](/ko/mcp/claude-code), [ChatGPT](/ko/mcp/chatgpt), [Cursor](/ko/mcp/cursor), [OpenClaw](/ko/mcp/openclaw), [Hermes](/ko/mcp/hermes-agent)는 각각의 별도 페이지를 이용하세요. 이 페이지는 그 밖의 클라이언트를 위한 범용 원격 MCP 연결과 로컬 stdio 연결을 다룹니다.

<span id="cli-install" />

## 터미널 에이전트를 위한 별도의 CLI 가이드

터미널, 스크립트, Gemini CLI, OpenCode, GitHub Copilot CLI에서는 [EvoLink CLI 설정](/ko/cli/setup#cli-install)을 따라 설치, 로그인, 스킬 설치 대상 지정, 무료 검증을 진행하세요. 명령을 실행할 수 있는 에이전트는 CLI를 사용할 수 있습니다. 네이티브 MCP는 아래의 원격 또는 로컬 안내에 따라 설정하세요.

<span id="ssh-login" />

### Linux와 SSH 로그인

CLI는 원격에서 실행되고 브라우저는 로컬에 있는 경우, Linux의 보안 자격 증명 저장소 요건을 충족한 뒤 [SSH 콜백 포워딩](/ko/cli/setup#ssh-login)을 따르세요. 원격 MCP 콜백은 호스트가 관리하며 CLI의 포워딩 단계를 사용하지 않습니다.

<span id="local-mcp" />

## API Key를 사용하는 로컬 stdio MCP

stdio만 지원하는 클라이언트는 로컬 MCP 프로세스를 실행할 수 있습니다. 이 경우 원격 MCP의 브라우저 OAuth 대신 **Node.js 20+** 환경과 개인 API Key가 필요합니다.

<Steps>

<Step title="Node와 전용 키 준비">

```bash
node --version
npx --version
```

두 명령 모두 동작해야 하며 Node는 20 이상이어야 합니다. [API Keys](https://evolink.ai/dashboard/keys)에서 한도를 설정한 전용 개인 키를 만드세요. `EVOLINK_API_KEY`는 에이전트 채팅, 공유 스크린샷, 저장소가 아니라 클라이언트의 안전한 환경 변수 설정이나 시크릿 설정을 통해 제공하세요.

</Step>

<Step title="로컬 실행 설정">

클라이언트의 MCP 설정에서 local/stdio를 선택하세요:

```text
command: npx
args: -y @evolinkai/mcp@latest
```

처음 실행할 때 npx가 패키지를 내려받습니다. 호스트는 stdio로 통신하고, 로컬 프로세스가 플랫폼 API를 호출합니다. 호스트가 npx를 찾을 수 있는지 확인하세요. GUI 애플리케이션의 환경은 터미널의 환경과 다를 수 있습니다. 아래의 `YOUR_API_KEY`는 비공개 로컬 설정에 넣을 값의 자리 표시자입니다. 지원된다면 환경 변수를 상속하는 방식을 우선 사용하세요.

```json
{
  "mcpServers": {
    "evolink": {
      "command": "npx",
      "args": ["-y", "@evolinkai/mcp@latest"],
      "env": {"EVOLINK_API_KEY": "YOUR_API_KEY"}
    }
  }
}
```

</Step>

<Step title="로컬 파일이 필요하면 디렉토리 허용">

로컬 경로로 업로드하려면 프로세스 환경에서 `EVOLINK_UPLOAD_ALLOWED_DIRS`를 허용할 절대 경로 디렉토리로 설정하세요. 디렉토리가 여러 개면 macOS/Linux에서는 `:`으로, Windows에서는 `;`으로 구분합니다. 이 설정이 없으면 로컬 경로 업로드는 비활성화됩니다. 원격 MCP는 `file_path`를 절대 받지 않습니다.

이 설정은 로컬 파일 접근을 제어할 뿐, 모델의 형식, 길이, 크기 제한과는 관계가 없습니다. URL/base64를 사용할 때는 로컬 디렉토리 접근이 필요 없습니다.

</Step>

<Step title="다시 로드하고 무료 도구로 검증">

설정을 저장하고 EvoLink를 활성화한 뒤, 호스트의 요구에 따라 다시 로드하거나 새 세션을 여세요. `check_balance`와 `search_models`를 호출해 달라고 요청하고 실제 결과가 나오는지 확인하세요. 프로세스가 시작되었거나 도구가 목록에 보인다는 것만으로는 계정 검증에 성공한 것이 아닙니다.

로컬 stdio는 원격 일회용 업로드 도구인 `prepare_upload` / `get_upload`를 제공하지 않습니다. 실제 `tools/list`를 확인하세요. 개인 키에는 OAuth 키의 한도가 아니라 그 키 자체의 한도가 적용됩니다.

</Step>

</Steps>

### Claude Code와 Codex 설정

안전한 환경 변수 설정을 통해 키를 이미 제공했다면, Claude Code에서는 JSON 예시 대신 다음 명령으로 등록할 수 있습니다:

```bash
claude mcp add --scope user evolink -- npx -y @evolinkai/mcp@latest
```

Codex에서는 이 섹션을 병합해 시작 환경의 변수를 상속받을 수 있습니다:

```toml
[mcp_servers.evolink]
command = "npx"
args = ["-y", "@evolinkai/mcp@latest"]
env_vars = ["EVOLINK_API_KEY", "EVOLINK_UPLOAD_ALLOWED_DIRS"]
```

업데이트한 뒤에는 다시 로드하고 실제 버전을 확인하세요. `@latest`를 지정해도 이미 실행 중인 프로세스가 교체되지는 않습니다. 시작, 키, 로컬 경로 관련 오류는 [통합 문제 해결](/ko/mcp/billing#mcp-connection)을 참고하세요.

## 다른 원격 MCP 클라이언트

클라이언트가 Streamable HTTP, OAuth, 브라우저 콜백을 지원해야 합니다. 고정 키나 stdio만 지원하는 클라이언트는 위의 로컬 MCP를 사용하세요.

<Steps>

<Step title="서버 추가">

Streamable HTTP와 다음 URL로 이름이 EvoLink인 MCP 연결을 만드세요:

```text
https://mcp.evolink.ai/mcp
```

문서 URL, 플랫폼 `/v1` URL, npx 명령을 입력하지 마세요.

</Step>

<Step title="OAuth를 완료하고 도구 활성화">

OAuth를 선택하고 클라이언트의 로그인 기능을 사용해 브라우저에서 승인한 뒤 돌아오세요. 연결과 도구가 활성화되어 있는지 확인하세요. 고정 API Key는 이 연결의 OAuth 토큰이 아닙니다.

</Step>

<Step title="무료로 검증">

```text
EvoLink로 제 잔액을 확인하고 사용할 수 있는 이미지 모델을 검색해 주세요. 아직 생성하지 마세요.
```

실제 잔액과 모델 결과가 반환되면 [첫 미디어 작업 흐름](/ko/mcp/overview#workflows)을 따르세요. 도구 목록은 보이는데 호출이 성공하지 않는다면 인증 문제를 해결해야 합니다.

</Step>

</Steps>

## 스킬과 플러그인 자료

번들로 제공되는 evolink-cli 스킬은 명령 실행을 안내하고, 저장소의 evolink-mcp는 네이티브 도구 사용을 안내합니다. 소스, 디렉토리, 업데이트는 [에이전트용 자료](/ko/cli-mcp/agent-resources#skills)를, 패키지로 제공되는 원격 설정은 [플러그인 가이드](/ko/mcp/plugins)를 참고하세요.
