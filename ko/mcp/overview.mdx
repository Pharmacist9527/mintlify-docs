클라이언트별로 선택하려면 [CLI/MCP 개요](/ko/cli-mcp/overview)를 참고하세요. 이 섹션의 공통 자료는 비용, 작업, 파일, 에이전트 지침을 다룹니다.

EvoLink MCP는 모델 탐색, 예상 비용 산정, 미디어 생성, 참조 파일, 작업, 잔액 기능을 에이전트의 네이티브 도구로 제공합니다. 이 섹션은 MCP를 다룹니다. 터미널 명령과 evolink-cli는 [별도의 CLI 섹션](/ko/cli/overview)에 있습니다.

이 가이드는 정식 출시된 **MCP 1.12.1**을 기준으로 합니다. 원격 MCP는 브라우저 OAuth를 사용하며 도구가 16개이고, 로컬 stdio는 개인 API Key를 사용하며 도구가 14개입니다. 실행하기 전에 현재 계정에서 사용할 수 있는 모델과 입력을 조회하세요.

## 빠른 시작: 원격 MCP

<Steps>
<Step title="서버 추가">
이름이 EvoLink인 커스텀 MCP/커넥터를 https://mcp.evolink.ai/mcp 주소로 추가하세요. 위의 클라이언트 가이드를 따르면 되며, 로컬 MCP 패키지는 필요 없습니다.
</Step>
<Step title="브라우저에서 로그인하고 인증">
OAuth를 선택하고 EvoLink에 로그인한 뒤 계정과 권한을 확인하고 승인한 다음 돌아오세요. 연결과 도구를 활성화하세요. CLI 로그인은 호스트의 MCP 인증을 대신하지 않습니다.
</Step>
<Step title="실제 도구를 무료로 검증">
아래 내용을 보내고 실제 잔액과 모델 결과가 나오는지 확인하세요:

```text
EvoLink로 제 잔액을 확인하고 사용할 수 있는 이미지 모델을 검색해 주세요. 아직 생성하지 마세요.
```

check_balance와 search_models 호출이 성공하면 접근이 확인된 것입니다. 도구 목록이 보이는 것만으로는 확인되지 않습니다. 이 확인 과정은 유료 미디어 작업을 만들지 않습니다.
</Step>
</Steps>

stdio만 지원하는 클라이언트는 [로컬 MCP 설정](/ko/mcp/other-clients#local-mcp)을 따르세요. 실행 방식과 인증은 따로 설정하세요.

생성에는 EvoLink 크레딧이 사용됩니다. 위 프롬프트들은 어시스턴트에게 승인을 기다리라고 요청합니다. 계정 인증, 호스트의 도구 권한, 작업 비용 승인은 서로 별개입니다. 네이티브 MCP는 서버 측의 대화형 승인 버튼을 제공하지 않으므로, 에이전트가 이번 작업에 대한 명시적인 승인을 받아야 합니다. [과금과 인증](/ko/mcp/billing)을 읽어 보세요.

## 동작 방식

원격 MCP는 `어시스턴트 → EvoLink MCP → 플랫폼 API` 순서를 따릅니다. OAuth 로그인은 호스트가 관리하고, 도구는 원격 서비스가 실행합니다. 브라우저 채팅 클라이언트에는 Node.js나 EvoLink CLI가 필요 없습니다.

로컬 stdio는 `어시스턴트 → 로컬 MCP 프로세스 → 플랫폼 API` 순서를 따릅니다. 어시스턴트를 실행하는 컴퓨터에 Node.js 20+를 설치하고, 호스트가 프로세스를 실행하게 한 뒤, 플랫폼 API Key를 제공하세요. 설정 방법은 [다른 MCP 클라이언트](/ko/mcp/other-clients#local-mcp)를 참고하세요.

두 방식 모두 모델, 예상 비용, 생성, 작업에 관한 주요 도구를 제공합니다. 원격 MCP는 여기에 더해 `prepare_upload`와 `get_upload`를 제공합니다. 선택 사항인 스킬과 플러그인은 사용 지침을 제공할 뿐, 서버 등록, 계정 인증, 호스트의 도구 권한을 대신하지 않습니다.

| 목표 | 도구 |
|---|---|
| 잔액과 계정 접근 권한 확인 | `check_balance` |
| 모델, 매개변수, 문서 찾기 | `search_models`, `get_model`, `search_docs` |
| 작업에 맞는 후보 비교 | `recommend_models` |
| 예상 비용 산정 | `estimate_cost` |
| 이미지, 영상, 오디오 생성 | `generate_image`, `generate_video`, `generate_audio` |
| 작업 조회, 대기, 목록 보기 | `get_task`, `list_tasks` |
| 계정 사용량 확인 | `get_task_usage` |
| 참조 파일 업로드 | `upload_file`. 원격에는 `prepare_upload`, `get_upload`도 있습니다 |

이 도구들은 코드 개발, 로컬 영상 편집, 웹사이트 제작 기능을 제공하지 않습니다. 에이전트 호스트가 자체적으로 그런 기능을 갖추고 있을 수 있습니다. EvoLink를 설명할 때는 그런 기능을 호스트의 것으로 밝히세요.

## 1단계: 모델을 선택하고 입력 검증하기

`search_models` 또는 `recommend_models`로 현재 후보를 찾은 뒤 `get_model`로 정확한 ID, 지원 기능, 필수 항목, 제한을 확인하세요. 추가 안내가 필요하면 `search_docs`를 사용하세요. 계열 이름이 반드시 유효한 제출용 ID인 것은 아닙니다.

선택 순서, 비교해 볼 최신 계열, 가격 규칙은 [모델, 비용, 할당량](/ko/cli-mcp/models-and-billing#models)을 참고하세요. 현재 계정의 모델 목록과 입력을 확인하세요. 예시 모델은 기본 권장 모델이 아닙니다.

아래 예시는 `z-image-turbo`를 사용합니다. 어떤 모델이든 사용하기 전에 매개변수를 확인하세요:

```json
{"name":"get_model","arguments":{"model":"z-image-turbo"}}
```

## 2단계: 참조 파일 준비하기

입력이 텍스트뿐이면 업로드를 건너뛰세요. 참조 이미지, 영상, 오디오를 쓰려면 먼저 지원되는 유형, 개수, 크기 제한을 확인하세요.

1. **접근 가능한 URL**: `file_url`을 지정해 `upload_file`을 호출하세요. 서버가 해당 URL을 가져올 수 있어야 합니다. 사용자 컴퓨터의 경로는 공개 URL이 아닙니다.
2. **작은 인라인 파일**: 원격 `upload_file`은 최대 1 MiB의 base64 콘텐츠를 받으며, 그에 맞는 MIME 유형이 필요합니다. 큰 파일은 도구 메시지에 넣지 마세요.
3. **원격 MCP에서 로컬 파일 사용**: `prepare_upload`를 호출하고, 파일 접근과 HTTP 요청이 가능한 환경에서 업로드한 뒤, `get_upload`로 접수 확인을 조회하세요. 업로드 한도는 95 MiB이며 모델 제한이 함께 적용됩니다. 업로드 권한은 한 번만 쓸 수 있고 약 15분 후에 만료됩니다. 상태 URL은 약 한 시간 동안 유지됩니다.
4. **로컬 stdio**: `upload_file`이 로컬 `file_path`를 지원합니다. 이 경로는 MCP 프로세스가 실행되는 컴퓨터의 절대 경로이며, 채팅 사용자의 컴퓨터 경로와 자동으로 같아지는 것은 아닙니다. 파일 서비스와 모델의 제한은 그대로 적용됩니다.

```json
{"name":"prepare_upload","arguments":{"file_name":"reference.png"}}
```

```json
{"name":"get_upload","arguments":{"upload_id":"UPLOAD_ID"}}
```

채팅 첨부 파일이 모델이 쓸 수 있는 URL로 자동으로 바뀌지는 않습니다. 호스트가 파일을 읽거나 업로드할 수 없다면 접근 가능한 URL을 요청하세요. 결과를 알 수 없을 때는 원래 `upload_id`를 보존하고, 곧바로 다시 업로드하지 마세요. 접수 확인의 호환 여부는 파일 서비스의 배포 환경에 따라 다릅니다. 참조 파일은 보통 72시간 동안 유지됩니다. 만료된 입력은 다시 업로드하고 요청을 수정하세요.

## 3단계: 예상 비용 산정, 승인, 이미지 생성

예상 비용을 산정하기 전에 최종 입력을 준비하세요. 모델, 이미지 수, 크기, 내용, 예상 비용을 보여 주세요. 예상 비용은 최종 정산 금액을 보장하지 않습니다. 정식 출시 버전의 가격 반영 범위와 한계는 [비용](/ko/mcp/billing#pricing)을 참고하세요.

```json
{"name":"estimate_cost","arguments":{"model":"z-image-turbo","input":{"prompt":"A minimalist coffee advertisement with a ceramic cup"}}}
```

이 계획과 예상 비용에 대한 명시적인 승인을 받은 뒤에만 생성을 호출하세요. `client_request_id`는 16–96자의 고정된 요청 ID입니다. 같은 제출을 재시도할 때는 그 요청 ID와 입력을 그대로 유지해야 합니다. 아래의 예산 값은 매개변수 사용법을 보여 주기 위한 것일 뿐이므로, 사용자가 명시한 예산에 맞춰 설정하세요:

```json
{"name":"generate_image","arguments":{"model":"z-image-turbo","input":{"prompt":"A minimalist coffee advertisement with a ceramic cup"},"client_request_id":"coffee-image-demo-001","max_cost_usd":1}}
```

`max_cost_usd`는 제출 전 검사이며, 강제되는 최종 청구액 상한이 아닙니다. `estimate_cost`는 이 값을 받지 않습니다. 호스트에서 도구 호출을 허용했다고 해서 그것만으로 구매가 승인되는 것은 아닙니다.

어시스턴트에게 예상 비용 산정이나 확인을 하지 말라고 말하면(예: "바로 생성해 주세요"), 어시스턴트는 사용자가 정한 범위 안에서 `skip_estimate: true`를 전달하고 묻지 않고 제출합니다. [예상 비용 산정 없이 생성하기](/ko/mcp/tools#skip-estimate)를 참고하세요. 한 모델로 여러 이미지나 작업을 만들 때는 `inputs`(최대 50개)를 `estimate_cost`와 생성 도구에 전달합니다. 예상 비용 산정 한 번, 승인 한 번, 그리고 모든 task_id를 한꺼번에 반환하는 호출 한 번으로 처리됩니다. [배치](/ko/mcp/tools#batches)를 참고하세요.

## 영상: 길이, 해상도, 사운드, 참조 파일 확인하기

`get_model`로 텍스트-영상 또는 이미지-영상 생성의 정확한 ID를 찾으세요. 길이, 해상도, 사운드 옵션, 참조 영상이 가격에 영향을 줄 수 있습니다. 다른 입력으로 산정한 예상 비용을 재사용하지 마세요. 같은 계열 안에서도 작업에 따라 다른 ID를 쓸 수 있습니다.

매개변수 검증 → 참조 파일 업로드 → 최종 입력으로 `estimate_cost` 호출 → 계획을 보여 주고 명시적인 승인 받기 → 같은 입력으로 `generate_video` 호출 → 원래 작업 조회 → 원본 영상 전달.

`media_seconds`가 필요할 때는 측정한 입력 길이를 사용하세요. 필요한 측정값을 알 수 없거나, 가격 산정이 불완전하거나, 예산 비교를 끝낼 수 없으면 진행을 멈추세요. 썸네일이 회색으로 보인다고 완성된 영상을 자동으로 편집하거나 다시 생성해서 해결하려 하지 마세요.

## 오디오: 음악과 음성 구분하기

음악에는 사용할 수 있는 Suno v6 모델을 비교하고, 내레이션이나 보이스오버에는 알맞은 음성 모델을 사용하세요. 모델 매개변수를 확인하고 텍스트, 언어, 목소리, 가사, 길이 또는 참조 오디오를 준비한 뒤, 최종 입력으로 예상 비용을 산정하고 승인을 받아 `generate_audio`를 호출하세요.

오디오 가격 정보가 불완전하다고 해서 무료로 사용할 수 있다는 뜻은 아닙니다. 완료된 작업의 원본 오디오 URL을 전달하고, 반환된 결과물을 모두 보관하고, 실제 형식과 저장 방법을 설명하세요.

## 4단계: 원래 작업을 기다리고, 조회하고, 복구하기

생성은 결과를 반환하거나 `task_id`를 반환할 수 있습니다. 생성을 다시 제출하지 말고 그 작업을 조회하세요. `get_task.wait_seconds`는 호출 한 번 안에서 기다리며 0–45초를 받습니다. 대기 시간 초과는 그 대기만 끝낼 뿐입니다.

```json
{"name":"get_task","arguments":{"task_id":"TASK_ID","wait_seconds":30}}
```

`task_ids`를 지정한 `list_tasks`로 일괄 조회하거나, 이 도구의 필터로 기록을 조회하세요. ID를 반환하기 전에 제출 시간이 초과되었다면, 복구를 위해 원래 요청 ID, 입력, 자격 증명, 오류를 보존하세요. 문제를 해결한다고 신원이나 요청 ID를 바꿔서 다시 생성하지 마세요.

현재 사용할 수 있는 공개 대기열 취소 도구는 없습니다. 에이전트의 대기를 멈추거나, 페이지를 닫거나, MCP 연결을 끊어도 서버의 작업은 취소되지 않으며, 요금이 부과되지 않았다거나 환불이 완료되었다는 근거도 되지 않습니다.

## 5단계: 원본 결과 전달하기

완료되면 접근 가능한 원본 URL을 모델, 결과물 수, 확인된 비용 정보, 만료 시점과 함께 알려 주세요. 생성된 원본은 보통 24시간 동안 유지되므로 바로 저장하세요. 호스트가 미리보기를 표시할 수도 있습니다. 결과가 링크로만 보이거나 썸네일이 회색이면 먼저 원본 URL을 확인하세요.

저장하기 전에 HTTP 상태, 콘텐츠 유형, 실제 파일 형식을 확인하세요. 오류 페이지는 미디어가 아닙니다. 직접 관리하는 Python 다운로드 코드에서는 기본 요청이 차단될 때 제품 User-Agent를 설정할 수 있습니다. [다운로드 문제 해결](/ko/mcp/billing#download)을 참고하세요.

전달이나 미리보기 문제를 승인되지 않은 재생성으로 해결하려 하지 마세요. 사용자가 편집을 따로 요청하면 해당하는 호스트 기능을 사용하고, 필요한 비용 승인을 받으세요.

인수와 결과는 [MCP 도구 레퍼런스](/ko/mcp/tools)를, 전체 에이전트 지침은 [스킬과 읽을 수 있는 자료](/ko/cli-mcp/agent-resources)를 참고하세요.
