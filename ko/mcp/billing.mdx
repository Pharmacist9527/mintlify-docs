## MCP 비용과 승인

이 페이지는 정식 출시된 MCP 1.12.1을 기준으로 합니다. `estimate_cost`를 호출한 뒤 모델, 최종 입력, 결과물 수, 예상 비용을 보여 주세요. 이번 작업에 대한 명시적인 승인을 받은 뒤에만 생성 도구를 호출하세요. 사용자가 이번 작업, 배치 하나, 또는 대화의 남은 부분에 대해 예상 비용 산정이나 확인을 하지 말라고 명시적으로 말한 경우에는, 어시스턴트가 대신 `skip_estimate: true`로 제출합니다. [예상 비용 산정 없이 생성하기](/ko/mcp/tools#skip-estimate)를 참고하세요.

예상 비용 상태, 공개 가격의 한계, 승인, 예산은 [모델, 비용, 할당량](/ko/cli-mcp/models-and-billing#pricing)을 참고하세요. 정식 출시된 버전의 max_cost_usd는 제출 전 예상 비용과 비교만 할 뿐, 최종 청구액에 상한을 두지 않습니다.

estimate_cost는 max_cost_usd를 받지 않으며, 생성 도구는 이 값을 받습니다.

네이티브 MCP에는 CLI의 로컬 `quote_id`와 `--confirm` 명령도, 세션 단위의 서버 승인 버튼도 없습니다. 에이전트가 이번 작업의 모델, 입력, 예상 비용, 승인을 보관해야 합니다. 입력이 바뀌었거나, 가격이 올랐거나, 승인이 만료되었다면 다시 승인을 받아야 합니다. 승인(`pricing_quote`)은 예상 비용을 산정한 시점부터 24시간 동안, 승인된 가격 이하일 때 유효합니다. 생성 도구는 예상 비용을 다시 산정하고 가격이 그대로이거나 더 낮으면 제출하며, 이후에 가격 규칙이 바뀐 경우에도 마찬가지입니다. 가격이 올랐으면 `price_changed`, 입력이 바뀌었으면 `quote_input_changed`, 승인이 `expires_at`을 지났으면 `quote_expired`를 반환합니다. 호스트의 도구 권한, 계정 인증, 구매 승인은 서로를 대신하지 않습니다.

모델, 잔액, 작업 조회는 생성을 제출하지 않습니다. 생성에는 요금이 부과되며, 파일 서비스의 제한은 별도로 적용됩니다. 실패한 작업에는 요금이 부과되지 않으며, 제출 시 선차감된 크레딧은 자동으로 반환됩니다. 시간 초과나 채팅 닫기는 요금이 부과되지 않았다거나 환불이 완료되었다는 근거가 되지 않습니다. 사용량 조회는 완전한 정산 영수증이 아닙니다.

[공통 접근 권한 규칙](/ko/cli-mcp/models-and-billing#authorization)을 참고하세요. 이 페이지에는 이 경로의 로그인과 로그아웃 방법을 남겨 두었습니다.

## 인증, 권한, 할당량

원격 MCP는 Passport 브라우저 OAuth를 사용합니다. 연결 자격 증명은 호스트가 저장하고, 서비스는 OAuth에 연결된 기존 키를 사용합니다. 원격 MCP와 CLI는 계정 접근 권한, 키 할당량, 권한을 공유할 수 있습니다. 공유 키를 일시 중지하면 그 키를 사용하는 쪽 모두에 영향을 줍니다. 호스트 세션 로그아웃은 이와 별개의 동작입니다.

로컬 stdio는 MCP 프로세스에 제공된 개인 API Key를 사용하며 그 키의 권한과 할당량을 따릅니다. 키를 채팅에 붙여넣지 말고, CLI 로그인을 네이티브 MCP 인증의 증거로 삼지 마세요.

연결 해제나 로그아웃은 호스트의 MCP 또는 커넥터 설정에서 하세요. 필요하면 계정의 인증 관리에서 계정 접근 권한을 해지하세요. 창을 닫는다고 접근 권한이 반드시 해지되는 것은 아닙니다. 잔액 부족, 일일/총 할당량, 모델 권한 문제는 계정 설정에서 해결하세요.

## MCP 문제 해결: 연결 방식 확인하기

원격 MCP는 `https://mcp.evolink.ai/mcp`, Streamable HTTP, 호스트의 OAuth 로그인을 사용합니다. 로컬 stdio는 호스트에 설정된 `@evolinkai/mcp` 프로세스와 플랫폼 키를 사용합니다. 실제로 사용하는 연결에 대해 자격 증명과 도구 인식 여부를 확인하세요.

| 증상 | 문제 해결 섹션 |
|---|---|
| 브라우저 인증이 실패하거나 반복됨 | [로그인](#login) |
| 스킬은 있지만 실제 도구가 없음 | [스킬과 권한](#skills-discovery) |
| MCP가 없음, 텍스트로만 응답함, 도구가 거부됨 | [연결과 도구 인식](#mcp-connection) |
| 모델이 없음, 입력이 유효하지 않음, 가격 정보가 불완전함 | [모델과 가격](#models-and-pricing) |
| 생성 시간 초과 또는 결과를 알 수 없음 | [작업과 복구](#tasks-and-recovery) |
| 첨부 파일을 읽을 수 없거나 업로드 실패 | [업로드](#uploads) |
| 원본 파일 403, 회색 미리보기 또는 링크만 표시되는 결과 | [다운로드](#download) |
| 문제가 계속됨 | [고객 지원에 전달할 정보](#support) |

이 호스트 연결이 활성화되고 인증되어 있으며 도구가 보이는지 확인한 뒤, 실제로 `check_balance`를 호출하세요. 원격 MCP는 도구 16개를, 로컬 stdio는 14개를 제공합니다. CLI가 동작한다고 해서 네이티브 MCP에 접근할 수 있다는 증거는 아니며, MCP 문제 해결에 CLI 설치가 필요하지도 않습니다.

### 브라우저 로그인과 인증

<Steps>
  <Step title="호스트에서 인증 시작하기">
    해당 MCP 또는 커넥터 항목의 로그인 또는 인증 기능을 사용하세요. 호스트의 명령이나 메뉴는 전용 가이드에서 확인하세요. 별도의 CLI에 로그인해도 이 연결이 인증되지는 않습니다.
  </Step>
  <Step title="브라우저에서 계정 승인 완료하기">
    올바른 EvoLink 계정으로 로그인하고 권한 범위를 확인한 뒤 승인하세요. 호스트의 인증 절차는 대기 상태로 그대로 두세요. 전체 인증 URL이나 콜백 매개변수를 공유하지 마세요. 절차가 실패하면 원래 호스트에서 다시 시작하세요.
  </Step>
  <Step title="호스트로 돌아와 검증하기">
    연결의 도구를 새로 고치고 `check_balance`와 `search_models`가 있는지 확인한 뒤 실제로 잔액을 조회하세요. 401이 나오면 다시 인증하세요. 403이면 계정 권한, 키 상태, 호스트의 도구 권한도 확인하세요.
  </Step>
</Steps>

로컬 stdio는 이 브라우저 절차를 사용하지 않습니다. 프로세스가 받은 플랫폼 키, 시작 환경, stderr를 확인하세요. 원격 OAuth와 개인 키를 섞어 쓰지 마세요. [다른 클라이언트](/ko/mcp/other-clients)를 참고하세요.

### 스킬은 설치되었지만 도구를 사용할 수 없음

1. `evolink-mcp` 도구 지침을 읽으세요. 네이티브 MCP는 CLI 스킬에 나오는 터미널 명령을 실행할 수 없습니다.
2. 호스트에서 실제 서버 설정과 도구를 확인하세요. 스킬을 읽는다고 서버가 등록되지는 않으며, 플러그인을 설치한다고 OAuth가 자동으로 완료되지도 않습니다.
3. 세션이나 플러그인을 다시 로드하고 도구 권한을 확인하세요. 도구 호출 기록이 없는 안내문만으로는 접근할 수 있다는 증거가 되지 않습니다.
4. 도구가 목록에는 보이는데 호출이 실패한다면 도구 오류와 원래 연결을 확인하세요. 유료 생성을 연결 테스트로 사용하지 마세요.

<span id="mcp-connection" />
### MCP 연결과 접근 권한: 도구 없음, 연결 실패, 401/403

1. 연결 유형을 확인하세요. 원격은 `https://mcp.evolink.ai/mcp`, Streamable HTTP, OAuth를 사용하고, 로컬 stdio는 실행 명령과 개인 키를 사용합니다. 문서 페이지, `llms.txt`, REST 엔드포인트는 MCP 서버가 아닙니다.
2. EvoLink를 활성화하고 이 호스트의 브라우저 인증을 완료한 뒤, 새로 고치거나 새 세션을 여세요. 기존 설정을 백업하고 EvoLink 항목만 병합하세요. 다른 서비스를 덮어쓰지 않도록 주의하면서 JSON의 따옴표/쉼표, YAML의 공백, 설정 범위를 확인하세요.
3. `check_balance`와 `search_models`를 호출하세요. 도구가 목록에는 보이는데 호출이 실패한다면 인증을 확인하세요. 잔액 조회는 되는데 생성 도구가 없다면 도구 토글과 워크스페이스 정책을 확인하세요.

| 증상 | 조치 |
|---|---|
| 서버 이름이 중복됨 | 기존 항목을 확인하고 출처를 하나만 선택하세요. 수동 등록과 플러그인 등록이 중복되지 않게 하세요 |
| 401 / 인증 만료 | 작업 ID를 보존한 채 해당 호스트에서 다시 인증하세요 |
| 403 / 도구 거부 | 호스트 정책, 계정/키 한도, 네트워크 차단 중 무엇이 원인인지 구분하세요. UA를 바꾸면 모든 403이 해결된다고 가정하지 말고 실패한 단계를 기록하세요 |
| 로컬 프로세스가 시작되지 않음 | Node 20+, npx 경로, 호스트 환경, 실행 오류를 확인하세요. 다시 로드한 뒤 검증하세요 |
| 로컬 키가 유효하지 않거나 권한이 없음 | 콘솔에서 키의 상태와 범위를 확인하고, 채팅이 아니라 호스트의 시크릿 설정에서 키를 수정하세요 |
| 설정을 바꿔도 반영되지 않음 | 그 연결을 소유한 프로세스를 새로 고치세요. 노트북의 터미널을 새로 고친다고 원격 Gateway가 새로 고쳐지지는 않습니다 |

설정 페이지: [ChatGPT](/ko/mcp/chatgpt), [Claude](/ko/mcp/claude), [Claude Code](/ko/mcp/claude-code), [Codex](/ko/mcp/codex), [Cursor](/ko/mcp/cursor), [OpenClaw](/ko/mcp/openclaw), [Hermes](/ko/mcp/hermes-agent), [다른 클라이언트](/ko/mcp/other-clients).

### 모델과 가격: 검색 결과 없음, 유효하지 않은 매개변수, 불완전한 예상 비용

1. 현재 제공되는 모델을 검색하고 반환된 정식 ID를 사용하세요. 계열 이름, 표시 이름, 별칭은 유효한 제출용 ID가 아닐 수 있습니다. 필요한 참조 파일 기능 조건은 버리지 말고 검색어를 넓히세요.
2. 해당 모델에 대해 MCP의 `get_model`을 확인하세요. 필수 항목, 철자, 열거형 값, 숫자 제한, 상호 배타적인 참조 입력을 확인하세요. 다른 모델의 `duration`, `size`, `quality` 필드를 그대로 복사하지 마세요.
3. 예상 비용을 다시 산정하고 `input_valid`, `problems`, `estimate.status`, `basis`, `warnings`를 확인하세요. 입력이나 신원이 바뀌었거나, 가격이 올랐거나, 승인이 만료되었다면 예상 비용을 새로 산정하고 다시 승인받아야 합니다.

`needs_input`이면 `missing_usage`와 `usage_help`에 명시된 입력 또는 과금 사용량을 `media_seconds` 또는 `pricing_parameters`로 제공하세요. `no_price`는 사용할 수 없고 `partial`은 합계가 아닙니다. 알 수 없는 길이나 참조 파일 배율을 시작 가격으로 채울 수는 없습니다. 예산은 그대로 유지하세요. 거부를 우회하려고 말없이 상한을 없애거나, 키를 바꾸거나, 사양을 낮추지 마세요.

`search_models`, `get_model`, `recommend_models`가 반환한 모든 모델에 가격이 없고 `pricing_warning`에 `Public pricing rules are unavailable or invalid`라고 표시된다면, 서버가 1.8.1 이하 버전입니다. 이 버전들은 구간별 규칙에 `multiplier`가 없으면 모든 가격을 표시하지 않습니다. 원격 MCP는 더 새로운 버전으로 실행되므로 도구를 다시 호출하세요. `npx -y @evolinkai/mcp@latest`로 설정한 로컬 stdio는 클라이언트를 다시 시작하면 새 버전을 사용합니다. 1.8.2부터는 규칙을 읽을 수 없는 모델만 제외되어 `pricing_warning`에 표시되고, 다른 모델의 가격은 유지됩니다.

`estimate_cost` 또는 `get_pricing_rules`가 초 단위 시간과 함께 `rate_limited`(`pricing_calls_per_minute`)를 반환하면, 그 시간만큼 기다린 뒤 다시 호출하세요. 원격 서버에서는 로그인한 계정마다 이 두 도구 각각에 대해 분당 30회까지 가격 규칙을 읽을 수 있습니다. 조금 전에 읽어 둔 규칙으로 답한 응답은 횟수에 포함되지 않습니다. 한 모델의 입력이 여러 개라면 입력마다 호출하지 말고 `inputs`를 사용해 호출 한 번으로 예상 비용을 산정하세요. 플랫폼 자체가 가격 규칙 읽기를 제한하는 경우, 예상 비용은 최근 10분 이내에 읽은 규칙을 사용하며 그 규칙을 읽은 시각을 알려 줍니다. 로컬 stdio에는 이런 제한이 없습니다.

정식 출시 버전의 공개 기본 가격 기준 예상 비용은 계정별로 확정된 견적(Quote)이 아니며, `max_cost_usd`는 최종 정산 금액의 상한이 아닙니다. [비용](/ko/mcp/billing)과 [명령/도구 레퍼런스](/ko/mcp/tools)를 참고하세요.

### 시간 초과, 실행 중인 작업, 알 수 없는 결과

<Steps>
  <Step title="원래 작업을 보관하고 조회하기">
    기존 `task_id`에 대해 `get_task`를 호출하세요. 제한된 시간 동안 기다리려면 `wait_seconds`를 0–45로 설정하세요. ID가 여러 개면 `list_tasks`를 사용하세요. 시간 초과는 그 대기만 끝낼 뿐 생성을 끝내지 않습니다. 조회가 `status_check: unverified`를 반환하면(`task_response_invalid`, `task_identity_mismatch`, `task_status_unknown` 또는 `task_query_timeout`인 경우, 또는 대기 중에 뒤이은 조회가 실패해 `last_known_status`가 나온 경우) 같은 작업을 다시 조회하세요. 이는 실패가 아닙니다. `submission_state: accepted`가 포함된 생성 결과에는 이미 `task_id`가 있습니다.
  </Step>
  <Step title="결과를 알 수 없는 제출은 원래 요청 ID로 복구하기">
    작업 ID가 반환되지 않았다면 `client_request_id`, 입력, 신원, 오류를 보존하세요. 같은 도구와 같은 요청 ID로 복구하세요. 계정이나 요청 ID를 바꿔서 다시 생성하지 마세요. EvoLink는 요청 ID를 24시간 동안 보관합니다. 그 시간 안에는 같은 요청 ID와 같은 입력으로 요청하면 새로 과금되지 않고 원래 작업이 반환되며, 배치는 결과에 마저 제출해야 한다고 나열된 항목만 제출합니다. 그때까지 승인이 만료되었다면 같은 입력으로 예상 비용을 다시 산정하고, 새 `pricing_quote`를 같은 요청 ID와 함께 전달하세요. 24시간이 지나면 그 요청 ID로는 두 번째 작업이 생기는 것을 막을 수 없습니다. 먼저 `list_tasks`를 확인한 뒤, 접수되지 않은 것만 새 예상 비용과 새 요청 ID로 제출하세요. `list_tasks`는 문서에 나온 매개변수만 받으며, 지어낸 필터는 받지 않습니다.
  </Step>
  <Step title="실패 여부와 계정 결과를 따로 확인하기">
    실제 오류와 시간을 기록하고, 원래 작업과 계정 사용량을 조회하세요. 실패한 작업에는 요금이 부과되지 않으며, 제출 시 선차감된 크레딧은 자동으로 반환됩니다. 결과를 알 수 없는 제출은 실패가 아니며, 요금이 부과되지 않았다는 증거도 아닙니다. 사용할 수 있는 공개 대기열 취소 도구는 없습니다. MCP 연결을 끊거나 페이지를 닫아도 작업은 취소되지 않습니다.
  </Step>
</Steps>

아직 제출하지 않은 작업은 입력이 바뀌었거나, 가격이 올랐거나, 승인이 만료되었다면 예상 비용을 새로 산정하고 다시 승인받아야 합니다. 제출했거나 결과를 알 수 없는 요청은 먼저 복구하세요. 매개변수와 예시는 [작업 도구](/ko/mcp/tools#task-progress-and-results)를 참고하세요.

### 읽을 수 없는 첨부 파일, 업로드 실패, 알 수 없는 결과

1. 호스트가 제공된 파일을 읽을 수 있는지 확인하세요. 원격 MCP는 데스크톱 경로를 직접 읽을 수 없으며, 채팅 첨부 파일이 모델용 URL로 자동으로 바뀌지도 않습니다.
2. 접근 가능한 URL에는 `upload_file.file_url`을 사용하세요. 원격 base64는 1 MiB로 제한됩니다. 더 큰 파일은 `prepare_upload`를 호출하고, 파일에 접근할 수 있는 환경에서 업로드한 뒤 `get_upload`를 호출하세요. 일회용 업로드는 최대 95 MiB까지 허용되며, 권한은 약 15분, 상태 정보는 약 한 시간 동안 유지됩니다.
3. 로컬 stdio는 MCP 프로세스가 실행되는 컴퓨터에서 `upload_file.file_path`를 사용할 수 있습니다. 경로, 권한, 형식, 파일 서비스 제한, 모델 제한을 확인하세요. 데스크톱 경로를 클라우드 호스트에서 자동으로 읽을 수 있는 것은 아닙니다.
4. 원래 `upload_id`를 보존하고 조회하세요. 결과를 알 수 없다는 것이 아무것도 업로드되지 않았다는 뜻은 아니며, 접수 확인의 호환 여부는 파일 서비스의 배포 환경에 따라 다릅니다. 새 업로드는 실패나 만료가 확인된 뒤에 요청하세요. 참조 파일은 보통 72시간 동안 유지됩니다. 만료된 입력은 다시 업로드하세요.

매개변수는 [업로드 도구](/ko/mcp/tools)를, 전체 단계는 [참조 파일 작업 흐름](/ko/mcp/overview#files)을 참고하세요. 호스트에 파일 처리 기능이 없으면 접근 가능한 URL을 사용하세요. 업로드 실패를 다시 생성하는 방식으로 해결하려 하지 마세요.

<span id="download" />

### 다운로드와 미리보기

원래 작업을 조회해 완료되었는지 확인하고, 그 작업의 원본 URL을 사용하세요. 원본은 브라우저에서 열거나 파일을 다룰 수 있는 환경에서 저장하세요. [MCP 결과 전달](/ko/mcp/overview#delivery)을 참고하세요.

HTTP/형식 검사, Python 제품 User-Agent 예시, 만료된 링크, 회색 미리보기는 [다운로드 문제 해결](/ko/cli-mcp/tasks-and-files#download)에서 다룹니다. 결과를 알 수 없는 작업은 다시 생성하거나 미리보기를 편집하지 말고 복구하세요.
