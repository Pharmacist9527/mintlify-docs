<span id="workflows" />
## 작업 하나 완료하기

로그인과 스킬 인식을 마친 뒤 다음 순서를 따르세요: 요구 사항 → 모델 매개변수 → 참조 파일 → 무료 예상 비용 산정 → 승인 → 한 번 제출 → 원래 작업 조회 → 원본 다운로드. 아래 명령은 각 단계를 보여 주는 예시이며, 생성해도 된다는 허가가 아닙니다.

<span id="models" />
## 1단계: 모델을 선택하고 입력 확인하기

```bash
evolink models search --type image --query seedream --limit 5 --json
evolink models recommend --type image --query "coffee advertisement" --json
evolink models show MODEL_ID --json
evolink models schema MODEL_ID --json
evolink docs search --query "reference images" --json
```

MODEL_ID를 검색 결과에 나온 정식 ID로 바꾸세요. reference_inputs, 필수 항목, 열거형 값, 범위, 상호 배타적인 옵션을 확인하세요. 첫 번째로 나왔다거나, 저렴하다거나, 새롭다거나, 베타라는 사실만으로는 적합하다고 볼 수 없습니다.

선택 순서, 최신 계열, 비용 규칙은 [모델, 비용, 할당량](/ko/cli-mcp/models-and-billing#models)에서 관리합니다. 요청받은 모델은 사용 가능한지 확인하세요. 예시는 기본 권장 모델이 아닙니다.

<span id="files" />
## 2단계: 참조 파일을 준비하고 업로드하기

CLI는 자신이 실행되는 컴퓨터의 파일을 읽습니다. 업로드하기 전에 경로, 권한, 형식, 크기, 모델 요구 사항을 확인하세요:

```bash
evolink upload ./reference.png --upload-path references --json
evolink uploads get UPLOAD_ID --json
```

일반 로컬 파일은 1바이트–95 MiB여야 합니다. 이미지/영상/오디오에는 이와 별도로 모델별 형식, 개수, 가로세로 크기, 길이 제한이 있습니다. 반환된 file_url을 image_url이나 image_urls 같은 지원 필드에 사용하고, 데스크톱 경로는 사용하지 마세요.

참조 파일은 보통 72시간 동안 유지됩니다. upload_id를 보관하고, 응답을 받지 못했다면 원래 접수 확인을 조회하세요. 호환되는 파일 서비스 복구를 사용할 수 없으면 결과를 알 수 없다고 알리세요. 시간 초과만을 이유로 업로드를 반복하지 마세요. 공개 HTTPS 참조 파일을 그대로 받아들이는지도 확인하세요.

<span id="images" />
## 3단계: 입력을 준비하고 무료로 예상 비용 산정하기

아래 이미지 예시는 먼저 z-image-turbo를 사용할 수 있는지 확인합니다. 흐름을 보여 주기 위한 것이며 기본 권장 모델이 아닙니다:

```bash
evolink models search --type image --query z-image --limit 5 --json
evolink models show z-image-turbo --json
```

작업 디렉토리에 input.json을 만드세요:

```json
{"prompt":"A cream ceramic coffee cup on a white background, soft morning light"}
```

```bash
evolink estimate --model z-image-turbo --input-file input.json --json
```

input_valid, problems, estimate.status, basis, warnings, quote_id를 읽으세요. 모델, 출력, 참조 파일, 수량, 비용 범위, 포함되지 않은 항목을 보여 준 뒤 승인을 기다리세요. partial과 no_price는 보장된 합계라고 설명할 수 없습니다. token_billed는 참고 가격이며 실제 토큰 수로 정산됩니다. [CLI 비용](/ko/cli/billing)을 참고하세요.

## 4단계: 승인 후 한 번만 제출하기

사용자가 이 계획을 승인하면 해당 견적으로 이미지를 제출하세요:

```bash
evolink generate image --quote QUOTE_ID --confirm --wait --json
```

--confirm은 이미 승인을 받았음을 선언합니다. 생성 단계에서는 새 모델이나 입력을 받지 않습니다. 견적은 예상 비용을 산정한 시점부터 24시간 동안 유효하며, 같은 입력은 가격이 승인된 가격 이하일 때 제출됩니다. 사양이나 계정이 바뀌거나, 가격이 오르거나(`price_changed`), 견적이 만료되면(`quote_expired`) 예상 비용을 다시 산정하고 승인을 받으세요. 견적 하나를 이미지, 영상, 오디오용으로 함께 제출하지 마세요.

<span id="batch" />
## 한 모델로 여러 이미지 또는 작업 실행하기

입력(1–50개, 각각 단일 입력과 같은 형식)을 JSON 배열 또는 JSONL 파일에 작성하고, 한꺼번에 예상 비용을 산정한 뒤, 배치 합계에 대한 승인 한 번을 기다리세요:

```bash
evolink estimate --model z-image-turbo --inputs-file inputs.jsonl --json
evolink generate image --quote QUOTE_ID --confirm --json
evolink tasks batch --ids TASK_ID_ONE,TASK_ID_TWO --json
```

`generate`는 모든 입력을 한꺼번에 제출하고, 기다리지 않고 입력별 작업 ID 또는 오류를 반환합니다. 일부 입력이 제출되지 않았다면 첫 제출 후 23시간 이내에 `tasks resume --quote QUOTE_ID`로 마무리하세요. 이미 접수된 입력은 새로 과금되지 않고 원래 작업을 반환합니다. 이 기간 안에는 새 예상 비용 산정이나 generate 명령으로 이 배치의 입력을 다시 제출해서는 안 됩니다. 견적이 만료되었거나 가격이 올랐다면 `tasks resume`은 아무것도 보내지 않습니다. 이때는 `tasks batch` 또는 `tasks list`로 접수된 입력을 확인한 뒤, 나머지만 새 배치로 예상 비용을 산정하세요. GPT Image 같은 일부 모델은 `n`보다 적은 수의 이미지를 반환하는 경우가 많으므로, 이미지 한 장마다 입력을 하나씩 사용하세요.

사용자가 예상 비용 산정이나 확인을 하지 말라고 명시적으로 말한 경우, `--model`과 `--input-file` 또는 `--inputs-file`을 지정한 `generate`에 `--skip-estimate`를 추가하고 견적 단계를 건너뛰세요. [CLI 레퍼런스](/ko/cli/reference)를 참고하세요.

<span id="video" />
## 영상 작업

실제 모델 스키마를 바탕으로 video-input.json을 준비하세요. 프롬프트, 길이, 비율, 품질, 오디오, 참조 파일을 확인하세요. 이미지-영상 생성, 참조 영상, 편집, 연장은 서로 다른 모델과 입력을 사용할 수 있습니다.

```bash
evolink estimate --model VIDEO_MODEL_ID --input-file video-input.json --json
```

예상 비용에 포함된 범위를 보여 주고, 이 작업에 대한 승인을 기다린 뒤 다음을 실행하세요:

```bash
evolink generate video --quote VIDEO_QUOTE_ID --confirm --json
```

task_id를 저장하고 그 작업을 조회하세요. 기다리는 대신 다시 생성하지 마세요. 품질, 오디오, 참조 파일의 길이가 비용에 영향을 줄 수 있으며, 정식 출시된 예상 비용 산정이 모든 배율을 반영하지는 않습니다. 로컬에서 자동 편집, 프레임 보간, 자막 추가를 하지 말고 원본 영상을 먼저 전달하세요.

<span id="audio" />
## 음악, 노래, 음성

음악 모델과 음성 모델은 따로 선택하세요. 스키마에 맞춰 audio-input.json을 준비하세요. 지원되는 가사/설명, 언어, 목소리, 연주곡 모드, 참조 파일, 상호 배타적인 옵션을 포함합니다.

```bash
evolink estimate --model AUDIO_MODEL_ID --input-file audio-input.json --json
```

이 견적에 대한 승인을 받은 뒤 다음을 실행하세요:

```bash
evolink generate audio --quote AUDIO_QUOTE_ID --confirm --json
```

길이 지정을 지원하지 않는 모델에 길이를 억지로 넣지 마세요. media_seconds는 과금 계산용 힌트이며 출력 길이를 조절하는 값이 아닙니다. 출력 길이나 사용량을 알 수 없으면 그 점을 설명하고, 모든 오디오 결과를 보관하세요.

<span id="tasks" />
## 5단계: 조회, 대기, 복구

```bash
evolink tasks get TASK_ID --json
evolink tasks wait TASK_ID --timeout 1800 --json
evolink tasks batch --ids TASK_ID_ONE,TASK_ID_TWO --json
evolink tasks list --status processing --page 1 --limit 20 --json
```

processing에는 대기열 상태도 포함됩니다. completed, failed, cancelled는 최종 상태입니다. 작업 실패와 조회 명령 실패는 서로 다릅니다. 시간 필터는 현재 페이지에만 적용되며, 빈 페이지가 제출이 없었다는 증거는 아닙니다. 시간 초과, Ctrl-C, 창 닫기는 작업을 취소하지 않습니다. CLI에는 현재 대기열 취소 명령이 없습니다.

제출 응답을 받지 못했다면 원래 계정과 견적 기록을 보존하세요:

```bash
evolink tasks resume --quote QUOTE_ID --json
```

outcome_unknown은 요금이 부과되지 않았다는 뜻이 아닙니다. 다시 제출하려고 기록을 삭제하거나, 키나 경로를 바꾸거나, 대체 견적을 만들지 마세요. 먼저 복구하세요. `tasks resume`은 첫 제출 후 23시간 이내에, 견적이 만료되지 않았고 가격이 오르지 않은 경우에 원래 요청 ID로 요청을 다시 보냅니다. 23시간이 지나면 `recovery_window_passed`로 거부하고, 견적이 만료되었거나 가격이 올랐으면 `quote_expired` 또는 `price_changed`로 거부합니다. 어느 경우든 아무것도 보내지 않으므로, 예상 비용을 다시 산정하기 전에 최근 작업을 확인하세요. 실패한 작업에는 요금이 부과되지 않으며 선차감된 크레딧은 자동으로 반환됩니다. 다만 과금 증빙이 없으면 환불이 들어왔다고 말하지 마세요.

<span id="delivery" />
## 6단계: 원본을 다운로드하고 전달하기

```bash
evolink download TASK_ID --output ./coffee-cup.png --json
evolink download TASK_ID --all --output-dir ./results --json
evolink download TASK_ID --all --output-dir ./results --resume --json
```

결과 하나만 받는 모드와 전체를 받는 모드 중에서 선택하세요. 상위 디렉토리는 미리 만들어 두세요. 기존 파일은 덮어쓰지 않습니다. 원본은 각각 1 GiB로 제한되며 유형과 내용을 검사합니다. 배치 다운로드 재개는 원래 기록을 사용하며, 이름이 같을 뿐인 임의의 파일을 사용하지 않습니다. 인덱스는 1부터 시작하고, 확장자는 실제 형식과 일치해야 합니다.

원본 URL은 보통 24시간 동안 유지됩니다. 바로 저장하고, 저장 위치, 원본 링크, 모델, 사양, 보고된 실제 비용을 전달하세요. balance/usage는 완전한 청구서가 아닙니다. 썸네일이 회색으로 보인다고 다시 생성하지 말고 원본을 확인하세요. [CLI 레퍼런스](/ko/cli/reference)와 [다운로드 문제 해결](/ko/cli/billing#download)을 참고하세요.
