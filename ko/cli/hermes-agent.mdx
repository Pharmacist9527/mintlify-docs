Hermes는 EvoLink CLI를 통해 미디어 작업을 실행할 수 있습니다. 이 페이지는 호스트 환경과 스킬에서 달라지는 부분을 다루며, 공통 절차 전체는 [설치와 로그인](/ko/cli/setup)에 있습니다. 네이티브 도구를 쓰려면 [MCP 가이드](/ko/mcp/hermes-agent)를 바로 이용하세요.

## 에이전트에게 설치 요청하기

아래 내용을 에이전트 대화에 붙여넣으세요. 웹사이트의 프롬프트와 같은 내용입니다. 브라우저 로그인과 권한 검토는 직접 완료하세요.

```text
여기서 이미지, 동영상, 오디오를 바로 생성할 수 있도록 EvoLink를 설정해 주세요.
1. CLI 설치: `npm install -g @evolinkai/cli`를 실행하세요.
2. 로그인: `evolink auth login`을 실행하세요.
3. 함께 제공되는 스킬 설치: `evolink skills install`을 실행하세요.
4. 연결을 확인하고 성공하면 시작할 수 있다고 알려 주세요.
```

## 이 클라이언트를 위한 세 단계

<Steps>
  <Step title="공통 설치와 로그인 완료하기">
    Hermes가 터미널 명령을 실행하는 환경에 설치하고, 세션에서 명령 실행과 스킬 읽기가 모두 가능한지 확인하세요.

    처음 사용한다면 [다섯 단계 가이드](/ko/cli/setup#cli-install)를 여세요. Node.js 22+ 확인, CLI 설치, 브라우저 로그인 완료 순서로 진행합니다. 가이드에는 명령, 성공 표시, 문제 해결 방법이 들어 있습니다. 이미 마쳤다면 다음으로 검증하세요:

    ```bash
    evolink --version
    evolink auth status --json
    ```

    CLI 버전과 authenticated: true가 표시되는지 확인하세요. 실패한 단계에 따라 [설치 오류](/ko/cli/billing#cli-install), [로그인 오류](/ko/cli/billing#login), [SSH 콜백](/ko/cli/setup#ssh-login)을 참고하세요.
  </Step>
  <Step title="이 에이전트의 스킬을 동기화하고 인식 검증하기">
    ```bash
    evolink skills install --agent hermes
    evolink skills status --agent hermes --json
    ```

    디렉토리: ~/.hermes/skills/evolink-cli. current: true는 파일이 CLI와 일치한다는 뜻입니다. 에이전트에게 다음과 같이 요청하세요:

    ```text
    이 세션에서 evolink-cli 스킬을 인식하고 읽을 수 있는지 확인해 주세요. 미디어를 생성하지 말고 접근 권한을 검증하세요.
    ```

    assistant_discovery: not_checked이면 여전히 호스트에서 검증해야 합니다. 파일은 있는데 사용되지 않는다면 [스킬 인식](/ko/cli/billing#skills-discovery)을 따르세요. 필요한 실행 권한을 검토하고 개인 수정 사항은 그대로 유지하세요.
  </Step>
  <Step title="미디어를 만들기 전에 무료로 검증하기">
    ```bash
    evolink balance --json
    evolink doctor --agent hermes --json
    ```

    balance가 계정 데이터를 반환하고, doctor가 ok, connection_verified, model_discovery_verified를 true로 보고하고, 에이전트가 스킬을 읽었다고 확인하면 설정이 완료된 것입니다. 이 조회들은 유료 미디어 작업을 만들지 않습니다. 잔액이 없어도 연결은 검증할 수 있습니다.
  </Step>
</Steps>

### 이미 설치된 CLI를 한 번에 설정하기

```bash
evolink setup --agent hermes --json
```

이 명령은 환경을 확인하고, 스킬을 동기화하고, 필요하면 로그인하고, 접근 권한을 검증합니다. setup_complete: true가 표시되는지 확인하세요. 호스트의 스킬 인식은 여전히 따로 확인해야 합니다. 실패 원인은 phase, steps, error, recovery로 파악하세요.

## 업데이트와 로그아웃

CLI 0.10.0부터는 CLI가 새 릴리스를 직접 알려 줍니다. [새 버전이 나왔는지 확인하는 방법](/ko/cli/setup#update-check)을 참고하세요. CLI를 업데이트한 뒤에는 현재 에이전트의 스킬을 동기화하세요:

```bash
npm install -g @evolinkai/cli@latest
evolink --version
evolink skills install --agent hermes
evolink skills status --agent hermes --json
```

로컬 변경 사항은 유지됩니다. `modified` 또는 `conflict`는 [스킬 문제 해결](/ko/cli/billing#skills-discovery)을 참고해 처리하세요. 다음 명령은 CLI에서 로그아웃하려는 경우에만 실행하세요. 설치나 업데이트 단계가 아닙니다.

```bash
evolink auth logout
```

## 문제 해결 시작점

| 증상 | 다음 단계 |
|---|---|
| npm/evolink를 찾을 수 없음, 권한 문제, 설치 시간 초과 | [환경과 설치](/ko/cli/billing#cli-install) |
| 브라우저가 열리지 않음, OAuth 시간 초과, 자격 증명 저장소 오류 | [로그인과 콜백](/ko/cli/billing#login), [SSH 로그인](/ko/cli/setup#ssh-login) |
| 스킬은 설치되었지만 에이전트가 사용하지 않음 | [스킬 인식과 실행 권한](/ko/cli/billing#skills-discovery) |
| 제출한 작업의 시간이 초과되었거나 결과를 잃어버림 | [원래 작업 복구](/ko/cli/billing#tasks-and-recovery) |

연결한 뒤에는 [첫 미디어 작업 흐름](/ko/cli/workflows#workflows)을 따르세요. 모델, 매개변수, 비용을 확인하고 승인한 뒤 제출합니다. 전체 명령은 [CLI 명령 레퍼런스](/ko/cli/reference)에 있습니다.
