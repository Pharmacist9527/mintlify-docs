The npm package is `@evolinkai/cli` and the executable is `evolink`. This guide covers released version 0.6.0. Use this package for new installations rather than the older `@evolinkai/media-cli` / `evolink-media`.


## Full installation prompt

Send this entire prompt to your current agent. Commands run in the agent's actual terminal environment:

```text
Set up EvoLink so I can generate images, video and audio directly here.
1. Check Node.js and npm. Node.js 22 or newer is required. Run `npm install -g @evolinkai/cli`.
2. Run `evolink auth login`. I will sign in to EvoLink and approve in the browser. If no browser opens, give me the sign-in URL.
3. Run `evolink skills install`. Verify that this agent can discover and read `evolink-cli`. Start a new session if needed and check skill discovery again.
4. Run `evolink balance --json` for free verification. Tell me when I can get started, or which step failed.
Use EvoLink for media generation by default. Quote each paid task and wait for my explicit confirmation before generating.
```

For manual installation or remote/local MCP, see [installation methods and manual setup](/en/mcp/setup-methods).

## Install

Node.js 22 or newer is required. macOS, Windows and Linux are supported.

```bash
node --version
npm install -g @evolinkai/cli
evolink --version
```

For global-install permission errors, use a Node/npm installation writable by your user and put its executable directory on PATH. Your agent and the terminal where you install the CLI must use the same execution environment.

## Sign in, install the skill and verify

Run these in order:

```bash
evolink auth login
evolink skills install
evolink balance --json
```

In the browser, check the EvoLink account and requesting client, then select **Allow and connect**. Credentials are stored in the operating system's secure credential store. You do not need a platform API key, and the CLI does not fall back to plaintext files when secure storage is unavailable.

A successful `balance` verifies the CLI connection. Also ask your agent to confirm discovery of `evolink-cli`. An executable or skill file alone does not verify the whole setup. See the unified prompt in [Quickstart](/en/mcp/quickstart).

## Target one agent

### One-command setup in 0.6.0

```bash
evolink setup --agent codex --json
```

Replace `codex` with your agent type. This checks prerequisites, reuses or completes sign-in, synchronizes the skill and verifies the connection for free. It does not create paid media tasks. Still ask the current agent to confirm it can read `evolink-cli`; the separate commands above remain available.

Use `evolink skills status --agent codex --json` to check skill version and content, and `evolink doctor --agent codex --json` for prerequisite, connection, model and skill diagnostics. Modified skills are protected. If you choose to replace them, use `evolink skills install --agent codex --replace-modified`; replaced files are backed up.

`auth login` and `setup` accept `--timeout 600` to extend waiting: 30–900 integer seconds, default 180. Keep the initiating command running and forward the callback port reported by the terminal when using SSH.

### Install the skill for one agent

The default `evolink skills install` covers the supported skill directories. You can target one agent:

```bash
evolink skills install --agent codex
evolink skills install --agent claude-code
```

Supported names: `all`, `codex`, `claude-code`, `cursor`, `gemini`, `opencode`, `copilot`, `openclaw`, `hermes`. The skill is named `evolink-cli`. It runs CLI workflows and does not register native MCP tools.

## Status, logout and updates

```bash
evolink auth status --json
evolink auth logout
npm install -g @evolinkai/cli@latest
```

Sign in again after logout. After upgrading the package, rerun `evolink skills install` to update the bundled skill. Skill installation does not upgrade the CLI itself.

## Linux and SSH

Persistent Linux login requires a running, unlocked Secret Service credential store and D-Bus in the same user session. Otherwise the CLI returns `credential_store_unavailable`. Node.js or root access alone is not sufficient.

```bash
evolink auth login --no-browser
```

`--no-browser` suppresses browser opening; it is not a device-code flow. The CLI prints an authorization URL and listens on a random loopback port on the **machine running the CLI**. Login times out after approximately three minutes.

If the browser is on another computer, the callback must reach that listener. Inspect the URL's `redirect_uri` for the port, then open an SSH forward in a separate local terminal. Replace `CALLBACK_PORT`, `USER` and `HOST` with the actual port and SSH destination:

```bash
ssh -N -L CALLBACK_PORT:127.0.0.1:CALLBACK_PORT USER@HOST
```

Once forwarding is ready, open that authorization link in your local browser and approve. Do not publish authorization URLs, callback codes or tokens. The CLI does not accept a pasted final browser URL and has no device-code login command.

## Diagnose

```bash
evolink doctor --json
```

The released version checks runtime, login and the balance connection. Read its error code and the [troubleshooting guide](/en/mcp/troubleshooting) if it fails. CLI setup does not require `codex mcp add` or another client's MCP registration command.
