This is local stdio MCP, not EvoLink CLI. Package `@evolinkai/mcp` runs on the client machine with your platform API key and requires Node.js 18+. The `@evolinkai/cli` package instead requires Node.js 22+ and browser OAuth.

## When to use it

Choose local MCP for API-key authentication, stdio-only clients or allowed-directory file access. For terminal agents needing browser sign-in plus upload/download commands, see [CLI](/en/mcp/cli).

| | Remote OAuth MCP | Local stdio MCP |
|---|---|---|
| Runtime | EvoLink server | Client machine |
| Credentials | Browser sign-in | Your API key |
| Billing key | `EvoLink MCP (OAuth)` | Supplied personal API key |
| Files | Public URLs, small base64, one-time uploads | URLs/base64 or files inside allowed directories |
| Tools | 12 tools | Actual connected list; do not assume hosted one-time upload tools |

## Configure

Create or select a dedicated key in [API Keys](https://evolink.ai/dashboard/keys) and set limits. Provide `EVOLINK_API_KEY` through local secure settings or environment variables. Do not share it in chat or commit it.

Stdio command and arguments:

```text
command: npx
args: -y @evolinkai/mcp@latest
```

For clients with JSON MCP configuration, merge this service. `YOUR_API_KEY` is a placeholder filled only on your computer:

```json
{
  "mcpServers": {
    "evolink": {
      "command": "npx",
      "args": ["-y", "@evolinkai/mcp@latest"],
      "env": {"EVOLINK_API_KEY": "YOUR_API_KEY"}
    }
  }
}
```

Prefer secure environment inheritance if supported, instead of duplicating secrets in config. Desktop apps may not inherit a terminal's environment. Follow client instructions, preserve other servers and protect any local file containing a key.

Verify with free `check_balance`. For missing, disabled or expired keys, inspect local configuration and the dashboard. Do not mistake a native MCP error hint for a CLI authentication command.

### Which file to edit

- Cursor: back up `~/.cursor/mcp.json` or project `.cursor/mcp.json` and merge the JSON entry above into `mcpServers`.
- Claude Code: use project `.mcp.json` or user `~/.claude.json`. A local entry can explicitly include `"type": "stdio"`.
- Codex: merge this table into `~/.codex/config.toml`. Supply the key through the secure environment launching the client; `env_vars` contains names only:

```toml
[mcp_servers.evolink]
command = "npx"
args = ["-y", "@evolinkai/mcp@latest"]
env_vars = ["EVOLINK_API_KEY", "EVOLINK_UPLOAD_ALLOWED_DIRS"]
```

- Hermes: merge this entry under `mcp_servers` in `~/.hermes/config.yaml`. Its secure environment supplies the variable value:

```yaml
mcp_servers:
  evolink:
    command: npx
    args: ["-y", "@evolinkai/mcp@latest"]
    env:
      EVOLINK_API_KEY: "${EVOLINK_API_KEY}"
```

If a remote `evolink` entry already exists, choose a method and update that entry. Do not give remote and local services the same name in the same scope. Save and restart/reload the client, verify that it receives the required environment variables, then verify the connection for free. See [manual setup](/en/mcp/setup-methods) for other client paths.

## Allow local uploads

Set `EVOLINK_UPLOAD_ALLOWED_DIRS` to allowed absolute directories. Separate multiple directories with `:` on macOS/Linux or `;` on Windows. Without this setting, local paths cannot be uploaded.

An example allowed directory is `/Users/you/Pictures`. Clients may then use `upload_file` with `file_path` within that directory. Remote OAuth MCP does not accept this field. The per-file limit is approximately 95 MB; formats and 72-hour retention are in [files](/en/mcp/files).

## Billing, updates and migration

Generation charges the supplied personal key, separate from the OAuth internal key. `max_cost_usd` remains an estimate check; see [billing](/en/mcp/billing).

`@latest` requests npm's current release tag but does not guarantee immediate client-cache refresh. Reload/restart and verify versions and tools after upgrading. Use a specific version to pin a release.

Before migrating to CLI or remote MCP, inspect existing services to avoid duplicate connections and skills. Remove only the intended EvoLink entry and preserve other configuration. Revoke sessions through the appropriate client's logout action.
