## Identify your connection

- **CLI:** check `evolink --version`, `evolink auth status --json`, `evolink balance --json`. No native MCP tools in the client does not mean CLI failure.
- **Native MCP:** verify `https://mcp.evolink.ai/mcp`, complete sign-in and actually call `check_balance`.
- **Documentation MCP:** the documentation site's `/docs/mcp` searches documentation only; it is not the media generation service.

## Installed CLI is unavailable to the agent

| Symptom | Next step |
|---|---|
| `evolink: command not found` | Check the agent's PATH and whether installation occurred on another machine/container |
| Old Node version | Use Node.js 22+ in the actual execution environment |
| Skill exists but is not discovered | Run `evolink skills install --agent NAME`, open a new conversation and verify `evolink-cli` discovery |
| Only `evolink-mcp` is discovered | That is the native MCP skill; CLI requires `evolink-cli` |
| Agent command execution is denied | Follow host permission rules; do not switch invocation paths to bypass a denial |

## Login or browser problems

The CLI prints an authorization link you can open manually. Its callback must reach the CLI machine; see [Linux and SSH](/en/mcp/cli#linux-and-ssh). `--no-browser` is not device-code login and does not accept a pasted callback URL.

- `credential_store_unavailable`: check Linux Secret Service, D-Bus and the same user session. Do not replace secure storage with plaintext tokens.
- `login_timeout` or expired consent: start a new login rather than reusing an old URL. CLI waiting lasts roughly three minutes; the consent transaction may live longer.
- Wrong account: log out and sign in again in CLI, or disconnect/reconnect native MCP in that client.
- Claude/ChatGPT has no add-server entry: check version, account and workspace permissions; follow the client guide and official docs.
- Native MCP login succeeded but tools are missing: verify in the current chat first, then open a new chat if needed, then restart the client if still missing.

## Models and input

| Problem | Next step |
|---|---|
| Old model such as Topaz is absent | Search current available models; do not use retired entries from historic indexes |
| Missing prices or parameters | Inspect model docs or select a complete entry; never invent totals |
| Wan duration or GPT image dimensions rejected | Follow returned ranges, pixel and combination constraints; quote again |
| Seed Audio asks for duration but rejects input.duration | Do not add it; use separate `media_seconds` as an illustrative hint and disclose unknown output length |
| Both image and audio references supplied | Follow the model's mutually exclusive input rules |

## Quote failures or different final costs

MCP `max_cost_usd` and CLI budgets protect estimates, not guaranteed settlement. Reference video, incomplete multipliers, token billing and unknown audio duration are explained in [billing](/en/mcp/billing).

CLI errors can include `invalid_input`, `estimate_unavailable`, `uncheckable_cap`, `cost_exceeds_cap`, `price_changed`, `quote_expired` or `quote_session_changed`. Read JSON `error` details, retain the budget, and quote/approve any changed request again. Never silently remove budgets or replace failed quotes with starting prices.

## Timeouts and uncertain submission

- Task ID exists: query it or run `evolink tasks wait TASK_ID --json`.
- Original quote can recover a started submission: `evolink tasks resume --quote QUOTE_ID --json`, retaining the original request ID.
- Quote expired or local records are lost: inspect recent tasks and match model/time first.
- Do not generate again to refresh a preview or status. A new task incurs another charge.

## Download returns 403

Public media access may depend on client characteristics. Default Python urllib has been observed returning HTTP 403 with `error code: 1010`, while an explicit product User-Agent downloaded successfully. Set such a header when your application needs programmatic download. Your own application can use `YourApp/1.0`; this EvoLink client example uses `EvoLinkClient/1.0`:

```python
import urllib.request

request = urllib.request.Request(
    result_url,
    headers={"User-Agent": "EvoLinkClient/1.0"},
)
with urllib.request.urlopen(request, timeout=60) as response:
    content_type = response.headers.get("Content-Type", "")
    # Check status and media type before saving the response in your application.
```

`result_url` is the returned original link. Do not forward EvoLink authentication headers to media hosts. A successful header change does not guarantee every network works. If blocked, report HTTP status, content type and time without publishing secrets or private media links.

## Original opens but thumbnail is gray

Inspect client rendering before generating anything again. MCP provides compatible small previews, but old messages do not update automatically and failed previews can be cached. Query the existing task and retain its original links. See [tasks and downloads](/en/mcp/tasks).

## Local upload/download paths

Check file existence, readability, supported format and size. Download parent directories must exist and destination files must not. Some 0.5.0 filesystem failures are reported as `request_failed`; inspect the command and path. If a reported successful download will not open, check actual file type and HTTP response. Renaming an HTML error page does not make it an image. Do not assume unreleased file-header validation is already available.

## Reporting an issue

Include CLI/client version, connection mode, sanitized command and error code, task ID, timestamp and whether the original file opens. Never include API keys, tokens, verification codes, authorization callbacks or one-time upload URLs.
