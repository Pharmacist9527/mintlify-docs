## Choose an MCP connection

| Connection | Install or connect | Authentication | For |
|---|---|---|---|
| Remote MCP | https://mcp.evolink.ai/mcp | Browser OAuth | Web chat and native MCP clients |
| Local MCP | npx starts @evolinkai/mcp | Platform API key | stdio clients and allowed local uploads |

Remote MCP does not require the local MCP package. Installing CLI does not register a native MCP server. Installing a skill does not sign in or connect tools.

## Local stdio MCP with an API Key

A stdio-only client can launch a local MCP process. It needs **Node.js 18+** and a personal API Key, rather than remote MCP browser OAuth.

<Steps>

<Step title="Prepare Node and a dedicated Key">

```bash
node --version
npx --version
```

Both commands must work with Node 18 or newer. Create a dedicated personal Key with limits in [API Keys](https://evolink.ai/dashboard/keys). Supply `EVOLINK_API_KEY` through the client’s safe environment or secret settings, not agent chat, shared screenshots, or a repository.

</Step>

<Step title="Configure the local launcher">

Choose local/stdio in the client’s MCP settings:

```text
command: npx
args: -y @evolinkai/mcp@latest
```

On first launch, npx retrieves the package. The host communicates over stdio and the local process calls the platform API. Ensure the host can find npx; a GUI application may have a different environment from your terminal. `YOUR_API_KEY` below is a placeholder for private local configuration. Prefer environment inheritance when supported.

```json
{
  "mcpServers": {
    "evolink": {
      "command": "npx",
      "args": ["-y", "@evolinkai/mcp@latest"],
      "env": {"EVOLINK_API_KEY": "YOUR_API_KEY"}
    }
  }
}
```

</Step>

<Step title="Allow directories when local files are needed">

For local-path uploads, set `EVOLINK_UPLOAD_ALLOWED_DIRS` to allowed absolute directories in the process environment. Separate multiple directories with `:` on macOS/Linux or `;` on Windows. Local-path uploads are disabled without this setting. Remote MCP never accepts `file_path`.

This controls local file access, not model format, duration, or size limits. URL/base64 usage does not need local directory access.

</Step>

<Step title="Reload and verify free tools">

Save configuration, enable EvoLink, and reload or open a new session as your host requires. Ask it to call `check_balance` and `search_models` and confirm real results. Starting a process or listing tools alone is not successful account verification.

Local stdio does not provide remote single-use upload tools `prepare_upload` / `get_upload`. Inspect actual `tools/list`. The personal Key has its own limits, not OAuth Key limits.

</Step>

</Steps>

### Claude Code and Codex configuration

With the Key already provided through the safe environment, Claude Code can register using this command instead of the JSON example:

```bash
claude mcp add --scope user evolink -- npx -y @evolinkai/mcp@latest
```

Codex can merge this section to inherit variables from its startup environment:

```toml
[mcp_servers.evolink]
command = "npx"
args = ["-y", "@evolinkai/mcp@latest"]
env_vars = ["EVOLINK_API_KEY", "EVOLINK_UPLOAD_ALLOWED_DIRS"]
```

Reload after updating and inspect the actual version. `@latest` does not replace an already running process. See [central troubleshooting](/en/mcp/billing#mcp-connection) for startup, Key, and local-path failures.

## Other remote MCP clients

The client needs Streamable HTTP, OAuth, and browser callbacks. A client limited to static Keys or stdio should use local MCP above.

<Steps>

<Step title="Add the server">

Create an MCP connection named EvoLink with Streamable HTTP and this URL:

```text
https://mcp.evolink.ai/mcp
```

Do not enter a documentation URL, platform `/v1` URL, or npx command.

</Step>

<Step title="Complete OAuth and enable tools">

Choose OAuth, use the client’s sign-in action, approve in the browser, and return. Confirm the connection and tools are enabled. A static API Key is not this connection’s OAuth token.

</Step>

<Step title="Verify for free">

```text
Use EvoLink to check my balance and search available image models. Do not generate anything yet.
```

After actual balance and model results return, follow the [first media workflow](/en/mcp/overview#workflows). A tool list without successful calls still needs authorization troubleshooting.

</Step>

</Steps>
