## Query existing tasks

MCP `get_task` accepts `task_id` and `wait_seconds` (0–45, default 30). If still running, query the same ID again. CLI:

```bash
evolink tasks get TASK_ID --json
evolink tasks wait TASK_ID --timeout 1800 --json
```

Running tasks may be queued or processing. Completion is `completed`; handle `failed` or `cancelled` as returned. Queries are free. Do not call a `generate_*` tool to check progress: it creates a new paid task.

## Recover an interrupted task

```bash
evolink tasks list --since 2h --type image --limit 10 --json
```

MCP `list_tasks` can also read 1–50 known `task_ids` in one call. ID mode ignores recent-task filters.

Recent tasks cover the whole account, newest first, not just this conversation. Match model, time and task details. Not finding a task on one page does not prove submission failed. With a saved CLI quote whose submission started, use `tasks resume --quote QUOTE_ID` to recover the original request. See [workflows](/en/mcp/cli-workflows).

Ctrl-C, client timeouts and closed windows stop local waiting, not server tasks. MCP and CLI currently provide no server-side cancellation command.

## Deliver results

Include:

- Model, task ID and final status.
- An accessible original-file link for every relevant result.
- Actual charge; do not label an estimate as a final charge.
- Link expiry: results usually expire after 24 hours. Save promptly.

Thumbnails, video first frames and audio cover images are not originals. Music and multi-image tasks may have several results; do not deliver only the first.

## CLI downloads

```bash
evolink download TASK_ID --output ./result.png --index 1 --json
```

`--index` is 1-based and follows the task's `results` array. The parent directory must exist and the destination must not exist. Downloads do not overwrite files and are limited to 1 GiB. Choose the actual media extension; the command does not transcode. Success returns path, byte count and SHA-256.

## Gray or broken images

| Symptom | Check |
|---|---|
| Original opens, inline image is gray | Client preview, cache or decoder behavior; query the existing task and keep the original link |
| Original link also fails | Expiry, HTTP status, connectivity and file access |
| Default Python download returns 403/1010 | Use an explicit product User-Agent; see [troubleshooting](/en/mcp/troubleshooting#download-returns-403) |
| MCP was upgraded but old messages remain gray | Old messages do not refetch previews; query the task for a fresh response |
| Large images such as Qwen render slowly | Compare the small returned preview and original entry point to isolate client rendering; do not regenerate |

MCP attempts compatible thumbnails or video first frames. The client controls placement, dimensions, platform icons and click behavior, so a uniform card cannot be guaranteed. Do not automatically download or re-encode media to bypass host display restrictions. Use CLI download when the user requests saving the file.
