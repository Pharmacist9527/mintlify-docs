## Rate limits and retries

Limits may apply per account, path, model and user group; API keys belonging to the same account can share account limits. QPS and RPM are different windows. Use your effective account configuration and the 429 response rather than assuming one fixed limit for all endpoints. A requests-limit header may describe a minute quota rather than QPS. Cache `/v1/models` results, coalesce duplicate initialization calls, and briefly cache `/v1/credits` according to your balance freshness needs. On HTTP 429, honor `Retry-After`, use bounded retries with random backoff, and avoid synchronized retries across instances. For a limit review, provide the request time, path and request ID. Generation and task-query limits are evaluated separately.
