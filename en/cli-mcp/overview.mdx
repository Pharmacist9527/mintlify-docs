Use EvoLink from your agent to generate images, video, music, and speech, discover models and costs, upload references, track tasks, and save originals. Choose a connection method, then follow its installation and free verification guide.

## Choose a connection method

| Where you work | Recommended route | Installation and authentication |
|---|---|---|
| Claude chat or ChatGPT | [Remote MCP](/en/mcp/overview) | Add a connection and authorize browser OAuth; no CLI installation |
| Codex, Claude Code, Cursor, OpenClaw, or Hermes with terminal execution | [CLI](/en/cli/setup) | Install the CLI, sign in, and install/load the skill |
| Terminal, SSH, or scripts | [CLI](/en/cli/setup) | Install in the execution environment; SSH has separate callback steps |
| A terminal agent using native MCP tools | [MCP client guide](/en/mcp/overview#choose-your-assistant) | Configure and authorize the host connection directly |
| A client supporting only local stdio | [Local MCP](/en/mcp/other-clients#local-mcp) | Configure a local process, Node.js, and a personal API Key |

Codex CLI is your agent client; EvoLink CLI is the media tool it calls. They are different products. Each card recommends one route; CLI client guides also link to the native MCP alternative.

## Verify before generating

<Steps>
  <Step title="Install and authenticate your chosen route">
    Follow the five-step [CLI installation](/en/cli/setup) or your [MCP client guide](/en/mcp/overview#choose-your-assistant). Complete browser sign-in yourself. Keep Keys and tokens out of chat.
  </Step>
  <Step title="Query balance and models, and verify skills or tools">
    CLI users query balance, run doctor, and ask the agent to confirm skill discovery. MCP users actually call check_balance and search_models. Installed files or a tool list do not establish successful execution. These checks do not submit paid media tasks.
  </Step>
  <Step title="Review the plan and estimated cost before approving generation">
    Check the exact model and inputs, prepare references, and review the plan and estimate. After explicit approval, submit once, retain the task ID, and save originals. See [CLI workflows](/en/cli/workflows) or [MCP workflows](/en/mcp/overview#workflows).
  </Step>
</Steps>

## How the routes relate

CLI media requests follow `Agent / terminal → CLI → platform API`. Native MCP follows `Agent → remote or local MCP → platform API`. CLI media execution does not depend on remote MCP. Sign-in uses Passport; uploads and original downloads have separate file endpoints.

Installation, sessions, and connection checks are separate. Same-account OAuth can currently share internal Key permissions and quotas. Use one route for the task. Recover unknown submissions through the original route rather than generating again through the other.
