This page maintains business rules shared by CLI and MCP. See [CLI reference](/en/cli/reference) and [MCP reference](/en/mcp/tools) for exact inputs. It describes released CLI 0.14.1 and MCP 1.12.1. For search fees, check the actual returned `search_charges`.

<span id="models" />
## Choose a model

1. Identify the task: image generation/editing, text/image-to-video, music, or speech. Specify count, quality, duration, references, and budget.
2. Query the account-available catalog, use its exact model ID, and inspect the schema. Family names, aliases, and display names are not automatically submission IDs.
3. Compare suitable newer or recommended families, then explain quality, reference support, cost, and expected wait. Do not claim measured popularity without platform statistics.
4. Check required fields, ranges, and mutually exclusive inputs before estimating the final request. Reconfirm after changing models or inputs.

Families worth comparing include GPT Image 2.5/2.0 and Seedream 5.0 for images; Seedance 2.5/2.0 and Wan 3.0 for video; Suno v6 for music. These are search directions, not guarantees of account availability. Choose speech models for narration. Example models illustrate workflows rather than a default recommendation.

| Information | CLI | MCP |
|---|---|---|
| Available models | `models search`, `models recommend` | `search_models`, `recommend_models` |
| Parameters and limits | `models show`, `models schema` | `get_model` |
| Model documentation | `docs search` | `search_docs` |
| Estimated cost for final inputs | `estimate` | `estimate_cost` |

<span id="pricing" />
## Read an estimate

| Status | Meaning | Action |
|---|---|---|
| `estimated` | Estimated amount; actual settlement still applies | Present the plan, amount, and known limitations, then obtain approval |
| `partial` | Missing pricing factors | Do not treat as a complete total; identify and resolve missing factors |
| `token_billed` | Reference price for GPT Image, Gemini Omni Flash and Qwen TTS token models: what EvoLink reserves at submission; billed by actual tokens | Show it as a reference price, not a fixed total; the task settles at actual tokens, refunding or charging the difference |
| `needs_input` | Required input or billing usage missing | Read `missing_usage` and `usage_help`, supply what they name, and estimate again |
| `no_price` | No usable price | Do not describe as free or submit automatically |

GPT Image token models (`gpt-image-1.5`, `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`, `gpt-image-2.6-flare`, `gpt-image-2.6-sunburst`) return `token_billed` with a reference price: the credits EvoLink reserves at submission for the exact input, from the output tokens for the size and quality, the prompt tokens, and 1,536 tokens per reference image or mask, times `n`. With `size` set to `auto` it counts a 2048×2048 output, so setting a size gives a closer reference price. A `gpt-image-2.6` GIF counts the one image all its frames are drawn on (512×512 frames when `size` is `auto`). The task settles at the tokens it actually uses, so the final charge may be lower or slightly higher. Token counts in `pricing_parameters` are not used for these models. An explicit `max_cost_usd` must cover 1.5 times the reference price.

Gemini Omni Flash video models (`gemini-omni-flash-*`, `gemini-omni-1.1-flash-*`, `gemini-omni-1.2-flash-*`) also return `token_billed` with a reference price, counted the way EvoLink reserves at submission: video output tokens for the output's resolution and duration, the prompt tokens, 2,020 tokens per input image, and the tokens of any input or reference video. With an input or reference video, give its length as `media_seconds` (MCP) or `--media-seconds` (CLI); for several reference videos, give the longest one's. Without it there is no reference price, and the estimate asks for it. The request does not carry a video's resolution, which EvoLink reads at submission, so the reference price counts it at 4k and the estimate also lists the price at each input resolution: 360p, 720p, 1080p and 4k (`reference_usage.input_resolution_prices`); show the user these prices. Token counts in `pricing_parameters` are not used for these models either, and `max_cost_usd` is compared with 1.5 times the reference price. The task settles at the tokens it actually uses.

`qwen-audio-3.1-tts-flash` returns `token_billed` with a reference price as well, counted from the text the way EvoLink reserves at submission. Token counts in `pricing_parameters` are not used, `max_cost_usd` is compared with 1.5 times the reference price, and the task settles at the tokens it actually uses. `hot_fix: null` is read as no `hot_fix`.

Usage given as 0 that would price a generation at 0 counts as missing: no media generation is free.

<span id="missing-usage" />

When a model's price depends on usage the input does not give, such as the length of a reference video, the estimate returns no amount and no approval: `total_known` is `false`, `missing_usage` names each missing value, and `usage_help` says how to supply it, with `media_seconds` or `pricing_parameters` in MCP and `--media-seconds` or `--pricing-parameters` in CLI. Generation refuses such a request before submitting (`quote_usage_required`). A `partial` estimate keeps the priced part and names what else the total depends on. `get_model` and `models show` list the usage a model's price needs in `billing_usage`. Supply measured or explicitly expected values; do not invent them.

Estimates read the settings EvoLink bills by. Midjourney `speed` and `type` come from `model_params`; Seedream 5.0 Pro is priced at 2K when `size` or `quality` makes the output 2K; MiniMax H3 and H3 Max reference-to-video count reference images beyond the free ones. Tencent video upscale needs the source frame rate as `pricing_parameters.output_fps` unless `model_params.max_fps` is `"30"`. Seedance draft-to-video assumes the draft was made without the content filter unless `pricing_parameters.content_filter` is `true`.

Check `input_valid`, `problems`, `basis`, and `warnings`. Catalog starting prices are not complete request quotes. Resolution, sound, references, actual input duration, and audio billing methods can affect costs.

For Seedance 2.5 generation, `draft: true` with omitted `quality` uses `480p`. When the estimate returns `effective_input` and `defaults_applied`, show those effective settings before approval; generation uses the same settings. Draft-to-video conversion has separate inputs. Model-specific checks do not transfer to other model IDs or operations.

For `seedance-2.5-video-edit`, `input.duration: -1` selects editing. Expected output seconds for pricing belong in `pricing_parameters.duration_seconds`; they do not replace the generation setting or establish final usage.

Search defaults to off for seven media routes: `doubao-seedream-5.0-lite`, `gemini-3-pro-image-preview`, `gemini-3.1-flash-image-preview`, `gemini-nano-banana-2.1`, `seedance-2.0-text-to-video`, `seedance-2.0-fast-text-to-video`, and `seedance-2.5-text-to-video`. Seedream enables it with `model_params.tools: [{"type":"web_search"}]`; the others use `model_params.web_search: true`. Gemini 3.1 Flash Image and Nano Banana 2.1 also support independent `model_params.image_search: true`.

Keep model web and image search off unless the user explicitly requests or approves enabling it. Never enable search on your own or just because a copied example enables it. If the agent thinks search is needed, first explain the extra per-search rates and unknown total, then wait for explicit consent before enabling it. Approval of a task without search does not authorize adding search; changed search settings need a fresh estimate and approval. These are assistant instructions; the server does not verify conversational consent.

Do not add a search-fee warning when search is off. When the final input enables search, even when the user requested it, disclose the current unit rate for each enabled type before generation approval. Missing counts produce a `partial` known-cost subtotal assuming zero searches, excluding search fees. Other unknown usage, such as text/thinking tokens, is also excluded. A single task may perform no searches or multiple searches; actual counts depend on the task and model strategy, so total search fees are unknown before generation. Web and image searches are billed separately.

`pricing_parameters.search_count` and `image_search_count` describe expected usage, not execution limits. Expected zero does not disable search. An incomplete estimate cannot check an explicit user budget. Do not invent counts to remove unknown usage. If an older client treats enabled search with no expected count as a complete estimate, update the client before approving that quote.

Released clients mainly use public default prices, not complete account discounts, measured usage, or account-settlement Quotes. New endpoints or code candidates do not establish production adoption. Pause when pricing or budget comparison is incomplete. The reference conversion is about 68 credits per $1; use actual responses and account records.

<span id="approval" />
## Approval and budgets

Show the exact model, final inputs, output specifications/count, estimated cost, and limitations. Obtain explicit approval for this generation. An approval holds for 24 hours from the estimate, for the same input at the approved price or lower. Generation estimates again before submitting and proceeds when the price is unchanged or lower, also under later pricing rules. A higher price (`price_changed`), a changed model, input or reference (`quote_input_changed`), a different account, or an approval past its expiry (`quote_expired`) needs a new estimate and approval.

| Constraint | Current meaning |
|---|---|
| Account sign-in | Access to account services |
| Host command/tool permission | Permission for the agent to execute an operation |
| Per-task cost approval | Acceptance of this plan and estimated cost |
| Explicit `max_cost_usd` | Pre-submission estimate comparison in released clients (a reference price must fit 1.5 times); **not a final charge cap** |
| Platform Key quota | Account daily/total limits and access policies |

These are separate checks. Sign-in and host permission do not approve a charge. Do not remove budgets, change Keys, or switch routes to bypass rejection. Final caps require corresponding server support; current documentation cannot promise settlement never exceeds an estimate budget.

CLI stores a local `quote_id` and submits with `--confirm`. Native MCP keeps inputs, estimates, and explicit approval in the agent workflow; it has no CLI quote file or session-level server approval button. See [CLI approval](/en/cli/billing#pricing) and [MCP approval](/en/mcp/billing#pricing).

<span id="skip-estimate" />
### Generating without an estimate

When the user explicitly says not to estimate or confirm (for example "generate directly"), the agent submits without a quote: `skip_estimate: true` in MCP, `--skip-estimate` in CLI. The scope is what the user said: this task, this batch, or every later generation in the conversation. The agent never infers it from silence, the balance or its own suggestion. When the user opts out for the rest of the conversation, the agent says once that later generations will be submitted without asking; a new conversation, or asking to restore estimates, brings them back. Invalid inputs and an explicit budget are still checked, search still needs approval, and the task is charged by actual usage. When an estimate fails or has no total and the user has not opted out, the agent asks once whether to generate anyway at actual usage.

<span id="batches" />
### Several tasks of one model

One estimate covers up to 50 inputs of one model (MCP `inputs`, CLI `--inputs-file`): it returns each input's price, the total, and one approval for exactly that batch. After approval, one call submits every input at once and returns the task IDs without waiting; collect the results with `list_tasks` or `tasks batch`. If some inputs were not submitted, finish the batch with the same request ID and exactly the same inputs: in MCP, call again with the same `client_request_id` within 24 hours of the first submission (estimate again first if the approval has expired); in CLI, run `tasks resume --quote` within 23 hours of the first submission, while the quote is unexpired and the price has not risen. Accepted inputs return their original tasks without a new charge. Within that window, never resubmit accepted, not-submitted or unknown-outcome inputs under a new request ID. After it, check which tasks exist (`list_tasks`, `tasks batch` or `tasks list`) and submit only the inputs that did not go through, as a new batch with a new estimate and request ID. Some models, such as GPT Image, often return fewer images than `n`, so use one input per image.

<span id="authorization" />
## Permissions, balance, and quotas

Same-account CLI and remote MCP OAuth can currently share internal Key permissions, quotas, and paused status. Changes affect its consumers, while CLI and host sessions remain separate. Local stdio uses its configured personal API Key.

Model, balance, and task queries do not submit media generation. Generation is billed; uploads have separate file-service limits. Resolve insufficient funds, quota, or access in the relevant account settings. Reauthentication cannot add funds or unpause a Key.

A failed task (`status: failed`) is not charged; the credits reserved at submission are returned automatically. Timeout, sign-out, or closing a page do not establish no charge or a refund. Say a refund has arrived only from explicit billing evidence; usage queries are not complete statements.

<span id="troubleshooting" />
## Empty search, invalid inputs, or incomplete pricing

1. Broaden wording while retaining required task/reference capabilities; check account and permissions.
2. Read this model's schema again and check fields, enums, ranges, and mutually exclusive references.
3. Estimate final inputs and follow the status table. Do not fill unknown factors with starting prices.
4. Reconfirm requests not yet submitted. For submitted or unknown requests, [recover first](/en/cli-mcp/tasks-and-files#recovery).

See [CLI model troubleshooting](/en/cli/billing#models-and-pricing) and [MCP model troubleshooting](/en/mcp/billing#models-and-pricing) for route-specific actions.
